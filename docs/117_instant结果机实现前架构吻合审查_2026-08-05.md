## 二、现网可复用资产（应保留，勿重造）

| 资产 | 位置 | 对 instant 的价值 |
|:-----|:-----|:------------------|
| 三轴字段 | `lottery_draws.activity_kind / experience_type / result_mode` | `result_mode=instant` 已可存；模板默认仍 manual（防说谎） |
| 一身份一 entry | `idx_entries_unique(tenant, draw, type, value)` | 「同一用户」= 同一 entry，与 116 一致 |
| 参与闸门 | `joinDraw`：open + 时间窗 + 黑名单 + 模式 + 容量 | spin 应 **复用同一套活动可参与条件**，另加 left≥1 |
| 有效邀请 | `recordAttributedJoin`：仅新 join + ref → `joinedCount+1`；自邀拒绝 | 榜与裂变归因 **P0 零改** |
| 邀请榜 | `GET viral-leaderboard` + `aggregateViralInviteCounts` | 只留邀请榜 → **算法可原样复用** |
| 延迟裂变公式 | `viral-weight.ts`：`1+min(invited×per, maxExtra)` | **仅 delayed**；instant 须 **分路径**（+spins），禁止塞进加权抽样 |
| 锁码 CAS | `performDraw`：SELECT available → UPDATE WHERE id+available | spin 中奖应 **同模式**；注意 `winnerId` 现绑 entry（见 P0-4） |
| 邮件不回滚 | 通知 fire-and-forget | spin 中奖邮件同原则 |
| 幂等/提交 | `activity_submissions.idempotency_key`（索引未 UNIQUE） | spin 应更严：`UNIQUE(tenant, draw, idempotency_key)` |
| 结果族 | `my-result` 的 `resultFamily` | lottery 族可扩展 `wins[]`，勿再只 `limit(1)` |
| 发布预检 | `publish-check-service` 码量 vs 档位名额 | instant 须扩展 maxSpins / 权重 / 拒绝 scheduled 自动开奖 |
| Cron 纵深 | `processDueDraws`：`activityKind=lottery` + `drawTrigger=scheduled` | 仍 **缺** `resultMode≠instant` 过滤（P0-2） |
| 模板诚实 | `lottery-wheel` 默认 `resultMode=manual` + 单测锁 | 上线 instant 须 **新模板**，勿改现模板默认骗运营 |

## 三、P0 — 不修则无法闭环 / 必坏（实现顺序建议）

### P0-1  schema：`lottery_winners` 每 entry 唯一

| | |
|:--|:--|
| **现网** | `idx_winners_unique` = `UNIQUE(tenant_id, draw_id, entry_id)`（`schema.ts`） |
| **116** | 一人多奖 → 同一 entry 多行 winner；改为 `UNIQUE(tenant, draw, spin_id)` + 新建 `lottery_spins` |
| **不改后果** | 第二次中奖 INSERT 冲突 → 500 / 事务回滚；产品「多奖」无法落地 |
| **最佳实践** | 审计表（每次 spin 一行，含未中）+ 中奖表 1:1 spin；delayed 仍应用层保证一 entry 一奖 |
| **吻合度** | 与现网「中奖与 drawn 同事务」哲学一致；**迁移兼容旧数据** 必做 |

**实现顺序**：先 migration 草案（可空 spin_id 旧行）→ 再业务。

### P0-2  结果机互斥：`performDraw` / Cron / 管理端「立即开奖」均未拒 instant

| 入口 | 现网事实 | 缺口 |
|:-----|:---------|:-----|
| `performDraw` | 只 CAS `status=open`，**不读** `resultMode` | 若运营把 lottery 配成 instant，仍可整池开奖 → **双结果机** |
| `POST .../draw` | 仅 `activityKind === "lottery"` | 同上 |
| `processDueDraws` | `lottery` + `scheduled` + `drawAt<=now` | **无** `resultMode` 过滤；instant 若误配 scheduled+drawAt 会被 Cron 抽 |

| 116 要求 | 三入口对 `resultMode===instant`（及未来明确 instant 活动）**硬拒绝**；管理端隐藏按钮；发布预检禁 scheduled 自动开奖 |
| **最佳实践** | 单一结果机原则（docs/115/116）；与 claim 的 `resultMode=instant` 文案勿混——claim 不是概率 spin |

### P0-3  无 `lottery_spins` / 无 entry 次数字段 / 无 `maxSpinsPerEntry` 持久化

| 116 | 现网 |
|:----|:-----|
| `lottery_spins` + entry.`spins_left` / `spins_total_granted` | **表字段均不存在** |
| 活动 `max_spins_per_entry` 或 `activity_config.instant` | **无**；`activity_config` 现用于问卷/投票/reward |
| join 发 initial spins | join **只插 entry**，不发次数、不抽奖（正确 for delayed） |

| 不建后果 | 无法实现「1=只抽一次 / N 次」；无法审计未中；无法幂等回放 |
| **存放建议（吻合现网）** | 列优先：`lottery_draws.max_spins_per_entry` 或 versioned `activity_config.instant.maxSpinsPerEntry`；与 `promotion_config.viral` 分离（导流 JSON 已承担 delayed 裂变，instant 次数硬顶更宜活动级列或 `activity_config.instant`） |

### P0-4  码锁 `prize_codes.winner_id` 语义绑 entry

| 现网 | `performDraw` 锁码：`winnerId: entry.id`；再 `WHERE winnerId = entry.id` 回查 |
| 多奖冲突 | 同一 entry 第二次中奖时，按 `winnerId=entry.id` **可能命中第一次码**，回查/对账歧义 |
| 最佳实践 | `winner_id` 指向 **`lottery_winners.id` 或 `lottery_spins.id`**；或新增 `spin_id` 列；CAS 仍按 code.id |
| 116 | 建议 `lottery_spins.prize_code_id` + winners.prize_code_id |

### P0-5  `my-result` 单行 winner + 单码契约

| 现网 | `select ... lottery_winners ... limit(1)` → 单 `won` / 单 `prizeCode` |
| 116 | `wins[]` + `spinsUsed` / `spinsLeft` / `maxSpinsPerEntry` |
| 不改后果 | 第二奖对用户不可见；导出/邮件若仍按 entry 去重会丢奖 |
| 吻合 | 保持 `resultFamily`、JWT/OTP 防枚举、限流；**只扩展 payload** |

### P0-6  管理端 / API 已允许 `resultMode=instant`，但无结果机

| 现网 | `RESULT_MODES` 含 `"instant"`；`defaultResultMode` 对 lottery 仍 manual/scheduled；**模板禁止 lottery 默认 instant**（有单测） |
| 风险 | 手工 PATCH/API 可把 lottery 设成 instant → 公开页文案「即时」+ join 无 winners → **语义说谎**（docs/115 已防模板，未防手改） |
| P0 处置 | 发布预检：`lottery + instant` 在 spin 未上线前 **error**；上线后改为强制 maxSpins+权重配置 |

### P0-7  无 `POST .../spin`；转盘仅参与庆祝

| 现网 | `WheelGame`：`spinning` = 参与成功氛围；无服务端 prizeIndex |
| 公开路由 | 无 spin 端点 |
| 116 | 独立 spin + Idempotency-Key + 服务端 `prizeIndex` 后停扇 |

### P0-8  裂变激励路径仍是「加权票」文案与字段

| 现网 | `promotion_config.viral.extraEntriesPerInvite` / `maxExtraEntries`；`my-viral-stats` 返回 `extraEntriesEarned` / `drawWeight` |
| 116 instant | `extraSpinsPerInvite` / `maxExtraSpins` + **双顶** `min(..., maxSpins-granted, maxExtra-viralEarned)` |
| 风险 | 若 instant 误调 `computeViralDrawWeight` 进单次概率 → 架构级错误 |
| 榜 | **可不动**；激励字段与 i18n 必须分键（现网 viral-copy 已锁 delayed 诚实） |

### P0-9  并发与幂等门禁（实现期硬测，设计已写 116）

必须在 P1 编码时用测试锁住（现网 performDraw 已有并发/CAS 文化）：

- 同 entry 并发 spin 不超 `maxSpinsPerEntry`
- 同 Idempotency-Key 不双扣、不双发码
- 码池并发 CAS 不超发
- 裂变 actual 双顶；榜 +1 与 actual=0 可同存

## 六、架构吻合矩阵（116 决策 × 现网）

| 116 决策 | 与架构是否吻合 | 证据 / 动作 |
|:---------|:---------------|:------------|
| 独立 spin 结果机 | **是** | 与 experience≠result、claim instant≠lottery 一致 |
| 禁止改装 performDraw | **是** | performDraw 是池抽样 + drawn 终态；instant 是热路径多次 |
| maxSpinsPerEntry 活动可配 | **是** | 同 draw 级配置族（winnerCount、promotionConfig） |
| 1=只抽一次 | **是** | entry 唯一 + used≤max |
| 一人多奖 | **需迁库** | 现 UNIQUE 挡多奖 |
| 只留邀请榜 | **完全吻合** | leaderboard 已是 invitedCount；不做手气榜 |
| 裂变 +spins 双封顶 | **模式可对标** | 对标 `maxExtraEntries`；**字段与路径须新建** |
| 码 CAS | **可复用模式** | 修 winner_id 语义 |
| 邮件不回滚 | **可复用** | 已是原则 |
| 多租户 tenant_id | **必须贯穿** | 现网查询习惯良好 |
