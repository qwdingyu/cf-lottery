# 076 上线前 UX 死磕：开奖邮件失败与公开页状态闭环

> 日期：2026-08-04  
> 原则：死磕用户路径；低成本；有证据；不拆巨页、不改 API  
> 承接：docs/074–075、docs/055a

---

## 一、问题（代码证据）

| 路径断点 | 证据 | 用户感受 |
|----------|------|----------|
| 开奖后一律 success toast | `handleDraw` → `adminDrawDone` 再 `viewWinners` | 邮件失败被「开奖完成」盖住 |
| 邮件失败计数 vs 展示不一致 | `countLotteryEmailFailures` 用 `notificationStatus==='failed'`；`emailStatusLabel` / pending 用 `emailSent`/`emailError` | 后端 winners **只有** notification* 字段 → 失败可能显示成「待发送」，重发条不稳 |
| 中奖弹窗重发是 ghost 小按钮 | `btn btn-ghost btn-xs` | 失败主路径不够显眼 |
| Dashboard 邮件失败 → `/admin/draws` | 无 status 筛选 | 运营要自己翻 drawn |
| 公开 draft/paused | 仅 `statusPathHint` 一句 + 无按钮 | 「不能参与」无下一步 |

---

## 二、本轮改动

### 1. 邮件状态同源

- `isWinnerEmailSent/Failed/Pending`：`notificationStatus` 优先  
- `emailStatusClass` / `emailStatusLabel` / pending 计数统一  
- `drawDoneFeedbackKind`：开奖后 toast 分档（失败 / 待发 / 空池 / 成功）

### 2. 开奖 → 名单 → 重发闭环

- 先 `viewWinners`，再按邮件态 toast（失败用 **error**）  
- 失败 notice：危险色 + 说明「结果已保存不回滚」+ **主按钮重发**  
- 查看结果后缓存 `drawEmailFailHints`：drawn 行「查看结果」升 primary  
- Dashboard 待办 → `/admin/draws?status=drawn`；列表 onMounted 读 `status` query

### 3. 公开页非 open 状态

- `lottery-public-ux`：primary/secondary CTA 启发式  
- draft/paused：**刷新状态** + **复制链接**；横幅 warn 色  
- drawn：查结果 / 登录查询  
- 标签色：draft/paused/drawing/cancelled

### 4. 可测

- `ops-utils.email.test.ts`  
- `lottery-public-ux.test.ts`

---

## 三、刻意不做

- 不改 draw / retry-email API 契约  
- 列表不 N+1 拉 winners 预填失败数（仅打开结果后缓存）  
- 不重写 AdminLotteryView / LotteryView
