# 连续签到递增奖励 P0 实现（docs/172 P2 P0）

## 背景

基于真寻Bot签到奖励体系分析（docs/172），cf-lottery 需要实现连续签到递增奖励机制，
以激励用户每日签到，提升活跃度。社群玩法只保留最简闭环：**签到增加次数 → 抽奖消耗次数** ± 裂变邀请，坚决不做积分商城。

## 设计决策

### 奖励模式（4种）

| 模式 | 描述 | 计算公式 | 适用场景 |
|------|------|----------|----------|
| daily | 每日固定值或区间随机 | 固定/随机取[min,max] | 简单奖励，无递增需求 |
| linear | 线性递增 | base + (N-1) * increment | 每天稳定增长 |
| step | 阶梯递增 | base + floor((N-1)/stepDays) * increment | 每N天提升一个档次 |
| cycle | 周期循环 | base + (N >= cycleDays ? bonus : 0) | 每N天发放大奖后重置 |

### 区间随机

所有模式共享 `baseRange: { min, max }`：
- `min === max`：固定值（如 `{min:3, max:3}` 每天固定 3 次）
- `min < max`：区间随机整数（如 `{min:1, max:5}` 每天随机 1~5 次）

### 并发安全

签到去重沿用原有的 `lastCheckinDate < today` 条件原子 UPDATE 机制。
新增 `checkinStreak` 字段在同一 UPDATE 中维护，无需额外事务。
