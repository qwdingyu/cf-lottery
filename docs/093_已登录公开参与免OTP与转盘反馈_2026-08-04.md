# 093 已登录仍弹邮箱验证 + 大转盘无动画：根因与修复

日期：2026-08-04  
触发：`/lottery/demo` 顶栏已显示 `qwdingyu` + 退出，点转盘仍弹「邮箱验证 / 统一认证登录」；转盘几乎无动画。

## 1. 这是怎么设计的？是最佳实践吗？

### 设计意图（历史）

| 轨道 | 存储 | 用途 |
| --- | --- | --- |
| 管理端 L2/L3 | `localStorage.admin_token` | 后台 API |
| 公开参与 L1 | `sessionStorage.lottery_registered_*` + `lottery_session_email` | access-code / verify-join / my-result |

文档（046 / 064 / 084）把 **参与身份** 与 **管理登录** 拆开，原因合理：

1. 商场抽奖路人不需要注册账号 → open 模式邮箱 OTP 门槛最低。  
2. 中奖卡密是高价值秘密 → 不能只靠「本机记得邮箱」免 OTP。  
3. 活动页「退出」不应踢掉运营者后台会话。

**行业对标（Gleam / Typeform 等）**：参与门槛是活动级配置；**已登录用户再参与应免二次验证**。  
我们之前只在 `participation_mode=registered` 或「刚走完 cf-auth 回调写了 sessionStorage」时免 OTP；**管理端密码登录只写 admin_token**，活动页顶栏却用「有 username/email 展示」造成「已登录」错觉——**不是最佳实践，是双会话断层**。

### 截图场景的真实路径

1. 用户用后台账号登录 → 只有 `admin_token`。  
2. 顶栏若曾有 `lottery_session_email` 或用户名展示 → 看起来像已登录。  
3. demo 活动多为 **`participation_mode=open`**。  
4. `handleJoin` 旧逻辑：**仅 registered + registeredToken** 才直参；open 一律 `openLogin` → 邮箱验证弹窗。  
5. 后端其实早已支持：`verify-join` 在 Bearer JWT 且 `payload.email === body.email` 时 **跳过 OTP**（docs/059/084）——前端没用上。

### 大转盘「没动画」

有意设计（docs/055a）：**点击只 emit play，庆祝旋转等 join 成功后 `celebrateKey++`**，避免「未验证先转盘」假开奖。  
但若 join 被 OTP 弹窗打断，`joiningId` 短暂或根本不进 loading，用户感知 = **点了没反应**。时机错误：反馈应在「提交中」就开始，成功后再加速庆祝。

## 2. 修复（本波）

### 后端

- 登录 / 验邮 / 切租户 / 建租户签发 JWT 时写入 **`email` claim**（与 cf-auth exchange 对齐）。  
- 旧 token 无 email：活动页用 `/api/admin/me` 补邮箱再 verify-join。

### 前端

- `hydrateLotterySessionFromAdminToken`：把 `admin_token` 同步进 `lottery_registered_*`（不覆盖已有参与 token）。  
- `LotteryView` 挂载 + `handleJoin`：已登录 open 系 → `verify-join` + Bearer **免 OTP 直参**。  
- password/invite 仅补活动凭证，不强迫再发邮箱码。  
- `WheelGame`：`loading` 时慢速 idle 旋转 + 灯效 + 按钮脉冲；成功后 `celebrateKey` 接棒 2.8s 庆祝。

### 安全边界（仍坚持）

- 无 JWT 仅 sessionEmail → **仍 OTP**（防枚举卡密）。  
- JWT.email 与请求邮箱不一致 → 不授信。  
- registered 仍以 `user_id=sub` 参与。
