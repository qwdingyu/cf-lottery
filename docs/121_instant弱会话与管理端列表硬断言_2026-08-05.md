## 做了什么

### 1. 公开页 instant 决策纯模块

新增 `frontend/src/views/lottery/instant-spin-ux.ts`，从 `LotteryView` 抽出：

| 函数 | 锁住的契约 |
|------|------------|
| `isInstantLottery` | 仅 lottery + resultMode=instant |
| `isPublicGameDisabled` | delayed 已参与禁用；instant left=0 禁用；未知 left 可点 |
| `joinedPrimaryCta` / `isQueryResultPrimaryCta` | left>0 再抽，否则查结果 |
| `accessCodePurposeForIntent` | spin → purpose=query |
| `shouldVerifyCodeGoToSpin` | spin 验证不走 verify-join |
| `resolveInstantSpinClientGate` | 无 Bearer 无 OTP → open spin 弹窗（禁止假一键） |
| `loginModalCopyKeys` | spin 文案 key 与 join 分流 |

`LotteryView` 的 `handleInstantSpin` / 发码 / 验证 / 模板 CTA 已接上述纯函数，避免 UI 与单测双份逻辑漂移。

### 2. 管理端列表决策

`ops-utils.ts` 新增：

- `shouldShowAdminInstantResultTag`
- `adminOpenLotterySecondaryAction` / `shouldShowAdminDrawNowButton`

`AdminLotteryView` 列表标签与 open 行次按钮改用上述函数；instant **不展示「立即开奖」**。

### 3. 路由级弱会话闭环

`auth-and-public.test.ts`：已参与 → join access-code **409** → purpose=query **可发码落库** → 已知 OTP **spin 200 扣次**。
