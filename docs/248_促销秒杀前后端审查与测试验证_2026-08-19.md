## 审查结论

### 1. 超发（不会超发）✅

- **名额超卖**：`joinDraw` 用 `activeParticipantCount` 条件 UPDATE CAS（`< effectiveMax`）原子截单，
  并发下超额被拒绝（测试验证：5 并发抢 3 名额，成功数严格 = 3）。
- **卡密超发**：`handlePaymentCallback` 中 `confirmPrizeCodes`（reserved→issued）+ `acquirePrizeCodes`
  （available 兜底）在**同一事务**内执行，且 `acquirePrizeCodes` 用原子 `UPDATE ... WHERE status='available'`
  子查询逐张领取，不足时整体回滚返回 `[]`，不会出现"确认 N 张 + 兜底领 quantity 张"的超发。
- **回调幂等**：同一 attempt 重复回调被 `isPaidPaymentAttemptStatus` 跳过，不重复发卡（测试验证）。

### 2. 漏发（不会静默漏发）✅

- 卡密不足时订单进入 `paid_fulfillment_failed`，**不静默成功**，entry 保持 pending 占位。
- 运营补充码池后 `retryPaymentFulfillment` 补发，订单恢复 paid。
- 测试验证：回调时卡密被并发耗尽 → 订单 FULFILLMENT_FAILED，补发 3 张后恢复 paid，最终 issued 恰为 3。

### 3. 误发（不会误发）✅

- 回调 6 重防护：验签 / attempt 租户归属 / 渠道一致性 / 金额一致性 / 币种一致性 / 幂等。
- 金额不匹配的回调被拒绝，不发卡（测试验证）。
- 旧 attempt 迟到付款 → `paid_late_needs_refund`，不发卡，等待人工退款。
- 多卡密奖品 fail-closed：`findCodePrize` 命中多个 code 奖品时返回 null 并留日志，不发卡。

### 4. 订单超时释放（会释放）✅

- `expireOverdueOrders` 懒清理（30 分钟默认，systemConfig 可配）：
  - 超时 pending 订单 → expired；
  - 关联 entry → expired（名额释放）；
  - 预占卡密 reserved → available（可被他人复用）；
  - 活动 `activeParticipantCount` 按 quantity 扣减。
- 测试验证：超时后订单 expired、entry expired、卡密全部回 available、名额计数器归零。
- 超时释放后同一身份可复用原 entry 重新预约，不制造第二条参与记录（测试验证）。

### 5. 限购（不会超限）✅

- `maxPerUser=5` 两级防护：路由层 `normalizeFlashSaleQuantity` 钳制单笔数量；
  订单层 `validateOrderPreconditions` 事务内统计已有 PAID/FULFILLMENT_FAILED 订单总件数 + 本次 ≤ maxPerUser。
- 测试验证：已购 4 件后再买 2 件被拒（4+2=6 > 5）。

### 6. 金额权威（服务端计算）✅

- 前端不得提交金额，`calculateFlashSalePrice` 服务端按阶梯价计算权威金额。
- `validateOrderPreconditions` 校验 `amountCents === unitPriceCents * quantity`，不一致拒绝。
- 测试验证：5 件起按 8.9 元/件 → amountCents=4450；金额不一致被源头扼杀拒绝。

## 前端交互

`FlashSaleGame.vue` 是纯展示壳：只展示倒计时/进度/剩余/按钮并 emit('play')，
不调用支付、不扣库存，join 由 LotteryView 主路径完成。无发放逻辑，无资金风险。
