# 195 公开参与时间窗前置拦截与认证弹窗优化（2026-08-11）

## 背景

公开抽奖页存在严重体验断裂：活动虽然 `status=open`，但 `end_at` 已过期时，用户仍可继续点击参与、填写邮箱、发送验证码、校验验证码，直到最终提交参与才看到“不在参与时间内”。这会浪费验证码邮件成本，也会让用户误以为活动仍可参与。

本次修复的核心原则：`status=open` 只代表运营已发布，不代表当前时间一定可参与。公开详情、发码、验证码参与、Bearer 免码参与、前端弹窗入口必须共用同一套“参与时间窗”判断。

## 修复内容

### 后端闭环

- `src/routes/public-lottery.ts` 新增 `resolvePublicJoinWindow()`，统一返回：
  - `canJoin`
  - `joinDisabledReason`
  - `joinDisabledMessage`
  - `serverNow`
- 公开详情接口返回参与时间窗状态，前端可在首屏直接展示“尚未开始 / 已结束”。
- `/public/draws/:slug/access-code` 在生成或发送验证码前拒绝未开始、已结束活动。
- `/public/draws/:slug/verify-join` 在校验验证码、消费验证码、创建参与记录前拒绝未开始、已结束活动。
- `/public/draws/:slug/join` 在快捷直参前拒绝未开始、已结束活动。

### 前端闭环

- `LotteryView.vue` 新增 `joinWindowReason()`、`isDrawJoinable()`、`joinDisabledText()`，让页面入口、游戏入口、统一登录、发送验证码、校验验证码、OAuth 回跳续参加都先检查时间窗。
- 活动不可参与时，底部 CTA 改为展示原因和刷新按钮，不再打开邮箱验证弹窗。
- 统一认证登录上移为推荐入口，邮箱验证码降级为备用入口，视觉样式向 `/admin` 登录/管理后台靠拢。
- `joinDisabledText()` 的兜底不再回调 `statusPathHint()`，避免异常服务端字段组合导致递归。

## 测试覆盖

新增 `src/services/auth-and-public.test.ts` 集成测试：

- 过期但仍 `open` 的活动：公开详情提前标记不可参与，发验证码前拒绝且不写验证码。
- 未开始但仍 `open` 的活动：公开详情提前标记不可参与，发验证码前拒绝且不写验证码。
- 活动过期后 `verify-join` 前置拒绝：不消费既有验证码，不创建参与记录。

## 已执行验证

- `npx vitest run src/services/auth-and-public.test.ts --testNamePattern "open 的活动|verify-join 前置拒绝"`
- `npx tsc --noEmit`

## 发布风险与后续建议

- 当前修复已覆盖公开 Web 参与主链路；后续如果新增小游戏、支付秒杀、社群命令等入口，必须复用服务端时间窗判断，禁止只判断 `status=open`。
- 前端仍保留本地时间兜底判断，但以后端 `canJoin/joinDisabledReason` 为准；若客户端时间漂移，也不会绕过后端。
- 查询结果 `purpose=query` 不受参与时间窗限制，这是刻意设计：活动结束后用户仍应能通过邮箱验证码查询自己的结果。
