# 077 上线前 UX 死磕：邮件轮询收敛与查结果发码闭环

> 日期：2026-08-04  
> 原则：死磕用户路径；低成本；有证据；不拆巨页  
> 承接：docs/076

---

## 一、问题（代码证据）

| 路径断点 | 证据 | 用户感受 |
|----------|------|----------|
| pending 轮询静默结束 | `refreshWinnersStatus` 停轮询无 toast | 运营不知道邮件最终失败还是成功 |
| 查结果要「参与时验证码」 | i18n `codeHint`；UI 无发码 | 开奖后几乎查不到 |
| 已参与 access-code 409 | `if (existing) return 409` | 参与消耗 OTP 后无法再发码 |
| drawn 拒发码 | `status !== "open" → 活动已结束` | 开奖后发码不可能 |
| 未参与也显示「谢谢参与」 | `joined:false` 走 else 分支 | 误导 |

---

## 二、本轮改动

### 1. 管理端：轮询收敛反馈

- `winnersPollSettleKind`：pending 清零 / 变 failed / 触顶仍 pending  
- 停轮询时 toast（失败优先）

### 2. 公开：purpose=query 发码

- `POST /public/draws/:slug/access-code` 支持 `purpose: "query"`  
- query：允许 open/paused/drawing/drawn；**已参与可发**  
- join：语义不变（仅 open；已参与 409）  
- roster：未参与仍要在名单；已参与可发  
- registered query：拒邮箱码（应 JWT 直查）  
- 即使 `enable_email_verification=false`，query 仍发码（my-result 靠 OTP 防枚举）

### 3. 查结果弹窗

- 「发送验证码」+ 冷却  
- 触控 ≥44px、safe-area  
- registered 打开即查  
- `joined===false` 诚实文案

### 4. 可测

- `winnersPollSettleKind` 单测  
- access-code purpose=query 集成测  

---

## 三、刻意不做

- 不新开独立 `/query-code` 路由（复用 access-code + purpose）  
- 不改 my-result 鉴权模型  
- 不 N+1 列表预拉邮件失败数
