# 122 · 上线前 P1 优化：spin OTP 核销与裂变双写

日期：2026-08-05  
场景：发版当日收口审查发现的 P1/P2，**不**纳入未完成的 AdminShell 脏树。

## 1. spin 弱会话 OTP 核销（P1 安全）

### 问题

`POST /spin` 仅 `verifyEmailAccessCode`，成功后**不** mark `used=1`。  
同一 6 位码在过期前可重复用于多次 spin（直到次数用尽），弱于 join 路径。

### 修复

| 点 | 行为 |
|----|------|
| 首次成功 | `consumeEmailAccessCode`（CAS used=0→1） |
| 失败 | 不核销，便于改网重试 |
| 幂等回放 | 若同 `Idempotency-Key` 已有 spin 行 → **免 OTP**、不核销 |
| 新幂等键 | 仍须新 OTP |

辅助：`consumeEmailAccessCode`（`public-lottery-helpers.ts`）。

### 测试

- 成功后同码新 key → 400  
- 同 key 无码回放 → 200 + `replayed`  
- 缺幂等键失败后同码仍可用 → 200  

## 2. instant 裂变配置双写（P2）

管理端 `buildPromotionConfigPayload`：

- 始终写 `extraEntries*`（发布预检）  
- `resultMode=instant` 时额外写 `extraSpins*` / `maxExtraSpins`（runtime 优先）  
- 回填：entries 缺省时读 spins 字段  

## 3. 多奖 UI

`wins.length > 1` 时每行卡密补「点击复制」提示。
