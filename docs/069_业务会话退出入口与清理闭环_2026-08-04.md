# 069 业务会话退出入口与清理闭环

> 日期：2026-08-04  
> 背景：cf-auth 接入后 exchange 会同时写 `admin_token`（localStorage）与 `lottery_registered_*`（sessionStorage）；审计发现首页/Onboarding 缺退出，且管理端退出只清 admin。

---

## 一、问题

| 位置 | 原状 | 风险 |
|------|------|------|
| 首页 `/` | 仅「登录」，不读登录态 | 已登录无法退出；点登录被 guest 守卫踢回后台 |
| Onboarding | 仅「稍后再说」 | 有 token 无租户时无法换号 |
| Admin / Platform 退出 | 只 `removeItem(admin_*)` | 活动页仍像已登录 |
| Lottery 退出 | 手写清参与键 | 与 cf-auth pending/PKCE 清理不一致 |
| 401 处理 | 只清 admin 两键 | 同上残留 |

**不在范围**：IdP（auth.eforge.xyz）全局登出；业务 JWT 无服务端黑名单，`POST /api/auth/logout` 仍为空壳。

---

## 二、方案（最小闭环）

### 1. 纯函数 `frontend/src/composables/business-session.ts`

| 函数 | 行为 |
|------|------|
| `clearLotteryParticipationSession` | 清参与三键 |
| `clearAdminAuthStorage` | 清 admin / impersonation / platform_role |
| `clearFullBusinessBrowserSession` | 管理 + 参与 + cf-auth 临时键（含 pending） |
| `clearLotteryBrowserSessionOnly` | 参与 + cf-auth 临时键，**保留** admin |

### 2. 入口接线

| 入口 | 调用 |
|------|------|
| `useAdminAuth.clearToken` | `clearFullBusinessBrowserSession` |
| `useAdminRequest` 401 | 同上 |
| AdminLayout / PlatformLayout「退出」 | 仍走 `clearToken()`（自动完整） |
| Landing 已登录 | 「进入后台」+「退出」→ `clearToken` |
| Onboarding | 「退出登录」→ `clearToken` → `/admin/login` |
| Lottery「退出」 | `clearLotteryBrowserSessionOnly`（不踢运营后台） |

### 3. 测试

- `business-session.test.ts` 纳入 vitest include  
- 断言：完整登出双边全清；活动页退出保留 admin

---

## 三、验收

- [ ] 未登录首页：仅「登录」
- [ ] 登录后首页：出现「进入后台」「退出」；退出后变回「登录」
- [ ] Onboarding：可「退出登录」到 `/admin/login`，再换号
- [ ] 管理后台退出后，活动页不再显示参与已登录（同一浏览器）
- [ ] 活动页退出后，管理后台 token 仍在（运营预览场景）
- [ ] `npx tsc --noEmit`；`npx vitest run` 相关用例通过

---

## 四、刻意不做

- 不跳转 auth.eforge.xyz 做 IdP logout（无共享 BA cookie，RP 业务会话独立）
- 不引入服务端 token 黑名单
- 不改动密码登录 / OTP 主路径
