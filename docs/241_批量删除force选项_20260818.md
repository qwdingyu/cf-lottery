# 批量删除 force 选项（调试/测试清场）（docs/241）

## 背景

用户需要在调试和测试阶段具备删除功能——当前 `/admin/draws` 批量删除对 `open/drawing` 活动硬性拒绝（`isDrawStatusDeletable`），无法清理测试产生的进行中活动。

## 借鉴 cf-shop 的优点（仅借鉴，不照搬）

| cf-shop 优点 | cf-lottery 适配 |
|---|---|
| `force` 选项（勾选"全部删除"包含非安全状态） | ✅ 新增 `force` 参数：允许删除 open/drawing 活动 |
| 双层门槛 + All-or-Nothing + 409 提示 | ✅ 非 force 时 open/drawing 整批拒绝；force 时放行 |
| 前端选项式确认弹窗 | ✅ 选中含 open/drawing 时弹窗附"包含进行中活动"选项 |

## 关键安全保护（cf-lottery 特有，不照搬 cf-shop）

**`cascadeDeleteDraw` 的 `paymentOrders` fail-closed 保护保持**：
- 有支付订单的活动**永远拒绝删除**（force 也不能删）——防资金事故
- 这是 cf-lottery 与 cf-shop 的本质差异：cf-shop 订单可 force 删，cf-lottery 活动涉及支付回调/退款/补发，必须保护

## 改动清单

### 后端
- `parseBatchDeleteIds`：解析 `force`（true/1/"true"）
- `POST /draws/batch-delete`：非 force 时 open/drawing 拒绝（与单条一致）；force 时放行，但级联仍 fail-closed 保支付
- 审计记录 `force` 标志

### 前端
- `batchDeleteLotteryDraws(ids, force)`：API 封装加 force 参数
- `batchDeleteDraws`：选中含 open/drawing 时用 `askConfirmWithOptions` 提供 force 选项（默认不勾选）；否则普通确认
- i18n：`adminConfirmBatchDeleteForce` / `adminBatchDeleteForceOption`

### 测试
- `admin-batch-delete.test.ts`：force=true 删除 open 活动 + 审计记录 force 标志
