# 140 秒杀功能闭环断裂审查

> 日期:2026-08-08
> 范围:秒杀全链路(创建活动→参与→支付→发卡→用户查卡→运营管理)

## 闭环断裂点(按严重程度排序)

### 已修复：用户支付后订单/卡密找回

- 不能恢复旧的 `GET /api/public/draws/:slug/payment-orders?email=xxx`：仅凭裸邮箱列单会造成邮箱枚举和支付状态泄露。
- 新增 `POST /api/public/draws/:slug/payment-orders/recover`，必须通过当前活动邮箱 OTP。
- `my-result` 成功后，直付活动自动恢复已支付卡密；待支付、过期或可重试订单继续走统一支付入口恢复，并重新签发短期 Bearer。
- 单订单状态/卡密查询仍由 `GET /payment-orders/:orderId` + Bearer 保护。

### P2 after_win CTA 与 paymentRequired 可同时配置

- 直付秒杀 `paymentRequired=true` 时,after_win CTA 跳转外部链接与支付弹窗冲突
- 发布预检无互斥检查

### P2 卡密库存不足无运营预警

- `paid_fulfillment_failed` 后运营需手动查看 AdminPaymentOrdersView → 补发
- 无库存阈值告警、无邮件/日志通知
- 用户体验:已扣款,等待后收不到卡密,需联系客服

### P3 支付后卡密查看无持久入口

- 支付弹窗显示卡密(code+secret),关闭后无"我的卡密"入口
- 付款确认页无引导文案("卡密已发送,请在 xxx 查看")
- 等待轮询的体验无预期时间

### 已闭环(评审通过)

- 创建秒杀活动→配置价格/库存/支付 ✅
- 参与秒杀→flashSale.stockLimit 原子截单 ✅
- 支付→回调→发卡(pending→paid) ✅
- 超时释放→expired+claimed排除 ✅
- 迟到付款→paid_late_needs_refund(落库不补卡) ✅
- 运营查看订单列表+补发卡密 ✅
- 卡密不足→paid_fulfillment_failed(不静默 paid+null) ✅
- 价格上限→systemConfig动态读取 ✅
- OTP 订单找回→已支付展示卡密/待支付恢复支付入口 ✅
