## 紧迫感增强方案（已实施）

### 改动范围

仅修改 `FlashSaleGame.vue`（真实存在的组件）+ i18n。不创建新文件，不伪造数据。

### 具体改动

| 改动 | 位置 | 说明 |
|------|------|------|
| 低库存紧迫提示 | 模板 `flash-urgency` | `remaining ≤ 10` 显示橙色"⚡ 仅剩 N 份，抢完即止！"；`≤5` 转红色"⚡ 仅剩 N 份，手慢无！" + 脉动动画 |
| 按钮动态文案 | `buttonLabel` 函数 | `remaining ≤ 5` 时从"抢"变为"立即抢购（仅剩 N 份）" |
| 按钮紧迫视觉 | `.flash-btn.urgent` | `remaining ≤ 5` 时按钮红色强化 + 红色边框 + 脉动 |
| 售罄引导 | 模板 `flash-soldout-hint` | 售罄后显示"本场已结束，请关注下一场"（如实提示，不制造假按钮） |
| CSS 动画 | `@keyframes flashUrgencyPulse` | 尊重 `prefers-reduced-motion` |

### 不动红线

- 所有数据来自 `props.flashSale`（后端 API 真实数据）
- 不碰支付/下单逻辑（`@play` → `LotteryView.handleGamePlay` → `joinDraw`）
- 不创建新组件/页面
- 不做"预约下一场"假按钮

## 二次审查修复（2026-08-18）

**发现并修复：upcoming/disabled 状态下的紧迫感误报**

`remaining = effectiveStockLimit - claimed` 与活动 phase 无关。upcoming（未开始）时 claimed=0，若 stockLimit 很小（如 5），会误报"⚡仅剩5份手慢无"——但活动还没开始，紧迫感是误导。

| 位置 | 修复 |
|------|------|
| `FlashSaleGame.vue` 紧迫提示 | 加 `phase === 'running' && !disabled` 守卫——upcoming/ended/已参与不显示紧迫文案 |
| `FlashSaleGame.vue` 按钮 urgent 高亮 | 加 `phase === 'running' && !disabled` 守卫 |
| `FlashSaleGame.vue` buttonLabel | 低库存文案加 `phase === 'running' && !props.disabled` 守卫 |
| `LotteryView.vue` merch 区 is-urgent | 加 `draw.status === 'open'` 守卫 |
