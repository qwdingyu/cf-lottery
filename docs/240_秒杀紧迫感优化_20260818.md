# 秒杀紧迫感优化（docs/240）

## 背景

用户反馈 FlashSaleGame 组件（Image #1 主抢购页）缺少紧迫感——文案过于平淡（仅显示"价格/数量/倒计时"），用户容易犹豫或错过。

## 检查结果

### 真实文件结构（vs 幻觉中的文件）

| 幻觉声称的文件 | 真实情况 |
|---|---|
| `FlashSaleCard.vue` | ❌ 不存在——秒杀游戏壳由 `FlashSaleGame.vue` 承载 |
| `FlashSaleModal.vue` | ❌ 不存在——Modal 由 `GameResultModal.vue` 通用组件实现 |
| `FlashSaleView.vue` | ❌ 不存在——秒杀详情页由 `LotteryView.vue` 的 `flash_sale` 分支渲染 |
| 本地 `ref` 剩余 10 份 + 本地 `handleBuy` 扣减 | ❌ 幻觉——真实数据来自后端 API (`props.flashSale.remaining`)，购买走后端 `joinDraw` |
| "预约下一场"按钮 | ❌ 幻觉——后端无预约能力，不能制造假按钮 |
| 已抢 0/10 进度条 + 0% 文案 | ❌ 幻觉——真实进度条已存在（`flash-progress-wrap`），数据来自 `props.flashSale.progressPercent` |

### 真实代码已具备的元素

- 倒计时（upcoming/running/ended 三态，每秒刷新）
- 进度条（百分比，`progressPercent` prop）
- 剩余数量（`remaining` prop，"剩余 {n} 份"）
- 按钮（"抢"/"已抢光"/"本场已结束" 等）
- 信任条（LotteryView 中"平台直付/外链 + 名额锁定 + 限时限量"）

## 紧迫感增强方案（已实施）

### 改动范围

仅修改 `FlashSaleGame.vue`（真实存在的组件）+ i18n。不创建新文件，不伪造数据。

### 具体改动

| 改动 | 位置 | 说明 |
|------|------|------|
| 低库存紧迫提示 | 模板 `flash-urgency` | `remaining ≤ 10` 显示橙色"⚡ 仅剩 N 份，抢完即止！"；`≤5` 转红色"⚡ 仅剩 N 份，手慢无！" + 脉动动画 |
| 按钮动态文案 | `buttonLabel` 函数 | `remaining ≤ 5` 时从"抢"变为"立即抢购（仅剩 N 份）" |
| 按钮紧迫视觉 | `.flash-btn.urgent` | `remaining ≤ 5` 时按钮红色强化 + 红色边框 + 脉动 |
| 售罄引导 | 模板 `flash-soldout-hint` | 售罄后显示"本场已结束，请关注下一场"（如实提示，不制造假按钮） |
| CSS 动画 | `@keyframes flashUrgencyPulse` | 尊重 `prefers-reduced-motion` |

### 不动红线

- 所有数据来自 `props.flashSale`（后端 API 真实数据）
- 不碰支付/下单逻辑（`@play` → `LotteryView.handleGamePlay` → `joinDraw`）
- 不创建新组件/页面
- 不做"预约下一场"假按钮
