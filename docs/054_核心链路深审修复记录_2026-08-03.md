# 054 核心链路深审修复记录

> 日期：2026-08-03
> 背景：承接 `053_核心链路逐文件深审报告_2026-08-03.md` 中已确认的 4 个代码级问题。

## 一、修复清单

### 1. 公开端敏感操作补持久限流

涉及文件：
- `src/routes/public-lottery.ts`
- `src/security-audit-verification.test.ts`

修复内容：
- 新增 `checkPublicRateLimit()`：内存 Map 只做单实例预过滤，最终通过 `checkDbRateLimit()` 写入 `rate_limit_log`。
- 新增 `checkPublicIdentityRateLimit()`：对活动 + 身份再做 DB 限流，身份值先 SHA-256 hash，不把邮箱明文写入限流日志。
- 覆盖端点：`events`、`access-code`、`verify-join`、`join`、`result`、`my-result`、`cancel`。
- `my-result` 和 `cancel` 从“无任何限流”改为 IP + 身份双层限流。

说明：
- 本次复核时，`src/routes/public-lottery.ts` 的持久限流代码已存在于当前基线提交；本轮补充正式回归测试，确保该修复不会被后续改动回退。

回归测试：
- `my-result` 连续 10 次错误验证码返回 400，第 11 次返回 429。
- `cancel` 连续 10 次错误验证码返回 400，第 11 次返回 429。
- 断言 `rate_limit_log` 中存在对应 IP 限流记录。
- 断言身份限流 key 不包含邮箱明文。

### 2. Node IP 解析不再默认信任 X-Forwarded-For

涉及文件：
- `src/lib/platform.ts`
- `src/security-audit-verification.test.ts`

修复内容：
- `CF-Connecting-IP` 仍保持最高优先级，兼容 Cloudflare Workers。
- `X-Forwarded-For` 只有在 `TRUST_PROXY_HEADERS=true` 时才读取。
- 未开启信任代理时返回 `unknown`，避免客户端伪造 IP 绕过限流 key。

回归测试：
- 默认请求只带 `X-Forwarded-For` 返回 `unknown`。
- 显式传入 `TRUST_PROXY_HEADERS=true` 后读取首个代理 IP。
- 同时存在 `CF-Connecting-IP` 和 `X-Forwarded-For` 时优先使用 Cloudflare 头。

### 3. 管理端 token 写入统一走 useAdminAuth.setToken()

涉及文件：
- `frontend/src/App.vue`
- `frontend/src/views/AdminRegisterView.vue`

修复内容：
- Logto 回调成功后调用 `setToken(data.token)`。
- 注册邮箱验证成功后调用 `setToken(data.token)`。
- 不再直接 `localStorage.setItem('admin_token', token)`，避免绕过 8 小时过期时间和 `impersonated_token` 清理。

验证方式：
- `npm run type-check:frontend` 通过。

### 4. maxParticipants 语义统一为“正整数或空”

涉及文件：
- `src/routes/admin-lottery.ts`
- `src/services/lottery/draws.ts`
- `src/services/lottery-service.test.ts`

修复内容：
- 创建活动：`undefined/null/""` 表示未显式传入，走系统配置或套餐默认；显式传 `0`、负数、小数直接拒绝。
- 编辑活动：`null/""` 表示清空；显式传 `0`、负数、小数返回 400。
- 服务层 `createDraw()` 增加兜底校验，防止绕过 HTTP 路由直接调用时重新引入歧义。
- 服务层写库从 `requestedMaxParticipants || default` 改为 `requestedMaxParticipants ?? default`。

回归测试：
- `maxParticipants: 0` 被拒绝。
- `maxParticipants: -1` 被拒绝。
- `maxParticipants: 1.5` 被拒绝。

## 三、剩余风险

- `rate_limit_log` 当前仍按请求写入，公共端高流量场景需要继续依赖既有清理任务控制表规模。
- `TRUST_PROXY_HEADERS=true` 只能在可信反代已覆盖或清洗 `X-Forwarded-For` 时开启；否则会重新引入可伪造 IP 的风险。
- 本次没有实现“连续失败后作废验证码”，只完成了限流闭环；如要进一步降低验证码猜测风险，可作为后续独立小改动处理。
