### 3.3 多租户隔离

- 所有 DB 查询均带 `tenant_id` 过滤
- JWT 携带 `tenantId`，`requireTenantMember` 中间件每次查询数据库校验
- 租户被禁用后，已持有 JWT 的成员立即不可写（检查 `tenants.status`）
- 用户被禁用后，已签发 JWT 立即无效（`requireAuth` 检查 `users.status`）
- 平台成员（platform_members）与租户成员（tenant_members）分离管理

### 3.4 安全防护

| 防护措施 | 实现 |
|----------|------|
| JWT 鉴权 + 用户状态实时检查 | `middleware/auth.ts` 每次请求查 users.status |
| 密码存储 | HMAC-SHA256 + pepper（低 CPU，适配免费层） |
| API Key 存储 | SHA-256 哈希，支持 legacy salt 兼容升级 |
| 支付凭据加密 | AES 加密存储，`enc:` 前缀标识 |
| 公开限流 | IP 级 + 身份级双重限流，验证码约 10 次/分钟 |
| 防枚举 | 查询验证码不消耗验证码（防 OTP 枚举） |
| 支付回调防跨租户 | 路径 tenantId 与订单 tenantId 比对 |
| 支付交易号唯一 | 同一租户同一渠道同一交易号唯一索引 |

## 5. 本轮二次验证新增实现

### 5.1 卡密库存预警（P0-1）

实现位置：
- `src/routes/admin-lottery.ts` — dashboard 端点新增库存预警逻辑
- `frontend/src/views/admin/AdminDashboardView.vue` — 待办事项中展示预警
- `frontend/src/i18n/zh-CN.ts` / `en.ts` — 中英文文案
- `src/routes/admin-dashboard.test.ts` — 8 个测试用例

设计要点：
1. **只查 open 状态的活动**：只有 open 状态才接受参与和支付，draft/cancelled 等不触发预警
2. **只查直付秒杀（paymentRequired=true）**：免费秒杀壳、导流壳不需要卡密，不产生预警
3. **只查码奖品（prizeType=code）**：实物/虚拟奖品没有卡密池，不产生预警
4. **LEFT JOIN 保证 availableCount=0 仍返回行**：码池为空时正确触发 critical 告警
5. **多租户隔离**：查询条件天然带 tenant_id，不同租户互不可见
6. **阈值**：availableCount=0 → critical（红色）；availableCount ≤ 5 → low（黄色）

使用说明：
- 运营者打开后台即可在待办事项看到预警
- 点击预警跳转到奖品管理页（`/admin/prizes`），可导入新的卡密码
- 预警仅在运营台概览展示，不影响用户端支付流程
