# 102 开奖结果：卡密/订单号空白修复

日期：2026-08-04  
触发：管理端「开奖结果」表：邮箱有值，**订单号 `-`、卡密 `-`、邮件「待发送」**；运营质疑「有卡密的活动为何什么都没有」。

---

## 1. 根因（三层叠在一起）

| 层 | 事实 | 后果 |
| --- | --- | --- |
| 产品文案 / 表头 | 仍写「0 元 lottery 订单 + 发卡」「订单号 / 卡密」 | 运营期待电商订单号 |
| 独立孵化 | **故意不创建** `orders`；开奖只写 `lottery_winners` + 锁 `prize_codes`（docs/001） | `orderNo` **本应永远为空** |
| API | `getDrawWinners` **只 `select lottery_winners`**，不 join 码/奖品 | 即便 `prize_code_id` 已有，UI `cardAccountLabel` 仍空 → **卡密列全是 `-`** |
| 测试 | 「完整闭环」创建了 code 奖+码，但 `setupDraw` 默认挂 **manual** 档位，**未断言 prizeCodeId** | 假绿：从未验证锁码水合 |

「待发送」只表示中奖**邮件** `notification_status=pending`（异步发信），**不是**「还没分配卡密」。

---

## 2. 正确语义

```text
开奖成功
  → lottery_winners 行（必有）
  → 若档位 prize 为 code 且码池有 available → 锁码，prize_code_id 非空
  → 若 manual_fulfillment → prize_code_id 空，展示奖品名 + 人工履约
  → 不创建电商 orderNo
邮件
  → 异步 pending → sent/failed；与是否锁码正交
```

管理端列：

| 列 | 内容 |
| --- | --- |
| 邮箱/身份 | identityDisplay / identityValue |
| 奖品 | prizeName / tierName |
| 履约/卡密 | 有码 → code[:secret]；人工 → 标签+说明；code 但未锁 →「未锁定卡密」警示 |
| 邮件 | pending/sent/failed |

---

## 3. 修复

- `getDrawWinners`：水合 tier/prize/`prize_codes` → `cardAccountLabel`、`prizeCode`、`fulfillmentKind` 等；`orderNo: null`
- 管理端结果表 + CSV：去掉订单号主列，按履约展示
- 文案：去掉「自动创建 0 元订单」误导
- 测试：code 档位真正断言锁码；manual 断言无码有奖品名

---

## 4. 运营自检

1. 奖品类型是否为 **卡密**，且码池 **available ≥ 中奖名额**
2. 活动奖项是否绑定该奖品（空 prizeId 不会锁码）
3. 结果表「未锁定卡密」→ 补码后用「补发码」API
4. 「待发送」→ 查 RESEND / 通知开关，不是卡密问题
