## 一、本轮目标

在 **109 公式与公开卡状态机已正确** 的前提下，继续证据级打磨：

1. 不产生 UX/产品幻觉  
2. 核心业务（参与归因 → 统计 → 开奖加权）保持正确  
3. **裂变转化链路**不断：已参与用户随时能复制带 `?ref=` 的专属链接  

---

## 二、证据级断点（非幻觉）

### P0：`POST /my-result` 成功载荷缺 `entryId`

| 事实 | 说明 |
|------|------|
| 后端 | 已查 `lottery_entries` 得 `entry`，但响应**不返回** `entryId` |
| 前端 | `hydrateJoinedStateFromSession` / `queryMyResult` 写 `data.entryId`；`ViralLeaderboard` 依赖 entry 才生成专属链 |
| 后果 | JWT 回访 / 跨设备「查结果」后仍是 **已参与无 entry** → 只能诚实提示，**无法自我裂变** |

### P1：顶栏 / 查结果内分享复制**裸链**

| 入口 | 旧行为 | 问题 |
|------|--------|------|
| `handleCopyPublicLink` | 永远 `/lottery/{slug}` | 已参与用户最显眼的分享按钮**无归因** |
| `shareMyWin` | 仅 `lastJoinResult` 同场快照 | 查结果路径恢复后仍复制裸链 |

### P1：`access-code` 等 409「已参与」不带 `entryId`

重复参与/已参与提示路径只 toast + 开查结果，**本机 hints 无 entry**，公开卡继续「无 entry」态。

### P2：`GameResultModal` 无 shareUrl 时复制 `location.href`

可能把**别人的 `?ref=`** 再扩散，污染归因；且复制失败仍 toast 成功。

---

## 三、修复（闭环）

### 后端

1. **`my-result`**：`joined` 时返回 `entryId: entry.id`  
2. **`access-code` 预检已参与**：409 JSON `{ alreadyJoined, entryId }`  
3. **`joinDraw` UNIQUE / 各 join 入口**：`alreadyJoined` + 回查 `entryId`  

### 前端

1. **`queryMyResult` / hydrate**：`markDrawJoined` + `rememberJoinSuccess` 写入 entryId  
2. **`handleAlreadyJoined`**：接收 409 的 entryId  
3. **`handleCopyPublicLink` / `shareMyWin`**：有 entry 且活动未终态 → `POST /share` 复制 `?ref=`  
4. **GameResultModal**：无专属链不静默复制当前页；复制失败展示错误  

### 文案

- `viralNeedEntryHint`：说清「查结果 → 专属邀请码 → 好友算你的邀请」
