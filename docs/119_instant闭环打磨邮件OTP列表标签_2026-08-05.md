# 119 · instant 闭环打磨：中奖邮件 / spin OTP / 列表标签

**日期**：2026-08-05  
**关联**：docs/116、docs/117、docs/118

## 背景

S1–S10 落地后，docs/118 建议后续三项仍阻塞运营与弱会话体验：

1. instant 中奖后未发邮件  
2. 弱会话再抽时 OTP 弹窗仍走 join 语义  
3. 管理端列表看不出 `resultMode=instant`

## 本轮改动

### 1. instant 中奖邮件（多奖 = 多封）

| 点 | 说明 |
|----|------|
| 触发 | `POST /spin` 成功且 `won && !replayed` → `notifyInstantSpinWinner` fire-and-forget |
| 范围 | 只按 `spinId` 找 winner 行；不扫全表、不重发已 `sent` |
| 文案 | `productName` = 奖品/档位名；同 entry 多奖时 `deliveryNote` 提示「每奖单独一封」 |
| 模板 | `lottery_winner` 文案改为「结果已生成」，脚注说明多奖多邮 |
| 开关 | 复用 `notify_winner_email_enabled`（与 delayed 一致） |
| 失败 | 不回滚 spin |

`sendWinnerNotifications` 新增可选 `winnerIds`，管理端重发仍可全量。

### 2. 弱会话 spin OTP UX

| 点 | 说明 |
|----|------|
| 意图 | 登录弹窗 `loginModalIntent`: `join` \| `spin` \| `login` |
| 发码 | spin 用 `purpose=query`（已参与可发，不 409） |
| 验证 | 不走 `verify-join`，码直接进 `/spin` |
| 文案 | `spinVerifyTitle` / `spinVerifyHint` / `spinVerifyAndGo` |

### 3. 管理端列表标签

- `resultMode=instant` → `tag-info` + `adminResultInstantTag`（即时抽）  
- 其它 lottery resultMode 以 muted 小字展示 `resultModeLabel`

## 测试（强化后）

### 服务层 `spin-execution.test`（确定性，禁止「未中就 skip」）

| 场景 | 断言 |
|------|------|
| 扣次 + 幂等回放 | 同 key 不双扣、单行 spin |
| 单档有码必中 + 多奖 | 两次 `won=true`、不同 spinId/码、winners UNIQUE |
| 码池耗尽 | 仍扣次、`won=false`、无 winner |
| 档位 winnerCount 封顶 | 第二人未中但仍扣次 |
| 按 spin 发信 | productName=奖品名、卡密入信、同 spin 不重发、多奖备注 |
| winnerIds 过滤 | 只发 A，B 保持 pending |
| 开关/无 Key | 不发信、pending |
| 幂等占码 | 回放不二次 issued |

### 路由层 `auth-and-public` · 公开 instant spin

| 场景 | 断言 |
|------|------|
| OTP 门禁 | 无码/错码 400；正确码 200 扣次 |
| 中奖邮件 | 路由 fire-and-forget 发出；回放不二次发 |
| JWT 免 OTP | Bearer.email 一致可 spin |
| 拒单 | 非 instant 400、次数用尽 409、缺幂等键 400 |

### 配额纯函数 `spin-quota.test`

- 双封顶、initial 夹紧、加权边界（含非法 random / 1:3 比例）

### 回归

- 全量 `npx tsc --noEmit` + `npx vitest run`

## 验收

1. instant 中奖后（配置 Resend）收到邮件；二次中奖再收一封，第一封不重发  
2. 弱会话点转盘 →「验证后抽奖」→ 发码 → 验证并抽奖，不重复报名  
3. 管理端活动列表 instant 行可见「即时抽」  
4. **测试不得依赖随机「运气中奖」**：单正权重档 + available 码 → 断言必中
