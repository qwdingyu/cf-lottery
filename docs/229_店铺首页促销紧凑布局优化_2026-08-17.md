# 店铺首页促销紧凑布局优化

## 背景

店铺首页需要具备限时抢购和促销页面的紧凑节奏，但不能为了视觉效果推断后端不存在的库存、售罄或历史活动数据。

## 审查结论

- 店铺公开接口只返回仍未结束的公开活动，因此页面不新增“已结束商品”假数据。
- 现有接口已经提供商品图、价格、秒杀场次、倒计时、进度和剩余数量，适合在前端做信息层级优化。
- 秒杀和普通活动混在同一网格中，会削弱用户对当前促销的注意力。

## 方案

- 秒杀活动独立成首要专区，保留已有倒计时、进度、库存和跳转逻辑。
- 普通活动独立成“更多活动”，作为低优先级浏览内容。
- 普通活动统一使用商品图占位区域，避免无图时卡片高度和标题位置跳动。
- 移动端允许分类筛选横向滚动，避免按钮挤压换行。
- 不修改公开接口、库存计算、支付、订单和开奖业务。

## 活动详情导流闭环

- 公开活动详情接口补充所属店铺的公开 `storeSlug`、名称和品牌信息。
- 深链活动页在顶部操作区提供醒目的“进入店铺”入口，目标为 `/shop/{storeSlug}`。
- 不从活动链接或内部 ID 推断店铺，不暴露 `tenantId`。
- 分享链接仍保持 `/lottery/{publicSlug}`，用户完成当前活动后可以继续浏览同店铺的其他促销。

## 验证重点

- 秒杀和普通活动仍使用原有分类与排序结果。
- 页面只改变展示结构，不改变活动详情链接。
- 中英文文案均补齐，类型检查和全量测试通过。
