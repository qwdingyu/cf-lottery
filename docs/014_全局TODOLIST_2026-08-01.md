## 七、实施建议

### 7.1 立即开始（P0）

1. 解耦 `participation_mode` 与 `experience_type` — 新增字段，不修改现有逻辑
2. 修复游戏组件伪中奖展示 — 刮刮卡/翻牌不展示未确认的奖品
3. 确认 `public_slug` 使用 — 检查所有分享链接逻辑

### 7.2 上线前（P1）

1. 公开端统一状态机 — 让参与者明确知道当前状态
2. 游戏组件无障碍 — 键盘/触摸/无动画
3. UTM 安全 — 不写入身份标识
4. 导流配置版本化 — 为未来扩展做准备

### 7.3 后续迭代（P2-P3）

按照 013 文档的建议，先做共享骨架最多的模式（接龙/预约），再往外扩展。每次扩展时确保不破坏已冻结的顶层抽象。

下一步优先顺序按 019 文档执行：

1. 补 Webhook delivery，做到签名、重试、失败记录和事件幂等键。
2. 为公开前端接入 `activity_events` 自动埋点：page_view、participation_started、participation_completed、cta_click。
3. 把接龙候补转正、通知和导出做成稳定平台能力。
4. 再扩展预约、问卷/资料领取、投票、签到、审核、领券等高复用玩法。
