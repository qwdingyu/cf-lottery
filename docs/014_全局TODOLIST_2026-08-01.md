## 七、实施建议

### 7.1 立即开始（P1 收尾）

1. 建立 `tenant_usage_snapshots` 设计稿：明确统计粒度、字段、Cron 刷新频率、后台读取兜底策略。
2. 持久化登录/注册限流：当前内存限流不是多实例强保证，至少对邮箱/用户名/IP hash 做数据库级窗口记录。
3. 把 P0/P1 已完成项重新验收一遍：公开链接、游戏组件伪中奖、UTM 身份泄漏、导流配置版本化。
4. 对统计 API 增加耗时观测：记录 `/api/admin/stats`、事件汇总、Webhook 投递查询的响应耗时，先观测再决定是否预聚合。

### 7.2 MVP 稳定期（P2）

1. 资料领取/问卷 vertical slice：先做通用表单 schema、提交记录、导出和基础统计。
2. 接龙稳定化：候补转正、通知、导出，把第二玩法做扎实。
3. 平台运营后端最小闭环：先做只读/低风险 API，允许平台方看到租户、套餐、兑换码、用量、失败投递，不先做复杂财务系统。
4. 外部转化治理：来源校验、API Key scope、调用日志、回传导入。
5. Webhook 租户侧可视化和失败告警。

### 7.3 商业化前（P3）

1. 平台运营后台最小版：租户、套餐、兑换码、用量快照、失败投递、系统配置、平台审计。
2. 领券/核销：唯一码池、领取记录、核销入口，承接导流变现但不做完整电商。
3. 分享裂变反作弊：有效邀请、冷却窗口、IP/设备/身份去重、异常来源治理。
4. 预约、投票/调研、签到/打卡按共享骨架逐步扩展，禁止为单一玩法推翻活动引擎抽象。
