## 零、本次同步后的总判断

当前项目已经从“抽奖工具”推进到“轻量活动引擎 SaaS”的正确方向：活动类型、体验类型、结果模式、模板、奖品图片/价值、媒体上传、平台后台、用量快照、额度码、Webhook/API Key、事件和外部转化都已有基础。

但发布路线必须从“继续加玩法”切回“让客户快速把活动做对”：

```text
P0：发布闸门和安全/资源灾难风险
P1：SaaS 客户快速创建、少出错、能复盘、能承接的最小闭环
P2：更多玩法 vertical slice 和平台运营增强
P3：规模化、白标、复杂协作和架构升级
```

当前最需要补齐的不是再增加十个 `activity_kind`，而是：

1. **问卷/投票配置器**：不能只靠活动描述写选项或问题，必须有运营者能理解的字段/选项设置界面。
2. **发布前预检**：资格、容量、码池、Webhook、CTA、问卷字段、投票选项必须在发布前发现明显错误。
3. **活动模板产品化**：模板已存在，但要把“目标入口 -> 默认规则 -> 可发布检查 -> 二维码/海报/链接”串成 3 分钟创建体验。
4. **租户侧复盘看板**：浏览、开始、完成、CTA、分享、外部转化要能被运营者看懂。
5. **奖品媒体测试与治理**：奖品图片/价值字段已闭环，图片上传已走 R2 和 2MiB 限制；仍需补正式媒体路由测试和存储治理规则。

## 八、实施建议（按 027 §10 阶段对齐）

### 8.1 阶段 0：发布闸门（当前）

1. 公开事件上报限流和写入治理，避免 rows written 被恶意刷爆。
2. 首个 `platform_owner` 初始化流程文档化或脚本化。
3. 平台写操作审计设计，不污染租户审计表。
4. 核心链路完整回归：抽奖、接龙、奖品图、码池、平台门禁、静态资源、Webhook。
5. 建立最小观测：按路由记录请求量、耗时、错误；定期查看 Turso rows read/write。
6. 游戏体验文案收口：转盘/老虎机奖品滚动只表示动画，最终结果以后端返回为准。

验收标准：

```text
租户管理员不能访问平台能力
平台成员不能绕过平台门禁
静态资源不再大量消耗 Worker 请求
公开参与热路径没有全租户 COUNT
兑换码不会超发
前端不会展示伪业务结果
```

### 8.2 阶段 1：受控 Beta（完成 P1 后）

1. 问卷字段配置器：字段 schema、公开提交、后台查看/导出、基础统计。
2. 投票选项配置器：固定选项、单选/多选、去重、票数统计、结果公开开关。
3. 发布前预检升级：资格、容量、码池、Webhook、CTA、问卷字段、投票选项。
4. 活动模板产品化：目标入口、默认规则、必填项、二维码/海报/复制链接。
5. 租户侧活动漏斗看板：浏览、开始、完成、CTA、分享、外部转化。
6. Webhook 租户侧可视化和失败告警。

### 8.3 阶段 2：小规模商业化（P2 完成后）

1. 平台运营后台最小版：租户、套餐、兑换码、用量快照、失败投递、系统配置、平台审计。
2. 领券/核销：唯一码池、领取记录、核销入口。
3. 分享裂变反作弊：有效邀请、冷却窗口、IP/设备/身份去重、异常来源治理。
4. 预约、投票/调研、签到/打卡按共享骨架依次扩展。

### 8.4 阶段 3：规模化架构升级（触发条件）

触发条件：日 Worker 请求稳定超 50,000 / 单活动峰值超 5,000-10,000 参与 / Turso 月用量超 Free 50% / 有付费客户要求 SLA。

升级路径：Workers Paid → 快照表/预聚合 → 事件采样/批量 → DB CAS 仍不足时引入 Durable Objects → 大客户独立 Turso DB → R2 异步导出。

## 九、当前最优执行顺序

> 目标：先让 SaaS 客户能快速、低风险地创建活动，再扩展更多玩法。
> 详细实施基准见：`docs/031_P1运营闭环完善详细方案_2026-08-01.md`。

1. **补发布闸门**：平台审计覆盖检查、Webhook/UI/静态路由专项、首个 `platform_owner` 真实新环境演练。
2. **补奖品媒体治理**：核心媒体测试已完成；下一步补 `media_assets`、租户图片数量/容量治理、R2 生命周期策略实际配置。
3. **补发布前预检**：把资格、容量、码池、CTA、Webhook、问卷字段、投票选项作为发布前可见检查。
4. **做轻量问卷/投票配置器**：先做字段/选项 schema + 管理端设置 + 公开提交 + 后台查看/导出/统计，不做复杂表单平台。
5. **做租户侧漏斗看板**：把现有事件汇总产品化为浏览、开始、完成、CTA、分享、外部转化漏斗。

这五步完成前，不建议继续扩展预约、签到、核销、白标或复杂分享裂变。否则会出现“玩法很多，但客户仍然不能稳定搭建和复盘活动”的产品灾难。
