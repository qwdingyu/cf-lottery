# V2 独立订单/订单项模型

## 背景

V1 的支付订单模型（`payment_orders`）绑定以下约束：

1. **`entry_id UNIQUE`**：一个参与身份（entry）只能有一笔订单，即"一参与一订单"。这导致用户无法在已购买后再次购买（"已有订单"作为终止条件）。
2. **`prize_code_id` 在订单级**：整笔订单只记录一个卡密 ID，批量订单（quantity > 1）的额外卡密只能通过 `payment_order_id` 关联查询，无法表达"每件卡密的独立履约/退款/换码"。
3. **无购买身份快照**：订单通过 `entry_id` 回查参与记录获取购买者身份，但 entry 可能被改名/回收，审计链断裂。

## 设计

### 核心变更

| 变更 | 说明 |
|------|------|
| `payment_orders.entry_id` 去 UNIQUE | 改为普通索引，同一参与身份可产生多笔独立订单 |
| 新增购买身份快照 | `buyer_identity_type/value/display_name`，下单时从 entry 拷贝 |
| 移除 `payment_orders.prize_code_id` | 不再在订单级记录卡密 ID |
| 新增 `payment_order_items` 表 | 每行 = 一个已购单元，履约后绑定 `prize_code_id` |
| 下单不再以"已有订单"作为终止条件 | 已有 paid 订单的用户可以再次购买 |

### 数据流

**下单（createPaymentOrder）：**
1. 查 entry 当前 paymentStatus
2. 若 entry 为 `reserved`（首次下单）：base=1 已在 joinDraw 时计入，需补 reserveQuantity = qty - 1
3. 若 entry 为 `paid`/`pending`（再次购买）：base=1 已被之前订单消费，全额预约 reserveQuantity = qty
4. CAS 预约 draw.activeParticipantCount
5. 创建 order（含 buyer 快照）+ quantity 条 order_items（pending 状态）+ 1 条 attempt

**回调发卡（handlePaymentCallback）：**
1. acquirePrizeCodes 原子领取 quantity 个卡密
2. 更新 attempt 为 PAID
3. fulfillOrderItems：依次绑定已领取的卡密到 order_items（status → fulfilled）
4. 更新 order 为 PAID（或 FULFILLMENT_FAILED 若卡密不足）

**人工补发（retryPaymentFulfillment）：**
1. acquirePrizeCodes 原子重新领取 quantity 个卡密
2. fulfillOrderItems：绑定到 pending 的 order_items
3. 更新 order 为 PAID

**取消/超时（cancelPaymentOrder / expireOverdueOrders）：**
1. 更新 order 为 CANCELLED/EXPIRED
2. 标记 order_items 为 refunded
3. 释放容量
4. 若该 entry 无其他活跃订单，释放 entry 的 pending 状态

### 公开查单/找回

- 卡密查询通过 `payment_order_items` 关联 `prize_codes` 获取，不再依赖 `order.prize_code_id`
- 找回通过 `order.buyer_identity_value` 匹配，不再回查 entry

### 迁移

`0045_v2_independent_orders.sql`：
1. 重建 `payment_orders` 表（去掉 entry_id UNIQUE、新增 buyer 快照、移除 prize_code_id）
2. 创建 `payment_order_items` 表
3. 迁移存量数据：对每笔已支付/已发卡订单，按 quantity 创建 order_items（绑定已发卡密）

## 边界

- **再次购买时容量预约**：`createPaymentOrder` 根据 entry.paymentStatus 判断是否已有前置订单，决定全额预约还是补量预约
- **取消时 entry 释放**：只有该 entry 无其他活跃订单时才释放 entry.paymentStatus 为 expired
- **并发安全**：`activeParticipantCount` CAS 预约在事务内，与 V1 一致
- **V1 存量数据**：迁移脚本从 `prize_code_id` 提取存量卡密绑定到 order_items（第1件），V2 查单/找回通过 order_items 关联
