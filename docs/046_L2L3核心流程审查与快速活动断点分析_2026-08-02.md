# cf-lottery L2/L3 核心流程审查与"3 分钟快速活动"断点分析

> 文档编号：046
> 创建时间：2026-08-02
> 定位：审查 SaaS 租户管理员（L2）是否能 3 分钟内完成活动创建，平台运营者（L3）功能完整性

---

## 一、L2 核心流程：注册 → 创建活动 → 发布

### 1.1 当前步数统计

```
登录 → 运营台（1 步）
  ↓
点击「创建活动」→ 选择模板（1 步）
  ↓
填写表单 → 保存草稿（N 步，见下）
  ↓
去奖品管理 → 创建奖品 → 导入/生成码 → 返回活动（3-5 步）
  ↓
重新打开活动 → 关联奖品到奖项 → 发布前检查 → 发布（3 步）

总计：8-12 步
```

### 1.2 表单字段数量（当前）

| 区域 | 字段数 | 必填 |
|:-----|:------:|:----:|
| 基本信息 | 3（标题/描述/中奖人数） | 2 |
| 时间配置 | 3（开始/结束/开奖） | 3 |
| 奖品 & 奖项 | 动态（1-N 个奖项，每奖项关联奖品+名额） | 至少 1 |
| 参与模式 | 1-3（模式选择 + 密码/名单） | 1 |
| 导流配置 | 4（URL/标题/价格/图片） | 0（可选） |
| 裂变传播 | 3（开关/次数/排行榜） | 0（可选） |
| CTA 承接 | 4（中奖/未中奖 URL+标题） | 0（可选） |

**合计：14-19 个字段，7 个折叠区域。**

### 1.3 断点分析

#### 🔴 断点 1：奖品配置与活动创建分离

当前流程强制用户先去"奖品管理"创建奖品、导入码，再回到活动表单关联奖品。这是最大的速度杀手。

```
用户体验：创建活动中点击「奖品」下拉 → 显示"暂无奖品，去创建" → 点击跳转
         → 打开奖品页面 → 创建奖品 → 导入码 → 关闭 → 回到活动表单 → 刷新
         → 重新关联奖品
```

**影响**：抽奖类活动（最常用的类型）必须完成这个循环才能发布。非抽奖活动（问卷/投票/接龙）不需要奖品，但表单仍然展示奖品区域。

**建议**：表单内嵌"快速创建奖品"——一个 mini 弹窗，一键创建奖品 + 自动生成 100 个码。

#### 🔴 断点 2：模板默认值不够激进

当前模板只填充 `activityKind/experienceType/participationMode`。时间、中奖人数、奖品仍需手动填写。

**建议**：模板应预设"一键可用"的完整活动：
- 抽奖模板：自动创建"默认奖品"（1 个名额，自动生成 10 个码）
- 接龙模板：预设容量 30，候补开启
- 问卷模板：预设 2 个示例问题
- 投票模板：预设 2 个示例选项

#### 🟡 断点 3：发布前预检阻断过于严格

`publish-check-service.ts` 对抽奖活动强制要求至少配置 1 个奖项。但对于"手动发放"（manual_fulfillment）类型的奖品，不应该强制要求码池。

当前校验逻辑（`publish-check-service.ts:164`）：
```typescript
if (tiers.length === 0) {
  add(result.errors, "prizes", "prizes.tiers.required", "抽奖活动必须至少配置一个奖项");
  return;
}
```

**建议**：manual_fulfillment 类型的奖品不要求码池检查，降低快速发布的门槛。

#### 🟡 断点 4：表单区域过多，新手迷失

7 个折叠区域中，导流配置、裂变传播、CTA 承接对首次使用者是噪音。应该默认折叠为"高级配置"一个汇总区域，而非分开展示。

## 二、活动类型专项审查

### 2.1 抽奖（lottery）

| 检查项 | 当前状态 | 问题 |
|:-------|:--------|:-----|
| 模板 | 大转盘/刮刮卡 | ✅ |
| 时间配置 | 时间预设按钮（5m/10m/.../7d） | ✅ 好设计 |
| 奖品 | 需单独页面配置 | 🔴 流程断裂 |
| 发布 | 强制有奖项 | 🟡 可放宽 |

**优化后理想路径**：点击"大转盘抽奖" → 标题 + 时间预设"30分钟" → "快速创建奖品"（一键） → 发布（3 步，2 分钟）

### 2.2 接龙/报名（signup_chain）

| 检查项 | 当前状态 | 问题 |
|:-------|:--------|:-----|
| 模板 | 报名接龙 | ✅ |
| 容量配置 | 参与人数 + 候补策略 | ✅ |
| 奖品 | 不需要 | ✅ |
| 体验类型 | 接龙列表/排队队列 | ✅ |

**评价**：接龙是最接近"一键发布"的活动类型。只需填写标题 + 时间 + 人数即可发布。无需奖品配置。

**优化建议**：接龙模板应预设容量 30 + 候补开启，让用户可以直接点击发布。

### 2.3 问卷调研（survey）

| 检查项 | 当前状态 | 问题 |
|:-------|:--------|:-----|
| 模板 | 问卷调研 | ✅ |
| 字段配置 | 手动添加每个字段（文字/单选/多选/邮箱/电话） | 🟡 没有预设字段 |
| 发布预检 | validateActivityConfigForPublish | ✅ |

**优化建议**：模板应预设 2 个字段（姓名 + 建议），降低空白恐惧。

### 2.4 投票评选（vote）

同问卷——模板应预设 2 个选项。

## 三、L3 平台运营功能矩阵

| 功能 | 路由 | 状态 |
|:-----|:-----|:----:|
| 租户列表 | GET /api/platform/tenants | ✅ |
| 租户详情 | GET /api/platform/tenants/:id/summary | ✅ |
| 调整套餐 | PATCH /api/platform/tenants/:id | ✅ |
| 平台成员管理 | /api/platform/members | ✅ |
| 系统配置 | /api/platform/system-config | ✅ |
| 兑换码管理 | /api/platform/redemption-codes | ✅ |
| 审计日志 | GET /api/platform/audit-logs | ✅ |
| Webhook 监控 | /api/platform/webhook-deliveries | ✅ |
| 数据清理 | platform data cleanup | ✅ |
| **租户登录模拟** | 无 | ❌ |
| **平台通知推送** | 无 | ❌ |
| **全局活动封禁** | 无 | ❌ |
| **用量预警** | 无（快照已有但无预警） | 🟡 |

### 3.2 关键缺失

| 功能 | 重要性 | 说明 |
|:-----|:------:|:-----|
| **租户登录模拟** | 🔴 | 平台运营者需要能"以租户身份"登录，排查问题时看不到租户视角 |
| **全局活动封禁** | 🟡 | 违规活动需要能一键封禁（设置 status=banned），当前只能删除 |
| **用量预警通知** | 🟡 | `tenantUsageSnapshots` 已有数据，但无超限邮件/Webhook 预警 |
