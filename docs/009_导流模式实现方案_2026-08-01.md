## 二、导流模式设计

### 2.1 商品链接（最简单的导流方式）

**不需要商品管理，不需要库存，不需要上架流程。** 运营者只需要在创建活动时填写一个商品链接。

### 2.2 配置方式（在活动创建/编辑弹窗中）

直接在现有的活动创建弹窗中添加一个"导流配置"区块：

```
┌─────────────────────────────────────────────────────────────────┐
│ 导流配置（可选）                                                 │
│                                                                   │
│  ☐ 关联商品推广                                                    │
│                                                                   │
│  商品链接: [https://shop.example.com/product/123]                │
│  商品名称: [AI 智能音箱 Pro Max]                                 │
│  商品图片: [https://img.example.com/xxx.jpg]                     │
│  展示价格: [¥299]                                                │
│                                                                   │
│  ☐ 未中奖优惠券码                                                 │
│  优惠券码: [LUCKY2026]                                           │
│  折扣说明: [满100减20]                                           │
│  有效期: [7] 天                                                   │
└─────────────────────────────────────────────────────────────────┘
```

**关键设计：** 不引入新的商品表，不搞复杂的商品管理。商品链接只是一个字段，存储在 `lottery_draws` 表的 `product_link` JSON 字段中。

### 2.3 数据模型（极简）

```typescript
// lottery_draws 扩展一个 JSON 字段
productLink: {
  url: string        // 商品链接
  title: string     // 商品名称
  imageUrl: string  // 商品图片 URL
  price: string     // 展示价格
}
```

**没有新表，没有新路由，没有新服务。** 只是一个字段的扩展。

## 三、后端实现（复用 cf-shop 模式）

### 3.1 路由扩展

在 `admin-lottery.ts` 的 `PATCH /draws/:id` 中增加 `productLink` 字段的处理：

```typescript
// admin-lottery.ts 中已有的 PATCH 路由增加 productLink 处理
...(body.productLink !== undefined ? { productLink: JSON.stringify(body.productLink) } : {}),
```

在 `POST /draws` 中增加：

```typescript
...(body.productLink ? { productLink: JSON.stringify(body.productLink) } : {}),
```

### 3.2 公开 API 返回

在 `GET /api/public/draws/:slug` 中返回 `productLink`：

```typescript
// 如果活动配置了商品链接，返回给前端展示
if (draw.productLink) {
  result.productLink = JSON.parse(draw.productLink);
}
```

### 3.3 点击追踪（极简）

不需要新表，不需要新路由。使用 UTM 参数即可：

```
https://shop.example.com/product/123?utm_source=lottery&utm_medium=draw&utm_campaign={draw_id}
```

如果未来需要统计点击量，可以加一个简单的点击计数器，用 `wrangler analytics` 或 Worker 日志来统计。

## 七、为什么不搞复杂的商品管理

| 方案 | 复杂度 | 说明 |
|------|--------|------|
| 自建商品管理 | 高 | 需要商品表、分类、上架、库存、图片上传...这是 cf-shop 做的事 |
| 商品链接字段 | 低 | 运营者填写一个 URL，简单直接 |
| 对接第三方 API | 中 | 需要 API 适配，依赖外部系统 |

**选择"商品链接字段"方案的原因：**
1. cf-lottery 是抽奖工具，不是电商系统
2. 运营者已经有自己的商品页（淘宝/有赞/Shopify/自建站）
3. 只需要一个链接就能引流到商品页
4. 不增加系统复杂度，不上线风险

## 八、数据追踪方案

### 8.1 点击统计（极简版）

不需要点击表，不需要追踪服务。使用 UTM 参数即可：

```typescript
function productUtmUrl(url: string, drawId: string, entryId: string): string {
  const u = new URL(url)
  u.searchParams.set('utm_source', 'lottery')
  u.searchParams.set('utm_medium', 'draw')
  u.searchParams.set('utm_campaign', drawId)
  return u.toString()
}
```

### 8.2 效果衡量

运营者可以通过自己的分析工具（Google Analytics、百度统计等）查看 UTM 参数带来的流量。

### 8.3 未来扩展

如果未来需要平台级别的效果统计，可以：
1. 在 `lottery_draws` 中加一个 `click_count` 计数器字段
2. 每次点击通过 Worker 的 `fetch` 事件统计
3. 在管理端展示点击数据
