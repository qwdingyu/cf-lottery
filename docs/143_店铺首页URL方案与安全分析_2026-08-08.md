# 143 店铺首页 URL 方案与安全分析

> 日期:2026-08-08

## 方案对比

### 方案 A:租户ID(用户提议但否决)

| 维度 | 评估 |
| --- | --- |
| 暴露内部 ID | ❌ 违反 AGENTS.md 铁律——**公开链接使用 public_slug,不暴露内部 ID** |
| 枚举攻击 | 若攻击者知晓 tenant_id,可遍历所有租户 |
| URL 美观 | 38 字符 UUID,不适合推广/二维码 |

### 方案 B:brandConfig.storeSlug

| 维度 | 评估 |
| --- | --- |
| 不用新字段 | ✅ 复用 brandConfig JSON |
| 唯一性 | ❌ 无 DB UNIQUE 约束,可能重名 |
| 黑白单 | brandConfig 包含 slug,管理端可配 |

### 方案 C(推荐):tenants.store_slug UNIQUE

| 维度 | 评估 |
| --- | --- |
| 唯一性 | ✅ DB UNIQUE 保证,自动生成默认值 `shop_{id[0:8]}` |
| L2 可配 | ✅ 管理端品牌设置页输入 |
| URL 安全 | ✅ 与 public_slug 模式一致,不暴露内部ID |
| 扩展性 | ✅ 后续支持自定义域名绑定 |
| 迁移成本 | 1 个字段 + 1 个接口 + 管理端 1 个输入框 |

### 推荐方案 C:tenants.store_slug

```
URL: /shop/{store_slug}
示例: /shop/my-shop
默认: /shop/shop_a1b2c3d4(自动生成,可改)
```

L2 后台品牌设置页中,租户 admin 配置 storeSlug,立即生效。自动生成默认值避免空值。

工期:1 天(schema 迁移 + 接口 + 管理端输入)。已验证 brandConfig 管理端已有增删改查接口,品牌设置页在此基础上扩展。

## 安全闭环

| 要求 | 实现 |
| --- | --- |
| 不暴露内部 ID | store_slug 是公开标识,与 tenant_id 无关 |
| 唯一性 | DB UNIQUE 约束 |
| 权限 | 仅租户 owner/admin 可修改 store_slug |
| 历史兼容 | 现有 public_slug 模式保持一致 |
