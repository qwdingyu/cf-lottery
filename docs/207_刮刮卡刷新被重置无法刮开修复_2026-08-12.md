# 刮刮卡「永远刮不开」根因修复

## 背景

用户反馈：刮刮卡活动页（`/lottery/:slug`，如 `181967b1`）存在定时刷新，**还没等刮开页面就刷新了，导致永远刮不开**。

## 根因（root cause）

公开活动页 `LotteryView.vue` 有多个**静默刷新**入口会替换 `draws.value`：

1. **30 秒轮询**：`pollTimer = setInterval(...)`（LotteryView.vue:4188）
2. **`focus` 事件**：`window.addEventListener('focus', refreshWhenVisible)`（:4199）
3. **`online` 事件**：`window.addEventListener('online', refreshWhenVisible)`（:4200）
4. **`visibilitychange`**：`handleVisibilityChange` → `refreshWhenVisible`（:4201）

`refreshWhenVisible` / `pollTimer` 都调用 `fetchDraws({ silent: true })`，其中执行 `draws.value = [draw]`（:3391）→ 触发模板重渲染。

模板渲染游戏壳用的是：

```html
<component
  :is="getGameComponent(draw.experienceType || ...)"
  :key="draw.id"
  ...
/>
```

而 `GameRegistry.getGameComponent()` 原实现是：

```ts
return defineAsyncComponent(loader)   // ← 每次调用都返回全新组件引用
```

**关键点**：`defineAsyncComponent()` 每次调用都创建一个**新的**异步组件包装对象。重渲染时 `getGameComponent()` 被重新调用，返回一个与上一次**引用不同**的组件。Vue 对 `<component :is>` 按引用比较，误判「组件类型变了」→ **卸载旧 `ScratchGame`、重挂新实例** → canvas 涂层被清空复位。

于是：
- 每 30 秒，涂层被重置一次；
- 每次 focus/切回前台/网络恢复，涂层又被重置；
- 用户永远刮不满 50% 透明阈值，`scratched` 永远不触发 →「永远刮不开」。

## 排查过程

1. 复现描述锁定「定时刷新」→ 全库搜 `setInterval`，命中 `LotteryView.vue` 的 30s `pollTimer`（已参与才停，未参与不停）。
2. 搜 `addEventListener` → 命中 `focus` / `online` / `visibilitychange` 三通道静默刷新。
3. 追踪 `fetchDraws({ silent: true })` → `draws.value = [draw]` 必然触发重渲染。
4. 追踪游戏壳渲染 → `getGameComponent()` 每次调用 `defineAsyncComponent()`，返回新引用 → 组件卸载重挂 → canvas 复位。根因成立。

> 注：`:key="draw.id"` 相同并不能阻止重挂——`:is` 组件类型引用变化时，Vue 会无视 key 直接重挂。

## 解决方案

在 `GameRegistry.ts` 中缓存 `defineAsyncComponent` 结果，保证同一体验类型返回**同一组件引用**：

- 新增 `GAME_COMPONENT_CACHE: Map<string, Component>`；
- `resolveCachedComponent(key)` 先查缓存，未命中才 `defineAsyncComponent` 并缓存；
- 未知体验 `canonicalKey` 归一到 `"submit"`，避免每个未知 key 都新建不同引用；
- `getGameComponent` 改为走缓存。

修复后，静默刷新重渲染时 Vue 复用同一组件实例，`ScratchGame` 的 canvas 涂层与刮开进度得以保留。

配套回归测试：`GameRegistry.test.ts` 新增「同一体验多次调用返回同一组件引用」用例，断言 `getGameComponent('scratch') === getGameComponent('scratch')`，并覆盖大小写归一与未知 key 回退复用。

## 验证

- `npx tsc --noEmit`：0 errors，退出码 0
- `cd frontend && npx vue-tsc -b --pretty false`：0 errors，退出码 0
- `npx vitest run frontend/`：30 个文件 / 204 例全部通过（含新增 GameRegistry 回归测试）

## 建议（后续，非本次改动）

- 刮刮卡/卡片翻转等**有中断状态**的体验，可考虑在静默刷新时跳过 `draws.value` 整体替换，或仅更新非交互字段，进一步降低重渲染面。
- 30s 轮询只服务「看开奖结果/参与人数」，刮开阶段可暂停轮询，待用户完成交互后再恢复。
