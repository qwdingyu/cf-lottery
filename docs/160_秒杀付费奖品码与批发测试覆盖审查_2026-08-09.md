## 本轮新增 5 个测试（payment-service.test.ts 37 → 42）

1. **多租户隔离**：A 租户回调只消耗 A 租户码池，B 租户卡密保持 available 未绑定订单
2. **混合状态码池**：只有 status=available 的码被领取，issued/revoked/redeemed 不被改写
3. **领取顺序确定性**：按 id 升序（子查询 `ORDER BY id LIMIT 1`），min id 优先
4. **多卡密奖品 fail-closed**：findCodePrize 对多 code 奖品返回 null，不发卡、订单进履约失败
5. **奖品未激活 fail-closed**：prizes.active=0 时 findCodePrize 过滤，不发卡、履约失败

## 结论与剩余缺口

- 核心原语（acquirePrizeCodes / fulfillOrderItems / findCodePrize）为**私有函数**，
  通过公开 API（handlePaymentCallback / retryPaymentFulfillment）间接测试。
- `fulfillOrderItems` 的「部分绑定（领取数<明细数）」分支是防御性代码，正常流程不可达
  （acquirePrizeCodes 始终全量或 []），故未单独测试。
- 建议后续：若需对原语做更细粒度测试，可将三者导出并入 `_internal` 命名空间，
  但需评估是否值得为测试暴露内部实现。
