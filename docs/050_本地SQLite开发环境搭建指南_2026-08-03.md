# 本地 SQLite 开发环境搭建指南

> 日期：2026-08-03
> 适用：本地开发 / 云服务器部署

## 背景

cf-lottery 默认使用远程 Turso（libSQL）数据库。生产环境通过 Cloudflare Workers 直连 Turso。本地开发时，可以用本地 SQLite 文件替代远程 Turso，消除每次查询 ~2ms 的网络延迟。

`@libsql/client` 原生支持两种模式，切换只需修改 `.env` 中的 `TURSO_URL`，无需任何代码改动。

## 一、从 Turso 导出数据到本地

### 方式 A：使用 Turso CLI（推荐）

```bash
# 1. 导出 Turso 数据库结构 + 数据
turso db shell cf-lottery-db-qwsky ".dump" > data/local.sql

# 2. 导入本地 SQLite
sqlite3 data/local.db < data/local.sql
```

### 方式 B：如果只需要空库（结构）

```bash
# 创建空数据库
sqlite3 data/local.db "VACUUM;"
```

然后通过 `src/test-setup.ts` 中的迁移系统自动建表（需要在代码中调用 `applyMigrations`）。

### 方式 C：复制已有的共享测试数据库

```bash
# 如果本地有测试留下的数据库文件
cp "$TMPDIR/cf-lottery-vitest-*.db" data/local.db
```

## 二、配置 .env

```env
# ── 本地开发（SQLite 文件） ──
TURSO_URL=file:./data/local.db
TURSO_TOKEN=

# ── 远程 Turso（生产环境） ──
# TURSO_URL=libsql://cf-lottery-db-qwsky.aws-ap-northeast-1.turso.io
# TURSO_TOKEN=eyJhbGciOiJFZERTQSIs...
```

## 三、启动

```bash
npm run dev:local
# 或
tsx src/server.ts
```

输出：
```
[server] cf-lottery on http://localhost:8787
[server] platform: local
```

## 四、验证

```bash
# Health 检查（db 应为 true）
curl http://localhost:8787/api/health
# → {"ok":true,"db":true,"dbError":null}

# 登录测试
curl -X POST http://localhost:8787/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"1234qwer!!"}'
```

## 五、数据同步

| 方向 | 命令 |
|------|------|
| Turso → 本地 | `turso db shell cf-lottery-db-qwsky ".dump" \| sqlite3 data/local.db` |
| 本地 → Turso | `sqlite3 data/local.db ".dump" \| turso db shell cf-lottery-db-qwsky` |

> ⚠️ Turso `.dump` 导出的 SQL 包含 `PRAGMA foreign_keys=OFF`，本地导入后需手动确认数据完整性。

## 六、注意事项

1. **本地文件与生产数据相互独立**——修改本地数据库不会影响生产，反之亦然。
2. **SQLite 文件级锁**——本地开发单进程无影响。多进程同时写同一文件会报 `SQLITE_BUSY`。
3. **不提交 data/ 目录到 git**——已在 `.gitignore` 中忽略 `*.db` 文件。
4. **远程开发需要 Turso**——如果多人协作需要共享数据，继续用 Turso URL，不要用本地文件。

## 七、切换回 Turso

将 `.env` 中的 `TURSO_URL` 和 `TURSO_TOKEN` 改回远程 Turso 的值即可。重启服务器生效。

```env
TURSO_URL=libsql://cf-lottery-db-qwsky.aws-ap-northeast-1.turso.io
TURSO_TOKEN=eyJhbGciOiJFZERTQSIs...
```

## 八、原理

`@libsql/client` 的 `createClient()` 根据 URL scheme 自动判断模式：

```typescript
// 远程模式（HTTP 协议，需要 authToken）
createClient({ url: "libsql://db.turso.io", authToken: "..." })

// 本地模式（文件系统，不需要 authToken）
createClient({ url: "file:./data/local.db" })
```

cf-lottery 的数据库初始化代码（`src/index.ts:158`）已经兼容两种模式，无需任何代码改动：

```typescript
const url = getEnv(c, "TURSO_URL");
c.set("db", url ? createDb(createClient({ url, authToken: getEnv(c, "TURSO_TOKEN") })) : undefined);
```

本地模式下 `getEnv(c, "TURSO_TOKEN")` 返回空字符串，libsql client 自动忽略。
