# cf-lottery 营销能力全维度差距分析与补强路线图

> 文档编号：042
> 创建时间：2026-08-02
> 定位：以 AARRR 海盗模型为框架，逐层审查营销能力短板，给出可落地的补强方案
> 角色：营销技术顾问 + 增长专家 + 产品架构师

## 一、审查方法论

以 **AARRR 海盗模型**（获客→激活→留存→变现→传播）为框架，结合 **RFM 客户分层** 和 **营销自动化** 行业标准，对 cf-lottery 进行全维度审查。

```
获客 Acquisition  →  激活 Activation  →  留存 Retention  →  变现 Revenue  →  传播 Referral
     ↓                    ↓                    ↓                 ↓                ↓
  活动怎么被         用户参与           参与后如何          活动如何            用户如何
  目标用户发现       体验如何           持续触达            产生商业价值        自发传播
```

## 二、获客 (Acquisition) — 活动如何被目标用户发现

### 2.1 当前状态

| 渠道 | 实现方式 | 能力评级 |
|:-----|:---------|:--------:|
| 运营手动分发链接 | 管理端"复制活动链接"按钮 | ✅ 基础 |
| 二维码 | 管理端生成二维码（前端实现） | ✅ 基础 |
| 分享裂变 | 刚完成的裂变系统（排行榜+加权） | ✅ 已补强 |
| 社交媒体嵌入 | Telegram Mini App BackButton 适配 | ⚠️ 仅 Telegram |
| SEO | 无 | ❌ |
| 活动聚合页 | 无公开活动列表 | ❌ |
| 短信/推送 | 无 | ❌ |

### 2.2 行业标杆对比

| 标杆产品 | 获客方式 | cf-lottery 差距 |
|:---------|:---------|:---------------|
| 活动盒子 | 模板市场 + 案例展示 | 无活动模板市场、无案例库 |
| 兔展 | H5 传播页 + SEO 优化 | 无 SEO、无独立落地页 |
| 金数据 | 表单嵌入 iframe | 有嵌入能力但未产品化 |
| Mailchimp | 登录页 + 付费广告 | 有 LandingView 但只是产品介绍页 |

### 2.3 补强方案（按优先级）

**P0 — 活动嵌入 SDK（最高频需求）**
```
当前：运营者复制链接 → 粘贴到自己的网站/公众号
问题：链接只是一个 URL，没有预览卡片（Open Graph），在微信/微博中展示效果差

方案：
1. 活动详情页添加 Open Graph meta 标签（og:title, og:description, og:image）
   → 分享到微信/微博时展示富媒体卡片，点击率提升 3-5 倍
2. 提供 iframe 嵌入代码片段（一键复制）
   → 运营者可直接嵌入到自己的网站中
3. 嵌入模式自动隐藏页面头尾，仅展示活动核心交互区
```

**P1 — 活动公开列表 + SEO**
```
1. LandingView 改造：支持按分类浏览公开活动（可选，租户可控制是否公开）
2. 每个活动独立 SEO meta（title/description 来自活动配置）
3. 站点地图（sitemap.xml）自动生成
```

**P2 — 社交媒体卡片优化**
```
1. 活动创建时支持上传社交分享图（og:image）
2. 预生成社交分享文案模板（可自定义）
3. 支持微信 JS-SDK 分享接口（自定义分享标题/描述/图片）
```

## 三、激活 (Activation) — 参与体验与转化

### 3.1 当前状态

| 能力 | 实现方式 | 能力评级 |
|:-----|:---------|:--------:|
| 邮箱验证码参与 | `POST /access-code` + `POST /verify-join` | ✅ 完整 |
| 多种参与模式 | open/roster/password/invite_code | ✅ 完整 |
| 多种体验类型 | wheel/scratch/slot/card/reveal/form/submit/grid/ballot | ✅ 丰富 |
| 导流商品卡 | promotionConfig.destination → 参与后展示 | ✅ 基础 |
| 提交后 CTA | 参与成功弹窗 → 商品链接 | ⚠️ 单一 CTA |
| 参与漏斗追踪 | page_view → participation_started → completed | ✅ 完整 |

### 3.2 断点分析

**断点 1：参与后弹窗只有 1 个 CTA**

当前逻辑：参与成功 → GameResultModal → 展示"知道了"按钮 + 可选的商品链接。
问题：一个参与者只能看到一个 CTA。实际上应该根据用户状态展示不同 CTA：
- 首次参与 → 引导关注公众号/加入社群
- 已参与多次 → 引导升级套餐/购买
- 裂变达人 → 引导分享

**断点 2：参与漏斗有数据但无优化手段**

`activityEvents` 记录了 page_view / participation_started / participation_completed，但：
- 没有漏斗流失分析（在哪一步放弃最多？）
- 没有分渠道对比（微信 vs 微博 vs 直接访问）
- 没有 A/B 测试能力（两个版本的 promotionConfig 哪个转化率更高？）

### 3.3 补强方案

**P0 — 多状态 CTA 配置（promotionConfig 扩展）**
```json
{
  "promotionConfig": {
    "version": 2,
    "ctas": {
      "after_join": { "destination": {...}, "viral": {...} },
      "after_win": { "destination": {...}, "message": "中奖了！看看这个" },
      "after_loss": { "destination": {...}, "message": "没中奖？试试这个" },
      "first_time": { "destination": {...}, "message": "欢迎！关注我们" }
    }
  }
}
```
当前 promotionConfig 是 version 1，位置单一的 `after_join`。扩展为 version 2 支持多状态 CTA 后，每个参与状态（首次/再次/中奖/未中奖）可以展示不同的导流卡片。

**P1 — 漏斗流失仪表盘**
```
管理端活动详情 → 新增"漏斗分析" tab：
- 桑基图/漏斗图展示 page_view → started → completed
- 分渠道（source/medium/campaign）对比
- 流失率预警（completed/page_view < 20% 时标红）
```

## 四、留存 (Retention) — 参与后如何持续触达

### 4.1 当前状态

| 能力 | 实现方式 | 能力评级 |
|:-----|:---------|:--------:|
| 中奖邮件通知 | `sendEmail(lottery_winner)` 模板 | ✅ 基础 |
| 未中奖发券 | `grantLoserRewards()` 异步执行 | ✅ 基础 |
| 候补转正 | `cancelSignupChainEntry()` 候补自动补位 | ✅ 完善 |
| 邮箱验证码 | `sendAccessCode()` | ✅ 基础 |

### 4.2 断点分析 — 🔴 最大的营销短板

**当前邮件能力极度薄弱：**

| 维度 | 当前 | 行业标准 | 差距 |
|:-----|:-----|:---------|:----:|
| 邮件模板数 | 2 个（中奖通知+验证码） | 10+ 个 | 🔴 大 |
| 触发时机 | 仅开奖后 | 全生命周期 | 🔴 大 |
| 模板自定义 | 无（硬编码 HTML） | 所见即所得编辑器 | 🔴 大 |
| 邮件序列 | 无 | 3-5 封自动化序列 | 🔴 大 |
| 退订管理 | 无 | 合规必须 | 🔴 大 |
| 打开/点击追踪 | 无 | 标配 | 🟡 中 |

**缺失的关键邮件触达时机：**

```
用户生命周期                当前状态          应该发送的邮件
─────────────────────────────────────────────────────────────
注册完成                    ❌ 无            欢迎邮件 + 快速入门引导
活动发布                    ❌ 无            活动上线通知（给订阅用户）
参与活动后 1 天             ❌ 无            相关活动推荐
开奖前 1 小时               ❌ 无            开奖倒计时提醒
开奖后 — 中奖               ✅ lottery_winner  中奖通知 + 后续引导
开奖后 — 未中奖             ❌ 无            安慰邮件 + 优惠券 + 下期预告
活动结束后 7 天             ❌ 无            回访邮件 + 满意度调研
长期未活跃（30 天）         ❌ 无            召回邮件 + 专属优惠
```

### 4.3 补强方案

**P0 — 开奖前提醒 + 未中奖安慰邮件（最小集）**

新增 2 个邮件模板和触发逻辑：
```
1. 开奖前 1 小时提醒：
   "您参与的《{活动名称}》将在 1 小时后开奖，祝你好运！"
   触发：Cron 扫描 drawAt 在未来 1 小时内的活动

2. 未中奖安慰邮件：
   "很遗憾您未中奖，但我们为您准备了专属优惠券 {code}"
   触发：开奖完成后，对所有未中奖参与者发送
```

**P1 — 邮件模板库 + 自定义**

```
1. 邮件模板从硬编码 HTML → 数据库存储（email_templates 表）
2. 平台运营者可编辑全局模板，租户可编辑自己的模板
3. 模板变量：{{drawName}}, {{prizeName}}, {{couponCode}}, {{shareUrl}} 等
4. 支持基础富文本（加粗/链接/图片）
```

**P2 — 自动化邮件序列**

```
运营者可配置：
- 触发条件：参与后 N 天 / 开奖后 N 天 / 未活跃 N 天
- 邮件模板：选择模板
- 启用/禁用

技术方案：
- email_campaigns 表存储序列配置
- Cron 定时扫描符合条件的用户 → 发送邮件
```

## 五、变现 (Revenue) — 活动如何产生商业价值

### 5.1 当前状态

| 能力 | 实现方式 | 能力评级 |
|:-----|:---------|:--------:|
| 商品导流 | promotionConfig.destination → 带 UTM 的商品链接 | ✅ 基础 |
| CTA 点击追踪 | `cta_click` 事件 | ✅ 完整 |
| 外部转化回传 | API Key → `externalConversions` 表 | ✅ 完整 |
| 优惠券核销 | `couponCodes` CAS 核销 | ✅ 完整 |
| 未中奖发券 | `grantLoserRewards()` | ✅ 基础 |
| ROI 计算 | 无 | ❌ |
| GMV 归因 | 无 | ❌ |

### 5.2 断点分析

**断点 1：有转化数据但没有 ROI 仪表盘**

`getExternalConversionSummary()` 返回 `{ totalCount, totalAmountCents, totals: { purchase: { count, amountCents } } }`。
但这个数据只在单个活动的 stats 面板中，没有：
- 租户级汇总 ROI（本月所有活动带来了多少 GMV？）
- 活动 ROI（投入奖品成本 vs 产出转化金额）
- 渠道 ROI（微信 vs 微博哪个渠道的转化率更高？）

**断点 2：没有引导用户走向成交的路径**

当前流程：参与 → 点击商品链接 → 离开平台。之后发生的事情全看外部系统。
缺少：
- 优惠券限时提醒（"您的优惠券还有 3 天到期"）
- 购物车放弃召回（需要外部系统配合）
- 复购引导（"上次您买过 X，这次 Y 也在促销"）

### 5.3 补强方案

**P0 — 租户 ROI 仪表盘**
```
管理端新增"营销效果"页面：
- 本月 GMV（外部转化 amountCents 汇总）
- 本月参与 → CTA 点击 → 外部转化 漏斗
- 各活动 ROI 排名
- 渠道对比（source 维度）

数据来源：
- externalConversions 表已有 amountCents 字段
- 搭配 activityEvents 的 cta_click 和 attributed_join 构建归因链路
```

**P1 — 优惠券到期提醒**
```
Cron 扫描即将过期的 couponCodes（status='issued', expiresAt 在未来 1-3 天内）
→ 发送提醒邮件："您的优惠券 {code} 还有 {N} 天到期，快来使用！"
```

## 八、关键设计决策

### 8.1 promotionConfig 版本化策略

当前是 version 1（单一 after_join CTA）。推广到 version 2 时：

```typescript
// PromotionConfig V2
{
  version: 2,
  ctas: {
    after_join:    { destination?, viral? },   // 参与后
    after_win:     { destination?, message? }, // 中奖后
    after_loss:    { destination?, message? }, // 未中奖
    first_time:    { destination?, message? }, // 首次参与
  }
}
```

向后兼容：version 1 的 `destination` 字段自动映射为 `ctas.after_join.destination`。

### 8.2 邮件模板架构

```
email_templates 表:
  id, tenant_id (null = 全局模板), template_key, subject, html_body, variables_json, updated_at

模板变量: {{drawName}}, {{prizeName}}, {{couponCode}}, {{shareUrl}}, {{expiresAt}}, {{unsubscribeUrl}}
```

### 8.3 ROI 仪表盘数据来源

```
GET /api/admin/roi-dashboard?period=30d

SELECT
  SUM(amountCents) as totalGMV,
  COUNT(*) as totalConversions,
  conversionType
FROM externalConversions
WHERE tenantId = ? AND occurredAt >= ?
GROUP BY conversionType

搭配 activityEvents 构建归因：
- cta_click → external_conversion_reported 转化率
- source 维度对比（微信 vs 微博 vs direct）
```

## 九、总结

### 9.1 一句话结论

> **cf-lottery 的留存（Retention）是最大营销短板 — 只有 2 个邮件模板，没有生命周期触达，参与后用户就"消失"了。其次是变现（Revenue）— 有转化数据但没有 ROI 仪表盘，运营者看不到活动的商业价值。**

### 9.2 最优先的 3 件事

1. **邮件序列**（留存 P0）：开奖提醒 + 未中奖安慰 — 把"参与后即流失"变成"持续触达"
2. **多状态 CTA**（激活 P0）：首次/再次/中奖/未中奖不同导流 — 精准承接
3. **ROI 仪表盘**（变现 P0）：让运营者直观看到活动创造了多少 GMV — 这是付费转化的最强理由
