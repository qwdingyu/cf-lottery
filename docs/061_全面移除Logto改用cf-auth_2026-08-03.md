# 061 全面移除 Logto，统一认证改用 cf-auth

> 日期：2026-08-03  
> 背景：Logto 在本仓库为半成品接入；用户推进 `https://auth.eforge.xyz`（cf-auth）部署，决定删除 Logto 双轨。

---

## 一、决策

| 项 | 结论 |
|----|------|
| Logto Cloud / `@logto/vue` / `/api/auth/logto-exchange` | **删除** |
| 统一外部 IdP | **仅 cf-auth**（OAuth 授权码 + PKCE → 业务自签 JWT） |
| 本地账号 | **保留**：用户名密码 + 邮箱验证码注册/登录 |
| 公开参与 OTP | **保留**：无业务 JWT 时仍走 6 位邮箱码 |
| Bearer 跳过 OTP | **保留**：有效自签 JWT 且 email 匹配（原 Logto 路径语义，现由 cf-auth 签发） |

历史文档 051 / 055b 仍保留作档案；**实现以 059 + 本文为准**。

## 三、保留与改名

- `public-lottery` verify-join：变量 `logtoVerified` → `bearerIdentityVerified`；注释改为 cf-auth / 业务 JWT。
- 前端唯一 OAuth 入口：`useCfAuthLogin` + `/auth/callback`。
- 部署 secrets：`CF_AUTH_ENABLED` / `ISSUER` / `CLIENT_*` / `REDIRECT_URI`（见 `local-deploy.sh`）。

---

## 四、上线注意（非幻觉清单）

1. 生产 lottery 必须配置 `CF_AUTH_*` 指向已部署的 IdP（如 `https://auth.eforge.xyz`），并注册 redirect `…/auth/callback`。  
2. 旧 Logto `sub`（如 `logto|…`）与 cf-auth `sub` **不兼容**；无迁移则视为新身份。  
3. cf-auth 交换 JWT 仍常为 `tenantId=""` → 管理端走 onboarding；**外部 sub 首次写入 `users` 表**若未做，create-tenant 仍可能失败（与删 Logto 前同类缺口）。  
4. 本机 `.env` 中原 `LOGTO_*` / `VITE_LOGTO_*` 已注释为 `removed-logto`；请补齐 `CF_AUTH_*`。
