# 180 社群功能套餐绑定与租户覆写详细设计

> 日期：2026-08-10
> 定位：docs/174 §4 优先需求（A 套餐→社群功能绑定 + B 按租户覆写）的**详细开发设计依据**。
> 排序依据：见产品评审——A/B 是商业化刚需（强需求、成本可控、直接支撑变现），C 延后、D 顺手修、E/F 推迟。
> 状态：**已实现代码（2026-08-10，docs/182）**。套餐值按产品评审定稿：free=1群×200人、pro=3群×2000人、team=10群×3000人、enterprise=不限。

---

## 1. 目标与范围

### 1.1 目标

让社群功能（QQ/Telegram 群助手）成为**可商业化分层的付费能力**：

- **A 套餐→社群功能绑定**：不同套餐（free/pro/team/enterprise）差异化开放社群绑定的**数量上限**。
- **B 按租户覆写**：平台运营者（L3）可对**单个租户**单独开关社群功能或调整**群数/群人数**上限，覆盖套餐默认值。
- **A2 群人数上限（本版新增，防免费容量膨胀）**：不仅限"能绑几个群"，更要限**每个群能容纳多少成员**。否则免费 1 个群 × 群内 2000-3000 人 = 免费容量随群规模无限放大，等于变相绕过套餐限制。

> ⚠️ **为什么要加 A2（群人数上限）**：现有 `maxParticipantsPerActivity=200` 只在**活动创建时**设上限，且群助手可**切换活动**（换一个新活动又可接入 200 人）。因此单单限制"群绑定数"无法堵住免费容量漏洞——一个 2000 人的免费群，靠反复切换活动就能无限服务。**必须按"群绑定"维度累计去重成员数，跨活动生效。**

### 1.2 范围（本次实现）

| 项 | 纳入 | 说明 |
|----|:----:|------|
| A 群数上限 | ✅ | `maxPlatformTargets`：扩展现有 `TenantPlanLimits` + `PLAN_LIMITS` |
| A2 群人数上限 | ✅ | `maxGroupMembers`：新增维度，按群绑定累计去重成员数 |
| B 租户覆写 | ✅ | 新增 `tenant_community_overrides` 表 + PATCH 接口（含群人数） |
| 管理端 UI（L3） | ✅ | 租户管理弹窗新增"社群功能"配置区（含群人数） |
| 测试 | ✅ | 单元 + 端到端 |
| 社群看板（C） | ❌ | 延后，见 §8 |
| system_config 动态覆盖 | ❌ | 延后，见 §8 |
| 群数上限业务层校验 | ❌ | **不强制**（grandfathering），见 §4.4 |
| 群人数上限业务层校验 | ✅ | **必须强制**（runtime gate），见 §3.3 |

### 1.3 核心设计原则（防灾难红线）

1. **群数上限（maxPlatformTargets）：新增不阻断存量（grandfathering）**。套餐校验只作用于"新建/修改绑定"，**绝不**自动下架存量绑定，**绝不**在 `inbound.ts` 业务层按套餐拦截群数（否则会杀死存量免费租户的 `/签到` `/抽奖`，这是灾难）。
2. **群人数上限（maxGroupMembers）：运行时强制（runtime gate）**。与群数上限不同——群人数上限是"每个群能服务多少成员"的**硬配额**，必须按群绑定累计去重成员数，跨活动生效，运行时拒绝超限新成员。**存量老成员不阻断**（已在群内的老成员继续使用）。
3. **与全局开关（L3）语义区分**：全局开关是平台级 kill-switch，必须业务层强停；套餐绑定是商业化配额 gate，只拦增量。
4. **小而美**：本次不做 `communityFeatures[]` 数组。
5. **错误消息可行动**：403 时明确告知"升级套餐"路径，而非模糊拒绝。

## 2. 数据模型设计

### 2.1 扩展 `TenantPlanLimits`（`src/services/lottery/types.ts`）

```typescript

  maxActivities: number | null;

  communityEnabled: boolean;            // 套餐是否开放社群功能（布尔硬门）
```

### 2.2 `PLAN_LIMITS` 默认值（`src/services/lottery/plan.ts`）

采用"免费试用 1 群 × 200 人 → 付费扩容"的行业变现模型：

| 套餐 | communityEnabled | maxPlatformTargets | maxGroupMembers | 变现逻辑 |
|------|:---------------:|:------------------:|:---------------:|----------|
| free | true | **1** | **200** | 免费 1 群 × 200 人尝鲜，促升级 |
| pro | true | **3** | **5000** | 升级后扩到 3 群 × 5000 人 |
| team | true | **10** | **20000** | 团队 10 群 × 20000 人 |
| enterprise | true | **null（不限）** | **null（不限）** | 大客户不限 |

```typescript
const PLAN_LIMITS: Record<string, Omit<TenantPlanLimits, "plan">> = {
  free:       { ..., maxWebhooks: 0,    communityEnabled: true, maxPlatformTargets: 1,  maxGroupMembers: 200 },
  pro:        { ..., maxWebhooks: 3,    communityEnabled: true, maxPlatformTargets: 3,  maxGroupMembers: 5000 },
  team:       { ..., maxWebhooks: 10,   communityEnabled: true, maxPlatformTargets: 10, maxGroupMembers: 20000 },
  enterprise: { ..., maxWebhooks: null, communityEnabled: true, maxPlatformTargets: null, maxGroupMembers: null },
};
```

> ⚠️ **为什么 free 不是 false/0**：若 free 设 `communityEnabled=false`，存量免费租户（几乎没有绑定）不会被破坏，但变现路径"试用→付费"比"禁用→付费"更顺；且 `maxPlatformTargets=1` + `maxGroupMembers=200` 让免费租户能真实体验但容量有限，**促升级**。这是经行业验证的低摩擦变现模型。

> ⚠️ **maxGroupMembers=200 与 maxParticipantsPerActivity=200 的关系**：两者数值相同但**维度不同**——`maxParticipantsPerActivity` 限制"单活动参与人数"（活动创建时设上限，群助手可切换活动绕过）；`maxGroupMembers` 限制"该群绑定累计去重成员数"（跨活动累计，运行时强制）。**后者才真正堵住免费容量漏洞**。

### 2.4 新增 `community_members` 表（成员注册表，用于群人数上限强制）

```typescript
/**
 * 群绑定成员注册表（docs/180 §3.3）。
 * 记录每个群绑定下已服务过的**去重成员**。
 * 用于运行时强制 maxGroupMembers 上限，跨活动累计。
 * 
 * 新成员首次与群交互时 INSERT，已存在则 ON CONFLICT DO NOTHING。
 * 超出 maxGroupMembers 时拒绝新成员，但不影响存量成员。
 * 
 * 注意：表名 community_members 而非 platform_members，
 * 避免与现有平台运营者表（schema.ts:148）冲突。
 */
export const communityMembers = sqliteTable("community_members", {
  id: text("id").primaryKey(),
  tenantId: text("tenant_id").notNull(),
  platformTargetId: text("platform_target_id").notNull(),
  userId: text("user_id").notNull(),          // users.id（Phase B 稳定 ID）
  identityValue: text("identity_value").notNull(), // 平台用户 ID（QQ号），兜底
  createdAt: text("created_at").notNull().default(sql`(datetime('now'))`),
}, (table) => ({
  uniqTargetUser: uniqueIndex("uq_community_members_target_user").on(table.platformTargetId, table.userId),
}));
```

- 迁移文件：`migrations/0053_add_community_members.sql`
- 唯一索引：`(platform_target_id, user_id)` — 保证同一群绑定下同一用户只计一次。

> **为何不用 `platformTargets` 计数器缓存**：计数器缓存（`memberCount` 列 + 原子递增）有并发超限风险，且无法精确去重。成员注册表在事务内 insert + count，天然原子、精确去重，且支持跨活动累计（`platform_target_id` 不变，`activeDrawId` 变化后仍统计同一群）。

## 3. 服务层设计

### 3.1 核心函数 `getTenantCommunityPolicy`（新增，建议放 `src/services/platform/community-policy.ts`）

```typescript
/**
 * 计算租户的社群功能生效策略。
 * 优先级：租户覆写（tenant_community_overrides）> 套餐默认（PLAN_LIMITS）
 *
 * @param db 数据库实例
 * @param tenantId 租户 ID
 * @returns 生效策略 + 来源（override/plan），供鉴权与 UI 展示
 */
export async function getTenantCommunityPolicy(
  db: DbType,
  tenantId: string,
): Promise<{
  communityEnabled: boolean;
  maxPlatformTargets: number | null;
  source: "override" | "plan";
}> {
  // 1. 查租户套餐
  const [tenant] = await db.select({ plan: tenants.plan }).from(tenants).where(eq(tenants.id, tenantId)).limit(1);
  const limits = getTenantPlanLimits(tenant?.plan);

  // 2. 查租户覆写表
  const [ov] = await db.select().from(tenantCommunityOverrides).where(eq(tenantCommunityOverrides.tenantId, tenantId)).limit(1);
  if (ov) {
    return {
      communityEnabled: ov.communityEnabled === 1,
      maxPlatformTargets: ov.maxPlatformTargets,
      source: "override",
    };
  }

  // 3. 无覆写 → 套餐默认
  return {
    communityEnabled: limits.communityEnabled,
    maxPlatformTargets: limits.maxPlatformTargets,
    source: "plan",
  };
}
```

### 3.2 配额校验辅助 `canTenantCreatePlatformTarget`（供 L2 路由复用）

```typescript
/**
 * 校验租户是否可新增一个群绑定（docs/180 §4.2 校验点）。
 * 返回 { ok: true } 或 { ok: false, message }。
 */
export async function canTenantCreatePlatformTarget(
  db: DbType,
  tenantId: string,
): Promise<{ ok: boolean; message?: string }> {
  const policy = await getTenantCommunityPolicy(db, tenantId);

  // 布尔硬门：套餐/覆写关闭了社群
  if (!policy.communityEnabled) {
    return { ok: false, message: "当前租户未开通社群功能，请联系平台运营者或升级套餐" };
  }

  // 数量软门：统计当前绑定数
  if (policy.maxPlatformTargets !== null) {
    const [{ total: count }] = await db
      .select({ total: count() })
      .from(platformTargets)
      .where(eq(platformTargets.tenantId, tenantId));
    if (Number(count || 0) >= policy.maxPlatformTargets) {
      return {
        ok: false,
        message: `已绑定 ${count}/${policy.maxPlatformTargets} 个群，已达当前套餐上限，请升级套餐`,
      };
    }
  }

  return { ok: true };
}
```

### 3.3 群人数上限强制 `enforceGroupMemberCap`（运行时 gate，核心新增）

**调用点**：`src/services/platform/inbound.ts` → `executeBuiltinPlatformCommand` 内，在 `ensurePlatformEntry` 之前（或 `executeBuiltinPlatformCommand` 分发前）。

**流程**：
1. 新成员首次与群交互 → 事务内 `INSERT community_members ON CONFLICT DO NOTHING`
2. 若为新成员，`COUNT(community_members)` 与该群绑定数对比
3. 超限 → **回滚插入**，返回"群人数已满"；未超限 → 提交，继续执行命令
4. 存量成员（已在注册表）→ 直接放行（grandfathering）

```typescript
/**
 * 强制群人数上限（docs/180 A2）。
 * 按 platform_target_id 累计去重成员数，跨活动生效。
 * 存量成员放行；新成员超限则拒绝且不落注册表。
 *
 * @returns { ok: true } 或 { ok: false, reply }
 */
export async function enforceGroupMemberCap(
  db: DbType,
  input: { tenantId: string; platformTargetId: string; userId?: string },
): Promise<{ ok: true } | { ok: false; reply: string }> {
  // provisioning 失败降级（userId 为空）：不阻断命令（避免僵尸用户卡死）
  if (!input.userId) return { ok: true };

  const policy = await getTenantCommunityPolicy(db, input.tenantId);
  if (policy.maxGroupMembers === null) return { ok: true }; // 不限

  let over = false;
  await withDbTransaction(db, async (tx) => {
    // 1. 是否已是存量成员
    const [existing] = await tx
      .select({ id: communityMembers.id })
      .from(communityMembers)
      .where(and(
        eq(communityMembers.platformTargetId, input.platformTargetId),
        eq(communityMembers.userId, input.userId),
      ))
      .limit(1);
    if (existing) return; // 存量成员放行

    // 2. 新成员：先计数，超限则标记不插入
    const [{ total: count }] = await tx
      .select({ total: count() })
      .from(communityMembers)
      .where(eq(communityMembers.platformTargetId, input.platformTargetId));
    if (Number(count || 0) >= policy.maxGroupMembers) {
      over = true;
      return;
    }

    // 3. 未超限：插入成员注册
    await tx.insert(communityMembers).values({
      id: randomUUID(),
      tenantId: input.tenantId,
      platformTargetId: input.platformTargetId,
      userId: input.userId,
      identityValue: input.userId, // identityValue 兜底用 userId；有平台ID时传平台ID
      createdAt: new Date().toISOString(),
    });
  });

  if (over) {
    return {
      ok: false,
      reply: `当前群参与人数已达上限（${policy.maxGroupMembers} 人），升级套餐可扩容群人数。`,
    };
  }
  return { ok: true };
}
```

> ⚠️ **并发安全**：事务内 count + conditional insert，极端并发下可能轻微超限（如 199→201），属**软上限**可接受（与现有活动配额一致）。若需硬上限，采用 `INSERT ... ON CONFLICT` + 事务内 `changes()` 严格判断，但会增加复杂度，本次不做。

> 🔒 **grandfathering 语义**：存量成员（已在注册表的）**始终放行**，即使之后套餐被降级让他们越过上限。只有**新成员**在满员时被拒。这避免"老用户突然用不了"的灾难，同时封住"新用户无限涌入"的漏洞。

> 🔒 **为什么必须在业务层（runtime）强制**：群人数上限是"该群已服务多少成员"的**存量状态**，无法在 POST/PUT 创建绑定时预判（群内成员是动态的）。因此必须与全局开关一样，在命令执行链路实时校验。这与群数上限（`maxPlatformTargets`，用 POST/PUT 拦增量）**刻意不同**——群数上限无存量成员状态，故 grandfathering 即可。

### 4.3 新增：L3 租户覆写（`src/routes/platform.ts` PATCH `/tenants/:id/community`）

```typescript
platformRoute.patch(
  "/tenants/:id/community",
  requirePlatformMember(["platform_owner"]),   // 仅平台所有者可覆写
  async (c) => {
    const db = getDb(c);
    const actorUserId = c.get("userId") as string;
    const actorRole = c.get("platformRole") as string;
    const tenantId = c.req.param("id");
    if (!tenantId) return fail(c, "缺少租户 ID", 400);

    const body = await c.req.json<{
      communityEnabled?: boolean;
      maxPlatformTargets?: number | null;  // null 表示清除群数限制
      maxGroupMembers?: number | null;     // null 表示清除群人数限制
      note?: string;
    }>();

    const [tenant] = await db.select().from(tenants).where(eq(tenants.id, tenantId)).limit(1);
    if (!tenant) return fail(c, "租户不存在", 404);

    // 校验：maxPlatformTargets / maxGroupMembers 必须 >= 0；null 或不传表示不修改
    const isNonNegIntOrNull = (v: unknown) =>
      v === undefined || v === null || (Number.isInteger(v) && (v as number) >= 0);
    if (!isNonNegIntOrNull(body.maxPlatformTargets)) {
      return fail(c, "maxPlatformTargets 必须是非负整数或 null", 400);
    }
    if (!isNonNegIntOrNull(body.maxGroupMembers)) {
      return fail(c, "maxGroupMembers 必须是非负整数或 null", 400);
    }

    const [{ total: bindings }] = await db
      .select({ total: count() })
      .from(platformTargets)
      .where(eq(platformTargets.tenantId, tenantId));

    // 防灾难：不允许把群数上限设到低于当前已有绑定数
    if (body.maxPlatformTargets !== undefined && body.maxPlatformTargets !== null
      && body.maxPlatformTargets < Number(bindings || 0)) {
      return fail(c, `当前已有 ${bindings} 个群绑定，不能把上限设到低于该值`, 400);
    }

    // 防灾难：不允许把群人数上限设到低于任一群当前已有成员数
    // 取该租户下所有群绑定中成员数最大的值作为下限
    if (body.maxGroupMembers !== undefined && body.maxGroupMembers !== null) {
      const [{ total: maxMembers }] = await db
        .select({ total: sql<number>`COALESCE(MAX(total), 0)` })
        .from(
          db.select({ total: count() })
            .from(communityMembers)
            .where(eq(communityMembers.tenantId, tenantId))
            .groupBy(communityMembers.platformTargetId)
            .as("g"),
        );
      if (body.maxGroupMembers < Number(maxMembers || 0)) {
        return fail(c, `已有群绑定成员数达到 ${maxMembers}，不能把群人数上限设到低于该值`, 400);
      }
    }

    // 读取现有覆写 upsert
    const [existing] = await db.select().from(tenantCommunityOverrides)
      .where(eq(tenantCommunityOverrides.tenantId, tenantId)).limit(1);

    const now = new Date().toISOString();
    await withDbTransaction(db, async (tx) => {
      if (existing) {
        // 部分更新：只覆盖传入字段，未传字段保持原值
        await tx.update(tenantCommunityOverrides).set({
          communityEnabled: body.communityEnabled !== undefined
            ? (body.communityEnabled ? 1 : 0)
            : existing.communityEnabled,
          maxPlatformTargets: body.maxPlatformTargets !== undefined
            ? body.maxPlatformTargets
            : existing.maxPlatformTargets,
          maxGroupMembers: body.maxGroupMembers !== undefined
            ? body.maxGroupMembers
            : existing.maxGroupMembers,
          note: body.note !== undefined ? body.note : existing.note,
          updatedBy: actorUserId,
          updatedAt: now,
        }).where(eq(tenantCommunityOverrides.tenantId, tenantId));
      } else {
        // 首次覆写：未传字段用安全默认（communityEnabled=1, maxPlatformTargets=1, maxGroupMembers=取套餐默认）
        const planLimits = getTenantPlanLimits(tenant?.plan);
        await tx.insert(tenantCommunityOverrides).values({
          tenantId,
          communityEnabled: body.communityEnabled !== undefined ? (body.communityEnabled ? 1 : 0) : 1,
          maxPlatformTargets: body.maxPlatformTargets !== undefined ? body.maxPlatformTargets : 1,
          maxGroupMembers: body.maxGroupMembers !== undefined
            ? body.maxGroupMembers
            : planLimits.maxGroupMembers,   // 首次覆写沿用套餐默认，避免误设
          note: body.note || "",
          updatedBy: actorUserId,
          updatedAt: now,
        });
      }
      // 平台审计（与覆写同事务写入，保证可追溯）
      await writePlatformAudit(tx, {
        actorUserId, actorRole,
        action: "platform.tenant.community.override",
        targetType: "tenant", targetId: tenantId, tenantId,
        metadata: { communityEnabled: body.communityEnabled, maxPlatformTargets: body.maxPlatformTargets, maxGroupMembers: body.maxGroupMembers, note: body.note },
      });
    });

    return ok(c, { updated: true });
  },
);
```

> 🔒 **防灾难校验**：`maxPlatformTargets < 当前绑定数` 直接 400 拒绝——避免运营者误设群数上限导致租户瞬间"超配额"。`maxGroupMembers < 任一群当前成员数` 同样 400 拒绝——避免误设群人数上限导致存量成员被拒。

### 4.4 刻意不做的校验点（防灾难关键）

| 位置 | 是否强制 | 原因 |
|------|:-------:|------|
| POST/PUT `/platform-targets` 群数上限 | ✅ 强制 | 拦新增，配额 gate |
| `inbound.ts` 业务层 **群数上限** | ❌ **不强制** | 若按套餐强制群数，存量超配额免费租户的 `/签到` `/抽奖` 会被业务层拦截 = **灾难** |
| `inbound.ts` 业务层 **群人数上限** | ✅ **强制** | 见 §3.3。群人数上限是**存量状态**（该群已服务多少成员），无法在 POST/PUT 预判，必须运行时实时校验。且只拦**新成员**，不伤存量成员 |
| 全局开关（L3）`inbound.ts` | ✅ 保持强制 | 平台级 kill-switch，语义本就该全停 |

> ⚠️ **这是与 docs/174 全局开关"业务层闭环"的本质区别，必须写清楚**：全局开关是合规/安全 kill-switch，必须业务层全停；套餐绑定中的**群数上限**是商业化配额 gate，只拦增量、不伤存量。而**群人数上限**因维度不同（存量状态），必须业务层实时校验，但与全局开关不同——它只拦**新成员**，不伤存量。**三个机制不可混为一谈。**

### 4.5 新增：L3 清除覆写（`src/routes/platform.ts` DELETE `/tenants/:id/community`）

```typescript
platformRoute.delete(
  "/tenants/:id/community",
  requirePlatformMember(["platform_owner"]),
  async (c) => {
    const db = getDb(c);
    const actorUserId = c.get("userId") as string;
    const actorRole = c.get("platformRole") as string;
    const tenantId = c.req.param("id");
    if (!tenantId) return fail(c, "缺少租户 ID", 400);

        .where(eq(tenantCommunityOverrides.tenantId, tenantId));
      await writePlatformAudit(tx, {
        actorUserId, actorRole,
        action: "platform.tenant.community.override.clear",
        targetType: "tenant", targetId: tenantId, tenantId,
        metadata: {},
      });
    });
    return ok(c, { updated: true });
  },
);
```

> 删除覆写后，该租户的社群策略立即恢复为**套餐默认值**（`getTenantCommunityPolicy` 返回 `source: "plan"`）。
