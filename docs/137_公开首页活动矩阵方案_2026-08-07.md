# 137 公开首页活动矩阵方案

> 日期：2026-08-07  
> 背景：希望将 `https://lucky.eforge.xyz/` 首页从纯 SaaS 介绍页升级为公开活动入口，让 SaaS 商家的秒杀、免费福利、留资和问卷活动能被快速浏览、点击和转化。
> 边界：`cf-lottery` 已经承接限时抢购的身份、名额、支付、回调、发卡闭环；`cf-shop`、淘宝、咸鱼或其他商城只等价为外部导流目标，不是本项目主战场。

## 1. 路线判断

这个方向是合理的，但边界必须清楚：

| 维度 | 判断 |
| --- | --- |
| 产品定位 | 合理。cf-lottery 是活动引擎，公开首页可以成为“活动货架”，承接限时抢购、免费抽奖、资料领取、问卷投票等活动入口。 |
| 成交效率 | 合理。秒杀活动天然需要商品名、价格、场次和库存展示，公开首页能减少“只靠单活动链接分发”的摩擦。 |
| 产品矩阵 | 合理。cf-lottery 管活动内商品展示、价格、库存、支付和发卡；cf-shop/第三方商城只作为可选导流目标，不复制购物车、SKU、商品后台。 |
| 多租户风险 | 可控。只展示商家明确公开的 `visible=1`、`status=open` 且未结束活动，不暴露内部 `draw.id`、租户后台信息或未开放活动。 |
| 工程难度 | 中等偏低。已有 `lottery_draws.product_link`、`promotion_config.flashSale`、`public_slug`、`visible` 字段，只需新增安全公开列表接口与首页 UI。 |
| 后续扩展 | 中等。若要做到真正电商首页级体验，后续需要推荐排序、分类、搜索、活动级客服、活动组合模板、转化归因。 |

结论：可以推进，但第一阶段只做“公开活动矩阵”，不要把 cf-lottery 做成完整商城，也不要把 cf-shop 变成限时抢购的依赖。

## 2. 第一阶段边界

只展示以下活动：

1. `visible = 1`
2. `status = open`
3. `end_at > now`
4. 有 `public_slug`

卡片分两类：

| 类型 | 判定 | 首页展示 |
| --- | --- | --- |
| 限时抢购 | `experience_type=flash_sale` 或 `promotion_config.flashSale.enabled=true` | 商品名、价格、场次、倒计时/状态、已抢进度、剩余名额、抢购按钮 |
| 免费活动 | 非直付活动，或无价格配置 | 免费标签、活动类型、活动时间、参与按钮 |

卡片还必须展示承接方式，防止用户误解支付链路：

| 承接方式 | 判定 | 文案 |
| --- | --- | --- |
| 站内支付 | `flashSale.paymentRequired=true` | 站内支付 |
| 外部承接 | `paymentRequired=false` 且存在安全 `product.url/destination.url` | 外部承接 |
| 免费参与 | 无站内支付、无外部承接 URL | 免费参与 |

价格来源：

1. 直付秒杀：`flashSale.priceCents + currency`
2. 外部承接型活动：`productLink.price` 或 `promotion_config.destination.priceText`
3. 免费活动：前端展示“免费”

## 3. 不做的事

1. 不新增商品表、SKU 表、购物车、店铺页。
2. 不把 cf-shop 的商品管理复制到 cf-lottery；也不让 cf-lottery 的直付秒杀依赖 cf-shop。
3. 不展示 draft、paused、cancelled、hidden、已结束活动。
4. 不暴露内部活动 ID、租户 ID、支付配置、卡密库存明细。
5. 不在首页直接发起支付；首页只进入活动页，活动页完成身份、名额、支付和发卡闭环。

## 4. 实施方案

### 后端

新增公开接口：

```http
GET /api/public/home-activities?limit=12
```

返回字段只包含公开展示所需内容：

- `publicSlug`
- `title`
- `description`
- `activityKind`
- `experienceType`
- `startAt`
- `endAt`
- `product.title/imageUrl/priceText/url`（活动内展示素材或外部承接链接，不代表 cf-shop 商品域模型）
- `flashSale.paymentRequired/priceCents/currency/sessionLabel/remaining/progressPercent`

### 前端

首页改为“活动矩阵 + SaaS 入口”：

1. 首屏展示“今日公开活动”与核心 CTA。
2. 有公开活动时，优先展示活动卡片网格。
3. 无公开活动时，展示当前 SaaS 注册/创建活动路径。
4. 卡片点击进入 `/lottery/:publicSlug`。
5. 保留登录/进入后台入口。

### 备份

改版前主页备份到：

```text
docs/backups/LandingView_2026-08-07_before_public_marketplace.vue
```

## 5. 上线风险

| 风险 | 控制 |
| --- | --- |
| 多租户误展示 | 后端只查 `visible=1/status=open/end_at>now/public_slug` |
| 空活动页影响转化 | 前端有空态，仍保留 SaaS 创建入口 |
| 首页查询成本 | 首期限制 `limit<=24`；参与数使用一次 `GROUP BY draw_id` 聚合，避免每个活动单独 COUNT；后续再加推荐索引 |
| 支付误导 | 首页不直接支付；直付仍在活动页完成身份、名额、订单、回调、发卡 |

## 6. 后续路线

1. 活动分类 Tabs：秒杀、免费、问卷、抽奖、资料领取。
2. 营销组合模板：免费活动结果 CTA 自动指向付费秒杀。
3. 活动级客服联系方式。
4. 推荐排序：即将结束、转化率、剩余名额、商家置顶。
5. 未来 cf-pay 独立后，首页可展示统一支付能力标签，但仍不在首页创建订单。
