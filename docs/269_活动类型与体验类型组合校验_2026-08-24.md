# 269 活动类型与体验类型组合校验

> 时间：2026-08-24
> 关联：docs/267 低成本高价值功能路线图（审查阶段发现的架构间隙）
> 状态：✅ 已完成

---

## 一、问题背景

活动类型（activityKind，9 种）与互动体验（experienceType，15 种）是两个独立维度，通过 `defaultExperienceForActivity()` 建立默认值关联。

**原有缺陷**：
1. 编辑活动时，experienceType 下拉框展示全部 14 个选项，**仅 `wheel` 在非 lottery 时被 disabled**
2. 后端 POST/PATCH API 只校验 experienceType 是否在合法枚举内，**不校验与 activityKind 的组合合法性**
3. 管理员可手动选择语义不匹配的组合（如 `vote` + `wheel`、`checkin` + `slot`）
4. 发布预检仅拦截 `wheel + 非lottery`，其余不匹配组合不拦截

## 二、解决方案

### 2.1 白名单映射（前后端共享）

在 `src/lib/activity-utils.ts`（后端）和 `frontend/src/lib/activity-defaults.ts`（前端）中新增 `ALLOWED_EXPERIENCE_TYPES` 常量：

| activityKind | 允许的 experienceType |
|---|---|
| lottery | wheel, slot, scratch, card, grid, flash_sale, submit |
| signup_chain | list, submit |
| reservation | calendar, submit |
| vote | ballot, form, submit |
| survey | form, submit |
| checkin | checkin, submit |
| waitlist | queue, submit |
| approval | form, submit |
| claim | reveal, flash_sale, submit |

新增 `isValidExperienceForActivity(activityKind, experienceType)` 校验函数。

### 2.2 前端改动

**文件**: `frontend/src/views/admin/AdminLotteryView.vue`

- experienceType 下拉框的每个 `<option>` 添加 `:disabled="!isValidExperienceForActivity(...)"` 
- 管理员切换 activityKind 时，不匹配的体验选项自动变灰不可选
- 当前已选的 experienceType 如果不匹配新 activityKind，会被 `handleActivityKindChange()` 自动重置为默认值

### 2.3 后端改动

**文件**: `src/routes/admin-lottery.ts`

- **POST（创建）**：在 `createDraw` 调用前校验 `isValidExperienceForActivity(activityKind, experienceType)`
- **PATCH（更新）**：在 `nextExperienceType` 计算后校验 `isValidExperienceForActivity(nextActivityKind, nextExperienceType)`
- 不合法组合返回 400：`互动体验 "wheel" 不适用于活动类型 "vote"`

### 2.4 平台配置修复

**文件**: `src/lib/system-config-definitions.json`

- `enabled_activity_kinds` enum 补充 `waitlist`（候补排队）
- 原因：后端 ACTIVITY_KINDS 和前端 activityKindLabels 均包含 waitlist，但平台配置 enum 遗漏

### 2.5 附带修复

**文件**: `frontend/src/views/admin/lottery/growth-config.ts`

- 修复 `formatLeaderboardRewardsText` 调用处缺少 `rewardType` 字段的类型错误（排行榜奖品增强遗留）

## 三、测试覆盖

| 测试 | 文件 | 说明 |
|------|------|------|
| PATCH 不合法组合 → 400 | admin-lottery.test.ts | vote + wheel 被拒绝 |
| POST 不合法组合 → 400 | admin-lottery.test.ts | 创建时 vote + wheel 被拒绝 |
| PATCH 非 lottery 活动 winnerCount=0 | admin-lottery.test.ts | 修复：DB 直接改 activityKind 时同步设合法 experienceType |

## 四、审查补充修复

深度审查（后台代理 + 直接验证）发现两处白名单遗漏：

| 修复 | 原白名单 | 修复后 | 依据 |
|------|----------|--------|------|
| claim 补充 submit | `['reveal', 'flash_sale']` | `['reveal', 'flash_sale', 'submit']` | e2e-payment-draw.test.ts:39 支付后留资场景 |
| lottery 补充 submit | `['wheel','slot','scratch','card','grid','flash_sale']` | 追加 `'submit'` | e2e-payment-draw.test.ts:248+ 测试支付/开奖流程 |

`submit` 作为通用表单壳，所有非 lottery 类型已允许；补充到 lottery 与 claim 保持一致性，覆盖"纯信息收集式参与"场景。
