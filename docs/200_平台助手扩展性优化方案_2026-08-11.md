# 200 平台助手扩展性优化方案

> 日期：2026-08-11
> 背景：`AdminPlatformTargetView.vue` 已完成通用化改造（docs/199），支持 QQ/Telegram 平台选择、平台特定配置动态渲染。当前扩展性中等——新增平台需改 3 个文件（常量 + 模板配置表单 + 后端适配器注册），模板中仍存在 `v-if="form.platform === 'xxx'"` 的平台特定配置片段。
> 目标：评估当前扩展性，设计组件注册制改造方案，实现新增平台「零改模板」。

---

## 0. 当前扩展性评估

### 0.1 扩展性评级：⭐️⭐️⭐️（中等）

| 维度 | 当前状态 | 评价 |
|------|----------|:---:|
| 后端新增平台 | `adapter-factory.ts` 注册一行工厂函数 | ⭐️⭐️⭐️⭐️⭐️ 优秀 |
| 前端常量 | `SUPPORTED_PLATFORMS` 数组，v-for 渲染 | ⭐️⭐️⭐️⭐️ 良好 |
| 前端配置表单 | 模板中 `v-if="form.platform === 'qq'"` 硬编码 | ⭐️⭐️ 一般 |
| 前端回调 URL | `getCallbackUrl()` 函数 mapping 表 | ⭐️⭐️⭐️⭐️ 良好 |
| 前端 i18n | `adminPlatformTarget.*` 分组，键名通用 | ⭐️⭐️⭐️⭐️ 良好 |

### 0.2 当前新增平台（如微信小程序）的改动清单

| 文件 | 改动 | 行数 |
|------|------|:---:|
| 前端 `SUPPORTED_PLATFORMS` 常量 | 加 `{ value: 'miniapp', label: '小程序' }` | 1 行 |
| 前端 `AdminPlatformTargetView.vue` 模板 | 加 `v-if="form.platform === 'miniapp'"` 配置表单区块 | ~20 行 |
| 前端 `AdminPlatformTargetView.vue` script | 添加 `miniapp` 配置字段到 form 对象 | 2 行 |
| 前端 `AdminPlatformTargetView.vue` saveTarget | 处理 miniapp 的 adapterConfig 构建 | 5 行 |
| 前端 `getCallbackUrl` | 自动 fallback，无需改（已支持 `miniapp` 路径） | 0 行 |
| 后端 `adapter-factory.ts` | 注册 `miniapp` 工厂函数 | 1 行 |
| 后端路由 `index.ts` | 注册 `miniapp` 路由 | 1 行 |
| 后端路由文件 `platform-miniapp.ts` | 创建 `POST /message` | ~30 行 |
| **合计** | | **~60 行** |

**关键瓶颈**：`AdminPlatformTargetView.vue` 模板中每个平台都需要一段 `v-if="form.platform === 'xxx'"` 的配置表单片段。当平台数量达到 4+ 时，模板会膨胀到难以维护，且新增平台需要改主模板文件。

## 1. 组件注册制改造方案（P2）

### 1.1 设计思路

仿照后端 `adapter-factory.ts` 的工厂注册模式，把前端平台特定配置表单抽取为独立组件，通过注册表统一管理。主模板不再需要 `v-if` 判断平台类型。

```
frontend/src/components/platform-configs/
├── index.ts                    # 注册表 + 类型定义
├── QqConfigForm.vue            # QQ 平台配置表单
├── TelegramConfigForm.vue      # Telegram 平台配置表单
└── MiniAppConfigForm.vue       # 未来：微信小程序（示例）
```

### 1.2 注册表设计

```typescript
// frontend/src/components/platform-configs/index.ts
import type { Component } from 'vue'
import type { PlatformTarget } from '@/views/admin/AdminPlatformTargetView.vue'
import QqConfigForm from './QqConfigForm.vue'
import TelegramConfigForm from './TelegramConfigForm.vue'

/** 平台配置表单组件需实现的 Props 接口 */
export interface PlatformConfigFormProps {
  /** 目标对象（编辑时传入，创建时为 null） */
  editingTarget: PlatformTarget | null
  /** 表单数据（双向绑定，由父组件维护） */
  modelValue: Record<string, unknown>
  /** 适配器配置 JSON（编辑时从后端返回，创建时为空字符串） */
  adapterConfigJson: string
}

/** 平台配置表单组件需暴露的事件 */
export interface PlatformConfigFormEmits {
  (e: 'update:modelValue', val: Record<string, unknown>): void
}

/** 平台配置表单组件注册表 */
export const PLATFORM_CONFIG_FORMS: Record<string, Component> = {
  qq: QqConfigForm,
  telegram: TelegramConfigForm,
  // 新增平台只需在此注册一行：
  // miniapp: MiniAppConfigForm,
}
```

### 1.3 主模板改造（替换 `v-if` 硬编码）

**改造前**（当前）：
```html
<!-- QQ 平台特定配置 -->
<template v-if="form.platform === 'qq'">
  <div class="form-group">
    <label>NapCat URL</label>
    <input v-model="form.adapterBaseUrl" />
  </div>
</template>
<!-- Telegram 平台特定配置 -->
<template v-if="form.platform === 'telegram'">
  <div class="form-group">
    <label>Bot Token</label>
    <input v-model="form.botToken" />
  </div>
</template>
```

**改造后**：
```html
<PlatformConfigForm
  :is="configFormComponent"
  :editing-target="editingTarget"
  :adapter-config-json="editingTarget?.adapterConfigJson || ''"
  v-model="formData"
/>
```

```typescript
// script 中
import { PLATFORM_CONFIG_FORMS } from '@/components/platform-configs'

const configFormComponent = computed(() => {
  return PLATFORM_CONFIG_FORMS[form.value.platform] || null
})

// 监听子组件传递的 modelValue，合并到 form
watch(formData, (val) => {
  Object.assign(form.value, val)
})
```

### 1.4 平台配置表单组件示例

**QqConfigForm.vue**：
```vue
<template>
  <div class="form-group">
    <label>{{ $t('adminPlatformTarget.labelAdapterBaseUrl') }}</label>
    <input v-model="form.adapterBaseUrl" class="form-input" />
  </div>
  <div v-if="editingTarget" class="form-group">
    <label>{{ $t('adminPlatformTarget.labelNewInboundSecret') }}</label>
    <input v-model="form.inboundSecret" class="form-input" />
  </div>
</template>
<script setup lang="ts">
import { computed } from 'vue'

const props = defineProps<{
  editingTarget: any
  modelValue: Record<string, unknown>
  adapterConfigJson: string
}>()
const emit = defineEmits<{ (e: 'update:modelValue', val: Record<string, unknown>): void }>()

const form = computed({
  get: () => props.modelValue,
  set: (val) => emit('update:modelValue', val),
})
</script>
```

**TelegramConfigForm.vue**：
```vue

  <div class="form-group">
    <label>{{ $t('adminPlatformTarget.labelBotToken') }}</label>
```

### 1.5 改造效果对比

| 维度 | 改造前 | 改造后 |
|------|:---:|:---:|
| 新增平台需改模板 | ✅ 是（加 `v-if` 区块） | ❌ 否（零改模板） |
| 新增平台需改文件数 | 3 个 | 2 个（注册表 + 组件文件） |
| 主模板文件行数 | ~720 行 | ~600 行（减少平台配置片段） |
| 平台配置复用性 | 嵌套在模板中，不可复用 | 独立组件，可独立测试 |

## 2. 其他优化建议

### 2.1 后端动态平台列表（P2）

当前 `SUPPORTED_PLATFORMS` 是前端常量，与后端的 `getSupportedPlatforms()` 可能不同步。建议新增一个 API 端点让前端动态获取支持的平台列表：

```typescript
// 后端：在 platform 路由中新增
platformRoute.get("/supported-platforms", async (c) => {
  return ok(c, { platforms: getSupportedPlatforms() });
});
```

```typescript
// 前端：启动时动态获取
const SUPPORTED_PLATFORMS = ref<{ value: string; label: string }[]>([])
onMounted(async () => {
  const data = await api<{ platforms: string[] }>('/supported-platforms')
  const labelMap: Record<string, string> = { qq: 'QQ', telegram: 'Telegram' }
  SUPPORTED_PLATFORMS.value = data.platforms.map(p => ({
    value: p, label: labelMap[p] || p
  }))
  await loadTargets()
})
```

**注意**：当前 `getSupportedPlatforms()` 返回 `Object.keys(PLATFORM_ADAPTER_FACTORIES)`，即 `["qq", "telegram"]`。新增平台时前端会自动感知，无需手动同步常量。

### 2.2 平台配置表单验证（P2）

当前表单验证在 `saveTarget` 函数中内联处理。抽取为独立验证器：

```typescript
// frontend/src/utils/platform-validators.ts
const PLATFORM_VALIDATORS: Record<string, (form: any) => string | null> = {
  qq: (form) => form.targetId ? null : '缺少 QQ 群号',
  telegram: (form) => form.botToken ? null : '缺少 Bot Token',
}
```

### 2.3 平台特有 i18n 键名隔离（P3）

当前 `adminPlatformTarget.*` 分组包含所有平台的通用键名和平台特有键名（如 `labelBotToken` 仅 Telegram 使用）。当平台增多时，键名会膨胀。建议按平台隔离：

```typescript
// 当前（混合）
adminPlatformTarget: {
  labelBotToken: 'Bot Token',
  labelAdapterBaseUrl: 'NapCat URL',
  // ...
}

// 优化后（平台隔离）
adminPlatformTarget: {
  title: 'Platform Assistant',
  // ... 通用键名
}
adminPlatformTargetQQ: {
  labelAdapterBaseUrl: 'NapCat URL',
}
adminPlatformTargetTelegram: {
  labelBotToken: 'Bot Token',
}
```
