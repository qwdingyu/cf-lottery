## 2. P0 — 结构性断点（证据）

### P0-1 「我的参与记录」永不出现（空壳承诺）

| 符号 | 写入点 | 结论 |
| --- | --- | --- |
| `myEntryList` | **仅** `clearSession` 赋 `[]` | 无任何 fetch / push |
| `recordsLoading` | 声明为 `ref(false)`，**从不** `= true` | 加载态死代码 |
| `myWonById` | 仅 clear 清空 | 中奖标签永不来自服务端列表 |
| 模板 | `(sessionEmail \|\| registeredUsername) && sortedMyEntries.length > 0` | 长度恒 0 → 整段不渲染 |

头部「登录查看记录」→ 登录后仍无记录区。096 把记录行做成可点，**建立在空列表上**，属于**假闭环**。

**根因：** 公开 API 无「按身份列我的 entries」；深链 Option C 又是单活动。前端却保留了多活动记录 UI 与文案。

**方向（择一）：**

1. **诚实删/改文案**：无列表 API 前不承诺「记录」；登录只服务查结果。  
2. **最小真闭环**：`completeJoinSuccess` / 成功 `my-result` 写入当前 draw 的一条 `MyEntry`；刷新后用 JWT 调 `my-result` 静默 hydrate `myJoinedById`。

---

### P0-2 刷新后丢失「已参与」→ 可再次点参与 → 409 当失败

- `myJoinedById` **只**在 `completeJoinSuccess` 写入；`onMounted` **不**根据 JWT 回填。  
- `handleJoin` 对已参与的前端短路依赖该 map；刷新后 map 空 → 再请求。  
- 后端 `access-code` / `verify-join` 返回 409「您已参与此活动」。  
- 前端一律 `data.message \|\| joinFailed` toast，**不** `myJoinedById[id]=true`，**不**打开查结果。

用户心智：「我明明参加过，为什么又失败？」

---

### P0-3 每 30 秒全页骨架闪屏

```text
onMounted → setInterval(fetchDraws, 30000)
fetchDraws → loading.value = true → 模板 v-if="loading" 整页 skeleton
```

参与中、填表中、弹窗打开时也会把主内容卸掉再装上。这是**稳定性灾难**，比文案细修严重一个数量级。

**方向：** `fetchDraws({ silent?: boolean })`；轮询 silent，失败不擦掉已有 `draws`。

---

### P0-4 `queryMyResult` / 分享 slug 脆弱

| 位置 | 问题 |
| --- | --- |
| `queryMyResult` fetch URL | `` `/public/draws/${myResultDraw.value.publicSlug}/my-result` ``：无 `encodeURIComponent`；无 `\|\| id`；`publicSlug` 空 → **`undefined`** |
| `lastJoinDrawSlug` | 只 `return draw?.publicSlug`，无 id 回退 → GameResultModal 分享失败 |
| 其它 join 路径 | 多数 `encodeURIComponent(drawId)`，但 drawId 有时是内部 id、有时是 slug（深链 props.id 通常是 slug，尚可） |

---

### P0-5 `handleJoin` 无进行中互斥

`joiningId` 在 `joinOpenWithBearer` / `joinWithRegisteredToken` **内部**才设置；`handleJoin` 先 `await ensureParticipationSessionFromAdmin()`。  
双击 / 连点转盘：两次会话补齐 + 两次 verify-join 竞态（后端 UNIQUE 可挡，但 UX 双 toast / 双弹窗）。

---

### P0-6 `openLogin(draw.id)` 用于「登录后查结果」

非 open 态 `login_to_check`：`@click="openLogin(draw.id)"` → `pendingJoinDrawId` 有值 → **不是** `isLoginOnly`，而是参与验证弹窗。  
活动已 `drawn` 时用户以为「登录查结果」，看到的是「邮箱验证参与」路径，语义错位。

`handleCfAuthForMyResult` 同样写 `pendingJoinDrawId` 再 OAuth，回调可能 `resumeCfAuthJoinAfterCallback` **尝试参与** drawn 活动。

## 5. 已相对扎实（避免误报）

- verify-join / my-result：**Bearer.email 与 body 一致免 OTP**（085）；大小写 toLowerCase（094）。  
- registered：`joinDraw` 服务层拒绝非 `user_id`（防 /join 绕过）。  
- password/invite：缺凭证弹窗；096 凭证-only。  
- 游戏壳 list/queue/ballot 别名 + 未知 Submit（096）。  
- Form/Submit/Reveal loading + 已参与文案（096）。  
- 结果弹窗「查我的结果」事件（096）；回访已参与由本波 JWT 静默 hydrate + 409 友好处理补齐。

## 7. 验收（修后）

```bash
npx tsc --noEmit
npx vitest run
cd frontend && npx vue-tsc --noEmit
```

手工：

1. 参与成功 → 刷新 → 应仍显示已参与或一键恢复，而非二次失败。  
2. 停留 30s+ → 主内容**不得**闪 skeleton。  
3. 仅登录 → 文案不承诺空「记录」或真有一条本地/静默 hydrate。  
4. drawn + 未登录点「登录查询」→ 登录-only，不进参与 OTP。
