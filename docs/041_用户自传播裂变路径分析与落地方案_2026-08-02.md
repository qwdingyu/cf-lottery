## 一、产品设计

### 1.1 问题

运营者手动分发活动链接 → 用户参与 → 传播终止。活动跑不出运营者朋友圈半径。

### 1.2 方案：双循环自传播引擎

```
循环 1 — 参与即传播：
  用户参与 → 弹窗展示裂变引导 → 复制专属链接 → 分享到社交圈
    → 好友通过 ?ref=xxx 进入 → 参与 → 归因到分享者
    → 分享者获得额外抽奖机会 → 排行榜更新 → 更多竞争 → 更多分享

循环 2 — 中奖即传播：
  用户查询结果 → 中奖 → "分享好运"按钮 → 复制链接分享
    → 好友看到"朋友中奖了" → 信任背书 → 参与意愿更强
```

### 1.3 行业对标

参考拼多多砍一刀（动机激励）、微信红包（社交赠予）、美团外卖红包（分享互惠）的最佳实践，选取适合活动引擎的轻量方案：
- **额外参与次数**（每邀请 1 人 +N 次抽奖机会）—— 最直接的动机
- **邀请排行榜**（Top 20 公开排名）—— 社交竞争驱动
- **中奖社交证明**（中奖后分享引导）—— 信任背书

## 三、数据流

### 3.1 promotionConfig 结构（viral 子对象）

```json
{
  "version": 1,
  "enabled": true,
  "kind": "destination",
  "placement": "after_join",
  "destination": { "url": "...", "title": "...", "imageUrl": "...", "priceText": "..." },
  "tracking": { "enabled": true },
  "viral": {
    "enabled": true,
    "extraEntriesPerInvite": 1,
    "maxExtraEntries": 10,
    "leaderboardEnabled": true
  }
}
```

### 3.2 分享码生成 → 归因链路

```
POST /draws/:slug/share { entryId }
  → shareRecords 写入 (sharerEntryId, shareCode)
  → 返回 { shareCode, shareUrl: "/slug?ref=xxx" }

GET /draws/:slug/ref/:shareCode
  → shareRecords.clickedCount++
  → activityEvents 写入 share_click

joinDraw(refCode: shareCode)
  → recordAttributedJoin() 
  → shareRecords.joinedCount++ (原子 SQL UPDATE)
  → activityEvents 写入 attributed_join
```

### 3.3 开奖加权算法

```
performDraw():
  1. 读取 lottery_entries → entries[]
  2. 解析 viral config → if enabled:
     a. SELECT shareRecords WHERE drawId → 聚合 SUM(joinedCount) per sharerEntryId
     b. 构建 weightedCandidates[]:
        for each entry: push entry (1 + min(invitedCount, maxExtraEntries)) times
     c. 传递给 randomSelect(weightedCandidates, totalWinners)
  3. 去重: seenEntryIds Set → 同一 entryId 只中奖一次
```

### 3.4 排行榜查询

```
GET /draws/:slug/viral-leaderboard?entryId=xxx
  1. SELECT shareRecords WHERE drawId → 按 sharerEntryId 聚合 SUM(joinedCount)
  2. JOIN lotteryEntries → 获取 displayName（脱敏）
  3. 按 invitedCount DESC 排序 → Top 20
  4. 如果提供 entryId → 返回我的排名
```

## 四、防刷与安全

| 防护层 | 机制 |
|:-------|:-----|
| 邮箱验证码 | 每个参与者需通过 6 位邮箱验证码 |
| UNIQUE 约束 | `lottery_entries(tenantId, drawId, identityType, identityValue)` |
| IP 限流 | `checkRateLimit` 每分钟 10 次参与 |
| 黑名单 | `lotteryBlacklist` 表封禁 |
| 容量隔离 | 加权展开不消耗 maxParticipants |
| 去重保护 | `seenEntryIds` Set 防止同一人多次中奖 |
| 基数不变 | `candidateCount` 始终为真实参与人数 |

## 六、运营视角

### 6.1 如何开启裂变

运营者在管理后台创建/编辑活动时：
1. 勾选"裂变传播"区块中的"开启裂变传播"
2. 设置每邀请额外次数（建议 1-3）
3. 设置最多额外次数（建议 10-20）
4. 勾选"展示邀请排行榜"

### 6.2 裂变效果指标

| 指标 | 定义 | 数据来源 |
|:-----|:-----|:---------|
| 分享点击 | 通过分享链接打开的点击次数 | `activityEvents.share_click` |
| 有效邀请 | 通过分享链接完成参与的人数 | `activityEvents.attributed_join` |
| 裂变系数 | 有效邀请 / 总参与人数 | 管理端漏斗面板 |
| 排行榜活跃度 | 有邀请记录的参与者比例 | `shareRecords` 聚合 |

## 七、不做清单

| 不做 | 原因 |
|:-----|:-----|
| 助力/组队 | 复杂状态机 + 反作弊，超出活动引擎边界 |
| 红包/分销 | 需要支付/结算系统 |
| 强制分享才能参与 | 损害体验 + 违反平台政策 |
| 写入额外 lottery_entries | 污染参与表语义 + 挤占活动名额 |
| 修改 randomSelect 算法 | 保持核心算法不变，降低回归风险 |
