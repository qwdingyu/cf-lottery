## 一、NapCatQQ 消息发送能力全景

### 1.1 OneBot 11 标准消息 API

NapCatQQ 通过 OneBot 11 协议暴露以下消息发送 API：

| API 动作 | 功能 | cf-lottery 实现 |
|----------|------|----------------|
| `send_group_msg` | 发送群消息 | ✅ `qq-adapter.ts` 已实现 |
| `send_private_msg` | 发送私聊/临时消息 | ❌ 未实现 |
| `send_msg` | 统一发送（自动路由群/私聊） | ❌ 未实现 |

### 1.2 底层消息发送机制

NapCatQQ 的核心发送路径（`napcat-core/apis/msg.ts` `sendMsg`）：

```
sendMsg(peer, msgElements)
  ├─ 如果 peer.chatType === KCHATTYPETEMPC2CFROMGROUP (100)
  │    └─ 且有 guildId → 调用 PrepareTempChat 建立临时会话
  └─ 调用 NTQQ 内核 NodeIKernelMsgService.sendMsg()
       └─ 等待 onMsgInfoListUpdate 回调确认发送成功
```

关键 ChatType 值（`napcat-core/types/msg.ts`）：

| 常量 | 值 | 含义 |
|------|----|------|
| `KCHATTYPEC2C` | 1 | 私聊（好友） |
| `KCHATTYPEGROUP` | 2 | 群聊 |
| `KCHATTYPETEMPC2CFROMGROUP` | 100 | **群临时会话**（非好友临时消息） |
| `KCHATTYPETEMPC2CFROMUNKNOWN` | 99 | 未知来源临时会话 |

### 1.3 好友识别与消息路由逻辑

`createContext`（`onebot/action/msg/SendMsg.ts`）处理私聊消息时的完整路由：

```
收到 send_private_msg { user_id, group_id? }
  ├─ UserApi.getUidByUinV2(user_id) → 获取 UID
  ├─ FriendApi.isBuddy(UID)
  │    ├─ 是好友 → chatType = KCHATTYPEC2C (1) → 直接私聊
  │    └─ 非好友 →
  │         ├─ 有 group_id → chatType = TEMPC2CFROMGROUP (100)
  │         │                   guildId = group_id → 临时消息
  │         └─ 无 group_id → 尝试 getTempChatInfo
  │                           └─ 有历史临时会话 → TEMPC2CFROMGROUP
  │                           └─ 无历史会话 → 降级为 C2C（可能失败）
  └─ sendMsg 检查 chatType === TEMPC2CFROMGROUP
       └─ GroupApi.getGroupMember(guildId, uid) → 获取昵称
       └─ PrepareTempChat(uid, guildId, nick) → 建立临时会话窗口
       └─ NTQQ 内核发送消息
```

## 二、群聊消息 vs 私聊消息 vs 临时消息

### 2.1 三种消息对比

| 维度 | 群聊消息 | 私聊消息（好友） | 临时消息（非好友） |
|------|----------|-----------------|-------------------|
| **OneBot API** | `send_group_msg` | `send_private_msg` | `send_private_msg` + `group_id` |
| **ChatType** | `KCHATTYPEGROUP` (2) | `KCHATTYPEC2C` (1) | `KCHATTYPETEMPC2CFROMGROUP` (100) |
| **前提条件** | 机器人已在群中 | 用户是机器人好友 | 1. 同群 2. 用户未禁止临时会话 |
| **发送前准备** | 无需准备 | 无需准备 | 需调用 `prepareTempChat` 建立会话窗口 |
| **接收方视角** | 群内可见 | 私聊窗口 | 临时会话窗口 |
| **QQ 限制** | 频率限制 | 好友数量 + 频率限制 | 限制严格（用户可全局关闭） |

### 2.2 OneBot 11 下 send_private_msg 的临时消息机制

根据 OneBot 11 标准，`send_private_msg` 的 `group_id` 参数可选：

- **不传 group_id**：NapCat 尝试发私聊。好友走 C2C；非好友且无群上下文，尝试 `getTempChatInfo` 获取历史临时会话，获取不到则降级为 C2C（可能被 QQ 拒绝）。
- **传 group_id**：NapCat 先判断是否为好友。非好友时，明确使用 `TEMPC2CFROMGROUP` 类型，并自动调用 `prepareTempChat` 建立临时会话，发送成功率更高。

### 2.3 QQ 临时消息的限制

QQ 平台的临时消息（群临时会话）受以下限制：

1. **用户隐私开关**：用户可在 QQ 设置中关闭"允许群成员发起临时会话"，关闭后所有临时消息发送失败。
2. **频率限制**：QQ 对临时消息有严格的频率限制，短时间内大量发送可能触发风控。
3. **会话窗口**：用户必须曾在群中与机器人有交集（至少同群），否则 `prepareTempChat` 可能失败。
4. **消息量限制**：临时会话的消息量较大时，QQ 可能自动转为需要好友验证。

## 三、cf-lottery 当前消息投递模型

### 3.1 当前架构

```
NapCatQQ (OneBot 11)
  ├─ HTTP 上报 (webhook) → cf-lottery platform-qq.ts
  │    ├─ 解析消息 → handleInboundPlatformEvent → executeBuiltinPlatformCommand
  │    │    └─ 返回 PlatformCommandResult { reply: string }
  │    │         └─ HTTP 响应 → NapCat QuickAction 处理
  │    │              └─ 回复到**群聊**（与来源相同的上下文）
  │    └─ 只支持 `group` 消息类型（platform-qq.ts line 54 过滤非群消息）
  │
  └─ cron 出站投递 → dispatchPlatformDeliveries
       └─ QQ 适配器 → sendGroupMessage (只发群消息)
```

### 3.2 当前 QQ 适配器能力

`qq-adapter.ts` 只暴露三个方法：

| 方法 | 说明 |
|------|------|
| `sendGroupMessage(groupId, text)` | 发群文本消息 |
| `sendGroupImage(groupId, imageUrl)` | 发群图片消息 |
| `getGroupMemberList(groupId)` | 获取群成员列表 |

**没有** `sendPrivateMessage`、`sendTempMessage` 等私聊/临时消息能力。

### 3.3 当前消息投递类型

`PlatformMessage` 类型定义（`types.ts`）：

```typescript
export type PlatformMessage = {
  platform: PlatformType;
  targetId: string;       // 目前只用于 groupId
  type: "text" | "image" | "card";
  text?: string;
  imageUrl?: string;
  cardData?: Record<string, unknown>;
};
```

`targetId` 始终是 `groupId`，没有 `userId` 或 `targetType` 字段区分私聊/群聊。

### 3.4 入站回复路径（QuickAction 机制）

NapCat 的 HTTP 上报模式（`onebot/network/http-client.ts`）：

1. 群消息事件 → NapCat POST 到 cf-lottery
2. cf-lottery 返回 HTTP 响应 `{ handled: true, reply: "..." }`
3. NapCat 解析响应为 `QuickAction`（`api/quick-action.ts` `handleMsg`）
4. QuickAction 的 `reply` 字段 → 回复到**消息来源的上下文**

**关键限制**：QuickAction 永远回复到消息来源的上下文——群消息回复群，私聊消息回复私聊。当前 `platform-qq.ts` 第 54 行过滤了非群消息，所以所有回复都走群聊。

## 四、各命令/事件的消息发送模式分析

### 4.1 当前各命令/事件的消息去向评估

| 命令/事件 | 当前去向 | 建议去向 | 原因 |
|-----------|---------|---------|------|
| `/签到` 成功 | 群聊 | ✅ 群聊 | 公开签到成功，有激励其他用户的效果 |
| `/签到` 重复 | 群聊 | ✅ 群聊 | 告知用户今天已签到 |
| `/抽奖` 中奖（普通奖品） | 群聊 | ✅ 群聊 | 普通奖品群内公布增加氛围 |
| `/抽奖` 中奖（卡密奖品） | 群聊脱敏 | ❌ **必须私聊** | 卡密在群内公开会被秒抢，需私聊发给中奖用户 |
| `/抽奖` 未中奖 | 群聊 | ✅ 群聊 | 公开结果，无敏感信息 |
| `/我的奖品` | 群聊 | ❌ **应私聊** | 涉及个人中奖记录，含卡密时需脱敏 |
| `/排行榜` | 群聊 | ✅ 群聊 | 公开数据 |
| `/秒杀` | 群聊 | ✅ 群聊 | 购买链接，公开 |
| `/帮助` | 群聊 | ✅ 群聊 | 帮助信息，公开 |
| 出站事件（开奖通知） | 群聊 | ✅ 群聊 | 公开通知 |

### 4.2 敏感信息分级

| 级别 | 内容 | 发送方式 | 当前实现 |
|------|------|---------|---------|
| 🔴 最高敏感 | 卡密明文、密码、私钥 | 必须私聊，含防截屏提示 | 群内脱敏显示"已发放" + 引导后台查看 |
| 🟡 中敏感 | 个人中奖记录、个人信息 | 私聊优先，群聊脱敏 | 群内显示脱敏信息 |
| 🟢 公开 | 签到、排行榜、开奖通知 | 群聊 | 群聊正常发送 |

### 4.3 卡密奖品的当前处理方式

当前代码在 `commands.ts` 中对卡密中奖做了特殊处理：

```
卡密中奖 → 不显示卡密在群内
           ↓
"恭喜你中奖了！卡密已发放。为避免群内泄露，请通过主办方后台核验或后续私聊/网页查看能力领取。"
```

这是一个**临时方案**——用户需要手动去后台查看，体验不流畅。卡密其实已经发放到 `lotteryWinners` 表，但缺少一个"私聊发送卡密"的通道。

## 五、非好友临时消息可行性分析

### 5.1 技术可行性

**结论：NapCatQQ 技术上支持向非好友发送临时消息。**

路径：
```
send_private_msg + user_id + group_id
  → createContext 识别非好友 + 有 group_id
  → chatType = KCHATTYPETEMPC2CFROMGROUP (100)
  → sendMsg 自动调用 PrepareTempChat 建立临时会话
  → 发送消息到用户的临时会话窗口
```

### 5.2 前提条件

| 条件 | 说明 | 能否控制 |
|------|------|---------|
| 机器人账号与用户同群 | 必须同群，否则无法建立临时会话 | ✅ 可控，bot 加入群即可 |
| 用户未关闭"允许临时会话" | QQ 隐私设置，用户可关闭 | ❌ 不可控 |
| 用户未触发 QQ 风控 | 频繁发送临时消息可能被风控 | ⚠️ 可控制频率 |
| 用户未设置不接收群消息 | 用户可设置"不接收某群消息" | ❌ 不可控 |

### 5.3 发送失败时的表现

- 用户关闭了临时会话 → `sendMsg` 返回超时或失败，无明确错误原因
- 用户已不在群中 → `PrepareTempChat` 失败，`sendMsg` 超时
- 用户被机器人拉黑 → `sendMsg` 返回失败
- 频率过快 → 触发 QQ 风控，消息被吞

### 5.4 失败兜底策略（必须设计）

**私聊/临时消息发送不是 100% 可靠的，必须有降级方案：**

```
尝试发送私聊/临时消息
  ├─ 成功 → ✅
  └─ 失败 → 在群内 @用户 告知：
            "系统无法给您发送私聊消息，请检查是否开启了「允许群成员临时会话」。
            您也可以私聊机器人发送「/我的奖品」查看。"
```

## 六、现有架构缺失与改造建议

### 6.1 缺失清单

| 缺失项 | 影响 | 优先级 |
|--------|------|--------|
| QQ 适配器缺少 `sendPrivateMessage` | 无法发送私聊/临时消息 | P0 |
| `PlatformMessage` 缺少 `targetType` 和 `userId` 字段 | 无法区分群发和私发目标 | P0 |
| 卡密发放没有私聊通道 | 卡密只能群内脱敏或后台查看 | P0 |
| 私聊/临时消息无失败兜底 | 用户关闭临时会话后收不到消息 | P1 |
| 入站路由只接受群消息 | 没有私聊消息入口 | P1 |
| 命令结果全部返回群聊 | 个人敏感信息泄漏风险 | P1 |
| 无 `sendPrivateMessage` 出站投递 | 出站事件无法私聊通知 | P2 |

### 6.2 QQ 适配器扩展方案

在 `qq-adapter.ts` 中增加私聊发送能力：

```typescript
// 新增：发送私聊/临时消息
sendPrivateMessage(userId: string, groupId: string, text: string) {
  // 传 group_id 以支持非好友临时消息（KCHATTYPETEMPC2CFROMGROUP）
  return request("/send_private_msg", {
    user_id: userId,
    group_id: groupId,
    message: text,
  });
},

// 新增：安全版私聊发送，自动捕获异常，返回 { success, messageId }
async sendPrivateMessageSafe(
  userId: string, groupId: string, text: string
): Promise<{ success: boolean; messageId?: string; error?: string }> {
  try {
    const response = await this.sendPrivateMessage(userId, groupId, text);
    return { success: true, messageId: readProviderMessageId(response) };
  } catch (err) {
    return { success: false, error: String(err) };
  }
},
```

### 6.3 PlatformMessage 扩展方案

```typescript
export type PlatformMessage = {
  platform: PlatformType;
  targetId: string;           // 群或用户的目标 ID
  /** 新增：目标类型，默认为 "group" */
  targetType?: "group" | "private" | "temp";
  /** 新增：群 ID（私聊/临时消息时用于建立临时会话上下文） */
  groupId?: string;
  type: "text" | "image" | "card";
  text?: string;
  imageUrl?: string;
  cardData?: Record<string, unknown>;
};
```

### 6.4 卡密奖品私聊发放流程

```
用户发送 /抽奖 → 中奖（卡密奖品）
  ├─ 系统发放卡密，标记 lotteryWinners.prizeCodeId
  ├─ 尝试 sendPrivateMessage(userId, groupId, "恭喜您中奖！卡密：XXXX")
  │    ├─ 成功 → 群内显示 "🎉 恭喜 xxx 中奖！卡密已私聊发送。"
  │    └─ 失败 → 群内 @用户 显示 "🎉 恭喜中奖！但系统无法给您发私聊，
  │                 请检查隐私设置。您可私聊机器人发送「/我的奖品」查看。"
  └─ 同时将卡密记录入库，/我的奖品 可查
```

### 6.5 命令回复策略调整

| 命令 | 当前 | 改为 |
|------|------|------|
| `/抽奖` 卡密中奖 | 群内脱敏 | 群内公告 + 私聊发卡密（失败时群内 @ 提示） |
| `/我的奖品` | 群内回复 | 群内回复仅显示概要（"您有 3 件奖品，其中 1 件含卡密"），引导私聊查看详情 |
| 出站事件（prize.issued） | 群发 | 群发公告 + 含卡密时私聊通知 |

### 6.6 出站投递扩展

`delivery.ts` 的 `dispatchPlatformDeliveries` 需要扩展：

1. 根据 `delivery.targetType` 决定使用 `sendGroupMessage` 还是 `sendPrivateMessage`
2. 私发失败时记录失败原因，降级为群发 @ 通知
3. 私发版本也需要重试机制（但快速失败，避免风控）

## 附录：关键代码路径

### A. 临时消息发送路径（NapCatQQ）

```
send_private_msg { user_id, group_id }
  → SendPrivateMsg._handle (ContextMode.Private)
  → createContext (onebot/action/msg/SendMsg.ts)
    → UserApi.getUidByUinV2(user_id)
    → FriendApi.isBuddy(uid) → false
    → group_id 存在 → KCHATTYPETEMPC2CFROMGROUP + guildId = group_id
  → sendMsg (napcat-core/apis/msg.ts)
    → chatType === TEMPC2CFROMGROUP && guildId 存在
    → GroupApi.getGroupMember(guildId, uid)
    → PrepareTempChat(uid, guildId, nick)
      → session.getMsgService().prepareTempChat({ chatType: 100, ... })
    → NTQQ 内核发送
```

### B. 当前群消息回复路径（cf-lottery）

```
NapCat HTTP 上报 → platform-qq.ts
  → handleInboundPlatformEvent (inbound.ts)
  → executeBuiltinPlatformCommand (commands.ts)
  → 返回 PlatformCommandResult { reply }
  → HTTP 响应 → NapCat QuickAction → handleMsg
    → createContext(peerContextMode = Group)
    → 回复到群聊
```

### C. 出站消息投递路径（cf-lottery）

```
enqueuePlatformEvent → 写入 platformDeliveries (status: pending)
  → dispatchPlatformDeliveries (cron)
    → 查 adapterConfig → getPlatformAdapter → QQ adapter
    → adapter.send(message) → sendGroupMessage(groupId, text)
```

---

> **总结**：当前 cf-lottery 的 QQ 消息发送模型是**纯群聊**模式。NapCatQQ 底层支持私聊和临时消息发送。关键改造点在于：QQ 适配器扩展私聊能力、`PlatformMessage` 增加目标类型字段、卡密奖品走私聊通道并在失败时降级为群 @ 通知。
