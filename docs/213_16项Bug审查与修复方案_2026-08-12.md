### 2. `handleDuplicate` — 奖项配置（tiers）未复制

### 10. Roster 模式编辑时未加载已有名单

**位置：** `AdminLotteryView.vue` 第 3654–3743 行

**现状：**

`handleEdit` 中没有加载已有 roster 成员的逻辑。`rosterInput.value` 保持默认 `''`。运营者编辑 roster 活动时看不到现有成员，必须重新录入。

**缓解机制：** `saveDrawRoster`（第 2409 行）在 `rosterInput.value` 为空时 `return`，不会调用 POST API。编辑后不重新录入不会导致数据丢失，但运营者无法确认现有成员。

**修复方案：**

在 `handleEdit` 中增加加载 roster 的逻辑，并展示只读提示（现有成员数量）：

```typescript
async function handleEdit(draw: LotteryDraw) {
  // ... 现有逻辑 ...
  // 加载已有 roster 成员（仅 roster 模式）
  if (draw.participationMode === 'roster') {
    try {
      const rosterData = await adminRequest<{ members: Array<{ email: string }> }>(
        `/api/admin/draws/${draw.id}/roster`,
      )
      if (rosterData.members?.length > 0) {
        rosterInput.value = rosterData.members.map((m) => m.email).join('\n')
      }
    } catch {
      // roster 加载失败不阻断编辑主流程
      rosterInput.value = ''
    }
  }
  // ...
}
```

> ⚠️ 依赖项：后端需新增 GET `/api/admin/draws/:id/roster` 接口（当前仅 POST 导入）。需审核后端路由与权限。

```typescript
    syncLoserReward()
    const config = form.value.activityConfig as any
    return { version: 1, kind: 'lottery', loserReward: config?.loserReward || { enabled: false, couponLabel: '' } }
  }
  return undefined  // ← checkin, signup_chain, claim, approval 等走到这里
})(),
```

对于 `checkin`、`signup_chain`、`claim`、`approval`、`reservation` 等类型，`activityConfig` 为 `undefined`。后端 `createDraw` 对 `undefined` 的处理是 `"{}"`（第 742 行），不会导致崩溃，但这些类型的配置无法通过创建表单传递。

**修复方案：**

明确每个活动类型的 `activityConfig` 处理策略，对非 lottery/survey/vote 也发送当前表单配置：

```typescript
activityConfig: (() => {
  if (['survey', 'vote'].includes(activityKind)) {
    return normalizeActivityConfig(activityKind, form.value.activityConfig)
  }
  if (activityKind === 'lottery') {
    syncLoserReward()
    const config = form.value.activityConfig as any
    return { version: 1, kind: 'lottery', loserReward: config?.loserReward || { enabled: false, couponLabel: '' } }
  }
  // 其他活动类型：发送当前 activityConfig（如果表单有定义）
  if (form.value.activityConfig?.kind) {
    return normalizeActivityConfig(activityKind, form.value.activityConfig)
  }
  return undefined
})(),
```

### 3. `handleCreate` — `accessPassword` 始终发送

对 open 模式发送 `accessPassword: ''`（空字符串）。

### 6. `AdminPrizesView.toggleActive` — 乐观更新失败不回滚

**结论：假阳性。**

**分析：**

实际代码（第 893–905 行）：
```typescript
async function toggleActive(prize: any) {

    const newActive = prize.active !== 0 ? 0 : 1;
```

## 架构原则总结

1. **单一真相源**：`growthFieldsFromDraw` 是解析 `promotionConfig` 的唯一入口，`handleDuplicate` 和 `handleEdit` 都应使用它，避免三处重复解析逻辑。
2. **职责边界**：`buildLotteryDuplicateDraft` 保持"基础字段草稿"语义，不膨胀。增长配置、展示开关、壳、秒杀等由 `growthFieldsFromDraw` 统一处理。
3. **前后端一致**：`handleCreate` 的 `winnerCount` 条件应与 `saveDrawTiers` 的条件保持一致，避免 claim+flash_sale 场景的语义分裂。
4. **回填必填**：`handleEdit` 中所有 `emptyForm()` 定义的字段，只要 API 有返回，就必须回填。遗漏会导致编辑后数据丢失。但注意：不要"幻觉式回填"——`prizeName`、`productName`、`maxWinners`、`expectedParticipants` 等字段后端从不返回，回填无效。应先确认字段是否真实存在于 DB/API。
