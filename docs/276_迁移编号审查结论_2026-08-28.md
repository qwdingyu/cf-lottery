# 276 数据库迁移编号审查结论

日期：2026-08-28
关联：docs/272（用户级邀请码）、docs/275（奖励幂等粒度与代码质量优化）

## 背景

2026-08-28 线上核查存量用户邀请码回填时，顺带审查了数据库迁移脚本的编号，
确认是否存在编号重复、跳号或编号与内容不匹配的问题。

## 审查过程

1. 列出本地 `migrations/` 目录全部 37 个迁移文件，提取编号排序。
2. 查询线上 `schema_migrations` 表，对比已应用迁移的编号与 name。
3. 对发现的编号异常，用 `git log` 追溯历史提交确认根因。
4. 检查迁移执行逻辑（`src/db/apply-migrations.ts`）的容错机制。

## 发现的问题：0036/0040 编号冲突（历史遗留）

### 本地 vs 线上编号不一致

| 编号 | 本地文件 | 线上 schema_migrations |
|------|---------|----------------------|
| 0036 | ❌ 缺失 | ✅ add_store_slug |
| 0040 | ✅ add_store_slug | ✅ add_store_slug |

### 根因（git 历史确认）

- 最初创建 `0036_add_store_slug.sql`（提交 `493920c1`，feat: 店铺首页-0036迁移）。
- 后来发现编号冲突，重命名为 `0040_add_store_slug.sql`
  （提交 `eac89486`，提交信息明确写"迁移0036重命名为0040解决编号冲突"）。
- 但**线上在重命名前已应用 0036**（schema_migrations 记录 `0036|add_store_slug|2026-08-08 03:42:56`），
  重命名后部署又应用了 0040（记录 `0040|add_store_slug|2026-08-08 07:42:02`）。
- `0040_add_store_slug.sql` 文件头注释仍写着 `-- 0036_add_store_slug.sql`，证实是重命名而来。

## 影响评估：无功能破坏

### 线上

0036 和 0040 都已应用，`tenants.store_slug` 列和 `idx_tenants_store_slug` 索引正常。
0040 执行时 `ADD COLUMN store_slug` 报 duplicate column，被迁移容错逻辑跳过
（`src/db/apply-migrations.ts:111` 处理 `already exists` / `duplicate column` / `duplicate index`），
`CREATE UNIQUE INDEX IF NOT EXISTS` 幂等，`UPDATE tenants SET store_slug` 幂等。
**store_slug 列只加了一次（0036），无破坏。**

### 本地 / 新环境

跳过 0036，通过 0040 创建 store_slug 列。0037-0039 是 payment 相关迁移，
不依赖 store_slug，能正确执行。**新环境迁移可正常完成。**

## 其他编号检查：无问题

- **本地**：0030-0067 各一个文件，无重复编号（`assertUniqueMigrationVersions` 会通过）。
- **线上**：0030-0067 连续，无重复、无跳号。
- 除 0036/0040 外，所有编号的 name 与本地文件名一致。

## 解决方案与建议

**不建议强行修复**：把 0040 改回 0036 会使线上已应用的 0040 记录失效，引入新的不一致；
补 0036 占位文件也会造成"空迁移"困惑。

**建议**：
1. 在本文档记录此历史遗留，供未来维护者知晓。
2. 未来大版本迁移（如 0100+）时统一整理编号，或引入迁移版本校验工具。
3. 新增迁移时，先 `git log --all -- migrations/` 确认编号未被占用，避免再次冲突。

## 踩坑记录

### 迁移编号重命名导致线上双记录

**背景**：0036 迁移因编号冲突被重命名为 0040，但线上已应用 0036。

**原因**：迁移编号是"一次性"标识，一旦在线上应用，重命名后旧编号记录仍保留，
新编号会再次执行（即使内容相同）。

**排查过程**：对比本地文件与线上 schema_migrations，发现 0036 缺失但线上有记录；
git log 追溯确认重命名历史。

**解决方案**：依赖迁移容错逻辑（duplicate column 跳过）保证无破坏；
文档记录历史遗留，不强行修复。

**建议**：迁移编号一旦发布到线上，**禁止重命名**。如需调整，应新增迁移而非改名。
