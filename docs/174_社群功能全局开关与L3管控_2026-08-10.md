# 174 社群功能全局开关与 L3 管控

> 日期：2026-08-10
> 定位：为「QQ/Telegram 群助手（社群）功能」补上平台级（L3）一键启停能力的最小成本实现
> 方法：基于实际代码逐项核实（`src/lib/system-config-definitions.json`、`src/routes/admin-lottery-platform.ts`、`src/services/platform/checkin-reward.ts`）

## 1. 背景

深入核查发现，社群功能（QQ/Telegram 群助手）缺少 **L3 平台级管控**：

- **L2（租户）侧**：`AdminQqAssistantView.vue` 已提供完整的群绑定 CRUD + 7 个内置命令开关 + 签到奖励 + 秒杀购买链接配置
- **L3（平台）侧**：缺少「平台运营者一键启停所有租户社群功能」的能力，也缺少「套餐→社群功能」的绑定关系

本次实现**最低成本修复**：平台级 `community_feature_enabled` 全局开关 + L2 后端写入校验。

## 2. 变更内容

### 2.1 新增系统配置：`community_feature_enabled`

文件：`src/lib/system-config-definitions.json`

```json
{
  "key": "community_feature_enabled",
  "label": "社群功能全局开关",
  "description": "平台级一键启停所有租户的 QQ/Telegram 群助手（社群)功能。关闭后租户后台无法新建或修改群绑定，已存在的绑定停止响应命令。",
  "effect": "配置关闭后，POST/PUT /api/admin/platform-targets 返回 403 拒绝写入；GET 列表仍可读（只读模式）。",
  "scope": "admin",
  "type": "boolean",
  "defaultValue": "true",
  "group": "平台运营",
  "order": 35,
  "difficulty": "basic"
}
```

- `scope: "admin"`：仅 L3 平台运营者在 `/platform/config` 可见可改
- `defaultValue: "true"`：未配置时默认启用，不影响存量租户
- `group: "平台运营"`：归入 L3 系统配置「通用」分区

### 2.2 L2 后端写入校验 + L2 业务层执行校验（闭环）

文件：`src/routes/admin-lottery-platform.ts`、`src/services/platform/inbound.ts`

将 `isCommunityFeatureEnabled` 提升为共享工具函数（`src/lib/system-config-registry.ts`），供**两处**闭环使用：

```ts
export async function isCommunityFeatureEnabled(db: DbType): Promise<boolean> {
  const [row] = await db
    .select({ value: systemConfig.value })
    .from(systemConfig)
    .where(eq(systemConfig.key, "community_feature_enabled"))
    .limit(1);
  // 未配置（无记录）或值为 "true" 时视为启用，仅显式 "false" 关闭
  return row ? row.value !== "false" : true;
}
```

**①（界面层）在创建（POST `/platform-targets`）和更新（PUT `/platform-targets/:id`）入口前置校验：**

```ts
if (!(await isCommunityFeatureEnabled(db))) {
  return fail(c, "社群功能已被平台运营者关闭，暂无法创建群绑定", 403);
}
```

**②（业务层）在入站命令执行链路 `inbound.ts` 的 `handleInboundPlatformEvent` 中校验：**

```ts
// 社群功能全局开关（docs/174）：平台运营者关闭后，已存在的绑定停止响应命令（业务层闭环）。
// 这里必须再次校验，而不仅靠 L2 路由的 POST/PUT 403——否则关闭后存量绑定仍会执行 /签到 /抽奖 等命令。
if (!(await isCommunityFeatureEnabled(db))) {
  return {
    handled: true,
    reply: "社群功能已被平台运营者暂停，当前群助手暂不响应命令，请稍后再试。",
  };
}
```

> ⚠️ **闭环关键**：仅靠界面层 403 拦截是不够的——关闭开关后，已绑定的 QQ/Telegram 群仍会收到 `/签到`、`/抽奖`、`/秒杀` 等命令并真正执行。必须在 `inbound.ts`（QQ/Telegram 共用的入站处理入口）再次校验，确保「一键停服」真正停掉**存量绑定的命令响应**，而不只是在参数界面阻止 CRUD。

行为设计：
- **界面层（写操作）**：创建/更新 → 返回 403 拒绝；列表/详情 → 保持可读（只读模式）
- **业务层（命令执行）**：关闭后 → 已存在绑定对 `/签到` `/抽奖` `/秒杀` 等命令返回「社群功能已被平台运营者暂停」提示，且不真正执行命令（不新增参与记录、不扣抽奖次数、不发放奖励）
- **运维操作**：删除/重置密钥/测试消息 → 不拦截（属于运维操作，不增加业务数据）

### 2.5 顺带修复 `checkin-reward.ts` 语法错误 + 修复 Telegram 测试遗留断言

核实中发现未跟踪新文件 `src/services/platform/checkin-reward.ts` 存在：

1. `toPositiveInt` 函数缺少闭合 `}`，导致后续所有 `export` 被嵌套进函数体（esbuild 报 `Unexpected "export"`）
2. 文件末尾多一个 `}`

这两处语法错误会导致整个平台测试套件无法构建（esbuild 失败）。已修复，`tsc --noEmit` 与全部平台测试恢复正常。

## 5. 踩坑记录

### 5.1 缺失闭合括号导致全套件构建失败

**背景**：`checkin-reward.ts` 是连续签到奖励（docs/172 P0）新增文件。
**根因**：`toPositiveInt` 函数少了闭合 `}`，后续 `export function computeCheckinReward(...)` 被当作函数体内的语句，esbuild 报 `Unexpected "export"`，导致所有引用该模块的测试套件无法 build。
**排查过程**：`tsc --noEmit` 报 `TS1184: Modifiers cannot appear here`，`grep` 看函数边界才定位到缺失闭合。
**解决方案**：补上 `}`，并删除文件末尾多余的 `}`。
**建议**：新增多函数文件后先跑 `tsc --noEmit` 再跑 vitest，避免 esbuild 级联失败掩盖真实测试结果。
