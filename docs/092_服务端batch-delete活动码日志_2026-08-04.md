# 092 实施记录：服务端 batch-delete（活动 / 码 / 日志）

日期：2026-08-04  
承接：docs/082 P2「`POST .../batch-delete` + 审计一条汇总」、docs/091 删除策略

## 1. 背景

P0/P1 前端多选已齐，活动/码仍走 **N 次单条 DELETE**，日志按钮为假提示。数据量稍大时请求多、审计刷屏。本波补服务端 batch，**不 force 删 open/drawing**，不引入一键炸租户。

## 2. API 契约

| 方法路径 | 请求体 | 成功体要点 | 审计 action |
| --- | --- | --- | --- |
| `POST /api/admin/draws/batch-delete` | `{ ids: string[] }` | `deleted` / `failed` / `deletedIds` / `failedItems[{id,reason}]` | `draw.batch_delete` |
| `POST /api/admin/prizes/codes/batch-delete` | 同上 | 同上 | `prize.codes.batch_delete` |
| `POST /api/admin/logs/batch-delete` | 同上 | 同上 | `logs.batch_delete` |

共用：

- `parseBatchDeleteIds`：去空、去重、**上限 100**（`ADMIN_BATCH_DELETE_MAX`）
- 单条审计 `targetId=batch`，metadata 含 requested/deleted/failed + 样本 ids
- 无 force 档；跨租户 id 视为不存在计入 failed

### 活动

- 状态规则与 `DELETE /draws/:id`、`isDrawStatusDeletable` / `describeDrawDeletePolicy` 一致
- 可删：`draft` / `paused` / `drawn` / `cancelled`
- 不可删：`open` / `drawing`（reason 提示先 pause/cancel）
- 级联：`cascadeDeleteDraw` 单条与 batch 同源；**每条独立事务**顺序执行，避免超长锁

### 奖品码

- 仅 `available`；已发放 / 不存在 → failed
- 一次 `inArray` 删除（仍带 `status=available` 条件防竞态）

### 日志

- 仅本租户 `audit_logs.id`
- 删除后**另写**汇总审计（新 id，不会被本次 ids 删掉）
- **不提供清空全部**；全量仍走平台 `data/cleanup`

## 3. 前端

| 页 | 行为 |
| --- | --- |
| AdminLotteryView | 优先 batch API；catch 后降级顺序 `DELETE /draws/:id` |
| AdminPrizesView 码池 | 优先 batch；catch 降级顺序单删 |
| AdminLogsView | 真实 batch；仅有 `id` 的行可删；ConfirmDialog |

单条删除 API **保留**（行内删、降级、兼容旧客户端）。

## 5. 明确不做（082 防灾难）

- Dashboard 多选
- force 删 open/drawing / 一键清租户测试活动
- 前端高并发（≤3）；batch 本身单请求，降级仍顺序
- 重型表格框架
