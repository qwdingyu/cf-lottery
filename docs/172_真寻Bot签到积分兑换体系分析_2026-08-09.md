# 172 真寻Bot签到积分兑换体系分析

## 背景

为优化 cf-lottery 的签到/抽奖次数体系，参考真寻Bot（Zhenxun Bot）——一个经过社区验证的成熟 QQ 机器人开源项目——的签到、积分、兑换设计，提取可借鉴的行业最佳实践。

## 真寻Bot 架构总览

```
┌─────────────────────────────────────────────────────────┐
│                    真寻Bot 经济体系                       │
│                                                         │
│  签到 → 好感度(Impression) ↕ 金币(Gold) → 商店(Shop)   │
│             ↑                    ↓                      │
│         银行(Bank) ←──── 存款/取款────                    │
│         (利息/贷款)                                      │
└─────────────────────────────────────────────────────────┘
```

- **货币：单货币（金币 Gold）**，无第二货币
- **好感度：累计签到属性**，影响额外奖励和银行额度
- **道具：JSON 字段存储**，商店购买 → 用户背包 → 使用触发效果

## 1. 签到系统 (sign_in)

### 1.1 数据模型

```python

class SignUser(Model):
    user_id: str                                        # 用户ID
    sign_count: int = 0                                 # 累计签到次数
    impression: Decimal = 0                             # 好感度

    specify_probability: Decimal = 0                    # 指定概率（道具）

# SignLog 表 — 签到日志（审计用）
class SignLog(Model):
```

### 1.2 签到流程

```python
async def _handle_sign_in(user, nickname, session):
    # Step 1: 计算好感度增量（随机 0.01~0.99，3% 概率翻倍）
    impression_added = (secrets.randbelow(99) + 1) / 100
    rand = random.random()
    if rand + user.add_probability > 0.97 or rand < user.specify_probability:
        impression_added *= 2

    # Step 2: 更新好感度 + 签到次数
    await SignUser.sign(user, impression_added, ...)

    # Step 3: 发放金币（随机 1~100）
    gold = random.randint(1, 100)

    # Step 4: 随机事件——可掉落道具或额外金币
    gift = random_event(float(user.impression))
    if isinstance(gift, int):
        gold += gift                                   # 额外金币
        user_console.gold += gold
    else:
        user_console.gold += gold                      # 基础金币
        user_console.props[goods.uuid] += 1            # 道具 +1
```

### 1.3 随机事件机制

```python
def random_event(impression: float) -> str | int:
    """好感度越高，道具掉落概率越高（impression / 1000 修正值）"""
    PROB_DATA = {
        SIGN_CARD3_PROB: "好感度双倍加持卡Ⅲ",  # 5%
        SIGN_CARD2_PROB: "好感度双倍加持卡Ⅱ",  # 9%
        SIGN_CARD1_PROB: "好感度双倍加持卡Ⅰ",  # 20%
    }
    rand = random.random() - impression / 1000          # 好感度偏移
    for prob, card in PROB_DATA.items():
        if rand <= prob:
            return card                                 # 掉落道具
    # 未掉落道具则给额外金币
    gold = random.randint(1, max(1, int(impression)))
    return min(gold, MAX_SIGN_GOLD)                     # 200 封顶
```

| 特性 | 说明 |
|------|------|
| 基础奖励 | 随机 1~100 金币 |
| 随机事件 | 34% 概率掉落双倍加持卡，66% 概率额外金币 |
| 好感度影响 | 高好感度 → 道具掉落概率更高、额外金币更多 |
| 封顶 | `MAX_SIGN_GOLD=200` 防止通胀 |

```python
    goods_description: str                              # 商品描述

    goods_limit_time: int = 0                           # 限时抢购（0=不限时）
    daily_limit: int = 0                                # 每日限购（0=不限）
    is_passive: bool = False                            # 是否被动道具

    icon: str | None                                    # 图标
```

### 3.2 购买流程

```python
async def buy_prop(user_id, name, num=1):
    # 1. 查找商品（支持按名称或序号）
    goods = GoodsInfo.find(name)

    # 2. 计算价格（支持折扣）
    price = goods.goods_price * num * goods.goods_discount

    # 3. 余额检查
    if user.gold < price:
        return "金币不够哦..."

    # 4. 每日限购检查
    if goods.daily_limit and today_count >= goods.daily_limit:
        return "今天买够了哦!"

    # 5. 原子扣减
    user.gold -= int(price)
    user.props[goods.uuid] = user.props.get(goods.uuid, 0) + num
    await user.save(update_fields=["gold", "props"])

    # 6. 记录日志
    await append_user_gold_log(user_id, price, GoldHandle.BUY, "shop")
```

## 5. 可借鉴到 cf-lottery 的核心设计模式

### 5.1 单货币体系（✅ 直接采用）

| 真寻 Bot | cf-lottery |
|----------|-----------|
| 金币（Gold）—— 唯一货币 | spins（抽奖次数）—— 唯一货币 |
| 签到产生金币 | 签到产生 spins |
| 金币购买道具 | spins 消耗抽奖 |
| 金币流水日志 | ✓ 建议新增 spins 流水日志 |

**结论**：cf-lottery 的 `spins` 单货币与真寻 Bot 的`金币`单货币完全一致，无需引入第二货币。

### 5.2 签到奖励：固定 + 随机 + 递增（✅ 建议采用）

真寻 Bot 的签到奖励是**三层结构**：

```
签到奖励 = 基础奖励(随机1~100金币) + 随机事件(道具/额外金币) + 好感度加成
```

对应 cf-lottery 的签到奖励设计：

```
签到奖励(spins) = grantSpinCount(固定) + streakBonus(连续递增) + [可选]随机事件
```

| 层 | 真寻 Bot | cf-lottery 建议 |
|----|---------|----------------|
| 基础 | 随机 1~100 金币 | `grantSpinCount`（固定值，已有） |
| 递增 | 好感度累计 | 连续签到天数递增（新增 `streakConfig`） |
| 随机 | 34% 概率掉落道具 | 可选：小概率额外 spins（未来可扩展） |

### 5.3 连续签到 vs 好感度

真寻 Bot 的「好感度」是累计签到属性，不重置。而行业标准（微信读书、多邻国）的「连续签到」会因断签重置。

**建议 cf-lottery 采用「连续签到递增 + 断签重置」**，原因：
- 更符合用户心理模型（"不能断！"的紧迫感驱动 DAU）
- 与行业主流一致（微信读书、多邻国、京东）
- 实现简单，无需累计属性

### 5.4 道具背包系统（❌ 当前不建议）

真寻 Bot 的 `UserConsole.props`（JSON 字段存储道具）是一个有趣的模式，但 cf-lottery 当前阶段不需要道具系统。后续如需扩展，可参考此模式。

### 5.5 流水日志（✅ 建议新增）

真寻 Bot 的所有金币变动都记录日志（`user_gold_log` 表），这是关键审计能力。

**cf-lottery 建议新增 `spins_log` 表**：

```typescript
// 抽奖次数流水日志
spinsLog: pgTable("spins_log", {
  id: text("id").primaryKey(),
  tenantId: text("tenant_id").notNull(),
  entryId: text("entry_id").notNull(),          // 关联 lottery_entries.id
  userId: text("user_id").notNull(),            // 用户标识
  delta: integer("delta").notNull(),            // 变动量（正=收入，负=支出）
  balanceAfter: integer("balance_after").notNull(), // 变动后余额
  reason: text("reason").notNull(),             // checkin / spin / purchase / viral
  refId: text("ref_id"),                        // 关联单据号（spin_id / order_id）
  createdAt: text("created_at").notNull(),
});
```

### 5.6 装饰器声明式道具注册（❌ 当前不需要）

真寻 Bot 的 `@shop_register` 装饰器模式非常优雅，但 cf-lottery 当前不需要道具系统。

## 6. 总结：cf-lottery 签到体系优化方案

基于真寻 Bot 的启发，**轻量级优化方案**：

```
【P0】连续签到递增（streakConfig）
  - 扩展 dailyCheckinPolicy.streakConfig
  - 新增 checkinStreak 字段
  - 原子 UPDATE 含 streak 增量
  - 前端 UI 配置

【P1】spins 流水日志（spinsLog）
  - 新增 spins_log 表
  - 签到/抽奖/购买时写入
  - 审计 + 排查

【P2】签到随机事件（可选）
  - 小概率额外 spins
  - 概率可配置
  - 不引入道具系统
```

**不引入**：独立积分体系、银行系统、道具系统、好感度系统 —— 保持单货币 `spins` 的简洁性。
