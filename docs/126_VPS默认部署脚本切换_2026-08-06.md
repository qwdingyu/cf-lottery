# VPS 默认部署脚本切换

## 背景

项目生产部署已暂停 Cloudflare Workers，切换到 VPS 模式。原 `local-deploy.sh` 名称容易让人误以为它仍是当前默认发布入口，但该脚本实际会执行 Wrangler 部署，容易误操作。

## 变更

1. 将旧 Cloudflare Workers 部署脚本重命名为 `local-deploy-cloudeflare.sh`。
2. 新增 `local-deploy-vps.sh`，作为当前默认本地部署入口。
3. `npm run deploy` 改为执行 `bash local-deploy-vps.sh`。
4. `npm run deploy:cloudflare` 才显式进入 Cloudflare Workers 回退部署。

## VPS 上传契约

默认目标：

```bash
root@38.47.198.72:/root/
```

默认命令：

```bash
VPS_SSH_KEY=~/.ssh/cf-lottery-vps.pem bash local-deploy-vps.sh
```

脚本流程：

1. 执行 `bash scripts/build-for-vps.sh --package`。
2. 找到最新 `deploy-*.tar.gz`。
3. 使用 `ssh -i "$VPS_SSH_KEY"` 确认远端目录存在。
4. 使用 `scp -i "$VPS_SSH_KEY"` 上传到 `/root/`。

## 安全边界

- 私钥不写入仓库，只通过 `VPS_SSH_KEY` 环境变量传入。
- 脚本只做构建和上传，不自动在 VPS 解压、安装依赖或重启服务，避免上传动作误触发线上发布。
- 数据库迁移仍必须显式执行 `npm run db:migrate`，不能用 Wrangler 部署绕过迁移闭环。

## 可配置项

```bash
VPS_HOST=38.47.198.72
VPS_USER=root
VPS_PATH=/root
VPS_SSH_PORT=22
VPS_SSH_KEY=~/.ssh/cf-lottery-vps.pem
VPS_BUILD_FLAGS="--obfuscate"
```

## 建议

后续如果希望上传后自动远端发布，应新增单独脚本（例如 `scripts/deploy-to-vps.sh` 这类远端执行入口），不要把自动重启混进 `local-deploy-vps.sh`。上传与发布分离，回滚和审计更清晰。
