# 平台内置命令抽奖与奖品查询实现

## 背景
P0 平台命令 `/抽奖` 和 `/我的奖品` 之前 fall through 到 fail-closed 块，返回"暂未实现"提示。
根据 docs/167 设计，需要逐个命令接入正式业务函数并补测试。

## 改动

### 1. `src/services/platform/commands.ts`
- 新增 `executeSpinCommand`：调用 `performInstantSpin` 执行即时抽奖，群内只展示奖品名称，不展示卡密明文
- 新增 `executeMyPrizeCommand`：查询 `lotteryWinners` 关联 `lotteryPrizeTiers`、`prizes`，群内只展示奖品摘要
- 新增 `buildPlatformSpinIdempotencyKey`：优先使用 QQ messageId 构建幂等键，防止同一条消息重试被重复扣次
- 新增 import：`lotteryWinners`、`lotteryPrizeTiers`、`prizes`、`performInstantSpin`、`SpinBusinessError`、`isNotNull`
- 命令路由表化：`executeBuiltinPlatformCommand` 用 `COMMAND_HANDLERS` Record 映射替代 if-else 链，新命令只需一行注册
- 边界收紧：`executeSpinCommand` 前置校验 `activityKind=lottery`，防止非抽奖活动被误接入 `/抽奖` 命令
- 查询优化：`executeMyPrizeCommand` 用 `isNotNull(lotteryWinners.prizeCodeId)` 语义化 `hasCode` 布尔标记，去掉未使用的 `lotteryWinners.id`

### 2. `src/services/platform/commands.test.ts`（新增）
- 11 个测试用例覆盖 `/抽奖` 和 `/我的奖品` 的完整路径：
  - spin：活动不存在、非 instant、非 lottery instant、未参与（自动创建 entry）、已参与可抽奖、命令禁用
  - my_prize：未参与、已参与无奖品、有奖品摘要、多奖品、命令禁用
- 测试辅助函数 `seedWinner` 增强：支持 `entryId` 复用（多奖品场景）、`tierName`/`sortOrder` 定制

## 设计决策
- **卡密安全**：`executeMyPrizeCommand` 不查询 `prizeCodes` 表，用 `isNotNull` 判断 `prizeCodeId` 存在性，避免群内泄露
- **幂等键**：`executeSpinCommand` 优先使用 QQ messageId 作为幂等key，防止同一条消息重试重复扣次；缺失 messageId 时使用随机 UUID
- **自动参与**：`executeSpinCommand` 先调用 `ensurePlatformEntry` 确保用户已参与，降低用户认知负担
- **边界防御**：命令层前置校验 `activityKind=lottery`，纵深防御防止后续把投票/报名类活动误接入即时抽奖链路

## 平台层扩展性改造（2026-08-09 补充）

### 背景
5 个硬编码点限制了新增平台（如 Telegram）的接入能力。改造遵循适配器模式 + 策略模式，确保新增平台只需新增文件，不改现有代码。

### 5 个硬编码点及改造

| 硬编码点 | 文件 | 改造方式 |
|----------|------|----------|
| `identityType: "qq"` 字面量 | `types.ts` | 改为 `string`，由入站层从 `event.platform` 推导 |
| `ipHash`/`userAgent`/`source`/`idempotencyKey` 写死 `qq:` 前缀 | `commands.ts` | 改为 `${input.source.platform}:` 动态派生 |
| `identityType: "qq"` 写死 | `inbound.ts` | 改为 `identityType: event.platform` |
| 适配器工厂缺失，硬编码 `createQQAdapter` 和 if-else 链 | `delivery.ts` | 改为 `getPlatformAdapter` 工厂函数 |
| 管理端白名单 `VALID_PLATFORMS` 仅含 `"qq"` | `admin-lottery-platform.ts` | 改为 `getSupportedPlatforms()` 动态获取 |

### 新增文件

- **`adapter-factory.ts`**：平台→适配器工厂映射表，`getPlatformAdapter`/`sendPlatformMessage`/`getSupportedPlatforms`/`getSupportedProviders`
- **`telegram-adapter.ts`**：Telegram 适配器桩（实现 `PlatformAdapter` 接口），展示扩展模式
- **`adapter-factory.test.ts`**：5 个测试覆盖工厂构造、平台校验、配置验证、消息发送

### 新增平台步骤

1. 创建 `telegram-adapter.ts`，实现 `PlatformAdapter` 接口
2. 在 `adapter-factory.ts` 的 `PLATFORM_ADAPTER_FACTORIES` 注册一行工厂
3. 创建 `platform-telegram.ts` 路由，解析 Telegram Bot API 入站格式
4. 编写测试

**无需修改的文件**：`commands.ts`、`inbound.ts`、`delivery.ts`、`admin-lottery-platform.ts`、`types.ts`
