# 270_排行榜券发放缺口修复_2026-08-24

## 背景

继续审查 57984a4e（排行榜奖励扩展 bonus_coupon）时发现 P1 功能缺陷：**排行榜 bonus_coupon 在码池不足时奖励永久丢失**。

## 根因

`grantLeaderboardRewards` 的发放流程是「先 CAS 标记 `leaderboardRewardedAt` → 再发放」：

1. 标记 `leaderboardRewardedAt`（防并发重复发放）在发放**之前**写入；
2. bonus_coupon 发放失败（码池空 / couponLabel 无匹配 / 收件人缺失）或部分发放（池子只有部分券）时，**标记已写、不回滚**；
3. 下次触发时幂等检查 `leaderboardRewardedAt 非空 → skip` → 缺额**永久丢失**（补货后也不补发）。

与 `referral-rewards-engine` 的 bonus_coupon 语义不一致：referral 引擎明确「`issued===0` 码池空不写标记，保持可重试」，排行榜路径却先标记后发放。

**同类陷阱**：bonus_spin 的「标记但发不满」是刻意设计（maxSpins 硬顶，发不满不该续发），而 bonus_coupon 的「标记但发不满」是缺陷（码池是可补的）。

## 解决方案

### 新增字段

`share_records.leaderboard_rewarded_count INTEGER NOT NULL DEFAULT 0`（迁移 0066）——跨触发持久化「该分享者已通过排行榜发放的券张数」。

### 发放逻辑（leaderboard-rewards.ts bonus_coupon 分支）

```
remaining = rewardValue - rewardedCount      # 本次只发差额
if remaining <= 0: 已发满 → 保持标记跳过
CAS 抢占标记（leaderboardRewardedAt）       # 并发防重（原逻辑不变）
issuedCount = grantBonusCoupon(remaining)   # 从码池 CAS 取券
rewardedCount += issuedCount → 持久化
if rewardedCount >= rewardValue: 保持标记（完成，后续幂等跳过）
else: 回滚 leaderboardRewardedAt = ''       # 下次触发按差额续发
```

### 并发安全

- **不超发**：`rewardedCount` 持久化在事务内，续发只发差额；SQLite 写事务串行 + `withDbTransaction` 的 SQLITE_BUSY 重试（retries=5），并发事务重跑回调时读到最新 `rewardedCount`；
- **不重复**：CAS 抢占标记保留（先标记后发放），并发另一事务看到标记非空 → skip；
- **失败可重试**：部分发放后事务内回滚标记，下次触发重新抢占、续发差额。

## 验证

- `spin-execution.test.ts` 59 tests 全过（新增 2 例 + 更新 1 例）：
  - 部分发放后 `leaderboardRewardedAt` 回滚、`rewardedCount=1`
  - 部分发放 → 补货 → 再触发按差额续发 1 张 → 累计 2 张发满 → 第三次幂等跳过（不超发）
  - 码池完全为空 → 不发放不标记 → 补货后正常发满 2 张
- `npx tsc --noEmit`：0 errors
- `npx vitest run src/migrations-0063-sanity.test.ts`：通过（0066 迁移不破坏迁移链）
