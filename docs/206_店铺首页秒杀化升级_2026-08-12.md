# 206 店铺首页秒杀化升级

> 日期：2026-08-12

## 背景

SaaS 租户的店铺首页 `/shop/:storeSlug`（ShopView）此前只是简单的活动卡片网格，缺少秒杀的紧迫感与转化抓手。用户诉求：每个活动卡片展示活动信息 + 结束时间，做出「秒杀性质」的视觉冲击力，促进用户参与，同时不得破坏全站现有暗色主题样式。

## 目标

- 每个活动卡片展示：活动信息 + 结束时间（紧扣需求原文）
- 秒杀活动卡片拥有强视觉冲击力：倒计时、已抢进度、剩余库存、抢购按钮
- 全程复用现有主题变量（`--shop-sale*` / `--tg-*` / `--surface*` / `--border` / `--brand*`），不新增全局样式、不破坏暗色主题

## 方案

### 1. 纯函数层：倒计时工具（新建）

`frontend/src/views/shop/countdown.ts`：

| 函数 | 职责 |
| --- | --- |
| `countdownParts(ms)` | 拆分天/时/分/秒 |
| `formatCountdown(ms)` | 格式化文本：`>1天 → "2天 01:00:00"`，`<=1天 → "01:10:45"`，已结束/非法 → 空串 |
| `formatEndTime(iso)` | 活动结束时间绝对时刻 `HH:mm` |

### 2. 卡片数据透传（扩展 `landing-activity-feed.ts`）

`LandingActivityCard` 新增字段，供店铺倒计时/进度/库存直接使用：

- `startAt` / `endAt`（活动时间窗）
- `flashSaleEnabled` / `paymentRequired` / `priceCents` / `currency` / `effectiveStockLimit`
- `showCountdown` / `showProgress` / `showStock`（运营可关闭某项展示）

### 3. ShopView 秒杀化 UI

- **秒杀英雄横幅**：有秒杀活动时置顶展示「⚡ 限时抢购」（渐变玫红底 + 呼吸⚡ + 最紧急场次的实时倒计时，等宽数字）。
- **秒杀卡片 Ribbon**：右上角玫红渐变「⚡秒杀」角标。
- **倒计时**：等宽等数字体（tabular-nums），每张卡显示「距结束/距开始 HH:MM:SS」；剩余 < 5 分钟进入红色呼吸「紧急态」。
- **进度条**：玫红渐变填充 + 「已抢 n%」。
- **剩余库存**：玫红色大字「剩 n 份」。
- **抢购按钮**：玫红渐变全宽 CTA「立即抢购」/ 售罄降级暗色「已抢光」。
- **非秒杀卡片**：保持简洁，同时展示结束（开始）绝对时间，满足「显示结束时间」。
- **排序**：秒杀运行中（最快结束优先）→ 秒杀即将开始 → 免费，塑造「最紧急在最前」的紧迫感。
- **统一时钟**：单 `nowMs` ref + 1 个 `setInterval`（每秒），所有卡片共享，避免每卡一个定时器。

### 4. i18n

`shop.*` 新增秒杀文案（中英双语一致镜像）：横幅、倒计时标签、售罄、已抢百分比、剩余份数、抢购 CTA、结束时间等。

## 验收

- `npx tsc --noEmit`：exit 0
- `cd frontend && npx vue-tsc -b --pretty false`：exit 0
- `npx vitest run`：新增 `shop/countdown.test.ts`（7 例）+ `landing-activity-feed.test.ts` 新增透传用例（2 例）全部通过；i18n 测试通过
- 视觉：秒杀卡片玫红描边 + 渐变 + 倒计时 + 进度 + 库存 + 抢购按钮；免费卡片保留原风格并显示结束时间

- 无障碍：`prefers-reduced-motion` 禁用动画

## 踩坑记录

- `npx tsc --noEmit` 与 `npx vue-tsc -b` 耗时长于 30s CLI 超时：改用「后台启动 + 轮询 PID」方式确认退出码，未用管道截断。
- 全量 vitest 套件耗时 > 30s 且存在 1 例**既有失败**（`admin-lottery-platform.test.ts` 的 `APP_ORIGIN` 环境变量用例），与本次前端改动无关（该文件未修改）。
- 批量写入大文件时 editor 工具单次 6000 字符上限：改用分段 `cat >>` 拼接。
- `--danger`/`--success` 未在全局 CSS 定义过：原 ShopView 已使用，属于既有问题。修复方案：给 `var()` 加回退值 `var(--danger, #e11d48)`，避免白字无底色。
- `day` i18n 键未使用：`formatCountdown` 硬编码 `天`，英文用户看到中文。修复方案：函数增加 `dayUnit` 参数，ShopView 传入 `t('shop.day')`。
- `buildLandingActivityCard` 未传 `nowMs`：`Date.now()` 与 `resolvePhase` 的 `nowMs.value` 存在微秒级时钟差。修复方案：传入 `nowMs.value` 统一时钟。
- 局部 `resolvePhase` 函数与 `landing-activity-feed` 导出的 `resolveLandingActivityPhase` 功能完全重复。修复方案：删除局部函数，统一导入使用。
- Hero 横幅 `flashBanner` 返回 `{ href }` 后 `bannerTarget()` 二次查找。修复方案：直接返回 `LandingActivityCard` 对象。
- 英雄横幅 `div` 无 `role="button"` / `tabindex="0"` / `@keydown`，键盘用户无法触发。修复方案：补全无障碍属性，并添加 `:focus-visible` 样式。
- `activities` 类型为 `any[]`，下游 filter/map 完全失去类型检查。修复方案：改为 `ref<LandingHomeActivity[]>`，消除所有 `(a: any)` 类型断言。
- 模板中 `cardPhase(card)` 每秒调用 2 次，`flashCountdown(card)` 内部再调用 1 次 `resolveLandingActivityPhase`，合计每秒 3N 次。`card.phase` 已由 `buildLandingActivityCard` 预计算。修复方案：统一使用 `card.phase`，删除 `cardPhase` 函数。
- `flashBannerSub` 两次独立 `.filter()` 遍历，算上 `flashBanner` 的两次 `.find()`，每秒 4 次遍历 `cards`。修复方案：合并为一次 `for` 循环，利用本地变量累加 running/upcoming 计数。
- 幻数 `300_000` 含义不明（5 分钟）。修复方案：提取为 `URGENT_THRESHOLD_MS = 5 * 60 * 1000` 常量。
- 秒杀卡片缺少商品图片，`imageUrl` 字段存在但未使用。修复方案：添加 `<img v-if="card.flashSaleEnabled && card.imageUrl" />`。
- 进度条 `role="progressbar"` 缺少 `aria-label`，读屏无法感知含义。修复方案：添加 `:aria-label="$t('shop.grabedPercent', { n: card.progressPercent })"`。
- 骨架屏仅 3 条线，与实际卡片布局（badge + title + countdown + progress + stock + button 等 8 区域）差异巨大，加载→内容切换时视觉跳跃感强。修复方案：扩展为 5 条线 + 1 个占位块，对应不同宽度以模拟真实布局。
- 倒计时 `aria-live="polite"` 每秒更新会触发读屏持续播报，属无障碍反模式。修复方案：不使用 `aria-live`，改为注释说明原因，读屏用户导航到此处按需读取即可。
