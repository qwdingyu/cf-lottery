# 136 秒杀商品化体验与导流门禁整改

> 日期：2026-08-07  
> 背景：用户反馈「限时抢购」没有价格、没有商品，公开页不像抢购活动，且与支付闭环关系不清。

## 1. 结论

可以借鉴京东秒杀这类高密度商品流界面，但不能把 cf-lottery 改成第二套电商系统。

本次采用的边界：

| 系统 | 职责 |
| --- | --- |
| cf-shop | 商品货架、SKU 库存、完整电商订单 |
| cf-lottery | 活动场次、抢购名额、商品链接展示、直付发卡 |
| cf-pay（未来） | 统一支付 Provider、订单与回调抽象 |

因此 cf-lottery 只做「活动商品卡」：从 `productLink` 与 `promotion_config.flashSale` 合成展示，不新增商品表、不复制 cf-shop 商品管理。

## 2. 已整改

1. 公开秒杀页新增商品化抢购卡：
   - 商品名：优先 `flashSale.title`，再回退 `productLink.title` / 活动名。
   - 价格：直付用 `flashSale.priceCents` 格式化；导流用 `productLink.price` 展示文案。
   - 图片：优先 `productLink.imageUrl`，再回退奖品图片。
   - 标签：场次、平台直付/外部下单、限量份数、剩余份数。

2. 「限时抢购」模板默认不再是空壳：
   - 默认启用 `enableFlashSale`。
   - 默认启用商品/导流配置表单。
   - 默认填入场次、名额、展示价和商品标题占位。
   - 运营仍必须填写真实商品链接或切换为直付并补齐支付配置。

3. 发布门禁收紧：
   - `paymentRequired=false` 的导流秒杀，如果没有安全商品链接 / destination / after_win CTA，直接阻断发布。
   - `paymentRequired=true` 的直付秒杀继续走价格、EasyPay/ZPay 配置、单一卡密码池门禁。

4. 文案收口：
   - 后台「导流配置」改为「商品 / 导流配置」。
   - 明确导流模式必须填写可下单链接。
   - 明确直付模式使用 EasyPay/ZPay 与卡密码池。

## 3. 仍不做

不在 cf-lottery 里新增商品表、分类、SKU 库存、购物车或完整订单中心。这些属于 cf-shop 或未来产品矩阵能力；当前活动引擎只承接单活动、单商品/卡密的促销闭环。

## 4. 后续建议

下一步高价值方向是「营销组合模板」：一键创建免费大转盘 + 付费秒杀，并自动把免费活动结果 CTA 指向秒杀活动。这样更符合产品矩阵促销，而不是让运营手动创建两个孤立活动。
