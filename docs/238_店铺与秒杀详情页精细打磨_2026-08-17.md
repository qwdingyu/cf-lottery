# 店铺与秒杀详情页精细打磨

## 背景

店铺首页与单个限时抢购详情页已经具备促销结构，但实际观感仍偏粗糙：

- 店铺首页倒计时区块略重，首屏横幅占用过多注意力。
- 单活动详情页的商品卡、倒计时、进度和“抢”按钮之间留白过大，转化链路不够紧凑。
- “仅剩 00:xx”容易和库存剩余混淆，不如“距结束 00:xx”语义明确。

## 调整原则

1. 秒杀页首屏必须优先回答：卖什么、多少钱、还剩多少、什么时候结束、现在怎么抢。
2. 只使用一套玫红促销强调色，避免同时出现多套高饱和强调。
3. 店铺首页维持“一行一个”活动”的横向列表，不退回方块卡片。
4. 详情页减少固定高度和大面积空白，让商品卡与抢购操作形成一个连续购买区。

## 修改内容

- 店铺首页：压缩秒杀横幅高度，降低横幅字重，缩短活动行图片高度，倒计时标签向内容侧收拢。
- 秒杀详情页：针对深链单活动的秒杀卡增加紧凑覆盖样式，商品卡、价格、库存、倒计时、进度和 CTA 更靠近。
- 二轮打磨：店铺秒杀行改为右侧购买决策区展示倒计时，形成“距结束 → 价格 → 立即抢购”的扫读顺序。
- 二轮打磨：详情页秒杀视觉仅作用于真实 `flashSale` 活动，深链活动的“始终展开”规则仍对所有活动生效，避免影响抽奖/问卷等单活动详情。
- 二轮打磨：`FlashSaleGame` 自身为进行中倒计时增加高优先级红底样式，并补充按钮按压反馈，保证组件复用时仍有紧迫感。
- 三轮打磨：深链秒杀详情页桌面端改为宽版双栏购买面板，左侧商品/价格/库存，右侧倒计时/进度/主 CTA，减少窄卡片造成的大面积空白。
- 三轮打磨：当商品化秒杀卡已展示库存时，操作区不再重复显示“剩余 N 份”，避免同一信息在首屏重复出现。
- 四轮打磨：未参与的秒杀活动不再显示通用“请在上方互动区完成参与”提示，改为秒杀专属信任条：平台直付/跳转购买、名额实时锁定、限时限量。
- 四轮打磨：已锁定名额/待支付的直付秒杀状态条强化为订单闭环入口，主按钮高亮“继续支付或追加购买”，次按钮保留找回订单。
- 五轮打磨：店铺首页秒杀活动行右侧升级为紧凑购买面板，把倒计时、抢购价、立即抢购按钮收在同一区域；移动端保持“倒计时/价格在上，抢购按钮全宽在下”的电商扫读顺序。
- 六轮打磨：单活动分享详情页顶部强化“进入店铺”闭环入口，店铺按钮作为主动作、复制链接作为次动作，并补充短提示引导用户回到店铺首页继续浏览促销活动。
- 七轮打磨：店铺秒杀横幅去掉标题重复闪电符号；秒杀行价格标签按“抢购中/马上开始/已结束/已抢光”动态展示，关闭态按钮改为“查看详情”，避免可点击按钮写成不可操作状态。
- 八轮打磨：店铺分类筛选无结果时不再显示通用市场空态，改为店铺内筛选空态，并提供“查看全部活动”按钮，避免用户误以为店铺没有活动。
- 九轮打磨：店铺活动行保留整行可点击，内部 CTA 改为视觉引导而非第二个可聚焦按钮，并补充包含标题、类型、阶段、价格和动作的 `aria-label`，减少键盘与读屏重复导航。
- 十轮打磨：店铺分类筛选升级为分段控件，补充 `tablist/tab`、`aria-selected` 和包含数量的读屏标签，移动端保持横向滑动但隐藏滚动条。
- 十一轮打磨：店铺顶部“刷新”从全局后台按钮改为 ShopView 局部按钮样式，与“返回主页”和筛选控件统一，并补充加载中的 `aria-busy`。
- 十二轮打磨：店铺秒杀购买面板右侧提示从固定“手慢无”改为按阶段、库存和进度动态展示“库存紧张/正在热抢/即将开抢/本场结束”等短提示，避免重复具体库存又能强化购买判断。
- 十三轮打磨：店铺活动行的 `aria-label` 同步纳入秒杀动态购买提示，让读屏用户也能听到“库存紧张/正在热抢/本场结束”等决策信息。
- 倒计时文案：中文从“仅剩 {time}”调整为“距结束 {time}”，避免与“剩余库存”混淆。
- 移动端：保留 104px 商品图宽度，按钮不低于 54px，避免文字溢出和点击区过小。

## 验证

- `cd frontend && npm run type-check`
- `cd frontend && npm run build`

构建仍存在 Vite 对 `useAdminAuth.ts` 的动态/静态混合 import 警告，该警告为既有构建提示，不影响本次样式打磨。
