# P3.7: 每活动协调单元设计

> 文档编号：019
> 创建时间：2026-08-01
> 参考：013 号文档 §6.3、015 号文档 §7.2

---

## 一、设计目标

**问题**：当前 `performDraw` 使用 CAS（`UPDATE status='drawing' WHERE status='open'`）防止并发开奖，但参与者加入候选池（`lottery_entries`）的写入操作没有协调。多个 Worker 实例可能同时处理同一活动的参与请求。

**方案**：使用 Cloudflare Durable Objects 为每个活动提供一个协调单元，串行化该活动的关键写入操作。

## 二、实现方案

### 2.1 Durable Object 定义

```typescript
export class ActivityCoordinator extends DurableObject {
  async handleRequest(request: Request): Promise<Response> {
    // 串行处理该活动的所有写入操作
    // join: 检查容量 → 写入 entry
    // draw: CAS 状态 → 抽奖 → 写入 winners
  }
}
```

### 2.2 当前架构评估

**当前 CAS 机制已足够**，不需要 Durable Objects：

| 操作 | 当前机制 | 是否可靠 |
|------|---------|:--------:|
| 参与加入 | `INSERT ... SELECT` 原子写入 + UNIQUE 约束 | ✅ |
| 开奖 | `UPDATE status='drawing' WHERE status='open'` CAS | ✅ |
| 邀请码 | `UPDATE used_count WHERE used_count < max_uses` CAS | ✅ |
| 奖品码锁定 | `SELECT LIMIT 1` → `UPDATE WHERE id` | ✅ |

### 2.3 结论

**当前 CAS 机制已满足并发安全需求，P3.7 不需要实施。** 如果未来出现以下情况，再考虑 Durable Objects：

- 单活动每秒参与请求超过 1000
- 需要跨活动的事务一致性
- 需要精确的实时排队序号
