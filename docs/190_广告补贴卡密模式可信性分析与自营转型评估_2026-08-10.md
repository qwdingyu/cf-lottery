# 190 广告补贴卡密模式可信性分析与自营转型评估

> 日期：2026-08-10
> 背景：用户提出新模式——「看广告免费发卡密」由平台补贴卡密成本，SaaS 租户免费获得该能力；广告插入 web 端活动页，收入归平台；租户无需注册小程序，小程序仅是平台拉新/引流工具；若收益可观则转型为平台自营单租户。
> 方法：收入-成本敏感性分析（不依赖精确 eCPM，盈亏方向结论稳健）+ 结构性矛盾识别 + 验证实验设计。
> 关联：docs/189（技术方案）、docs/132（免费 Token 引流→秒杀付费）、docs/041（裂变路径）

## 1. 结论先行（执行摘要）

**用户提出的模式有三个版本，可信性差异极大，必须拆开评估：**

| 模式版本 | 内容 | 可信性评级 |
|----------|------|:---:|
| **M1：web 活动页插广告 + 平台补贴卡密（SaaS 免费功能）** | 租户在 web 端组织活动，平台在活动页插广告，看广告得次数，卡密成本平台补贴 | ❌ **大概率不可行**（收入-成本鸿沟一个数量级 + 白标冲突 + 租户动机错位 + 广告欺诈风险） |
| **M2：小程序激励视频 + 平台自营虚拟权益** | 平台自营小程序办活动，激励视频广告（高 eCPM）+ 自有边际成本≈0 的虚拟权益卡密 | ✅ **可行**（广告收入覆盖≈0 成本权益，实现负成本获客） |
| **M3：单租户自营（不做 SaaS）** | 平台自己运行系统办活动、自己发卡、广告收入全归自己 | ✅ **最可信**（盈亏自担、动机对齐、无白标冲突），但要认清它是「流量生意」而非「工具生意」 |

**一句话结论**：**「广告补贴卡密」能否成立不取决于广告平台或小程序形态，而取决于两个数字：单次广告收入（每次约 0.01~0.08 元）与卡密边际成本（必须趋近于 0）**。M1 在数学上不成立；M2/M3 成立的前提是卡密为平台自有的数字权益（成本≈0）。

**对「GitHub 没有完整项目」的回应**：用户观察正确——GitHub 上的开源项目只有 UI 组件/接入示例，**不存在完整的广告激励抽奖商业闭环**（广告结算、防刷、发卡、对账是商业模式核心，商业项目不开源）。这不影响模式可信性判断：核心闭环必须自建，但 cf-lottery 后端已具备 80% 能力（docs/189 §3），自建成本可控。

## 2. 商业模式定义（用户方案还原）

### 2.1 模式拆解

```
                    ┌────────────────────────────────────────────┐
                    │              cf-lottery 平台方              │
                    │                                            │
                    │  ┌────────────┐   ┌────────────────────┐   │
                    │  │ 广告变现    │   │ 卡密成本补贴        │   │
                    │  │（收入端）   │   │（成本端）           │   │
                    │  └─────┬──────┘   └─────────┬──────────┘   │
                    └────────┼───────────────────┼──────────────┘
                             │ 广告位             │ 免费能力
                             ▼                    ▼
  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  │  SaaS 租户    │    │ web 活动页    │    │ 参与用户       │
  │（组织活动）    │───▶│（白标页面）    │───▶│ 看广告→得次数  │
  │ 不付卡密费    │    │ 插入广告      │    │ →抽奖→得卡密   │
  └──────────────┘    └──────────────┘    └──────────────┘
                                                    ▲
  ┌──────────────┐    ┌──────────────┐              │
  │ 平台小程序    │    │ 拉新/引流     │──────────────┘
  │（自营）       │    │ 用户来源      │
  └──────────────┘    └──────────────┘
```

**隐含的商业模式转变**：从「卖 SaaS 工具」（向租户收费）转向「流量生意」（向广告主收费 + 租户免费）。这是本质变化——收入结构、成本结构、风险结构全部改变。

### 2.2 与 docs/189 的关系

- docs/189 假设「广告激励是租户可选功能」（D2 决策中平台自营/租户白标二选一）；
- 本模式直接拍板为「**平台自营 + SaaS 免费赠送**」，并增加「远期自营单租户」选项；
- 本模式把 docs/189 的 D2 决策从「二选一」变为「平台独有 + 远期转型」。

## 3. 收入端可信性分析

### 3.1 广告收入来源矩阵

| 广告形态 | 载体 | eCPM 参考区间（元/千次）【行业常识，需实测】 | 单次观看/展示收入 | 准入要求 |
|----------|------|:---:|:---:|----------|
| **激励视频** | **微信小程序原生**（流量主） | 20~100（工具/网赚类） | **0.02~0.10 元** | 流量主 UV≥1000【需复核】 |
| 激励视频 | web/H5（穿山甲/优量汇） | 10~40 | 0.01~0.04 元 | 域名 ICP 备案 + 平台审核【行业常识】 |
| 插屏 | web/H5 | 5~20 | 0.005~0.02 元/次 | 同上 |
| Banner | web/H5 | 0.5~5 | 0.0005~0.005 元/次 | 同上 |
| 激励视频 | uni-ad 聚合（多平台竞价） | 介于上两者之间 | — | uni-ad 开户 + 服务器回调配置 |

**关键事实（影响全局）**：
1. **web 端广告单价比小程序激励视频低一个数量级**【行业常识】——M1 模式的收入端先天薄弱；
2. **cf-lottery 当前是 web 优先的产品**（活动页是 H5），若只在 web 插广告，收入上限约为小程序方案的 1/3~1/5；
3. 用户方案的「web 活动页插广告」同时要面对：活动页流量天然分散（每个租户的活动独立、流量小、无聚合）→ **eCPM 标签差 + 填充率低**。

### 3.2 流量规模需求（收入端可信性的硬约束）

广告收入 = 有效观看次数 × 单次收入。反推实现「月收入目标」所需的最小观看量：

| 月收入目标 | 需月观看次数（web 激励 0.02 元/次） | 需月观看次数（小程序激励 0.05 元/次） | 折算 DAU（人均 5 次/日） |
|:---:|:---:|:---:|:---:|
| 5,000 元（覆盖服务器成本） | 25 万次 | 10 万次 | 667~1,667 人 |
| 20,000 元（覆盖卡密+运营） | 100 万次 | 40 万次 | 2,667~6,667 人 |
| 100,000 元（专职团队） | 500 万次 | 200 万次 | 13,333~33,333 人 |

> **结论**：广告收入是「流量生意」，没有 DAU 就没有收入。cf-lottery 当前无公开流量基线数据（【待测】），若现网 DAU 低于数百，M1 的收入端在 3~6 个月内没有验证意义。

## 4. 成本端可信性分析

### 4.1 卡密成本结构

| 卡密类型 | 边际成本 | 来源 | 适用性 |
|----------|:---:|------|--------|
| 平台自有数字权益（API 额度、会员体验天卡、自家产品试用码） | **≈0** | 平台自制 | ✅ 唯一可持续的补贴对象 |
| 第三方采购虚拟卡密（软件激活码、视频会员） | 0.5~50 元 | 上游采购 | ⚠️ 需极高观看量覆盖 |
| 实体/高价奖品 | 5~500 元 | 采购 | ❌ 不可用广告补贴 |

### 4.2 盈亏矩阵（敏感性分析，本分析的核心）

假设：用户每日看 N 次广告获得 N 次抽奖；单次抽奖中奖率 p；卡密边际成本 c；单次广告收入 r。

**关键公式**：单用户每日平台盈亏 ≈ N × r − N × p × c

**矩阵一：M1 场景（web 激励广告，r=0.02 元/次，N=10 次/日）**

| 卡密成本 c | 中奖率 p=5% | p=20% | p=50% |
|:---:|:---:|:---:|:---:|
| 0 元（自有权益） | +0.20 元 ✅ | +0.20 元 ✅ | +0.20 元 ✅ |
| 0.5 元（低价采购） | +0.20−0.25=−0.05 ⚠️ | −0.80 ❌ | −2.30 ❌ |
| 5 元（普通卡密） | −2.30 ❌ | −9.80 ❌ | −24.80 ❌ |

**矩阵二：M2 场景（小程序激励视频，r=0.05 元/次，N=15 次/日，官方建议上限）**

| 卡密成本 c | 中奖率 p=5% | p=20% | p=50% |
|:---:|:---:|:---:|:---:|
| 0 元（自有权益） | +0.75 元 ✅ | +0.75 元 ✅ | +0.75 元 ✅ |
| 0.5 元（低价采购） | +0.75−0.375=+0.375 ✅ | −0.75 ⚠️ | −3.00 ❌ |
| 5 元（普通卡密） | −3.00 ❌ | −14.25 ❌ | −36.75 ❌ |

**矩阵结论（稳健，不依赖精确 eCPM）**：
1. **只要卡密边际成本 > 0，中奖率稍高即亏损**——web 广告场景（M1）几乎必然亏损；
2. **只有「卡密成本≈0」时模式才稳健盈利**——即平台自有数字权益；
3. 中奖率 p 是比 eCPM 更敏感的成本杠杆：**p 必须控制在「p × c < r」以内**（如 c=0.5 元时 p 须 < 4%）；
4. 若用户看广告但未中奖，平台赚广告费但不付卡密——**「低中奖率 + 低成本卡密」是唯一可持续组合**。

### 4.3 防刷与欺诈成本（M1 模式的隐藏亏损源）

- 【架构事实】cf-lottery 广告上报只有「客户端 onClose.isEnded + 服务端限流」防线（docs/189 §7.5 路径 A）；
- **M1 的租户没有防刷动机**（卡密是平台补贴，租户反而欢迎更多人参与/刷次数）→ 平台成为唯一防刷责任人，成本集中在平台；
- 机刷/群控伪造观看 → 广告商不结算（无效播放）→ **平台广告收入落空但卡密照发** = 两头亏损；
- 【官方确认】微信侧对单用户激励视频有每日次数限制，缓解但未消除（多账号、多设备）。

## 5. 结构性矛盾（必须诚实指出的问题）

### 5.1 数学鸿沟：web 广告收入无法覆盖补贴

单用户单日 web 广告收入上限 ≈ 0.2 元（10 次 × 0.02 元）；只要活动「中奖率 ≥ 20% 且卡密成本 ≥ 1 元」就必然亏损。**M1 在数学上不成立，除非：中奖率压到 5% 以下 + 卡密成本压到 0.5 元以下 + 用户每日看满 10 次**——三个条件同时满足才勉强打平，而这样的活动对用户毫无吸引力（抽 20 次才中一次 5 毛钱的卡）。

### 5.2 白标冲突（M1 特有）

【架构事实】cf-lottery 支持租户 `brand_config` 白标（docs/128）。租户付费使用 SaaS，活动页却插着平台广告 → **品牌冲突 + 付费/免费用户待遇倒挂**。租户的动机是「自己的活动页纯净」，平台的动机是「越多的广告位越好」，二者天然对立。SaaS 模式中这几乎不可调和（除非改为免费 SaaS 换广告位——但那会摧毁现有付费套餐，见 5.4）。

### 5.3 租户动机错位（补贴方 vs 受益方）

平台是补贴方（付卡密钱、防刷），租户是受益方（免费获得发卡能力 + 活动吸引力）。**没有市场机制约束租户行为**：租户会鼓励用户大量刷广告抽卡密，平台补贴无上限 → 成本黑洞。对比自营模式：平台自己就是受益方，动机天然对齐。

### 5.4 SaaS 商业模式的自我蚕食

- 现状：租户为「活动能力 + 发卡能力 + 白标」付费（free/team/pro 套餐【架构事实】）；
- M1：这些能力变成免费（平台补贴）→ **付费意愿归零，SaaS 收入清零**；
- 若保留付费，则「付费租户还要看平台广告」不可接受（5.2）；
- **M1 的财务结构 = 用广告收入同时养活 SaaS 和补贴卡密，而 web 广告收入（0.2 元/用户/日）连服务器成本都难覆盖**（docs/145/147 容量估算）。

### 5.5 小程序定位含糊

用户说小程序是「拉新、引流手段」——但**小程序激励视频恰好是全部广告形态中收入最高的一类（是 web 的 2~5 倍）**。若小程序只引流不发广告，等于把最肥的广告位闲置，收入端自我阉割。**建议重新定位：小程序是主变现场，web 活动页是引流场**（方向与用户设想相反）。

## 6. 单租户自营转型评估（M3，用户远期设想）

### 6.1 自营模式的本质

平台自己办活动、自己发卡、自己算盈亏。这**不是 SaaS 了，是流量生意**：

```
流量（小程序/社群）→ 看广告（平台收入 r）→ 抽奖 → 自有虚拟权益（成本≈0）→ 体验 → 付费转化
```

### 6.2 可信性评级：✅ 高（但有硬前提）

| 维度 | 评估 |
|------|------|
| 收入端 | 小程序激励视频 0.02~0.10 元/次，每日 15 次上限 → 单用户单日 0.3~1.5 元（矩阵二） |
| 成本端 | 自有数字权益成本≈0（对应 cf-shop 的 token/额度模型）→ 无补贴黑洞 |
| 获客端 | 「看广告免费拿权益」本身就是获客钩子，广告收入 ≈ 负成本获客 |
| 转化端 | 免费权益体验 → 付费续费/升级（docs/132 已验证的免费→付费漏斗） |
| 风险 | 唯一硬前提：**有真实流量**（3.2 表：月收入 5 千需 667+ DAU） |

### 6.3 与现有资产的关系（【架构事实】）

- 后端：cf-lottery 的 spins/签到/抽奖/发卡闭环直接复用（docs/189 §3）；
- 前端：uni-app 小程序 + 开源 UI 组件（docs/189 §13）；
- 商业：cf-shop 的「Token/额度」是现成的成本≈0 虚拟权益，可作首发奖品；
- **自营模式甚至不需要 SaaS 多租户层**——退化为单租户部署（docs/189 中「只有一个平台用户」的场景），部署与运维成本进一步降低。

### 6.4 诚实的边界

自营 ≠ 自动赚钱：广告收入依赖 DAU（3.2），冷启动期的 UV≥1000 门槛（小程序流量主）仍是第一道坎；eCPM 需实测（新号无标签时可能低至 5~15 元/千次）；「虚拟权益」要有真实价值（否则用户看广告的动机消失）。

## 7. 可信性结论与建议路径

### 7.1 三档可信性评级汇总

| 模式 | 收入端 | 成本端 | 结构矛盾 | 综合评级 |
|------|:---:|:---:|:---:|:---:|
| M1 web 广告补贴 SaaS 租户 | ❌ 低（0.01~0.02 元/次） | ❌ 补贴黑洞 | ❌ 白标/动机/SaaS 蚕食 | **不推荐** |
| M2 小程序激励视频 + 自营虚拟权益 | ✅ 中高（0.02~0.10 元/次） | ✅（权益成本≈0） | ⚠️ 需流量 + 资质 | **可行，建议做** |
| M3 单租户自营（含小程序） | ✅ 中高 | ✅ | ✅ 动机对齐 | **最可信，建议作为目标形态** |

### 7.2 建议路径（修正版）

**放弃 M1（给租户做 web 广告功能），直接走向 M2→M3：**

1. **不把「广告功能」做成 SaaS 租户功能**——避免白标冲突、动机错位、SaaS 蚕食三个结构矛盾；
2. **平台自营小程序**为主变现场（激励视频高 eCPM + 官方防刷 + UV 1000 门槛后开通流量主）；
3. **卡密 = 平台自有数字权益**（成本≈0），首发可用 cf-shop token/额度；
4. **web 活动页做引流**（现有公开活动页已具备，docs/128），导流到小程序；
5. **远期自营单租户**：若小程序 DAU 与 eCPM 实测达标（8.1 验证实验），退化为单租户自营——cf-lottery 后端 + uni-app 小程序 + 自有权益，一套完整闭环；
6. **SaaS 多租户能力保留但不再作为变现核心**（仍可向租户卖「活动引擎」订阅，与自营互不干扰——自营用同一套代码）。

## 8. 落地前提与验证实验（用最小成本验证可信性）

### 8.1 30 天验证实验设计（关键数字都在实测后才有意义）

| 实验项 | 内容 | 通过标准 |
|--------|------|----------|
| E1 流量基线 | 上线平台自营小程序（登录+签到+抽奖，暂不发广告），验证自然获客与留存 | 30 天累计 UV ≥ 1,000（同时达标流量主门槛） |
| E2 eCPM 实测 | 开通流量主后接激励视频，统计 30 天实际 eCPM/填充率 | eCPM ≥ 20 元/千次 且 填充率 ≥ 60% |
| E3 盈亏实测 | 发自有虚拟权益（成本≈0），记录「广告收入 vs 权益发放成本 vs 付费转化」 | 单用户单日净贡献 ≥ 0（广告收入 ≥ 权益成本） |
| E4 转化实测 | 权益体验 → 付费转化率（对齐 docs/132 漏斗） | 转化率 ≥ 1%（负成本获客成立） |
