# 114 邀请排行榜功能审查与修复

> 日期：2026-08-05  
> 范围：公开页 `ViralLeaderboard` UI + `/viral-leaderboard` / `my-viral-stats` + 管理端裂变配置回填  
> 状态：已修复关键断点；后端单测补强  

---

## 一、结论摘要

| 层级 | 结论 |
|:-----|:-----|
| **排名算法 / 聚合** | 正常：按 `shareRecords.joinedCount` 按 sharer 聚合，Top20 + 全量真实名次（含未进榜、0 邀请 rank=0） |
| **公开 UI 挂载** | 正常：`viral.enabled` 时挂载；榜与「我的邀请」分卡；终态弱化邀请 CTA |
| **关键缺陷（已修）** | ① `leaderboardEnabled` 缺省语义前后端不一致 → 榜 API 400、UI 假「网络错误」 ② 管理端编辑**不回填**裂变 → 再保存可能擦掉配置 ③ 编辑关闭增长时 PATCH 不带字段 → 关不掉 |
| **体验缺陷（已修）** | 榜接口业务失败时 UI 只显示笼统「网络错误」，不展示服务端 `message` |

**一句话**：算法与组件主路径大体可用；真正会让「排行榜看起来坏了」的，是**配置缺省/编辑回填**与**错误展示**，不是 TopN 计算本身。

## 二、证据级断点

### P0-1：`leaderboardEnabled` 缺省不一致（UI 显示榜、API 拒榜）

| 端 | 旧行为 |
|:---|:-------|
| 管理端默认 / 保存 | `viralLeaderboardEnabled ?? true`，正常创建会写入 `true` |
| 公开 UI `ViralLeaderboard` | `leaderboardEnabled !== false` → **缺省当开** |
| 后端 `GET .../viral-leaderboard` | `!viral?.leaderboardEnabled` → **缺省当关**（`undefined` 为 falsy） |
| 发布预检 | `if (!viral.leaderboardEnabled)` → 缺省误报「排行榜未开启」 |

**后果**：手工 JSON、旧数据、脚本只写 `viral.enabled` 未写 `leaderboardEnabled` 时：

1. 公开卡**画出**「邀请排行榜」区块并请求 API  
2. API **400**「该活动未开启裂变排行榜」  
3. UI 旧逻辑把非 2xx 一律标成 **网络错误**（用户以为挂了）

**修复**：后端与预检改为 **仅 `leaderboardEnabled === false` 关闭**；与 UI 对齐。

### P0-2：管理端 `handleEdit` 不回填裂变 / 导流

`handleEdit` 只回填基础字段与奖项，**不读** `detail.draw.promotionConfig` / `productLink`。  
表单默认 `enableViral: false`。用户「改个标题再保存」时：

- 创建路径：`promotionConfig: undefined` → `JSON.stringify` 丢掉该键 → PATCH **不更新** promotion（旧裂变侥幸保留）  
- 若同时开着商品/CTA 或后续改成「无增长写关闭包」前的中间态，存在**整包覆盖丢 viral** 的风险  
- 运营侧：**看不到**已开启的裂变开关（高级区默认折叠 + 未回填），误以为没配排行榜

**修复**：

- 详情优先解析 `promotionConfig` / `productLink` 回填 enableViral、排行榜开关、CTA、商品  
- 已有增长配置时 **自动展开**高级增长区  
- 编辑保存：无增长时显式写 `enabled: false` 包，避免「关不掉」；有增长整包覆盖且依赖回填  

### P1：榜错误文案不诚实

`lbRes.ok === false` 时不解析 body，统一 `networkError`。  
**修复**：读 JSON，优先展示 `message`（如「未开启裂变排行榜」）。

### P1（附带）：`productLink: null` 清导流

编辑关闭商品时传 `null`；后端原 `validateProductLink(null)` 会报「配置无效」。  
**修复**：null / 空 url 视为清空，落库 `"{}"`。

## 三、已核实正常的部分

1. **挂载条件**（`LotteryView`）：`getDrawViral(draw)?.enabled` + `publicSlug`；公开详情返回解析后的 `promotionConfig`。  
2. **排行数据**：`buildViralLeaderboardRanking` 全量排序再 slice；未进 Top20 名次真实；0 邀请 `rank=0` + UI「尚未上榜」。  
3. **「是我」高亮**：响应带 `entryId`；`isMeOnRow` 优先比 entryId。  
4. **我的邀请**：`my-viral-stats` 与开奖同一 extra 公式；share 码 `orderBy desc createdAt` 与 POST /share 一致（112）。  
5. **终态**：`inviteOpen` / `shouldShowInviteShareCta` 弱化复制 CTA，榜与历史统计仍可读。  
6. **单测**：原 Top20 名次 + 本轮「缺省开启 / 显式关闭」+ 预检缺省不误报 off。

## 四、仍存在的限制（非本轮必改）

| 项 | 说明 | 建议 |
|:---|:-----|:-----|
| 前端「复制活动」 | `handleDuplicate` 硬编码 `enableViral: false`，不拷贝裂变 | 优先用后端 duplicate API（已拷 `promotionConfig`）；或前端补 growth 回填 |
| 并列名次 | 同邀请数按 entryId 稳定排序，名次为密集 1..n，无并列并列显示 | 产品可接受；若要「并列第 3」需改算法 |
| 榜不实时推送 | 依赖挂载/`entryId` watch 与手动 ↻ | 邀请成功后可 `emit` 刷新（增强） |
| 无 entryId 的已参与 | 诚实提示去「查结果」恢复（110） | 保持，勿假生成链接 |
| 脱敏名 | `displayName \|\| maskIdentity` | 正常 |
