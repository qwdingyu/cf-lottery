# 268 签到功能设计方案

> 设计时间：2026-08-23
> 基于：三轮审查后的代码事实（非推测）
> 原则：最小改动、最大复用、闭环验证

---

## 一、现状分析

### 1.1 已实现的签到机制
- **每日一签**：`participation.ts:120-128` 在 identity_value 后追加日期后缀 `:${todayStr()}`
- **防重复**：UNIQUE(tenant_id,draw_id,identity_type,identity_value) 约束
- **前端判断**：`joined-session.ts:264-275` `isCheckinSignedToday()` 函数
- **参与记录**：每次签到创建 `lottery_entries` 表新记录

### 1.2 缺失的能力
- **streak 计算**：连续签到天数的后端计算
- **日历展示**：前端签到日历组件（本月哪些天签到了）
- **streak 奖励**：连续签到 N 天触发奖励（可复用里程碑引擎）

---

## 二、数据模型设计

### 2.1 策略：复用现有表，不新增表

**理由**：
- `lottery_entries` 表已有 `joinedAt` 字段记录参与时间
- 签到数据已通过 identity_value + 日期后缀区分每天的记录
- 避免数据冗余和同步问题

### 2.2 查询设计

**本月签到记录**：
```sql
SELECT joinedAt FROM lottery_entries
WHERE tenantId = ? AND drawId = ?
  AND identityValue LIKE '%@%' -- 过滤签到记录
  AND joinedAt >= '2026-08-01' AND joinedAt < '2026-09-01'
ORDER BY joinedAt ASC
```

**streak 计算**：
- 从今天往回推，检查每天是否有签到记录
- 如果今天签到了，streak 包括今天
- 如果今天没签到，从昨天开始算

## 三、API 设计

### 3.1 新增端点：`GET /api/public/lottery/:slug/checkin-status`

**请求**：
- 路径参数：`slug`（活动公开标识）
- 查询参数：`month`（可选，格式 YYYY-MM，默认当前月）

**响应**：
```typescript
{
  success: true,
  data: {
    // 本月签到日期列表（YYYY-MM-DD）
    signedDates: ["2026-08-23", "2026-08-22", "2026-08-21"],
    // 当前连续签到天数（从今天往回推）
    currentStreak: 3,
    // 历史最长连续签到天数
    maxStreak: 15,
    // 本月签到天数
    monthlyCount: 20,
    // 今日是否已签到
    signedToday: true
  }
}
```

### 3.2 复用现有端点：`POST /api/public/lottery/:slug/join`

签到操作已通过 `joinDraw` 实现，无需修改。

## 五、streak 奖励设计

### 5.1 复用里程碑引擎

**配置示例**：
```json
{
  "referralRewards": [
    { "threshold": 3, "type": "bonus_spin", "amount": 1 },
    { "threshold": 7, "type": "bonus_spin", "amount": 2 },
    { "threshold": 14, "type": "bonus_coupon", "amount": 1 },
    { "threshold": 30, "type": "bonus_spin", "amount": 5 }
  ]
}
```

**触发逻辑**：
- 在签到成功后，检查当前 streak 是否达到里程碑阈值
- 如果达到，调用 `grantBonusSpin` 或 `grantBonusCoupon`

## 七、风险评估

| 风险 | 等级 | 说明 |
|------|------|------|
| 查询性能（大数据量 GROUP BY） | 低 | 签到记录按月查询，索引覆盖 |
| 并发签到（同一用户同时签到两次） | 低 | UNIQUE 约束已保护 |
| 时区问题（streak 计算跨时区） | 低 | 使用 todayStr() 本地时区 |

## 十、总结

**核心思路**：最小改动、最大复用
- 不新增表，复用 `lottery_entries` 表
- 不修改现有 API，新增只读状态 API
- 复用现有组件（SubmitGame、canvas-utils、i18n）
- 复用里程碑引擎实现 streak 奖励

**预估工期**：3-5 天
**风险等级**：低
