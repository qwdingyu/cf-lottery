# 101 多玩法「我的结果」语义修复

日期：2026-08-04  
触发：

1. 人工发放中奖被显示为「未获得奖品」（见 docs/100）
2. **接龙等非抽奖玩法**查「我的结果」同样落到「感谢参与，未抽中奖品」
3. 用户质疑：`https://lucky.eforge.xyz/lottery/da132402` 及整条查结果流程是否想清楚

---

## 1. 结论：旧流程不对

| 活动类型 | 真实结果存在哪 | 旧 my-result | 前端旧 else |
| --- | --- | --- | --- |
| lottery / claim | `lottery_winners`（+ 可选码池） | 查 winners | 未中 →「未抽中奖品」 |
| **signup_chain** | **`activity_outcomes`（占位/候补）** | **只查 winners → 永远 won=false** | **误显示未中奖** |
| waitlist / reservation | activity_outcomes | 同上 | 同上 |
| approval | activity_outcomes (review) | 同上 | 同上 |
| survey / vote / checkin | 仅 entry（参与即完成） | won=false | **误显示未中奖** |

历史债：

- 参与接口 `join` / `verify-join`：接龙**会**返回 `outcome`（第 N 位 / 候补）
- 旧公开接口 `POST .../result`：接龙**会**读 `getActivityOutcome`
- 前端主路径只调 **`POST .../my-result`**，而 my-result **从未**读 outcomes → **查结果链路与参与成功链路断裂**

「查结果 = 有没有中奖」是**抽奖心智**，不能套到活动引擎的所有 `activity_kind`。

---

## 2. 正确语义（resultFamily）

```text
resultFamily = lottery        → winners / 卡密 / 人工履约 / 未开奖 / 未中奖
resultFamily = assignment     → 接龙等：outcome.assigned | waitlisted + resultLabel
resultFamily = review         → 审批：pending / approved / rejected
resultFamily = participation  → 问卷/投票/签到：已参与，无中奖语义
```

映射：

| activityKind | resultFamily |
| --- | --- |
| lottery, claim | lottery |
| signup_chain, waitlist, reservation | assignment |
| approval | review |
| survey, vote, checkin, … | participation |

前端：**先按 resultFamily 分支**；仅 `lottery` 且终态且 `!won` 才用「感谢参与，本次未抽中奖品」。

---

## 3. 修复内容

### 后端 `POST /public/draws/:slug/my-result`

- 读取 `activityKind`
- 返回 `activityKind`、`resultFamily`、`joinedAt`
- assignment/review：`getActivityOutcome` → `outcome{ status, resultLabel, … }`
- lottery：保持 docs/100 奖品字段；安慰券仅 lottery 且未中时查

### 前端 `LotteryView` 结果弹窗

- assignment：已占位 / 候补 + 文案
- review：待审 / 通过 / 拒绝
- participation：已成功参与
- lottery：docs/100 分支不变

### 测试

- 接龙 assigned / waitlisted
- 问卷 participation

---

## 4. 关于 da132402

OG 标题为「大转盘抽奖」：该 slug 本身是 **lottery 模板活动**；公开详情若返回「活动未开放」，通常是 `status` 非 open/drawn 或 `visible=0`。

用户感知的「接龙也一堆问题」来自**同一套 my-result UI 被所有玩法复用且只实现了抽奖语义**——与具体 slug 是否接龙无关，必须在引擎层按 `activityKind` 修。

---

## 5. 明确不做

- 不为接龙伪造 `won=true` 或卡密
- 不删除旧 `POST .../result`（仍可对齐）；主路径统一强化 my-result
- 不在本单改接龙分配算法
