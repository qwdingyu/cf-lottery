# 三层用户体系实现现状与运行评估

> 本文档基于当前代码逐项核实（`src/db/schema.ts`、`src/middleware/auth.ts`、`src/routes/platform.ts`、
> `src/routes/admin-lottery.ts`、`frontend/src/composables/platform-access.ts`、`frontend/src/router/index.ts`、
> `scripts/bootstrap-platform-owner.mjs`、`platform-rbac.test.ts`），是三层用户体系（L1 普通用户 /
> L2 租户管理员 / L3 平台运营者）的**落地现状权威描述**。
> 设计期方案见 docs/026（开发期架构基线）与 docs/042b（L3 平台运营者操作指南）；本文档记录实现结果与运行评估。

## 一、三层用户体系总览

| 层 | 身份 | 表 | 角色 | 入口 |
| --- | --- | --- | --- | --- |
| L1 | 普通用户 | `users` | 无角色字段 | `/lottery/:slug` 公开参与 |
| L2 | 租户管理员 | `tenant_members` | owner / admin / viewer | `/admin` 租户后台 |
| L3 | 平台运营者 | `platform_members` | platform_owner / platform_operator / platform_support | `/platform` 平台后台 |

一个用户可同时是某租户成员（`tenant_members`）和平台运营者（`platform_members`），两者互不冲突
（schema.ts:70-78）。`users` 表本身无全局 role 字段——角色来自所属关系，而非用户全局属性。

## 二、后端实现

### 1. 中间件链（middleware/auth.ts）

| 中间件 | 职责 | 失效判定 |
| --- | --- | --- |
| `requireAuth` | 验证 JWT(hs256) + 查 `users.status` | 用户被禁用后已签发 JWT 立即失效(docs/070 HIGH #3) |
| `requireTenantMember(allowed=[owner,admin,viewer])` | 校验 `tenant_members.role` + `tenants.status` | 成员被移除/租户暂停立即失效 |
| `requirePlatformMember(allowed=[owner,operator,support])` | 校验 `platform_members.role` + `status` | 平台成员被禁用/移除立即失效 |

设计要点：**每次请求查数据库**(而非仅信 JWT 里的角色声明)，保证撤销立即生效；角色名严格白名单，
不兼容历史上 `operator`/`member` 等租户同义词(RBAC-lite 防发散)。

### 2. 平台路由鉴权矩阵（src/routes/platform.ts）

全局 `use("*", requireAuth, requirePlatformMember([...]))`，具体路由再收紧：

| 路由 | 功能 | 允许角色 |
| --- | --- | --- |
| `GET/POST/PATCH/DELETE /members` | 平台成员 CRUD | `platform_owner` |
| `POST /tenants/:id/impersonate` | 模拟租户登录 | `platform_owner` |
| `PATCH /tenants/:id` | 调整租户套餐/状态/额度 | `platform_owner` |
| `POST /webhook-deliveries/:id/retry` | 手动重试 Webhook | owner / operator |
| 审计日志/租户列表/用量快照 | 只读运营数据 | owner / operator / support |

其他平台路由：
- `platform-system-config.ts`：系统配置读写 → 仅 `platform_owner`
- `platform-redemption-codes.ts`：兑换码 → `platform_owner` / `platform_operator`

### 3. 模拟登录（impersonate，安全设计）

- 仅 `platform_owner` 可调用；模拟对象是租户的 **owner 成员**(非任意用户)
- 签发 1 小时 JWT，含 `impersonated: true` 声明
- 每次调用写平台审计(`writePlatformAudit`，action=`platform.tenant.impersonate`)
- 前端存独立会话键 `impersonated_token`，不覆盖运营者自己的 `admin_token`；仅接受 `impersonated===true`
  且未过期的 JWT(会话固定防护)，1 小时自动失效

## 三、前端实现

### 1. 平台路由准入（composables/platform-access.ts）

`resolvePlatformRouteGate(cachedRole)` 三态决策：
- `allow`：本地缓存是活跃 L3 角色 → 放行
- `resolve`：身份未解析 → 先打 `/api/admin/me` 再决策
- `deny`：已确认非 L3 → 硬拒绝，落点 `platformAccessDeniedTarget`(有租户→租户后台，无租户→onboarding)

产品不变量：**未确认身份前不得渲染平台壳**(菜单/空表)，避免「看得到壳、看不到数」。

### 2. 路由与菜单

- `router/index.ts`：`/platform` 路由组(`PlatformLayout` + tenants/members/config/redemption-codes 等)，`ensurePlatformRole` 守卫
- `AdminLayout.vue`：`isActivePlatformRole(readPlatformRole())` 控制平台后台入口显隐
- `AuthCallbackView.vue`：登录后 `ensurePlatformRole` 获取平台角色并缓存

### 3. 身份与上下文（/api/admin/me，admin-lottery.ts:188）

返回 `user / tenant / quota / platformRole(active 成员角色或 null) / tenants(多租户 membership)`。
前端据此展示平台入口与多租户切换。

## 四、引导与运维

### 首个平台运营者（scripts/bootstrap-platform-owner.mjs）

- **不提供公开 bootstrap API**(避免生产高危入口)；用户先正常注册存在于 `users` 表，再由 CLI 脚本授予平台角色
- 用法：`node scripts/bootstrap-platform-owner.mjs --email owner@example.com [--role platform_owner]`
- 只写 `platform_members`，不创建 `tenant_id=NULL` 或 `__platform__` 特殊租户
- 手工兜底方式见 docs/042b(直接 `INSERT INTO platform_members`)

### 平台成员管理

`platform_owner` 通过 `/platform/members` 添加/调整/移除成员(按用户名或邮箱查找用户)，角色白名单校验。

## 五、安全设计汇总

| 项 | 设计 |
| --- | --- |
| 撤销立即生效 | 中间件每次查库校验 status/role，不盲信 JWT 角色 |
| 角色白名单 | 后端 `PLATFORM_ROLES` + 前端 `ACTIVE_PLATFORM_ROLES` 双端对齐，拒收历史同义词 |
| impersonate | 仅 owner + 审计 + 1h 时效 + 独立会话 + 只模拟租户 owner |
| 禁用即失效 | users/tenants/platform_members 的 status 变更即时生效 |
| 平台审计 | 高风险写操作(impersonate/成员变更/租户调整)统一 `writePlatformAudit` → `admin_audit_logs` |

## 六、测试覆盖（platform-rbac.test.ts）

- owner/operator 角色矩阵(谁能读/写哪些平台资源)
- 边界：拒收 `operator`/`member` 等历史同义词、自降级防护、非活跃角色视为非 L3
- impersonate 的鉴权与审计
- `/api/admin/me` 的 platformRole 返回

## 七、与设计基线（docs/026）的差异

| 026 基线(计划) | 当前实现 |
| --- | --- |
| `platformMembers` 默认角色 `operator`(草案) | 显式写入，无模糊默认值；`platform_owner` 引导创建 |
| `requirePlatformMember` 草案未接入路由 | 已全面接入 platform.ts / platform-system-config / platform-redemption-codes |
| 平台成员表无 migration | `0016_platform_members.sql` 已落地 |
| 审计用租户 `audit_logs` | 独立 `admin_audit_logs`(P1-13 统一) |

## 八、运行评估与剩余建议

**现状评估**：三层用户体系已完整闭环(后端鉴权 + 前端守卫 + 引导 + 迁移 + 测试)。批次审查中发现的唯一缺陷(前端角色缓存过时导致被降级/移除用户仍可见平台壳)已修复——路由守卫改为每次导航 `force: true` 强制解析角色。

**低优先级建议**(非本次范围)：
1. `platform_support` 角色的前端 UI 支持度(只读态菜单/操作按钮禁用)可进一步细化
2. 平台 owner 变更的二次确认(如移除最后一个 owner 时的防护)**已确认安全**：PATCH 不能改自己、DELETE 不能删自己，存在至少 1 个活跃 owner 的不变量成立

**批次安全加固(已实施)**：`platform_support` 读取审计/用量/失败投递时**必须指定 tenantId**(最小权限,防止 support 全量拉取租户数据)；不传时返回空数组而非全部，`platform-rbac.test.ts` 新增用例锁定。

**验收命令**：`npx tsc --noEmit` 0 errors(无管道)、`npx vitest run` 全绿、`cd frontend && npx vue-tsc -b --pretty false` 0 errors。
