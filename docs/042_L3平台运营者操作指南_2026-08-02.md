# L3 平台运营者操作指南

> 日期：2026-08-02
> 适用版本：cf-lottery

## 概述

cf-lottery 采用三层用户体系：

| 层级 | 角色 | 入口路由 | 职责 |
|------|------|----------|------|
| L1 | 普通用户 | `/lottery/:slug` | 参与公开活动，无需登录 |
| L2 | 租户管理员 | `/admin/*` | 管理本租户的活动、奖品、团队 |
| L3 | 平台运营者 | `/platform/*` | 管理所有租户、系统配置、兑换码、审计 |

## L3 登录流程

```
第一步：注册普通账号
  → 访问 https://lucky.eforge.xyz
  → 点击「免费注册，开始使用」
  → 填写邮箱 / 用户名 / 密码
  → 邮箱收到验证码，输入后完成注册

第二步：平台运营者授权（由现有 L3 owner 或数据库运维执行）
  方式 A（推荐）：本地命令行
    cd cf-lottery
    node scripts/bootstrap-platform-owner.mjs --email 你的注册邮箱

  方式 B：直接数据库操作
    INSERT INTO platform_members (user_id, role, status, created_at, updated_at)
    VALUES ('用户ID', 'platform_owner', 'active', datetime('now'), datetime('now'))
    ON CONFLICT(user_id) DO UPDATE SET role='platform_owner', status='active'

第三步：重新登录
  → 登出后重新访问 https://lucky.eforge.xyz/admin/login
  → 输入用户名密码登录
  → 侧边栏出现「平台运营」折叠菜单

第四步：进入平台后台
  → 点击「平台运营」展开菜单
  → 可访问：租户管理 / 平台成员 / 系统配置 / 兑换码 / 审计日志 / Webhook投递
```

## 平台运营者能力

| 功能 | 页面 | 说明 |
|------|------|------|
| 租户管理 | `/platform/tenants` | 查看所有租户，调整套餐、暂停/恢复 |
| 平台成员 | `/platform/members` | 管理 L3 成员，添加/移除平台运营者 |
| 系统配置 | `/platform/config` | 控制全局参数：注册开关、套餐额度、限流 |
| 兑换码 | `/platform/redemption-codes` | 批量生成平台额度兑换码 |
| 审计日志 | `/platform/audit-logs` | 查看平台级操作记录 |
| Webhook 投递 | `/platform/webhook-deliveries` | 监控全平台 Webhook 投递状态，手动重试 |

## 关键系统配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enable_registration` | true | 关闭后禁止新用户注册（MVP 内测用） |
| `enabled_activity_kinds` | lottery,signup_chain,... | 控制可创建的活动类型 |
| `free_plan_max_webhooks` | 1 | Free 套餐 Webhook 数量 |
| `plan_free_max_activities` | 10 | Free 套餐最大活动数 |
| `rate_limit_login` | 5 | 登录频率限制（次/分钟） |

## 技术实现

```
认证流：
  /api/auth/login → 签发 JWT（含 userId + tenantId）
  requireAuth 中间件 → 解析 JWT，注入 ctx.userId / ctx.tenantId
  /api/admin/me → 查询 tenant_members + platform_members
                  → 返回 platformRole: "platform_owner" | null
  前端 router → readPlatformRole() → 非空时显示平台入口

授权表：
  platform_members (user_id PK, role, status)
  ↓
  requirePlatformMember() 中间件 → 每次请求查库，确保角色实时生效
```

## 添加新平台成员

```bash
# 必须先注册普通账号（邮箱验证），再授予平台角色
node scripts/bootstrap-platform-owner.mjs --email 新成员邮箱
```
