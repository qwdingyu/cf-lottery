# 106 查结果弱会话诚实与状态标签中性化

日期：2026-08-04  
前置：docs/105（分享失败 / 弱会话一键尝试）  
触发：对 docs/105 实现与后端契约再对照后，收口「假一键」与公开角标抽奖话术。

---

## 1. 问题清单（仅有代码证据）

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 仅有 `sessionEmail` 时打开「查结果」会自动 POST 无码 my-result | 前端把弱会话当可一键；后端 `public-lottery` 无 Bearer 必 `email+code` → **必 400** |
| 2 | 用户先看到「一键查询」再被迫切 OTP | 用失败当状态机，多一次无意义请求与错误闪现 |
| 3 | 卡片角标 `drawing` 一律「开奖中」 | `statusText` 不看 `activityKind` |
| 4 | `resultMode` 标签「定时开奖 / 手动开奖」 | 非抽奖也可配置 scheduled/manual |
| 5 | 文件头注释仍写「查单 / 订单链接」 | 电商遗留注释，与 docs/102 冲突 |

**后端契约（未改，作为前端约束）**

```text
POST /my-result
  Bearer 匹配 email → 免 OTP
  否则 → 必须 email + 有效验证码
  无码 → 400「请输入邮箱和验证码」
```

---

## 2. 正确规则

```text
查结果会话
  JWT 强会话 → 打开即查 / 一键查
  仅 sessionEmail → 预填邮箱 + 展示 OTP 表单（可一键「发送验证码」）
  禁止：无码自动请求 my-result

公开角标 status
  drawing + lottery|claim|缺 kind → statusDrawing（开奖中）
  drawing + 其它 kind → statusDrawingTagGeneric（处理中）
  其它 status 与 kind 无关

result_mode 短标签
  scheduled → 定时出结果（中性）
  manual → 手动出结果（中性）
  非抽奖 mode 仍走 adminResult* 键
```
