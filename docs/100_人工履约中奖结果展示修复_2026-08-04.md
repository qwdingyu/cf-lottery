# 100 人工履约中奖结果展示修复

日期：2026-08-04  
触发：刮刮卡活动奖品为 **人工发放**；开奖后「我的结果」显示「😊 感谢参与，本次活动未获得奖品」。

---

## 1. 错误逻辑（旧）

| 层 | 行为 | 问题 |
| --- | --- | --- |
| 开奖 | `manual_fulfillment` 奖品无码池 → `lottery_winners.prize_code_id=""`，**仍写 winner 行** | 中奖事实在 DB |
| my-result | 有 winner → `won=true`；无 `prizeCodeId` → `prizeCode=null` | API 其实可能已 won |
| 前端 | 结果弹窗：`won` 分支若无码仍可进「恭喜」；但若用户感知/文案或 `won` 未用好，else 落「未获得奖品」 | 更糟的是：仅用「有码=中奖」心智；未开奖也像未中 |

用户心智：选了人工发放奖品 = 中奖后线下发，**不是**「没中」。

---

## 2. 正确语义

```text
joined=false     → 未参与
joined + 未终态  → 已参与，结果尚未公布（勿写「未获得奖品」）
joined + won     → 恭喜中奖
  ├─ 有 prizeCode     → 展示可复制卡密
  ├─ prizeType=manual → 展示奖品名 +「人工发放，主办方联系/线下履约」
  └─ 无码非 manual    → 中奖但无码，请留意通知
joined + 已开奖 + !won + 安慰券 → 安慰奖
joined + 已开奖 + !won          → 未抽中奖品
```

---

## 3. 修复

### 后端 `POST .../my-result`

额外返回：

- `drawStatus` / `resultMode`
- `prizeName` / `prizeType` / `prizeValueText` / `fulfillmentNote` / `tierName`
- `won` 仍以 **winner 行** 为准（与有无卡密无关）

### 前端 `LotteryView` 结果弹窗

按上表分支；人工履约专用文案 `wonManualFulfillmentHint`。

### 测试

`auth-and-public.test.ts`：人工履约中奖 `won=true`、无 `prizeCode`、有 `prizeName`。

---

## 4. 明确不做

- 不为人工履约伪造卡密
- 不改开奖算法；只修查询与展示诚实性
