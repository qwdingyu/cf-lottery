## 二、详细踩坑记录

### 2.1 node_modules 大文件阻止推送

**背景**：项目初始化时从 cf-shop 复制了 `node_modules`，其中 `@cloudflare/workerd-darwin-64/bin/workerd` 文件 114MB，超过 GitHub 100MB 限制。

**原因**：`.gitignore` 未包含 `node_modules`，导致 `git add -A` 时将其纳入追踪。

**排查过程**：
1. `git push` 报错 `GH001: Large files detected`
2. 添加 `node_modules/` 到 `.gitignore` 并 `git rm --cached`
3. 重新推送仍然报错（文件在 git 历史中）
4. 使用 `git filter-branch` 清理历史

**解决方案**：
```bash
# 1. 添加 .gitignore
echo "node_modules/" >> .gitignore

# 2. 清理历史（如果已经提交）
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch -r node_modules/' \
  --prune-empty -- --all

# 3. 强制推送
git push origin main --force
```

**建议**：项目初始化时第一件事就是创建 `.gitignore`，包含 `node_modules/`、`dist/`、`.env`、`coverage/`。

### 2.2 前端构建语法错误 ×4

**背景**：从 cf-shop 复制前端代码后，`npm run build` 报多个语法错误。

**原因**：cf-shop 代码在剥离过程中产生了残留语法问题。

**错误列表**：

| 文件 | 错误 | 修复 |
|------|------|------|
| `AdminLotteryView.vue` | `requireToken` 函数重复声明（箭头函数 + function 声明） | 删除重复的 function 声明 |
| `AdminSystemConfigView.vue` | `config[key] = res.value` 缺少 `}` 前的闭合 | 补全 `},` |
| `AdminSystemConfigView.vue` | `clearBusinessConfirmText.value = ''` 缺少 `}` 前的闭合 | 补全 `},` |
| `LotteryView.vue` | `type MyEntry = { ... };` 后多余 `}` | 删除多余 `}` |

**解决方案**：
```bash
# 构建前端
cd frontend && npx vite build

# 逐个修复语法错误，每次修复后重新构建
# 直到构建成功
```

**建议**：从 cf-shop 复制代码后，立即运行 `npx vite build` 验证，不要等到部署前再检查。

### 2.3 @shared 别名缺失

**背景**：前端代码中使用了 `@shared/money` 和 `@shared/order-status` 导入，但 vite 未配置别名。

**原因**：vite config 从 cf-shop 复制时未包含 `@shared` 别名。

**解决方案**：
```typescript
// vite.config.ts
resolve: {
  alias: {
    '@': resolve(__dirname, 'src'),
    '@shared': resolve(__dirname, 'src/shared'),  // 新增
  },
},
```

### 2.4 shared 文件缺失

**背景**：`@shared/money` 和 `@shared/order-status` 文件不存在。

**原因**：从 cf-shop 剥离时，这些文件在 cf-shop 的 `shared/` 目录下，未复制到 cf-lottery。

**解决方案**：创建简化版文件：
```typescript
// frontend/src/shared/money.ts
export function formatMoney(cents: number, currency?: string): string {
  const major = (cents / 100).toFixed(2)
  return currency === 'CNY' ? `¥${major}` : `${currency || ''}${major}`
}
export function minorToMajorString(cents: number, currency?: string): string {
  return formatMoney(cents, currency)
}
export function parseMajorToMinor(value: string): number {
  return Math.round(parseFloat(value) * 100)
}
```

### 2.5 SPA 静态资源 404

**背景**：部署后访问 `https://cf-lottery.xxx/` 返回 404，前端 HTML 没有被返回。

**原因**：Hono 路由只处理了 `/api/*` 路径，未配置 SPA fallback 路由。

**解决方案**：
```typescript
// src/index.ts
app.get("*", async (c) => {
  try {
    const asset = await c.env.ASSETS.fetch(c.req.raw);
    if (asset.status === 404) {
      return c.env.ASSETS.fetch(new Request(new URL("/index.html", c.req.url)));
    }
    return asset;
  } catch {
    return c.env.ASSETS.fetch(new Request(new URL("/index.html", c.req.url)));
  }
});
```

### 2.6 Turso 多 group 报错

**背景**：`turso db create` 报错 `you have more than one database group`。

**原因**：账号下有多个 group（cf-shop-group、default、tokyo-group、xshop-group），需要指定。

**解决方案**：
```bash
HOMEBREW_NO_AUTO_UPDATE=1 turso db create cf-lottery-db --group tokyo-group
```

**建议**：使用 `HOMEBREW_NO_AUTO_UPDATE=1` 避免 Homebrew 更新阻塞命令。

### 2.7 schema database 类型已废弃

**背景**：`turso db create --type schema` 报 `Schema Databases are deprecated`。

**解决方案**：不指定 `--type` 参数，使用默认类型。

### 2.8 迁移多语句未执行

**背景**：`turso db shell cf-lottery-db < migrations/0001_init.sql` 执行后表未创建。

**原因**：`turso db shell` 管道输入时可能不支持多语句。

**解决方案**：将 CREATE TABLE 语句合并为一条语句或多条语句用分号分隔后一次性执行：
```bash
turso db shell cf-lottery-db "CREATE TABLE ...; CREATE TABLE ...;"
```

### 2.9 EMAIL_FROM 尖括号问题

**背景**：`.env` 文件中 `EMAIL_FROM=cf-lottery <noreply@eforge.xyz>` 导致 bash `source` 报错。

**原因**：bash 将 `<` 解析为输入重定向。

**解决方案**：加引号 `EMAIL_FROM="cf-lottery <noreply@eforge.xyz>"`

## 三、最佳实践部署流程

### 3.1 首次部署

```bash
# 1. 创建 .gitignore
cat > .gitignore << 'EOF'
node_modules/
dist/
.env
coverage/
test-lottery.db
EOF

# 2. 创建 Turso 数据库
HOMEBREW_NO_AUTO_UPDATE=1 turso db create cf-lottery-db --group tokyo-group

# 3. 获取 URL 和 token
turso db show cf-lottery-db
turso db tokens create cf-lottery-db

# 4. 创建 .env 文件
cat > .env << 'EOF'
TURSO_URL=libsql://cf-lottery-db-xxx.turso.io
TURSO_TOKEN=xxx
JWT_SECRET=cf-lottery-jwt-secret-change-me
RESEND_API_KEY=re_xxx
EMAIL_FROM="cf-lottery <noreply@eforge.xyz>"
CRON_SECRET=cf-lottery-cron-secret-change-me
APP_ORIGIN=https://cj.eforge.xyz
EOF

# 5. 运行迁移
turso db shell cf-lottery-db "CREATE TABLE IF NOT EXISTS tenants (...); CREATE TABLE IF NOT EXISTS users (...); ..."

# 6. 配置 secrets
cat .env | while read line; do
  key=$(echo $line | cut -d= -f1)
  value=$(echo $line | cut -d= -f2-)
  echo "$value" | npx wrangler secret put $key
done

# 7. 构建前端
cd frontend && npx vite build && cd ..

# 8. 部署
npx wrangler deploy
```

### 3.2 后续部署

```bash
# 1. 构建前端（如有变更）
cd frontend && npx vite build && cd ..

# 2. 部署
npx wrangler deploy
```
