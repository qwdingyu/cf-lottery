# 265 全面架构审查与运营闭环评估

> 审查时间：2026-08-23
> 审查范围：后端核心服务层 + 后端路由层 + admin 运营闭环
> 审查方法：三路并行 agent 逐文件深度审查

---

## 一、后端核心服务层审查

### 1.1 总体评分：8.5/10

**优点**：
- 并发安全设计完善：大量 CAS 乐观锁，关键路径有事务保护
- 幂等性保护充分：抽奖、spin、奖励发放都有幂等键或 CAS 保护
- 容错机制健全：外部依赖失败不影响核心流程
- 审计链完整：spins_log、activityEvents、auditLogs 覆盖关键操作

### 1.2 P1 级问题（5 个，均有纵深防御）

| 问题 | 文件 | 风险 | 现有兜底 |
|------|------|------|---------|
| 直付秒杀 CAS 回滚竞态 | participation.ts:280-305 | CAS 成功但 occupy 失败时回滚 -1，高并发下可能偏移 | 偏移上限=并发请求数，不影响资金安全 |
| 非秒杀路径 COUNT(*) 超发窗口 | participation.ts:336-338 | 两个请求同时通过 COUNT 检查 | UNIQUE 约束兜底 |
| performDraw 事务外状态更新竞态 | draw-execution.ts:80-95 | CAS 抢占在事务外，崩溃后 healDrawingState 可能误判 | 有 healDrawingState 修复机制 |
| 保底机制与码池 CAS 竞态 | spin-execution.ts:230-280 | 并发 spin 同时触发保底，码不足时未中 | 正确行为（码不足=未中） |
| markRewardIdsGranted CAS 失败处理 | referral-rewards-engine.ts:350-390 | 部分成功部分失败，已成功的不回滚 | best effort 语义，下次归因重试 |

**结论**：P1 问题均为已知权衡，有纵深防御（UNIQUE 约束、审计日志、人工补偿），实际风险可控。

### 1.3 P2 级问题（15+ 个，主要是优化空间）

- Fisher-Yates 取模偏差（偏差 < 10^-9，可忽略）
- processDueDraws 非 lottery 活动到期关闭无事务保护
- sendDrawReminders entries LIMIT 500（大多数活动足够）
- triggerRewardEarned 配额校验在事务内（正确但需注意回滚语义）
- consecutiveNoWinSpins 计数器溢出（JS 安全整数范围足够）
- enqueueWebhookEvent 幂等检查竞态（UNIQUE 约束兜底）
- grantBonusSpin balanceAfter 使用事务外预读（审计日志允许轻微偏差）
- cancelDraw 容量释放计算假设数据一致性

## 二、后端路由层审查

### 2.1 总体评估

- 多租户隔离：绝大多数查询带 tenantId 条件
- 认证授权：管理端路由有完整中间件链，公开端点有 OTP/JWT 验证
- 限流机制：公开 API 有 IP 和身份双维度限流
- 错误处理：大部分异常返回合适 HTTP 状态码

### 2.2 P1 级问题

| 问题 | 端点 | 风险 |
|------|------|------|
| 订单金额可篡改 | POST /draws/:slug/payment-orders | quantity 由客户端传入，可绕过 maxPerUser |
| 回调端点无统一签名验证 | ALL /:tenantId/:provider/callback | 依赖各支付网关实现，无统一中间件 |
| 验证码生成逻辑竞态 | POST /draws/:slug/access-code | 先标记旧码失效再插入新码，非原子性 |

### 2.3 P2 级问题

- verify-join Bearer 验证逻辑复杂易错
- my-result 邮箱身份校验不一致
- spin 幂等键长度限制过短（128）
- 跨租户券核销风险（slug 可选时退回到全局定位）
- cascadeDeleteDraw 无软删除
- escapeLike 未转义反斜杠
- validateProductLink 可能接受 javascript: 协议
- 开奖操作无确认机制（confirm: true）
