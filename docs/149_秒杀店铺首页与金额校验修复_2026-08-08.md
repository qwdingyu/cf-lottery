# 149 秒杀店铺首页与金额校验修复

## 背景

复核秒杀闭环时发现两个问题：

- 店铺首页 `/api/public/shops/:storeSlug` 的秒杀活动查询把 `public_slug` 当成 `lottery_entries.draw_id` 使用，并在未 join `lottery_draws` 的查询中引用 `lottery_draws.id`，导致有活动时可能返回 500。
- `flashSale.priceCents` 解析使用 `Math.floor(Number(...))`，会把小数金额静默截断。

## 原因

店铺首页是公开活动矩阵之后新增的入口，但没有复用 `/home-activities` 已经验证过的内部 ID 与直付计数器口径。直付秒杀的真实占用名额来自 `lottery_draws.active_participant_count`，非直付秒杀才需要按 `lottery_entries` 聚合。

金额字段以“分”为最小单位，运行时解析层必须严格要求整数。静默取整会让 API 手写 JSON 或脏数据绕过发布预检意图，造成订单金额低于运营配置。

## 修复方案

- 店铺首页查询显式选择内部 `lottery_draws.id` 和 `active_participant_count`，但响应仍只返回 `publicSlug`，不暴露内部 ID。
- 店铺首页非直付活动按内部 draw id 聚合参与记录；直付秒杀直接使用 `activeParticipantCount`。
- 店铺首页秒杀运行时统一调用 `buildFlashSaleRuntime`，与公开详情和首页活动流保持同源计算。
- `priceCents` 改为 `Number.isInteger` 严格校验，非整数返回 `flash_sale.price.invalid`。

## 回归测试

- `src/routes/public-home-activities.test.ts` 新增店铺首页直付秒杀回归：`activeParticipantCount=3`、库存 10 时返回 `remaining=7`、`progressPercent=30`，并确认不暴露内部活动 ID。
- `src/lib/flash-sale-config.test.ts` 新增金额小数回归：`priceCents=9900.9` 必须产生 `flash_sale.price.invalid`，不能解析为 `9900`。

## 建议

后续新增活动聚合入口时，应优先抽出后端共享的公开活动卡片构造函数，避免 `/home-activities`、`/shops/:storeSlug` 和公开详情重复维护计数、价格、商品信息拼装逻辑。
