# 082 表格批量操作：对照 cf-shop 与测试期清理能力分析

日期：2026-08-04  
范围：管理台/平台台列表多选、批量删除/状态更新、测试脏数据清理  
对照：`../cf-shop`（docs/024、025 与 composables/页面实现）

## 1. 背景

测试与联调阶段会产生大量临时数据：草稿活动、试导入卡密、试加黑名单/成员、Webhook 投递、兑换码、日志等。  
若只能「逐条点删除」，运营/开发体验会明显卡顿。cf-shop 已在同类 Turso/CF free 约束下沉淀出可复用的批量交互；cf-lottery 仅部分继承。

## 2. cf-shop 已验证的「丝滑」模式（应复用，不重造）

### 2.1 共性抽象

| 能力 | 位置 | 作用 |
| --- | --- | --- |
| `useTableSelection` | composable | 本页多选、全选、半选、Shift 连选、翻页/筛选后剔除不可见选中 |
| `useAdminBatchOperation` | composable | 顺序执行 + `operating/completed/total` 进度，防重复点击 |
| `useConfirmDialog` / `askConfirmWithOptions` | composable | 危险操作确认；可选「全部删除 / 解绑引用」勾选项 |
| `downloadCsv` + 安全单元格 | 工具 | 已选导出；防公式注入 |
| `.bulk-bar` / `.table-command-actions` / `.select-cell` | 共享 CSS | 选中后浮出命令条，busy 态统一 |

设计取舍（cf-shop docs/025，对 lottery 仍适用）：

- **默认不新开重型 CRUD 框架**；列与危险文案留在页面。
- **低频运维**可顺序打单条 API（可审计、适合 free 计划）。
- **高频/大体积清理**（卡密、订单、日志）再上 **服务端 batch + force/unlink** 选项。
- **Dashboard 概览表不加多选**。

### 2.2 命令条标准动作（写表）

选中后典型组合：

1. 摘要：`已选 N`（卡密/订单还会显示「默认可删 safeCount」）
2. 清空选择
3. 复制已选 / 导出已选（只读价值，测试排障极有用）
4. **批量状态**（启用/停用、上架/下架、作废…）— 比只删更常用
5. **批量删除** — 确认框带选项：默认安全终态；可选 force / unlinkRefs

### 2.3 后端危险删除契约（卡密/订单）

- 默认：仅 `SAFE_*` 状态且无危险引用
- `force`：扩大可删范围
- `unlinkRefs`：先解绑再删，避免孤儿引用挡删除  
测试期「清场」靠这两档，而不是每次手工解绑。

## 3. cf-lottery 现状（证据）

### 3.1 已有基础设施

- `frontend/src/composables/useTableSelection.ts`：与 shop **同源**（含 rangeAnchor / Shift 能力）。
- `useConfirmDialog` + `askConfirmWithOptions`：已有。
- `admin.css`：`.bulk-bar` / `.table-command-actions` / `.select-cell` 已有。
- `downloadCsv`：活动侧 `ops-utils` / 日志页本地实现有。
- **缺失**：`useAdminBatchOperation`（lottery 未迁入）。

### 3.2 页面覆盖矩阵

| 页面 | 多选 | 批量写 | 复制/导出已选 | 备注 |
| --- | --- | --- | --- | --- |
| 活动列表 AdminLotteryView | 有 | 仅批量删除 | 无 | 仅 `canDeleteDraw` 可选；顺序 DELETE；**未接 Shift** |
| 操作日志 AdminLogsView | 有 | UI 有，API **抛错未开放** | 有 | 与 shop 日志能力不对齐 |
| 奖品列表 AdminPrizesView | **无** | 无 | 无 | 启停/删仍单条 |
| 奖品码池（弹窗） | **无** | 「批量删除」= **当前页全部 available 盲删** | 有整池 CSV | **无多选**；危险且不丝滑 |
| 黑名单 / 成员 / 集成 | 无 | 无 | 无 | 测试脏数据只能逐条 |
| 额度兑换历史 | 无 | 无 | 无 | |
| 平台兑换码 | 无 | 仅**批量生成** | 无 | 不能批量禁用/删测试码 |
| 平台租户/成员/投递/审计 | 无 | 无（投递有单条重试） | 无 | |
| 平台数据清理 | N/A | 按**表**清日志/验证码/事件 | N/A | 不覆盖活动/奖品/码业务实体 |
| 运营台 Dashboard | 无（正确） | — | — | 与 shop 一致，不应加多选 |

### 3.3 与 shop 的关键体验差距

1. **覆盖面**：shop 写表几乎全覆盖；lottery 仅活动+日志半成品。  
2. **批量动作单一**：活动只有删，没有批量暂停/取消草稿/归档类状态；码池没有按勾选删。  
3. **进度与防抖**：活动批量删除手写 for 循环，无 `completed/total` 条；无统一 `useAdminBatchOperation`。  
4. **Shift 连选**：日志有 `$event.shiftKey`；活动列表 checkbox **未传** extendRange。  
5. **安全删除语义**：无 safeCount / force 选项；测试清场要么删不动，要么误伤（码池「删本页全部」）。  
6. **后端 batch**：lottery 几乎无 `batch-delete`；日志 batch 前端直接 throw。平台仅有兑换码 **batch 生成** 与 **表级 cleanup**。  
7. **码池「批量删除」反模式**：不选行、删 filter=available 的整页列表 — 测试期易误删、也无法精确清 10 条脏码。

## 4. 测试期「临时无用数据」痛点映射

| 脏数据类型 | 今天怎么清 | 痛点 | 目标体验（对齐 shop） |
| --- | --- | --- | --- |
| 大量 draft/测试活动 | 多选批量删（可删状态） | 无进度；open/drawn 策略不直观；无导出已选 | bulk-bar + 进度；摘要含可删数；可选仅 draft |
| 试导入卡密 | 码池「删当前页全部 available」或逐条 | 无多选；盲删 | 多选 + 仅 available 默认可删 + 导出 |
| 试加黑名单/成员 | 逐条 | 慢 | 多选删除 |
| 测试 Webhook/API Key | 逐条 | 慢 | 多选删除（确认） |
| 平台测试兑换码 | 无删/禁批量 | 码池膨胀 | 多选禁用/删（安全状态） |
| 日志/验证码/事件 | 平台「数据清理」或日志页（API 未开） | 日志多选删是空壳 | 接 batch-delete 或引导用 cleanup |
| 投递失败记录 | 单条重试 | 测试刷屏 | 多选重试/忽略（P2） |

## 5. 推荐方案（分阶段，避免灾难）

原则：**先前端共性 + 顺序单 API**；**仅在体积大或事务需要时加后端 batch**；危险删除默认安全，测试清场用显式选项。

### P0 — 基础设施与「已有页」修到可用（低风险高体感）

1. 迁入 `useAdminBatchOperation`（可从 shop 拷贝 + 单测）。  
2. 活动列表：  
   - checkbox 接 `shiftKey`；  
   - bulk 条统一 `bulk-bar`/`aria-busy`；  
   - 删除走 `runSequential` + 进度文案；  
   - 摘要展示「已选 / 可删」；  
   - 可选：复制/导出已选活动元数据（id、slug、状态）。  
3. 奖品码池：  
   - 真正多选；  
   - 批量删除 = **仅已勾选且 available**；  
   - 去掉「无勾选就删整页」行为（或改名为「清空本页可用码」并二次确认）。  
4. 日志：要么接真实 `batch-delete`（对齐 shop），要么隐藏删除按钮，避免「点了必失败」。

### P1 — 测试清场高频写表

按 ROI 铺多选 + 顺序删/状态：

| 优先级 | 页面 | 批量动作 |
| --- | --- | --- |
| 高 | 奖品列表 | 批量启停；批量删（无码池引用或仅停用） |
| 高 | 黑名单 | 批量删除 |
| 中 | 租户成员 | 批量移除（不可动 owner） |
| 中 | 集成 Webhook/API Key | 批量删除 |
| 中 | 平台兑换码 | 批量禁用；可选删未使用 |
| 低 | 平台成员/投递 | 状态/重试；删需审计 |

### P2 — 后端 batch / 安全清场（数据量大时）

- `POST .../batch-delete`（活动、码、日志）+ 审计一条汇总。  
- 活动删除策略文档化：哪些 status 默认可删；drawn 是否 force。  
- 平台 cleanup 扩展「按租户清测试活动」需 **极强确认 + 仅非生产标记**，避免误伤；默认仍建议列表多选而非一键炸租户。

### 明确不做（防灾难）

- 不给 Dashboard 加多选。  
- 不默认 force 删除已开奖/已履约数据。  
- 不一次前端并发打爆 Turso（保持顺序或小并发 ≤3）。  
- 不引入重型表格框架。

## 6. 实施顺序建议（若授权开发）

1. composable + 单测  
2. 活动列表体验对齐（Shift、进度、文案）  
3. 码池多选删除修正（修正危险默认）  
4. 日志 API 或下线假按钮  
5. 黑名单 / 成员 / 集成  
6. 平台兑换码禁用  
7. 视数据量再加 batch API  

每步：`tsc` + `vitest` + 该页手工多选路径；文档追加实施记录。

## 7. 结论

- cf-lottery **不是从零**：选择器、确认框、bulk 样式、活动批量删、日志多选壳都在。  
- 与 cf-shop 的差距主要在 **覆盖面、状态类批量、进度封装、Shift、安全删除语义、码池多选、日志 API 闭环**。  
- 测试期最大杠杆：**码池真多选删除**、**活动批量删体验修满**、**黑名单/成员/集成多选**、**日志删真或假下线**；再视需要上服务端 batch。

本文为分析与方案，**未改业务代码**。落地需单独授权按 P0→P1 实施。
