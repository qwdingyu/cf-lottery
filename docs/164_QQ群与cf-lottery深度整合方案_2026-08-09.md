# 164 QQ群与 cf-lottery 深度整合方案

> 日期：2026-08-09
> 定位：基于 cf-lottery 实际代码的 QQ 群整合方案设计
> 方法：阅读 cf-lottery 全部关键源码后形成的落地分析，非文档推测

## 1. 核心结论

**cf-lottery 本身已具备完整的活动营销引擎**，包含：
- 即时抽奖（大转盘/刮刮乐/老虎机 等 13 种体验类型）
- 秒杀直付（内嵌支付+发卡）
- 每日签到
- 裂变拉新（分享邀请+奖励+排行榜）
- 投票/问卷/接龙
- 卡密池管理
- 多租户隔离

**QQ 群的角色不是替代 cf-lottery 的功能，而是作为 cf-lottery 的「零距离触达层」**——让用户无需打开浏览器，在 QQ 群内即可完成签到、抽奖、查看结果、秒杀等所有操作。

**推荐架构**：**NapCatQQ + 自研轻量桥接插件**（不依赖 zhenxun_bot 的经济体系，因为 cf-lottery 已有完整的签到/抽奖/次数管理）。

### 2.3 即时抽奖（Instant Spin）—— 核心玩法

这是 QQ 群整合最关键的玩法。代码验证：

- **spin-execution.ts**：完整的即时抽奖引擎，包含幂等回放、CAS 扣次、加权抽档、卡密 CAS 原子发放
- **spin-quota.ts**：次数配额管理，支持 `maxSpinsPerEntry`、`initialSpinsOnJoin`、`extraSpinsPerInvite`、`maxExtraSpins`
- **viral-weight.ts**：裂变加权，开奖袋中按邀请人数加权

**QQ 群适用场景**：用户发送 `/抽奖` → 桥接调用 `POST /api/spin` → 返回结果 → 群内展示中奖/未中

### 2.4 参与模式 (`participationMode`，5 种)

| 模式 | 说明 | QQ 群适用 |
| --- | --- | --- |
| `open` | 公开参与，无需验证 | ✅ 默认，群内成员直接参与 |
| `roster` | 白名单模式 | ✅ 仅限群成员（通过 roster 同步群成员列表） |
| `password` | 密码验证 | ✅ 群内公布密码，群外不可参与 |
| `invite_code` | 邀请码 | ✅ 每个群成员一个专属邀请码 |
| `registered` | 需登录注册 | ❌ 不适合群内快速参与 |

## 3. 整合方案：多租户 QQ 群模型

### 3.1 租户映射

```
QQ 群 A → cf-lottery Tenant A
QQ 群 B → cf-lottery Tenant B
...

每个租户独立管理：
  - 活动（抽奖/秒杀/签到/投票）
  - 奖品池（prizes + prizeCodes）
  - API Key（桥接认证）
  - Webhook 配置（回调地址）
  - 黑名单
  - 支付配置
  - 活动额度
```

### 3.2 身份映射

```
QQ 号 (群成员) → cf-lottery identityValue

方案 A（推荐）：QQ 号直接作为 identityValue
  - identityType = "qq"
  - identityValue = "123456789" (QQ号)
  - 参与模式为 open（无需邮箱验证码）
  - 桥接插件在请求头添加内部 JWT 认证

方案 B：QQ 号 → 邮箱映射
  - identityType = "email"
  - identityValue = "qq_123456789@qqgroup"
  - 桥接插件处理验证码逻辑

采用方案 A，因为：
  - cf-lottery 的 identityType 是自由文本，不强制 email
  - 群内用户无需邮箱，直接通过 QQ 号参与
  - 需要修改公开路由的参与逻辑（允许非 email 身份直接参与）
```

### 3.3 API 调用方式

桥接插件通过 cf-lottery 的 REST API 操作，不需要数据库直连：

```
POST /api/v1/integration/conversions  - 外部转化回传
POST /api/v1/integration/events       - 事件上报（退群/发卡确认等）
  └─ 认证方式：X-CF-Lottery-API-Key 或 Authorization: Bearer <api_key>
  └─ API Key 在管理后台为每个租户生成
```

对于公开参与（抽奖、签到等），桥接插件直接调用公开 API：

```
GET  /api/public/draws/{slug}            - 获取活动详情
POST /api/public/draws/{slug}/verify-join - 参与活动
POST /api/public/draws/{slug}/spin       - 即时抽奖（instant spin）
POST /api/public/draws/{slug}/my-result   - 查询我的结果
POST /api/public/draws/{slug}/share       - 生成分享链接
GET  /api/public/draws/{slug}/viral-leaderboard - 裂变排行榜
```

## 4. QQ 群内玩法矩阵

### 4.1 每日签到

```
签到流程：
  用户发送：签到 或 /checkin
  桥接插件：
    1. 确定用户 QQ 号 → identityValue
    2. 调用 cf-lottery 签到活动的 verify-join
    3. cf-lottery 返回结果（签到成功/已签到）
    4. 群内回复：签到成功！获得 1 次抽奖机会 🎉
      或：今日已签到，明天再来哦~

cf-lottery 侧配置：
  - activityKind = "checkin"
  - experienceType = "checkin"
  - participationMode = "open"
  - checkin 活动 identityValue 自动附加 :YYYY-MM-DD 后缀（代码 verified）
```

### 4.2 大转盘/抽奖

```
抽奖流程：
  用户发送：抽奖 或 /lottery
  桥接插件：
    1. 确定用户身份
    2. 调用 cf-lottery 的 verify-join 参与（首次）
    3. 调用 spin 接口（即时抽奖）
    4. 返回结果：
       - 中奖：🎉 恭喜中奖！奖品：XXX Token x10
       - 未中：😅 未中奖，剩余抽奖次数：3 次
       - 邀请好友可增加抽奖次数！

cf-lottery 侧配置：
  - activityKind = "lottery"
  - resultMode = "instant"
  - experienceType = "wheel" | "scratch" | "slot" | "card"
  - maxSpinsPerEntry = 5（每人最多 5 次）
  - initialSpinsOnJoin = 1（首次参与送 1 次）
  - extraSpinsPerInvite = 1（每邀请 1 人 +1 次）
  - maxExtraSpins = 4（最多额外 4 次）
```

### 4.3 秒杀/抢购

```
秒杀流程：
  用户发送：秒杀 或 /flash
  桥接插件：
    1. 获取秒杀活动详情（剩余名额、价格）
    2. 群内展示：🔥 限时秒杀！XXX Token 仅 ¥9.90，剩余 15 份
    3. 用户发送：购买 2 份
    4. 桥接调用 cf-lottery 支付接口，返回支付链接
    5. 用户支付后，cf-lottery 自动发卡
    6. 桥接查询结果，群内通知：🎉 购买成功！卡密已发送到您的订单页面

cf-lottery 侧配置：
  - activityKind = "claim"
  - participationMode = "open"
  - promotionConfig.flashSale.enabled = true
  - promotionConfig.flashSale.paymentRequired = true
  - promotionConfig.flashSale.priceCents = 990
  - promotionConfig.flashSale.stockLimit = 50
```

### 4.4 裂变拉新排行榜

```
排行榜流程：
  用户发送：排行榜 或 /rank
  桥接插件：
    1. 调用 cf-lottery 的 viral-leaderboard 接口
    2. 群内展示：
       📊 邀请排行榜
       1. 张三 - 邀请 15 人 🏆
       2. 李四 - 邀请 10 人
       3. 王五 - 邀请 8 人
       ...
       你的排名：第 5 名，邀请 6 人
    3. 每邀请 1 人可多抽 1 次（自动增加 spins）

cf-lottery 侧能力：
  - viral-weight.ts 完整的排行榜计算
  - buildViralLeaderboardRanking 函数
  - 脱敏展示（maskIdentity）
```

### 4.5 群专属活动

```
群专属活动：
  桥接为每个 QQ 群（租户）创建专属活动：
  - 活动可见性：visible=1 仅公开 slug 可访问
  - 参与限制：群成员通过 roster 白名单或 invite_code 参与
  - 活动链接：https://lottery.example.com/lottery/{slug}?ref=群专属码
  - 群外用户无法参与（roster 模式校验）

应用场景：
  - 群内专享抽奖（仅群成员可参与）
  - 群内专享秒杀（更低价格）
  - 新人入群欢迎抽奖（自动触发）
```

### 4.6 退群处罚机制

```
退群处罚流程：
  1. QQ 群检测到成员退群事件
  2. 桥接插件调用 cf-lottery 的 integration/events 接口
     POST /api/v1/integration/events
     {
       "event": "ext:member.left_group",
       "payload": {
         "account": "QQ号",
         "groupId": "QQ群号"
       }
     }
  3. cf-lottery 执行 penalty 逻辑：
     - 计算该成员波及的邀请关系（leaver + inviter + invited）
     - 记录 penalty_requested 事件
     - 入队 penalty.requested Webhook
  4. 桥接接收 Webhook：
     - 收回已发放的卡密（revoke）
     - 扣除因裂变获得的额外抽奖次数
     - 群内公告（可选）
```

### 4.7 活动预告/定时推送

```
定时推送流程（通过 cf-lottery 的 Webhook 或 Cron 触发）：
  1. 运营在 cf-lottery 管理后台创建活动，设置 startAt/endAt
  2. 活动发布时 webhook: draw.published → 桥接 → 群内推送
  3. 开奖前 1 小时 webhook: draw.reminder → 桥接 → 群内提醒
  4. 开奖完成后 webhook: draw.completed → 桥接 → 群内公布

群内消息示例：
  ⏰ 活动预告
  今天 20:00 大转盘抽奖！
  奖品：免费 Token x100 份
  点击参与：https://lottery.example.com/lottery/group-a

  🎉 开奖啦！
  活动「每日 Token 大放送」已开奖！
  中奖人数：15 人
  查看结果：https://lottery.example.com/lottery/group-a/result
```

### 5.2 技术选型

| 组件 | 方案 | 理由 |
| --- | --- | --- |
| QQ 协议适配 | **NapCatQQ** | 轻量、无头、支持 WebSocket API，可直接对接 |
| 桥接服务 | **TypeScript + Hono** | 与 cf-lottery 同栈，可复用类型定义，部署简单 |
| 部署方式 | **VPS (同 cf-lottery VPS)** | 与 cf-lottery 同一 VPS 部署，减少延迟，或独立部署 |
| 身份存储 | **cf-lottery 的 entries 表** | 不额外建库，身份即 identityValue |
| 租户配置 | **cf-lottery 的 tenants/webhookConfigs** | 每个 QQ 群一个租户 |

### 5.3 为什么不选 zhenxun_bot / NoneBot

| 理由 | 说明 |
| --- | --- |
| 经济体系冗余 | cf-lottery 已有完整的签到/抽奖/次数管理，zhenxun_bot 的金币/商店体系是多余的 |
| 额外复杂度 | zhenxun_bot 是 Python 生态，需要额外维护 Python 运行环境，与 cf-lottery (TypeScript) 跨语言 |
| 控制力 | 自研桥接插件完全控制交互逻辑，不受上游插件框架限制 |
| 部署简单 | 一个 Hono 服务 + NapCatQQ 即可，无数据库/缓存依赖 |

## 6. 玩法组合方案（产生「碰撞」）

### 6.1 签到 + 抽奖 + 裂变（基础闭环）

```
每日签到 → 得 1 次抽奖机会 → 抽奖（可能中免费 Token）
  → 免费 Token 不够用 → 邀请好友进群 → 额外抽奖机会
  → 再次抽奖 → 循环建立日活
```

**技术实现**：cf-lottery 的 checkin + instant spin + viral 三个能力零开发组合，只需配置活动参数。

### 6.2 免费 Token + 秒杀转化（变现闭环）

```
免费抽奖得 Token → 体验价值 → 免费额度用完
  → 群内秒杀推送 → 付费购买 Token
  → 晒单得优惠券 → 下次复购
```

**技术实现**：cf-lottery 的 instant spin（奖品=免费Token） + flashSale（付费Token）+ coupon codes。

### 6.3 投票决策 + 秒杀（社群共识）

```
群内投票选下一期秒杀商品/价格
  → 投票结果决定秒杀配置
  → 群成员参与决策，购买意愿更强
  → 秒杀转化率提升
```

**技术实现**：cf-lottery 的 vote 活动 + 运营根据投票结果手动调整 flashSale 配置。

### 6.4 排行榜竞赛 + 阶梯奖励（竞技闭环）

```
邀请排行榜 Top 10 → 额外抽奖机会
  → 排行榜 Top 3 → 专属奖品（稀有 Token）
  → 每周重置 → 持续竞争
```

**技术实现**：cf-lottery 的 viral leaderboard + 运营手动给 Top 发放额外奖品。

### 6.5 新人入群欢迎 + 自动抽奖（拉新闭环）

```
新人进群 → 自动发送欢迎消息
  → 赠送 1 次免费抽奖机会
  → 抽到 Token → 体验价值 → 留存
  → 邀请朋友 → 裂变继续
```

**技术实现**：NapCatQQ 监听群成员增加事件 → 桥接调用 cf-lottery 的 verify-join（自动参与）+ spin。

### 6.6 退群处罚 + 关系链保护（风控闭环）

```
成员退群 → 波及链表计算
  → 收回该成员获得的奖励
  → 扣除邀请人因该成员获得的额外次数
  → 防止「薅羊毛后跑路」
```

**技术实现**：cf-lottery 已实现的 penalty 逻辑（integration.ts L200+）。

### 6.7 多群联动 + 跨群排行榜（扩展玩法）

```
同一个租户管理多个 QQ 群
  → 跨群裂变（A 群用户分享链接到 B 群，B 群用户参与）
  → 跨群排行榜（汇总所有群的邀请数据）
  → 跨群秒杀（多个群同时抢同一批名额）
```

**技术实现**：cf-lottery 的多租户架构天然支持。一个租户可以有多个活动，分享链接跨群传播。

## 11. 附录：cf-lottery 代码关键路径摘要

### 即时抽奖热路径

```
用户点击 → public-lottery.ts POST /api/public/draws/:slug/spin
  → performInstantSpin (spin-execution.ts)
    → 幂等检查 (idempotencyKey UNIQUE)
    → CAS 扣次 (spinsLeft - 1)
    → 加权抽档 (weightedPickTier)
    → CAS 取码 (prizeCodes available → issued)
    → 写 lotterySpins + lotteryWinners
  → notifyInstantSpinWinner (异步邮件通知)
```

### 签到热路径

```
用户签到 → participation.ts joinDraw
  → identityValue 附加 :YYYY-MM-DD 后缀
  → UNIQUE(tenant, draw, identityType, identityValue) 约束防重复签到
  → 写入 lotteryEntries
```

### 秒杀支付热路径

```
用户下单 → payment-service.ts createPaymentOrder
  → CAS 扣名额 (activeParticipantCount)
  → 创建 payment_orders + payment_order_items
  → 调用支付网关
  → 回调 → CAS 发卡 (prizeCodes available → issued)
  → 更新 entry paymentStatus = paid
```
