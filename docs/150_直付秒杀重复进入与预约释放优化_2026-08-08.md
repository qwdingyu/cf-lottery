# 150 直付秒杀重复进入与预约释放优化

## 背景

继续复核秒杀码核心链路时，重点检查 `active_participant_count` 在参与、下单、超时、重试、取消之间是否闭环。

本次没有发现会导致超卖的已知路径，但发现一个影响成交恢复的语义问题：同一邮箱已经抢到直付秒杀名额后，如果再次进入活动且整场已满，服务层会先尝试活动级 CAS 预约名额，失败后返回“已抢光”。这会让已抢到名额的用户无法通过重复进入恢复已有 `entryId`，影响继续支付体验。

## 原因

直付秒杀为了避免 `COUNT(*)` 热路径，使用 `lottery_draws.active_participant_count` 做活动级 CAS 占位。原实现只特殊处理 `expired` 软释放 entry，没有在 CAS 前优先识别同一身份已经存在的 `reserved` / `pending` / `paid` entry。

因此在 `stockLimit=1` 且该用户自己已占用名额时，第二次参与会被活动级容量判断挡在“售罄”分支，而不是进入“已参与，可恢复”的分支。

## 解决方案

1. `joinDraw()` 的直付秒杀分支先查询同一身份的已有 entry。
2. 已有 entry 非 `expired` 时返回 `alreadyJoined=true` 和原 `entryId`，让公开 API 保持 409 恢复语义。
3. 已有 entry 为 `expired` 时继续走原有重新预约逻辑：先用 `active_participant_count < effectiveMax` CAS 抢回名额，再把 entry 从 `expired` 改回 `reserved`。
4. 补充支付服务测试，锁定两个计数器不变量：
   - 网关创建失败并取消订单后，entry 释放为 `expired`，计数器扣回 0。
   - 没有成功生成订单的陈旧 `reserved` 预约会被 `expireOverdueOrders()` 释放，避免孤儿预约长期占用名额。
