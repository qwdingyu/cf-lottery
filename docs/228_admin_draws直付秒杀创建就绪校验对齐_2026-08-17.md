# 228 admin/draws 直付秒杀创建就绪校验对齐

> 日期：2026-08-17

## 背景

`admin/draws` 的直付秒杀发布门禁由服务端 `publish-check` 最终决定，但创建弹窗底部的就绪提示此前只检查了是否存在奖项配置。这样会出现表单提示“已准备好”，保存草稿后才发现价格、名额、卡密奖品或组合冲突仍不满足发布条件。

## 原因

直付秒杀的前端清单已经覆盖价格、名额、支付模式、唯一可用卡密奖品和 `lottery + 直付` 冲突；创建步骤状态却重复维护了更窄的一套判断，导致两套规则漂移。

## 解决方案

- 创建步骤第 4 步直接复用直付清单的阻塞项。
- 创建底部就绪提示直接展示清单中的缺项文案。
- 仅在秒杀开关已启用且选择直付模式时启用这些检查。
- 支付渠道凭据、卡密池实际库存等服务端事实继续由 `publish-check` 最终判定，不在前端复制。

## 建议

后续新增直付发布门禁时，优先扩展 `flash-sale-readiness.ts`，再由创建步骤和底部提示复用，避免在 `AdminLotteryView.vue` 中增加第二套条件判断。
