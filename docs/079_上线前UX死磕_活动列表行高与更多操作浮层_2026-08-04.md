# 079 上线前 UX 死磕：活动列表行高与「更多」操作浮层

> 日期：2026-08-04  
> 原则：死磕用户路径；低成本；有证据；不拆巨页  
> 承接：055a 列表操作收敛；线上截图反馈（lucky.eforge.xyz/admin/draws）

---

## 一、问题（证据）

截图可见：点击「更多」后，操作面板**嵌在表格单元格内**，把该行撑到接近半屏高：

| 现象 | 原因 |
|------|------|
| 行高爆炸 | `.table-actions-more-panel` 为 `flex: 1 1 100%` 行内块，插入 tbody 流 |
| 扫描表困难 | 邻行被挤开，无法对比「示例活动」与上下行 |
| 与「更多」语义冲突 | 「更多」应是**临时菜单**，不是**行扩展详情** |
| 易被裁切 | `.table-wrap { overflow: auto }` 对 absolute 子层不友好 |

旧设计意图（055a）：行内 ≤3 + 分组面板。分组正确，**载体错误**（应用浮层而非行内展开）。

---

## 二、本轮改动

### 1. 行内只保留主路径按钮

- 仍按 status：主 CTA + 次操作 +「更多」  
- **不再**把面板 DOM 放进 `td`

### 2. Teleport 浮层菜单

- `Teleport to="body"` + `position: fixed` 锚定「更多」按钮  
- 透明 backdrop 点击关闭；Esc 关闭  
- 滚动/resize 重定位（避免悬空错位）  
- 菜单项点击：先关菜单再执行 handler（避免与 Confirm 叠层）  
- 分组保留：分享与物料 / 运营 / 危险操作  
- 项纵向全宽，易扫读；`max-height: min(70vh, 420px)` 可滚  

### 3. 操作列 CSS

- `flex-wrap: nowrap`，单行紧凑  
- 去掉 `is-expanded` 加宽行高逻辑  

---

## 三、刻意不做

- 不引入第三方 Dropdown 组件  
- 不改主 CTA 优先级（分享优先等 074 结论）  
- 不拆 AdminLotteryView 巨页（P2）  
- 不把操作列改成纯图标（文案对运营更稳）  

---

## 四、验收

```bash
npm run type-check:frontend
npm run frontend:build
```

人工（/admin/draws）：

1. 默认行高稳定，多行可平行扫读  
2. 点「更多」→ 浮层出现，**行高不变**  
3. 点菜单外 / Esc → 关闭  
4. 分享 / 数据 / 取消 等项仍可用
