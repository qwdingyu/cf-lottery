### 4.2 需要代码修改的位置

| 参数 | 改动文件 | 改动内容 |
|:-----|:---------|:---------|
| `notify_winner_email_enabled` | `lottery-service.ts:1978` | 在 `if (emailEnv?.resendApiKey)` 后增加 `&& cfg["notify_winner_email_enabled"] === "true"` |
| `rate_limit_join_per_minute` | `public-lottery.ts:375,616` | 替换硬编码 `10` 为 `readConfig("rate_limit_join_per_minute", 10)` |
| `rate_limit_events_per_minute` | `public-lottery.ts:234` | 替换硬编码 `30` 为 `readConfig("rate_limit_events_per_minute", 30)` |

| `cron_draw_batch_limit` | `index.ts:54,209` | 替换 `20` 为 `readConfig("cron_draw_batch_limit", 20)` |

### 4.3 不需要参数化的

| 项目 | 原因 |
|:-----|:-----|
| `cron_webhook_retry_attempts` (5次) | 行业标准（指数退避 1/2/4/8/16 分钟），不适合随意调整 |
| `og_fallback_origin` | 应使用 `APP_ORIGIN` 环境变量，不是 system_config |
| eventTypeLimits 逐事件限流值 | 过于细粒度，配置爆炸，现有 30/min 总限流已足够 |
| `landing_demo_slug` | Demo 页面属于产品内容，不应变成运营配置 |

## 五、实施优先级

| 优先级 | 参数 | 理由 |
|:------:|:-----|:-----|
| **P0** | `notify_winner_email_enabled` | 与已实现的营销邮件开关形成完整的"邮件三件套"闭环 |
| **P0** | `rate_limit_join_per_minute` | 直接影响用户参与体验，高频活动需要调高 |
| **P1** | `dashboard_roi_days` | 运营者可能需要看 7 天/90 天数据 |
| **P1** | `activity_default_max_participants` | 不同租户的活动规模差异大 |
| **P2** | `rate_limit_events_per_minute` | 目前 30/min 足够，可暂缓 |
| **P2** | `cron_draw_batch_limit` | 运维级参数，正常情况不需要调整 |
