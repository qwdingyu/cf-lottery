# 低成本高价值玩法与客户入口审查

> 日期：2026-08-01  
> 目标：把“玩法列表”改写成“客户能快速理解并搭建活动的入口系统”，同时保持 cf-lottery 的轻量 SaaS 定位。

---

## 一、审查结论

用户真正购买的不是单个玩法，而是“能快速把活动做对”的确定性。

因此产品应该按下面顺序组织：

1. 先给客户一个清晰入口：我要做什么活动目标。
2. 再给一套默认规则：资格、容量、去重、候补、码池、时间。
3. 再给承接动作：CTA、资料、优惠、下一活动。
4. 最后才是玩法外观：抽奖、接龙、问卷、预约等交互皮肤。

如果一开始就把产品讲成“很多玩法”，客户会理解成娱乐工具；如果把产品讲成“运营确定性”，客户会理解成活动执行工具。

---

## 二、低成本高价值优先级

### 第一梯队

| 入口 | 价值 | 原因 |
|------|------|------|
| 抽奖 | 拉新、促活、传播 | 最容易理解，最容易验证参与和结果闭环 |
| 接龙 / 报名 | 报名、占位、候补 | 直接解决活动报名和名额分配问题 |
| 资料领取 / 问卷 | 留资、调研 | 成本低，转化清楚，最适合 SaaS 早期验证 |

### 第二梯队

| 入口 | 价值 | 原因 |
|------|------|------|
| 预约 | 咨询、到店、试听 | 适合有容量和时间约束的场景 |
| 审核 / 白名单 | 内测、试用、资格控制 | 适合小范围运营和高价值权益 |
| 签到 / 打卡 | 复访、训练营、留存 | 适合周期运营，但不应先做复杂任务体系 |
| 领券 / 核销 | 导流、到店、权益兑换 | 适合与活动结果承接联动 |

### 第三梯队

| 入口 | 判断 |
|------|------|
| 投票 / 调研扩展 | 可做，但必须先控制防刷和统计口径 |
| 盲盒 / 刮刮卡 / 翻牌 / 九宫格 | 只应作为体验皮肤，不是业务主链路 |
| 复杂任务中心、积分商城、广告交易 | 暂不进入基线，太重 |

---

## 三、客户入口设计

客户首页不应该先问“你要什么玩法”，而应该先问“你要完成什么目标”。

建议首页或新建活动入口固定为：

1. 拉新促活
2. 报名收集
3. 留资下载
4. 问卷调研
5. 预约确认
6. 审核白名单
7. 福利领取

每个入口都应映射到默认的：

- `activity_kind`
- `participation_mode`
- `experience_type`
- `result_mode`
- `promotion_config`

这样客户看到的是“我该怎么开始”，而不是“我得先理解整个系统”。

模板默认值必须进入创建接口，不能只停留在 UI 展示层。尤其是 `result_mode` 和 `winner_count`：非抽奖活动不能被旧抽奖逻辑覆盖成手动开奖或 1 个中奖名额，否则“快速创建”会变成“快速创建错误活动”。

---

## 四、必须共享的底层能力

所有玩法都必须复用同一套骨架，不允许各自起炉灶：

- 活动创建与复制
- 资格校验
- 去重与容量
- 候补与结果分配
- 事件埋点
- 承接动作
- Webhook / 导出 / 外部回传
- 平台租户与用量管理

这也是 cf-lottery 能保持“小而美”的前提。

---

## 五、最重要的风险

1. 玩法越加越多，但客户仍然不知道该先建什么。
2. 前端继续把自己说成“抽奖动画平台”，而不是“活动运营工具”。
3. 新玩法一旦不复用骨架，就会把系统拖向重型营销平台。

---

## 六、落地建议

1. 首页首屏改成“3 分钟搭建可复盘的活动”。
2. 新建活动先选目标，再选玩法。
3. 模板优先于自由配置。
4. 发布前预检必须覆盖资格、容量、去重、码池、Webhook、CTA。
5. 活动发布、复制链接、二维码、海报必须全部使用公开 `public_slug`，不能把内部活动 ID 交给运营投放。
6. 抽奖、接龙、问卷只作为第一批入口，不作为产品终局。
