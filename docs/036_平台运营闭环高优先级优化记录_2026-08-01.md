# 平台运营闭环高优先级优化记录

> 文档编号：036
> 日期：2026-08-01
> 范围：平台运营后台、轻量平台权限、租户套餐/状态调整、Webhook 失败重试、问卷/投票闭环口径

## 一、顶层判断

当前最高优先级不是继续增加玩法，而是让 SaaS 平台方和租户都能把已有活动稳定运营起来：

1. 租户侧要能快速创建、发布前少出错、活动后能复盘。
2. 平台侧要能看租户、调套餐/状态、处理失败 Webhook、追溯敏感操作。
3. 问卷/投票只能在配置器、提交校验和统计口径完成后再允许正式发布；导出和高级统计可以作为后续增强。

## 二、免费层约束

本项目继续以 Cloudflare Workers Free + Turso/libSQL Free 为硬约束：

- Cloudflare Workers Free 当前公开限制包含每日请求量、10ms CPU、128MB 内存等约束，不能在公开热路径做复杂计算或大量 I/O。
- Cloudflare R2 Free 当前有 10GB-month 存储和请求操作免费额度，但图片仍必须小文件、少数量、可治理。
- Turso Free 当前有 5GB 存储、500M monthly rows read、10M monthly rows written。COUNT 的主要风险是 rows read 和响应延迟，不应误判为直接消耗 Worker CPU。

参考：
- https://developers.cloudflare.com/workers/platform/limits/
- https://developers.cloudflare.com/r2/pricing/
- https://turso.tech/pricing

## 三、本次收口原则

1. 平台敏感写操作低频发生，可以接受一次短事务。
2. 公开参与和事件上报仍是热路径，不能新增持久化高频限流或全局累计 COUNT。
3. 平台权限继续使用 RBAC-lite：`platform_owner`、`platform_operator`、`platform_support`，不引入重型权限矩阵。
4. 额度调整只做“追加”，不做隐式扣减。扣减/回收属于高风险运营动作，未来如确实需要，应单独设计接口、原因字段和二次确认。
5. `activity_submissions` 是问卷/投票/资料领取的统一提交表；问卷/投票还必须以 `activity_config` 作为配置源，不能只靠提交表上线。

## 四、已实施内容

1. 平台租户调整接口：`PATCH /api/platform/tenants/:id`
   - 仅 `platform_owner` 可用。
   - 支持调整套餐、状态、额外活动额度、额外参与额度和额度到期时间。
   - 额度字段只允许 `1..1000000` 的整数追加。
   - 空请求、非法套餐、非法状态、非法日期全部拒绝。
   - 租户更新和 `platform_audit_logs` 写入在同一事务内完成。

2. 平台成员管理审计收口
   - 平台成员新增、修改、删除均改为业务写入和平台审计同事务。
   - 删除不存在的平台成员会返回 404，避免产生误导性审计记录。

3. 平台 Webhook 失败重试
   - `platform_owner` 和 `platform_operator` 可手动重试。
   - `platform_support` 只能查看，不能触发外部请求。
   - 重试后写入独立平台审计。

4. 问卷/投票口径修正
   - 问卷/投票缺少有效 `activity_config` 时继续阻断发布。
   - 有效问卷字段和投票选项配置可通过发布闸门。
   - 投票统计必须按 `activity_submissions.payload_json.optionId` 聚合，不再使用参与者邮箱 `identity_value`。

## 五、测试覆盖

新增和加固的回归点：

1. 平台 owner 可调整租户套餐/状态/额外额度。
2. 额外额度按追加累计。
3. 租户调整写入独立平台审计。
4. operator/support 不能调整租户。
5. 非法套餐、状态、额度、日期和空请求被拒绝。
6. Webhook 手动重试会 mock 外部请求并校验投递状态、尝试次数和平台审计。

## 六、仍未完成的高优先级事项

1. 问卷提交运营增强：后台 submissions 人性化展示、分页 CSV 导出、字段级基础统计。
2. 投票运营增强：后台结果展示、公开结果开关、多选投票另行设计后再启用。
3. 平台异常汇总：失败 Webhook、接近额度租户、连续错误租户的轻量列表。
4. R2 媒体资产治理：`media_assets` 表、租户图片数量/容量上限、生命周期策略验证。
5. 租户侧漏斗看板测试：浏览、开始、完成、CTA、分享、外部转化的数据口径回归。

## 七、后续开发警戒线

不要为了“看起来玩法多”跳过配置器、预检、统计和承接闭环。抽奖、接龙、问卷、投票只是入口；SaaS 客户真正购买的是快速创建、少出错、能复盘、能承接、能接系统、能托管运营。
