## 一、本轮修复 1：webhookOrigin 测试受 dev 环境 .env 污染

### 现象
`admin-lottery-platform.test.ts` 的「缺少 webhookOrigin 且无 APP_ORIGIN 环境变量时返回错误」
用例在本地全量跑时失败，但 CI 干净环境可能通过——**环境相关的不稳定测试**。

### 根因
- 该用例发送 `POST { }`（无 webhookOrigin），期望路由返回 400「无法确定 webhook URL」
- 但 `register-telegram-webhook` 路由的 origin 解析链是：
  `body.webhookOrigin → getEnv(c, "APP_ORIGIN") → c.req.header("Origin")`
- `getEnv` 在 Node 下回退 `process.env`（src/lib/platform.ts:63-64）
- 本地 shell `source .env` 后 `process.env.APP_ORIGIN = "https://lucky.eforge.xyz"` 被测试进程继承
  → origin 非空 → 路由继续调用 Telegram `setWebhook` → fetch mock 未打桩 → 返回「Unauthorized」

### 修复
在用例内显式清除 `process.env.APP_ORIGIN`，断言后恢复原值：
```typescript
const savedOrigin = process.env.APP_ORIGIN;
delete process.env.APP_ORIGIN;
// ... 发送请求、断言 ...
if (savedOrigin !== undefined) process.env.APP_ORIGIN = savedOrigin;
```

### 验证
- `admin-lottery-platform.test.ts`：44/44 通过
- 全量 `vitest run`：**85 files / 1166 tests，0 失败**（此前 1154+1fail）
- `tsc --noEmit` 0 errors；`vue-tsc -b` 0 errors

### 建议
测试环境不应依赖宿主 shell 的 .env 导出。后续可在 vitest.config.ts 的 `beforeAll`
中统一清除/隔离非白名单环境变量，避免同类问题再次出现。

## 二、本轮修复 2：platform-system-config.ts 使用 c.env 直接读取 env 变量

### 现象
`platform-system-config.ts` 的 `GET /` 和 `POST /email-test` 路由使用 `c.env` 直接读取
环境变量，而非 `getEnv` 辅助函数。在 Node standalone 模式（VPS 生产形态）下，`c.env` 为空
对象 `{}`，导致 `CREDENTIALS_ENCRYPTION_KEY` 和 `RESEND_API_KEY` 永远为 `undefined`。

### 根因
- `GET /`（line 43）：`c.env?.CREDENTIALS_ENCRYPTION_KEY` → 始终 undefined
  → 敏感配置项无法解密，前端看到的值为密文
- `POST /email-test`（line 230）：`c.env.RESEND_API_KEY` → 始终 undefined
  → 即使 server.ts 中 process.env.RESEND_API_KEY 已配置，仍返回 500「未配置」

### 修复
两处均改为 `getEnv(c, "KEY")`，与 `index.ts` 中 DB 中间件、`payment.ts` 等的做法一致。

- `tsc --noEmit`：0 errors

- `platform-rbac.test.ts`、`platform-telegram.test.ts`、`platform-qq.test.ts`：69/69 通过
- `payment.test.ts`：11/11 通过
