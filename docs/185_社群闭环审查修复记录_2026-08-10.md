# 社群与促销闭环审查修复记录

## 背景

2026-08-10 对 QQ 群、Telegram 群、签到、抽奖、发卡、导流、支付、秒杀和外部成交链路进行代码级审查，发现跨平台卡密查询、Telegram webhook 阻塞、平台投递并发重复和 VPS 调度配置等问题。

## 本次修复

1. 跨平台卡密访问改为多个平台身份 OR 匹配，并要求一次性访问令牌绑定 `drawId`。
2. 拒绝旧的空 `drawId` 卡密访问令牌，避免跨租户返回用户全部卡密。
3. Telegram 私聊消息改为写入 `platform_deliveries`，由维护任务异步发送，避免 webhook 同步等待 Bot API 重试。
4. 平台出站投递增加 `processing` 领取状态；超过 10 分钟的陈旧记录可重新领取，减少并发维护任务重复发送和进程崩溃后的永久卡死。
5. 平台目标创建时先检查重复目标，再检查套餐配额，返回更准确的业务错误。
6. VPS 部署包加入 systemd maintenance timer，远端部署脚本会安装并启用 `cf-lottery-maintenance.timer`，默认每 5 分钟触发 `/api/cron/maintenance`。

## 验证

- 需要继续运行根目录 TypeScript 检查、前端模板类型检查和完整 Vitest。

## 剩余风险

- Telegram `botToken` 仍需要迁移到租户级加密存储并在管理端脱敏返回。
- 使用仅上传模式的 `local-deploy-vps.sh` 后，仍需在服务器上按脚本提示安装并启用 systemd timer；全自动远端部署脚本已覆盖该步骤。
- `processing` 领取状态依赖超时回收；后续可增加显式 lease 字段和 worker 令牌。
- 邮件通知仍是异步 fire-and-forget，尚无独立邮件投递队列。
