# Admin Draws 创建表单紧凑布局与输入边界规范

日期：2026-08-15
适用范围：`/admin/draws` 活动创建与草稿编辑页
关联基线：`docs/222_秒杀与批发活动定义及全链路流程基线_2026-08-14.md`、`docs/225_大量活动与奖品下的后台信息架构规范_2026-08-15.md`

## 1. 目标与边界

本规范只约束管理端信息呈现、输入边界和响应式布局，不改变活动类型、参与模式、体验类型、秒杀销售模式、奖品绑定及发布校验的业务规则。

布局优化必须服务于以下原则：

1. 同一决策层的字段可同时比较，避免无意义的纵向留白。
2. 有依赖关系或需要阅读说明的字段不得为了“一行”而挤压、遮挡或省略。
3. 小屏优先保证可读和可操作；桌面端才使用多列紧凑布局。
4. 前端提示是辅助，服务端校验和发布预检仍是最终权威。

## 2. 固定布局规则

### 2.1 主路径决策区

“活动类型”“参与模式”“当前体验”在桌面宽度下为同一行：

```text
活动类型 | 参与模式 | 当前体验（只读摘要 + 更改入口）
```

三者分别描述活动是什么、谁能参加、用户看到什么交互，彼此不可互相推导，必须同时可见。窄屏或可用宽度不足时，自动退化为两列或单列，不得横向溢出。

条件字段，例如密码、名单、邀请码数量，必须独占后续完整行，不与上述三个稳定维度抢占空间。

### 2.2 秒杀配置区

在秒杀启用后，以下字段按业务组紧凑排列：

```text
CTA 文案 | 可售件数 | 每人限购（仅直付）
价格     | 币种     | 支付订单标题（仅直付）
```

销售模式、直付发布清单、阶梯价格、最终生效预览和展示开关各自保持独立完整行。原因是这些内容承担解释、风险提示或多项配置职责，不能被压缩到输入行中。

“显示倒计时”“显示已抢进度”“显示剩余名额”必须在同一可换行组内，不得逐项独占一行。

### 2.3 奖项配置

奖项表头与每个奖项行必须使用同一组网格列：

```text
奖品 | 奖项名称 | 中奖份数 | 权重（即时结果） | 相对命中倾向（即时结果） | 删除
```

奖品摘要可能包含价值、剩余卡密、停用状态，因此该列可以自然增高；其余输入列必须从同一行顶部对齐，不能受奖品摘要的内部布局影响。

小屏隐藏表头并退化为两列网格；奖品选择与概率摘要独占整行，其余输入仍保持固定列宽，删除按钮保持可触达。

## 3. 奖品选择器规则

奖品选择器通过服务端搜索和分页获取候选项，避免奖品量大时使用全量原生下拉框。直付秒杀场景只查询卡密奖品，并携带当前活动标识请求卡密池占用状态。

当候选卡密池已被其他进行中的直付活动占用时：

1. 该候选项必须禁用，前端不得绕过或改为可选。
2. 禁用项必须保留名称、库存和“卡密池被占用”的可读提示。
3. 禁用态使用明确的风险色背景和完整文本对比度，不能因透明度过低而被误判为接口失败或页面不可操作。
4. 选择器浮层必须使用管理端主题 token，不得回退为浅色面板。

此限制用于避免两个进行中直付活动竞争同一批卡密。服务端发布预检仍是最终校验。

## 4. 权重输入边界

即时结果活动的奖项权重固定为整数区间 `[0, 100000]`：

1. `0` 表示该档暂不进入随机分配，不能被前端静默改为 `1`。
2. 非整数保存时向下取整。
3. 负数、非数字归一化为 `0`。
4. 大于 `100000` 的值归一化为 `100000`。
5. 概率展示必须使用同一上限，避免“页面显示的相对比例”与“实际保存的权重”不一致。

`100000` 是既有服务端奖项保存接口的硬边界；前端不得自行缩小该范围。任何未来调整必须同时修改服务端校验、前端输入约束、概率计算及对应测试。

## 5. 底部操作栏

创建页底部固定操作栏采用三列结构：

```text
创建就绪提示（可换行） | 取消 | 保存草稿
```

提示文本占据可伸缩列；“取消”和“保存草稿”保持稳定按钮宽度。小屏下提示独占首行，两个操作按钮等宽并排，避免文本将操作按钮挤出可视区。

## 6. 验收清单

1. 桌面端活动类型、参与模式、当前体验在同一行，内容不重叠。
2. 秒杀的基础销量组和直付支付组在宽屏同排，窄屏自动换行。
3. 三个展示开关在同一可换行组中。
4. 即时奖项的中奖份数、权重和概率列与表头一致对齐。
5. 权重输入不能通过前端保存为大于 `100000` 的值，概率展示同步受该上限约束。
6. 奖品选择器与管理端深色主题一致；直付冲突奖品可读但不可点击。
7. 移动端无横向滚动、无重叠，底部取消和保存草稿按钮均可点击。
8. 本规范不改变 `docs/222` 定义的秒杀/批发订单、库存、限购、支付和履约规则。
