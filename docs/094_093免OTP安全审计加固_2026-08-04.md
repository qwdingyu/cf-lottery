# 094 093 免 OTP 安全审计与加固

日期：2026-08-04  
触发：用户要求对 093（已登录公开参与免 OTP / 转盘反馈）做灾难级复查。

## 1. 审计范围

| 面 | 结论 |
| --- | --- |
| JWT 签发路径（login / verify-email / switch-tenant / create-tenant / impersonate / cf-auth） | 均含 `email` claim；旧 token 无 claim 时前端 `/admin/me` 兜底 |
| 前端 hydrate / handleJoin | **曾**可能用陈旧 `sessionEmail` 压过 JWT.email → body/JWT 不一致 → 免 OTP 失败（可用性，非越权） |
| verify-join 后端授信 | **曾** `payload.email === body.email` 大小写敏感，与 my-result 不一致 |
| my-result | 已 toLowerCase 对齐；邮箱不一致不授信 |
| registered 模式 | 仍以 `sub` 为 user_id；残留 OTP 不能绕过登录 |
| 转盘 | loading idle ≠ 开奖；celebrateKey 仅成功后；不伪造中奖扇区 |
| 活动页退出 | 只清参与 session，保留 `admin_token`（有意设计） |

## 2. 灾难面评估（修前）

| 风险 | 严重度 | 说明 |
| --- | --- | --- |
| 伪造前端 JWT 免 OTP | **无** | 免 OTP 只在服务端 `verifyJwt` 通过后 |
| 拿 A 的 token 以 B 邮箱参与 | **无** | email 不一致不授信，无码 → 400 |
| 无 email claim 仅凭 sub 代 open 邮箱身份 | **无** | open 必须 claim.email 匹配 body |
| MixedCase claim 导致合法用户免 OTP 失败 | **中（可用性）** | 已修：与 my-result 同 toLowerCase |
| 陈旧 sessionEmail 压过 JWT | **中（可用性/错身份请求）** | 已修：`resolveOpenJoinEmail` JWT 优先 |
| 管理员预览他人 open 活动自动以己邮箱入池 | **低（产品）** | 有意：已登录身份参与；可用活动页「退出」清参与轨再 OTP |
| switch-tenant 后参与轨仍旧 token | **低** | hydrate 不覆盖已有 `lottery_registered_token`；同用户 email 通常不变；registered 身份为 sub 仍正确 |
| password/invite 被免 OTP 跳过凭证 | **无** | 前端 `missingJoinCredentialForMode` 仍弹窗；后端仍校验密码/邀请码 |

## 3. 本波加固

1. **`verify-join`**：`tokenEmail = String(payload.email).trim().toLowerCase()` 再与 body 比。  
2. **`resolveOpenJoinEmail`**：JWT.email > hint > sessionEmail。  
3. **hydrate**：已有参与 token 时用 JWT.email **纠偏**陈旧 `lottery_session_email`。  
4. **`buildCfAuthVerifyJoinBody`**：email 写入前 toLowerCase。  
5. **回归测试**：大小写免 OTP、不一致不授信、无 claim 不授信、前端 resolve/hydrate 纠偏。

## 5. 残留（非阻塞）

- 切租户后若不刷新参与页，sessionStorage 可能仍是切前 JWT；同用户 email 不变，open 免 OTP 仍正确；若需强制对齐 admin 新 token，可后续在 switch-tenant 成功时同步清/重写参与轨。  
- 旧无 email claim 的 JWT 仍依赖 `/admin/me`；登录签发已含 email，自然衰减。
