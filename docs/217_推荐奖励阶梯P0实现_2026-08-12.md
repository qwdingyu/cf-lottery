# 推荐奖励阶梯 P0 实现（docs/217）

## 概述

P0 实现推荐奖励阶梯（referral reward ladder），在现有 per-invite 单次邀请加次（`grantViralSpinsToSharer`）基础上，增加**里程碑式一次性奖励**：邀请人数跨过 requireCount 门槛时，发放一次性 bonus_spin 奖励。

> 与 per-invite 线性激励互补：per-invite 每邀固定 +k，受 maxExtra 双封顶；里程碑制造「再邀 N 人就达标」的临界激励。

## 配置格式

`promotion_config` JSON 新增 `referralRewards` 数组：

```json
{
  "viral": { "enabled": true, "extraSpinsPerInvite": 1, "maxExtraSpins": 10 },
  "referralRewards": [
    { "requireCount": 1, "rewardType": "bonus_spin", "rewardValue": 2 },
    { "requireCount": 3, "rewardType": "bonus_spin", "rewardValue": 5 },
    { "requireCount": 5, "rewardType": "bonus_spin", "rewardValue": 10 }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `requireCount` | number | 邀请人数达到该值时触发（≥1，浮点向下取整） |
| `rewardType` | string | P0 仅支持 `"bonus_spin"`，未知类型静默剔除 |
| `rewardValue` | number | 奖励数值（bonus_spin 为额外 spins 次数，≥1） |

### 限制

- **仅 instant 模式生效**（`result_mode=instant`，`maxSpinsPerEntry ≥ 1`）
- delayed 模式无 spins 体系，阶梯奖励暂不生效（defer 到 P1）
- 同 `requireCount` 去重：首个生效，后续忽略
- 不依赖 `viral.enabled`：`referralRewards` 作为独立激励通道，可独立运行

## 数据流

```
joinDraw(refCode)
  → recordAttributedJoin()
    → shareRecords.joinedCount++ (原子 SQL UPDATE)
    → activityEvents 写入 attributed_join
    → 返回 { attributed, shareRecordId, sharerEntryId }
  → maybeTriggerReward()
    → grantViralSpinsToSharer()  // 现有 per-invite 加次（双封顶）
    → processReferralMilestoneRewards()  // [NEW] 阶梯加次
    → triggerRewardEarned()  // 现有 webhook
```

## 幂等性

`shareRecords.reward_milestones_granted` 列存储已发放的 requireCount 数组（JSON）：

- 每次 join 时，读取 `joinedCount` + 已发放列表
- 计算 `evaluateReferralMilestones()`：`joinedCount ≥ requireCount` 且未发放 → 发放
- CAS UPDATE `lottery_entries`（`WHERE spinsTotalGranted = old`）防并发重放
- 同事务写入 `shareRecords.reward_milestones_granted = newGrantedList`
- 如果 CAS 失败（rowsAffected=0），放弃本次发放，下次 join 自动重试

## 与现有边界的交互

### spinsViralEarned

阶梯奖励**不更新** `spinsViralEarned` 字段，只更新 `spinsTotalGranted` + `spinsLeft`。原因：

- `spinsViralEarned` 的语义是"因有效邀请累计加到 granted 的部分（≤ maxExtraSpins）"
- 阶梯 requireCount 集合有限（不存在无限刷次风险），无需受 maxExtra 双封顶约束
- 后续 per-invite 的 `computeViralSpinGrant` 仍按 `roomViral = max(0, maxExtra - viralEarned)` 正确运行

### maxSpinsPerEntry

阶梯总额仍受 `maxSpinsPerEntry` 总顶约束：`actual = min(totalBonus, maxSpins - granted)`。

### 并发

同一事件同事务内，`grantViralSpinsToSharer` 先执行（per-invite），然后执行 `processReferralMilestoneRewards`。SQLite 串行化写事务 + CAS 确保原子性。

## 测试覆盖

### 纯函数测试（spin-quota.test.ts）

- `normalizeReferralRewards`：非数组/空数组、非法过滤、排序去重、浮点取整
- `parseGrantedMilestones`：空/非法解析、合法数组去重过滤
- `evaluateReferralMilestones`：未达门槛、单门槛、多门槛、已发放不重发、非法 granted 过滤

### 集成测试（lottery-service.test.ts）

- 完整流程：创建活动 → publish → 分享者 join → 创建 share record → 多次邀请
- 验证：per-invite 与 milestone 独立计算、milestone 不占用 viral 预算
- 验证：幂等性（重复参与不加次、不重发里程碑）
- 验证：milestone 超过 maxExtra 后仍能发放（里程碑不受 maxExtra 误伤）
- 验证：spinsLog 每条 milestone 发放有 `refId: "milestone:{requireCount}"`
