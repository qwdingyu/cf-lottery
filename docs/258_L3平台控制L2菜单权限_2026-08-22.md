# L3 平台运营控制 L2 菜单权限（docs/258）

日期：2026-08-22
编号：docs/258
关联：docs/255（终审）、docs/026 §5.4（权限不用数据库矩阵，代码常量表达）

## 背景

L3 平台运营者需要在平台后台全局控制 L2 租户管理员的菜单可见性（如关闭"支付配置"、
"集成设置"等菜单）。此前 L2 的 12 个菜单全部前端硬编码，无任何权限控制入口。

用户明确要求：
1. **全局生效**：对所有 L2 租户统一生效，不做按租户区分（功能简单）。
2. **L3 入口逻辑不变**：`/platform/*` 的 L3 访问控制（platform_members 角色矩阵 +
   AdminLayout"平台运营"入口的 isPlatformMember 判断）保持原样，不受本功能影响。

## 方案（复用现有基础设施，无新表）

### 数据模型
- `system_config.disabled_l2_menus`：JSON 数组，默认空（`[]` = 全部启用）。
- **不注册进 system-config-definitions.json**：避免 `/platform/config` 通用配置页
  出现第二个编辑入口（P1-2 双配置入口收敛教训）。
- 读写走 `getSystemConfigStoredValue` / `upsertSystemConfig`（服务层不依赖注册表）。

### 菜单目录常量
- 后端：`src/lib/l2-menu-keys.ts`
  - `L2_MENU_CATALOG`：12 项（AdminDashboard/AdminLottery/AdminPrizes/AdminBrand/
    AdminPaymentConfig/AdminPaymentOrders/AdminQuotaRedeem/AdminIntegrations/
    AdminPlatformTarget/AdminMembers/AdminBlacklist/AdminLogs）+ 中文标签
  - `resolveL2MenuKeyByPath`：L2 API 路径 → 菜单 key（剥离 /api/admin 前缀后按
    最长前缀匹配；/me、/dashboard 等基础设施路径无映射，天然豁免）
  - `readDisabledL2Menus` / `parseDisabledL2Menus`：读取 + 白名单过滤
- 前端：`frontend/src/views/admin/lottery/menu-keys.ts`（镜像 + `filterL2MenusByDisabled`）
- **一致性锁**：`menu-keys.test.ts` 读取后端源码提取 CATALOG 字面量比对，防命名漂移。

### 后端 API（`src/routes/platform.ts`）
| 端点 | 权限 | 说明 |
|------|------|------|
| `GET /api/platform/l2-menus` | owner/operator/support | 返回 menuCatalog + disabledMenus |
| `PATCH /api/platform/l2-menus` | 仅 owner | body `{ disabledMenus: string[] }`；白名单校验非法 key 400；审计 `platform.l2.menus.update` |

### 后端强制（安全边界，docs/024 R-005：菜单隐藏不是安全边界）
- 独立中间件 `requireL2MenuEnabled`（admin-lottery-helpers.ts）：
  命中禁用菜单的路径一律 403（不区分 GET/写）。
- 挂载点：
  - `adminLotteryRoute.use("*", ...)`（admin-lottery.ts）——覆盖 draws/prizes/members 等子模块
  - `adminPaymentConfigRoute.use("*", ...)`（admin-payment-config.ts）——**独立挂载于
    /api/admin 的路由必须单独挂**，否则禁用"支付配置"不生效（审查中发现的关键缺口）
- `GET /api/admin/me` 返回 `menuDisabled`（前端过滤数据源，与中间件共用同一读取函数）。

### 前端
- L3：`PlatformLayout` 新增菜单项"L2 菜单权限"→ `PlatformL2MenusView.vue`
  （12 个开关，勾选 = 禁用；保存 PATCH + 审计；i18n zh/en）。
- L2：`AdminLayout` 的 menuItems computed 按 `menuDisabled` 过滤（onMounted 拉取
  `/api/admin/me`，失败静默——后端 403 兜底）。
- **"平台运营"L3 入口是独立 RouterLink（isPlatformMember 控制），不在 12 项过滤范围内**，
  L3 权限判断逻辑保持原样。

## 测试

- `platform-rbac.test.ts` 新增 6 用例：
  1. 非平台成员访问 l2-menus → 403
  2. owner 读取目录 + 禁用列表（目录 key 白名单校验）
  3. owner 保存禁用菜单 + 审计留痕 + 读回
  4. 非法 key → 400
  5. **禁用后 L2 访问对应 API → 403（payment-config 独立路由也拦截）；未禁用正常；
     /me 基础设施豁免**
  6. L2 /me 返回 menuDisabled
- `menu-keys.test.ts` 4 用例：前后端目录镜像一致、无重复 key、过滤正确、空列表默认全开。

## 关键决策记录

1. **全局而非按租户**：用户明确"针对所有用户生效，不做特定用户"，放弃
   tenant_menu_overrides 1:1 覆写表方案，用全局 system_config（简单、无迁移）。
2. **黑名单（默认全开）**：disabled 列表为空 = 全部启用。若默认全关会破坏存量租户，
   风险不可接受。
3. **独立中间件而非塞进 requireTenantRouteCapability**：审查发现 adminPaymentConfigRoute
   独立挂载，不走能力门禁链；独立中间件可同时挂多路由，覆盖完整。
4. **不注册 definitions**：避免 /platform/config 出现第二入口（P1-2 教训）。
