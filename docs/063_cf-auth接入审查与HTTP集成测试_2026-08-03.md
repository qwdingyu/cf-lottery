## 四、上线清单（必须按序，避免灾难）

1. **Turso/库**：`npm run db:migrate` 含 `0025_auth_identities`。  
2. **Secrets/vars**（Worker）：`CF_AUTH_ENABLED=true`、`CF_AUTH_ISSUER=https://auth.eforge.xyz`（与 discovery 的 host 一致；路径由 RP 拼 `/api/auth/oauth2/*`）、`CLIENT_ID/SECRET`、`REDIRECT_URI=https://lucky.eforge.xyz/auth/callback`。  
3. **cf-auth 控制台**：登记同 redirect、client；TRUSTED_ORIGINS 已含 lucky/auth。  
4. **部署** 含 062/063 的 Worker；部署后验证：

```bash
curl -sS https://lucky.eforge.xyz/api/auth/cf-auth/meta
# 期望 JSON：{"ok":true,"enabled":true,...} 且 content-type application/json
# 若仍是 HTML：检查 wrangler assets.run_worker_first 与是否旧版本
```

5. 人工：管理端「统一认证」→ 回调 → onboarding → create-tenant → `/admin`。  
6. 旧 JWT（sub=裸 IdP sub）作废：重新 OAuth 一次。
