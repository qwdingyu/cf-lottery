## 2. 本轮发现并已修复（P0）

### P0-A 安慰券跨活动串场（安全/正确性）

**证据：** `public-lottery.ts` `my-result` 查 `coupon_codes` 仅 `tenantId + recipientEmail`，**未** `drawId`。  
发放侧 `draw-execution` 写入时带 `drawId`。同租户用户参加多场时，A 场查结果可能返回 B 场安慰券码。

**修复：** `where` 增加 `eq(couponCodes.drawId, draw.id)`。  
**测试：** `auth-and-public.test.ts`「my-result 安慰券仅返回本活动…」。

### P0-B 分享 API 不校验 entry 归属（完整性）

**证据：** `POST /public/draws/:slug/share` 直接 `insert share_records`，`sharerEntryId = body.entryId`，无「entry ∈ 本 draw」校验。  
任意 UUID 可污染裂变表；跨活动 entry 可挂到错误 draw。

**修复：** 插入前 `lottery_entries` 按 `id + drawId + tenantId` 校验，失败 404。  
**测试：** 「share：entry 不属于本活动则 404…」。

### P0-C 模板仍用 `myJoinedById[draw.id]` 未统一 `isDrawJoined`

**证据：** 098 在 `handleJoin` / `statusPathHint` 用了 id+slug 双键，但标签、问卷区、游戏 disabled、底部已参与条仍只看 `draw.id`。  
若 map 仅有 slug 键，UI 可能仍显示可参与。

**修复：** 模板四处改为 `isDrawJoined(draw)`。

### P0-D JWT 明确未参与时不清理脏 hints

**证据：** `hydrateJoinedStateFromSession` 在 `joined === false && hintHit` 分支为空注释，假灰钮可残留。

**修复：** `removeJoinedHintsForKeys` + 清 `myJoinedById` / `myWonById` / 本条 `myEntryList`；服务端 `won=false` 时清本机 won 标签。
