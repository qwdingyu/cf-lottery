---

## 一、结论先行

cf-lottery **后端骨架已搭建**（SaaS 底座 + 数据模型 + 基础路由），但存在**严重质量问题**：

1. **`lottery-service.ts` 未剥离 cf-shop 依赖**——仍引用 `orders`、`products`、`cards` 表，这是 084 文档明确禁止的行为
2. **`shared/` 目录残留 cf-shop 电商文件**——应清理
3. **`bindings.ts` 残留 cf-shop 电商配置**——应清理
4. **关键路由缺失**——暂停/开奖/导出/退出/当前用户等
5. **前端完全空白**——`frontend/src/` 为空
6. **无测试**——零覆盖率
7. **密码存储需要兼顾 Workers Free CPU 限制**——免费层不能在登录/注册热路径使用高迭代 PBKDF2、bcrypt、Argon2

### 2.4 服务层 🔴 严重问题

**`lottery-service.ts`（1277行）核心问题：**

1. 引用 `orders`、`orderItems`、`cards`、`products` 表（cf-shop 电商表，lottery 不含）
2. 引用 `getProduct`、`fulfillCardInventory`、`createOrderNo`、`createOrderToken` 等 cf-shop 服务
3. 引用 `getAvailableStockMap`、`writeOrderEvent`、`minorToMajorString` 等 cf-shop 工具
4. 引用 `RuntimeConfig` 类型（cf-shop 专属）
5. 开奖逻辑绑定到"创建 0 元 lottery 订单 + 发卡"模式
6. 活动创建绑定到"选择商品"模式（不是选择奖品）

**084 文档要求：** 奖品不是商品，奖品库存不是电商库存。中奖发奖只产生 `winner` 和 `prize_code` 状态，不产生支付订单。

**正确做法：** 重写 `lottery-service.ts`，使其：
- 只操作 `lottery_draws`、`lottery_entries`、`lottery_winners`、`prizes`、`prize_codes` 表
- 开奖 = 从 `lottery_entries` 随机抽取 → 锁定 `prize_codes` → 写入 `lottery_winners`
- 不涉及 `orders`、`products`、`cards` 等电商概念
