## 二、错误处理一致性

### 2.1 问题：同一场景不同端点返回不同状态码

| 场景 | 端点 A | 端点 B | 不一致 |
|:-----|:-------|:-------|:------:|
| 活动不存在 | 404 | 404 | ✅ |
| 活动未开放 | 404 | 400 | ❌ `GET /draws/:slug` 返回 404，`POST /verify-join` 返回 400 |
| 容量已满 | 400 | 400 | ✅ |
| 已参与 | 409 | 409 | ✅ |
| 限流触发 | 429 | 429 | ✅ |

**建议：** `活动未开放` 统一返回 400 + 明确 message（"活动未开启"/"活动已结束"），不混用 404。

### 2.2 问题：错误消息不统一

```
fail(c, "活动不存在", 404)      // 简洁
fail(c, "活动未开放", 404)      // 简洁
fail(c, "您已参与此活动", 409)  // 带"您"
fail(c, "请求过于频繁，请稍后再试", 429)  // 解释原因+建议
```

**建议：** 统一风格为 `"原因 + 建议"` 格式（如第 4 种）。

## 三、SQL 注入风险审查

### 3.1 生产代码中的 raw SQL

| 文件 | 行号 | 代码 | 风险 |
|:-----|:----:|:-----|:----:|
| `lottery-service.ts` | 1402 | `tx.run(sql\`INSERT INTO ... VALUES (${entryId}, ${draw.tenantId}...)`)` | ✅ 参数通过 drizzle `sql` 模板安全传递 |

**结论：无 SQL 注入风险。** 所有 raw SQL 均通过 drizzle-orm 的 `sql\`\`` 模板传递参数，底层使用参数化查询。测试文件中的 `client.execute()` 也使用 `args: []` 参数化。

### 3.2 XSS 风险

| 文件 | 行号 | 代码 | 风险 |
|:-----|:----:|:-----|:----:|
| AdminLayout.vue | 19 | `v-html="item.icon"` | ✅ 图标来自路由配置，硬编码 emoji |
| PlatformLayout.vue | 7 | `v-html="item.icon"` | ✅ 同上 |
| LotteryView.vue | 543 | `getResultCta(...).title` 直接渲染 | ⚠️ title 来自运营者配置的 promotionConfig，应做 HTML 转义 |

**建议：** LotteryView.vue 中 `getResultCta().title` 添加 XSS 防护（`{{ }}` 已做 HTML 转义，但 URL 应校验白名单协议）。

### 3.3 promotionConfig URL 校验

`publish-check-service.ts` 中 `isSafeHttpUrl()` 已校验 destination.url 只能为 http/https。但 **ctas.after_win.url 和 ctas.after_loss.url 未纳入校验**。
