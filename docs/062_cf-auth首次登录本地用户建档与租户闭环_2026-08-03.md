# 062 cf-auth 首次登录：本地用户建档与租户闭环

> 日期：2026-08-03  
> 前置：docs/059（OAuth RP）、docs/061（移除 Logto）、docs/045（方案 C 不自动建租户）

---

## 一、问题（删 Logto 后暴露的真实断点）

| 断点 | 后果 |
|------|------|
| exchange 把 **IdP `sub`** 直接写入 JWT.`sub` | 本地 `users` 无此行 |
| `POST /auth/create-tenant` 只信 JWT.`sub` 写 `tenant_members.user_id` | onboarding 创建租户后成员关系悬空 / 后续权限异常 |
| 无 identity 绑定表 | 无法稳定把「同一 cf-auth 用户」映射到「同一 lottery 用户」 |

**不做自动建租户**（045）：OAuth 用户与邮箱注册一样，`needsTenant` 时走 onboarding。

---

## 二、设计（保守、可回滚）

```text
cf-auth userinfo (sub, email)
        │
        ▼
provisionIdpUser(db)
  1. auth_identities(provider, provider_user_id) 已存在 → 用其 user_id
  2. 否则：email 命中 **email_verified=1** 的 users → 链接 identity（防未验证邮箱接管）
  3. 否则：新建 users（password_hash=oauth 占位，不可密码登录）+ identity
  4. 查 tenant_members → tenantId / needsTenant
        │
        ▼
JWT.sub = 本地 users.id
JWT.idpSub = 上游 sub（审计）
JWT.tenantId = 已有则带，否则 ""
        │
        ▼
needsTenant → /admin/onboarding → create-tenant（现有接口，无需改 FK）
```

### 明确不做（防灾难）

- **不**仅凭未验证 email 合并账号  
- **不**在 exchange 时静默创建租户  
- **不**把上游 sub 继续当业务主键  
- **不**改密码登录 / 邮箱 OTP 主路径  
- **不**自动把 OAuth 用户设成可密码登录  

### 并发注意

同一 `(provider, idp_sub)` 并发 exchange：后到者在 `auth_identities` 唯一冲突后**重读**已有绑定；若本轮已插入孤儿 `users`，会尽力删除后再返回胜者 `userId`。

### 同邮箱已验证账号

若运营者先用邮箱注册并验证，再用同一邮箱走 cf-auth：  
**链接到同一 `users.id`**，保留已有租户 membership → `needsTenant=false`。

## 四、运维

1. 部署前执行迁移：`npm run db:migrate`（含 `0025`）。  
2. 生产 `CF_AUTH_*` 指向 `https://auth.eforge.xyz`（或实际 issuer）。  
3. 旧会话若 JWT.`sub` 仍是裸 IdP sub：让用户重新走一次 OAuth 即可换新 token。
