# cf-lottery SaaS 多租户抽奖平台顶层设计方案

> 文档编号：005
> 创建时间：2026-07-31
> 版本：v1.0
> 状态：专家顾问评审版
> 适用范围：cf-lottery 产品架构、数据模型、API 设计、运营策略

---

## 一、结论先行

**cf-lottery 定位为轻量、多租户、自助服务的抽奖 SaaS 平台。** 核心设计原则：

1. **租户自助闭环**——客户注册即用，创建活动→配置奖品→发布→开奖→通知→导出，全程无需平台管理员介入
2. **多租户硬隔离**——所有业务数据按 `tenant_id` 隔离，一个租户完全看不到另一个租户的数据
3. **参与模式组合化**——不预设固定模式，而是将参与条件（公开/名单/密码/邀请码）和开奖方式（手动/定时）作为独立配置项，运营者自由组合
4. **奖品模式插件化**——支持卡密/手动发放/数字链接/实物奖品，且可扩展
5. **公平性可验证**——开奖使用 CSPRNG + Fisher-Yates 洗牌，记录随机种子 hash，事后可验证

## 二、顶层架构设计

### 2.1 多租户模型

```
┌─────────────────────────────────────────────────────────────────┐
│                       平台层（Platform）                         │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────────────────┐ │
│  │ 平台 Owner  │  │ 平台 Support │  │ 系统配置/风控/套餐管理  │ │
│  └─────────────┘  └──────────────┘  └────────────────────────┘ │
├─────────────────────────────────────────────────────────────────┤
│                       租户层（Tenant）                           │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │ 租户 A (企业 HR)    │  租户 B (社群运营)  │  租户 C (博主)  │ │
│  │  ├ 活动: 年会抽奖    │   ├ 活动: 粉丝福利  │   ├ 活动: 转发  │ │
│  │  ├ 奖品: 卡密       │   ├ 奖品: 手动发放  │   ├ 奖品: 实物  │ │
│  │  └ 模式: 名单+定时  │   └ 模式: 公开+手动 │   └ 模式: 密码  │ │
│  └────────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────────┤
│                        参与者层（Participant）                    │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │ 用户 A  │ 用户 B  │ 用户 C  │ ... 通过公开链接参与各活动   │ │
│  └────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 隔离原则

```
┌─────────────────────────────────────────────────────────────────┐
│                     隔离级别                                     │
├─────────────────────────────────────────────────────────────────┤
│ 1. 数据隔离：所有业务表含 tenant_id，查询强制 WHERE tenant_id   │
│ 2. 认证隔离：JWT 含 tenant_id 声明，中间件自动注入              │
│ 3. 存储隔离：同一数据库（Turso），按 tenant_id 逻辑隔离         │
│ 4. 公开隔离：活动链接使用不可枚举 public_slug（UUID 前 8 位）   │
│ 5. 奖品隔离：奖品/卡密/码池按 tenant_id 隔离                    │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 角色权限体系

| 角色 | 层级 | 权限范围 | MVP | 说明 |
|------|------|----------|:---:|------|
| 平台 Owner | 平台 | 管理平台配置、套餐、租户封禁 | P1 | 不代运营活动 |
| 平台 Support | 平台 | 只读排障，默认不得查看卡密明文 | P2 | 审计用 |
| 租户 Owner | 租户 | 管理租户、成员、活动、奖品、全部操作 | P0 | 注册时自动创建 |
| 租户 Admin | 租户 | 管理活动和奖品，不能管理成员 | P1 | 可邀请同事 |
| 租户 Operator | 租户 | 只能创建/编辑活动、查看统计，不能删除 | P2 | 运营人员 |
| 租户 Viewer | 租户 | 只读查看活动数据 | P2 | 审计/汇报用 |
| 参与者 | 公开 | 通过公开活动页参与，不进入管理后台 | P0 | 无需登录 |

## 三、使用场景与参与模式

### 3.1 典型使用场景矩阵

| 场景 | 组织者 | 参与者 | 推荐参与模式 | 推荐开奖模式 | 奖品类型 | 关键诉求 |
|------|--------|--------|------------|------------|---------|---------|
| 公司年会抽奖 | 企业 HR | 全体员工 | 限定名单（roster） | 手动（manual） | 实物/卡密 | 名单内参与、防作弊、导出名单 |
| 课程福利 | 老师/机构 | 学员 | 限定名单（roster） | 定时（scheduled） | 卡密/券码 | 学员邮箱验证、自动发码 |
| 社群活动 | 群主/运营 | 群成员 | 密码进入（password） | 手动（manual） | 手动发放 | 密码/口令进入、快速传播 |
| 粉丝抽奖 | 博主/KOL | 粉丝 | 公开（open） | 定时（scheduled） | 手动发放/实物 | 公开参与、分享传播 |
| 展会抽奖 | 展台运营 | 到场人员 | 公开（open） | 手动（manual） | 实物 | 手机扫码、现场开奖 |
| VIP 福利 | 商家 | 会员 | 名单/邀请码（invite_code） | 手动（manual） | 卡密/数字链接 | 仅会员可参与 |
| 内测资格 | 产品团队 | 申请者 | 公开（open） | 手动（manual） | 卡密（激活码） | 选中后发放激活码 |
| 门店促销 | 店主 | 到店顾客 | 公开（open） | 即时（instant） | 核销码/优惠券 | 二维码参与、中奖后核销 |
| 线上教育 | 培训机构 | 付费学员 | 邀请码（invite_code） | 定时（scheduled） | 卡密/资料链接 | 购课后自动发码、定时开奖 |
| 游戏社区 | 游戏运营 | 玩家 | 密码（password） | 定时（scheduled） | 游戏礼包码 | 密码每日更新、定时开奖 |

### 3.2 参与模式体系

MVP 支持四种参与模式，未来可扩展：

| 模式 | 标识 | 验证逻辑 | 适用场景 | MVP |
|:----:|:----:|---------|---------|:---:|
| 公开参与 | `open` | 无额外验证，输入邮箱即可参与 | 粉丝抽奖、展会、门店促销 | P0 |
| 限定名单 | `roster` | 预导入邮箱/手机号，仅名单内可参与 | 公司年会、课程福利 | P0 |
| 访问密码 | `password` | 输入活动密码（SHA-256 hash 校验） | 社群活动、游戏社区 | P0 |
| 邀请码 | `invite_code` | 输入唯一邀请码，CAS 扣减次数 | VIP 福利、线上教育 | P0 |
| 一人一码 | `unique_code` | 每人一个唯一码，不可重复使用 | 内测资格、门票验证 | P1 |
| 申请审核 | `approval` | 用户报名→运营审核→进入候选池 | 定向邀请、筛选 | P2 |
| API 校验 | `external_check` | 调外部 API 判断参与资格 | 企业集成、第三方平台 | P2 |

### 3.3 开奖模式

| 模式 | 标识 | 触发方式 | 适用场景 | MVP |
|:----:|:----:|---------|---------|:---:|
| 手动开奖 | `manual` | 租户后台点击"开奖" | 年会、展会、社群活动 | P0 |
| 定时开奖 | `scheduled` | 到预设时间自动开奖（Cron 兜底） | 粉丝抽奖、课程福利、游戏社区 | P0 |
| 即时开奖 | `instant` | 用户参与后立即知道结果 | 门店促销、刮刮卡 | P2 |
| 分批开奖 | `batch` | 每天/每小时抽一批 | 大型活动、持续运营 | P2 |
| 加权开奖 | `weighted` | 根据权重提高中奖概率 | 付费参与、会员专属 | P2 |

### 3.4 奖品模式

| 奖品类型 | 标识 | 发放方式 | 适用场景 | MVP |
|---------|:----:|---------|---------|:---:|
| 纯名单奖 | `manual_fulfillment` | 只生成中奖名单，运营者线下联系 | 实物奖品、线下核销 | P0 |
| 卡密/券码 | `code` | 从导入码池中取一条发给中奖者 | 游戏礼包、优惠券、激活码 | P0 |
| 数字链接 | `digital_link` | 中奖后展示固定链接/说明 | 电子书、课程、资料下载 | P1 |
| 实物奖品 | `physical` | 收集地址，运营者发货 | 电子产品、礼品 | P1 |
| 多奖项 | `tiered` | 一等奖/二等奖/三等奖，各奖项独立配置 | 年会、大型活动 | P0 |

## 四、数据模型设计

### 4.1 核心实体关系

```
tenants (1) ──→ users (N)          # 租户下有多个用户
tenants (1) ──→ lottery_draws (N)   # 租户创建多个活动
lottery_draws (1) ──→ prizes (N)    # 活动关联多个奖品
lottery_draws (1) ──→ lottery_prize_tiers (N)  # 活动配置多奖项
lottery_draws (1) ──→ lottery_entries (N)      # 活动有多个参与者
lottery_draws (1) ──→ lottery_winners (N)      # 活动产生中奖者
prizes (1) ──→ prize_codes (N)     # 奖品有多个码
lottery_draws (1) ──→ audit_logs (N)  # 活动有审计日志
```

### 4.2 表结构设计

#### tenants（租户）
```sql
id              TEXT PK       -- UUID
name            TEXT NOT NULL -- 租户名称（注册时默认为用户名）
plan            TEXT DEFAULT 'free'  -- 套餐：free/pro/enterprise
status          TEXT DEFAULT 'active' -- active/suspended/disabled
max_draws       INTEGER DEFAULT 0    -- 0=无限制
max_participants_per_draw INTEGER DEFAULT 5000
created_at      TEXT
updated_at      TEXT
```

#### users（用户）
```sql
id              TEXT PK
username        TEXT UNIQUE
email           TEXT DEFAULT ''
password_hash   TEXT          -- hmac_sha256_v1:<salt>:<mac>；免费 Workers 不在热路径使用高迭代 KDF
status          TEXT DEFAULT 'active'
created_at      TEXT
updated_at      TEXT
```

#### tenant_members（租户成员）
```sql
tenant_id       TEXT PK
user_id         TEXT PK
role            TEXT DEFAULT 'owner'  -- owner/admin/operator/viewer
created_at      TEXT
```

#### lottery_draws（抽奖活动）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
public_slug     TEXT UNIQUE     -- 公开链接 slug（UUID 前 8 位）
title           TEXT NOT NULL
description     TEXT DEFAULT ''
status          TEXT DEFAULT 'draft'  -- draft/open/paused/drawing/drawn/cancelled
participation_mode TEXT DEFAULT 'open'  -- open/roster/password/invite_code
draw_trigger    TEXT DEFAULT 'manual'   -- manual/scheduled
start_at        TEXT NOT NULL    -- 参与开始时间
end_at          TEXT NOT NULL    -- 参与结束时间
draw_at         TEXT            -- 定时开奖时间
access_password TEXT DEFAULT '' -- 密码模式（SHA-256 hash）
max_participants INTEGER DEFAULT 5000
winner_count    INTEGER DEFAULT 1
draw_seed_hash  TEXT DEFAULT '' -- 公平性验证 hash
draw_seed       TEXT DEFAULT '' -- 随机种子（开奖后公开）
algorithm_version TEXT DEFAULT 'uniform_v1'
failure_reason  TEXT DEFAULT ''
created_at      TEXT
updated_at      TEXT
```

#### prizes（奖品）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
name            TEXT NOT NULL
description     TEXT DEFAULT ''
prize_type      TEXT DEFAULT 'code'  -- code/manual_fulfillment/digital_link/physical
image_url       TEXT DEFAULT ''
fulfillment_note TEXT DEFAULT ''    -- 兑奖说明
created_at      TEXT
updated_at      TEXT
```

#### prize_codes（奖品码）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
prize_id        TEXT NOT NULL
code            TEXT NOT NULL
secret          TEXT DEFAULT ''  -- 码的密码/密钥
status          TEXT DEFAULT 'available'  -- available/issued/expired
winner_id       TEXT DEFAULT '' -- 关联的 lottery_winners.id
issued_at       TEXT
created_at      TEXT
```

#### lottery_prize_tiers（奖项配置）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
draw_id         TEXT NOT NULL
prize_id        TEXT NOT NULL
tier_name       TEXT DEFAULT '中奖'
winner_count    INTEGER DEFAULT 1
sort_order      INTEGER DEFAULT 100
```

#### lottery_entries（候选池）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
draw_id         TEXT NOT NULL
identity_type   TEXT DEFAULT 'email'  -- email/phone/name/external_id
identity_value  TEXT NOT NULL
display_name    TEXT DEFAULT ''
invite_code_id  TEXT DEFAULT ''
ip_hash         TEXT DEFAULT ''
joined_at       TEXT NOT NULL
UNIQUE(tenant_id, draw_id, identity_type, identity_value)
```

#### lottery_winners（中奖记录）
```sql
id              TEXT PK
tenant_id       TEXT NOT NULL
draw_id         TEXT NOT NULL
tier_id         TEXT NOT NULL
entry_id        TEXT NOT NULL
identity_type   TEXT NOT NULL
identity_value  TEXT NOT NULL
prize_code_id   TEXT DEFAULT ''
drawn_at        TEXT NOT NULL
notification_status TEXT DEFAULT 'pending'  -- pending/sent/failed
notification_error TEXT DEFAULT ''
UNIQUE(tenant_id, draw_id, entry_id)
```

#### email_access_codes（邮箱验证码）
```sql
id              TEXT PK
email           TEXT NOT NULL
draw_id         TEXT NOT NULL
code_hash       TEXT NOT NULL  -- SHA-256
expires_at      TEXT NOT NULL
used            INTEGER DEFAULT 0
```

#### audit_logs（审计日志）
```sql
id              TEXT PK

actor_user_id   TEXT NOT NULL
action          TEXT NOT NULL
target_type     TEXT NOT NULL
target_id       TEXT NOT NULL
metadata_json   TEXT DEFAULT '{}'
created_at      TEXT
```

#### system_config（系统配置）
```sql
key             TEXT PK
value           TEXT DEFAULT ''
updated_at      TEXT
```

### 5.2 参与流程

```
┌─────────────────────────────────────────────────────────────────┐
│                       参与流程                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  用户访问公开链接 → 查看活动详情 → 输入邮箱                       │
│       ↓                                                          │
│  发送验证码 → 用户输入 6 位验证码                                 │
│       ↓                                                          │
│  校验参与模式：                                                   │
│  ├─ open: 直接加入                                               │
│  ├─ roster: 检查邮箱是否在名单中                                  │
│  ├─ password: 同时校验密码 hash                                   │
│  └─ invite_code: CAS 扣减邀请码次数                               │
│       ↓                                                          │
│  原子写入候选池（INSERT ... SELECT 防超限）                       │
│       ↓                                                          │
│  参与成功 → 可查询结果                                            │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 开奖流程

```
┌─────────────────────────────────────────────────────────────────┐
│                       开奖流程                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  触发开奖（手动/定时）                                            │
│       ↓                                                          │
│  CAS 夺取开奖权：UPDATE status='drawing' WHERE status='open'     │
│       ↓                                                          │
│  生成随机种子 + 记录 SHA-256 hash                                 │
│       ↓                                                          │
│  读取候选池 → Fisher-Yates 洗牌                                  │
│       ↓                                                          │
│  事务内：                                                        │
│  ├─ 按奖项逐个分配中奖者                                          │
│  ├─ 原子锁码：SELECT LIMIT 1 → UPDATE WHERE id                   │
│  └─ 写入 lottery_winners                                         │
│       ↓                                                          │
│  UPDATE status='drawn' + 写审计日志                               │
│       ↓                                                          │
│  异步发送中奖通知邮件（不阻塞主流程）                              │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

## 六、运营闭环设计

### 6.1 租户自助闭环

```
注册 → 创建奖品 → 导入码（可选）→ 创建活动 → 配置参与规则
→ 发布活动 → 获取公开链接/二维码 → 分享给参与者
→ 参与者参与 → 开奖 → 查看中奖名单 → 导出 CSV
→ 发送中奖通知 → 中奖者查收奖品
```

**全程无需平台管理员介入。**

### 6.2 管理后台功能

| 模块 | 功能 | MVP |
|------|------|:---:|
| 仪表盘 | 活动统计（进行中/草稿/已开奖/待开奖） | P0 |
| 活动管理 | 创建/编辑/发布/暂停/取消/开奖 | P0 |
| 活动管理 | 查看候选池/中奖名单/CSV导出 | P0 |
| 活动管理 | 补发码/重发通知 | P0 |
| 活动管理 | 发布前校验（标题/时间/库存） | P0 |
| 奖品管理 | 创建/编辑奖品 | P0 |
| 奖品管理 | 导入码/查看码库存 | P0 |
| 系统配置 | 平台名称/发件人/频率限制/数据保留 | P0 |
| 审计日志 | 查看操作日志 | P0 |
| 成员管理 | 添加/移除租户成员 | P1 |
| 套餐管理 | 查看当前套餐/使用量 | P1 |

### 6.3 平台运营功能

| 功能 | 说明 | MVP |
|------|------|:---:|
| 租户列表 | 查看所有租户及其状态 | P1 |

| 系统配置 | 全局默认值（默认中奖数/参与上限等） | P0 |

## 八、技术风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| Worker 内存超限 | 候选池过大（>5000人）时可能 OOM | 强制 `max_participants` 默认 5000，需扩容时通过配置调整 |
| 并发开奖冲突 | 定时开奖和手动开奖同时触发 | CAS 状态机 + `healDrawingState` 治愈机制 |
| 邮件发送失败 | 中奖者收不到通知 | `notificationStatus` 追踪 + 管理端重发按钮 |
| 验证码暴力枚举 | 6 位码可被枚举 | 10 分钟有效期 + `used` 标记 + 次数限制 |
| 跨租户查询 | 数据泄露 | 所有查询强制 `tenant_id` 过滤 + JWT 注入 |
| 数据库写入冲突 | 并发参与时 UNIQUE 约束冲突 | 原子 INSERT + 合理错误提示 |

## 十、设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 数据库 | D1 vs Turso | Turso | D1 是 Cloudflare 原生，但 Turso 提供更成熟的 SQLite 兼容性 |
| ORM | Drizzle vs Prisma | Drizzle | 无运行时依赖，Tree-shakeable，与 Workers 兼容 |
| 认证 | JWT vs Session | JWT | 无状态，适合 Serverless，无需存储 |
| 密码算法 | bcrypt/Argon2id/PBKDF2 vs pepper HMAC | pepper HMAC（MVP） | Workers Free 每请求 CPU 时间有限；高成本 KDF 放到付费 Workers、外部认证或离线迁移阶段 |
| 前端框架 | Vue vs React | Vue | 继承 cf-shop 技术栈，降低迁移成本 |
| 部署 | Workers vs Pages | Workers + Assets | 单域名部署，API 和静态资源同源 |
| 参与模式 | 组合式 vs 预定义模板 | 组合式 | 更灵活，可覆盖更多场景 |
| 奖品码锁定 | UPDATE all vs SELECT+UPDATE | SELECT+UPDATE | 避免数据损坏，精准控制 |
