# 秒杀活动到结束时间不自动关闭根因分析与运维核查清单（docs/247）

## 背景

线上秒杀（活动号 `shop_43c49ec9` 等）到结束时间后，公开页仍显示「进行中」，
没有自动关闭/开奖。前期排查已排除「部署陈旧」（生产 bundle hash 与本地一致）。
本文件收口**自动开奖/自动关闭链路**的完整根因分析，并给出 VPS 运维核查清单。

## 一、自动关闭/开奖全链路（代码事实）

```
systemd timer（每 5 分钟 + 开机 2 分钟，Persistent=true）
  └─ cf-lottery-maintenance.service（oneshot）
       └─ curl -X POST http://127.0.0.1:8787/api/cron/maintenance
            Header: Authorization: Bearer ${CRON_SECRET}   ← 取自 /root/cf-lottery/.env
                 └─ app.post("/api/cron/maintenance")（src/index.ts:403）
                      ├─ 校验 CRON_SECRET 已配置，否则 503（index.ts:405）
                      ├─ timingSafeEqual 校验 Bearer，否则 403
                      └─ runScheduledMaintenance(db, env)（index.ts:72）
                           └─ processDueDraws(db, { limit: 20 })（index.ts:82）
                                ├─ lottery + scheduled + 非 instant + open + drawAt<=now
                                │    → performDraw（抽奖 + 中奖邮件）
                                ├─ 非 lottery 活动过期 → 直接置 drawn（afe9823 / docs/244 修复）
                                ├─ 卡死 drawing → healDrawingState 治愈重试
                                └─ 已 drawn → 幂等跳过
```

### 关键守卫

| 环节 | 位置 | 结论 |
|------|------|------|
| 定时器周期 | `configs/cf-lottery-maintenance.timer` | `OnBootSec=2min` + `OnUnitActiveSec=5min` + `Persistent=true` ✅ |
| 定时器执行体 | `configs/cf-lottery-maintenance.service` | `curl` 打本机 `/api/cron/maintenance`，`EnvironmentFile=/root/cf-lottery/.env` ✅ |
| 端点鉴权 | `src/index.ts:403-428` | 未配置 `CRON_SECRET` 直接 503；token 不匹配 403 ✅ |
| 并发安全 | `src/services/lottery/draw-execution.ts:84-137` | `performDraw` 用 CAS `open→drawing` 夺取，`drawing` 先 heal，`drawn` 幂等返回 ✅ |
| 触发推断兜底 | `src/services/lottery/draws.ts:223-227` | `lottery + drawAt` 且未显式传 trigger → 自动推断 `scheduled` ✅ |
| 非 lottery 过期关闭 | `afe9823`（docs/244） | 修复前非 lottery 活动（含秒杀）永不自动关闭 → 本次问题主因之一，已修并上线 ✅ |

## 二、根因结论

代码链路完整。**「到点不自动关闭」最可能的原因按概率排序：**

1. **VPS 上 maintenance timer 未安装/未启用**。
   `local-deploy-vps.sh`（当前默认部署方式）只上传代码并重启 `cf-lottery.service`，
   **不负责安装/启用 `cf-lottery-maintenance.timer`**。若线上是本地脚本部署而从未手动
   `systemctl enable`，则自动任务从未运行过——符合「一直不自动关闭」的观测。
   （`scripts/deploy-to-vps.sh` 会自动安装 timer，但当前默认部署不走它。）
2. **`/root/cf-lottery/.env` 缺 `CRON_SECRET`**。此时 `curl` 收到 503，
   `cf-lottery-maintenance.service` 因 `curl -f` 退出非 0 → systemd 记录失败。
3. **旧活动创建时属于「非 lottery」或 `result_mode=instant`**。
   - 非 lottery：`processDueDraws` 修复前不扫 → 已由 afe9823 修复（改为过期直接置 drawn）。
   - instant：设计上不做整体开奖（每用户即时出结果），到点不会「统一开奖」，这是正确行为，
     但若运营期望到点关闭，需要确认前端用 `drawAt` 展示结束时间而非依赖状态流转。
4. **`draw_trigger` 被显式写成 `manual` 且有 `drawAt`**。
   创建接口只在「未显式传 trigger」时推断 scheduled；存量异常数据不会被 cron 扫到。

> 注意：**没有启动补扫**。服务器重启后不主动扫过期活动，依赖 timer 的
> `OnBootSec=2min` + `Persistent=true`（timer 已启用时）在开机后补跑一次。

## 三、VPS 运维核查清单（按序执行）

```bash
# 1) timer 是否安装且启用
systemctl list-timers | grep -i cf-lottery
systemctl is-enabled cf-lottery-maintenance.timer    # 期望 enabled
systemctl cat cf-lottery-maintenance.timer | grep -E 'OnBootSec|OnUnitActiveSec'

# 2) 最近执行历史（失败会在这里显示非 0 退出）
journalctl -u cf-lottery-maintenance.service --since "-7 days" --no-pager | tail -50

# 3) CRON_SECRET 是否存在于 .env（服务端通过 EnvironmentFile 读取）
grep -c '^CRON_SECRET=' /root/cf-lottery/.env

# 4) 手动触发一次，确认端点到 DB 全程可用
CRON_SECRET="$(grep '^CRON_SECRET=' /root/cf-lottery/.env | cut -d= -f2-)"
curl -sS -X POST -H "Authorization: Bearer ${CRON_SECRET}" \
  http://127.0.0.1:8787/api/cron/maintenance | head -c 400
# 期望 {"ok":true,...,"draws":{...}} ；若 {"ok":false,"message":"未配置 CRON_SECRET"} → 补 .env 后重启

# 5) 复核具体活动的扫条件（用平台账号/DB 查询）
#    需要确认三列：activity_kind=lottery、draw_trigger=scheduled、result_mode 非 instant、
#    draw_at 已过且 status=open
```

若 timer 缺失，安装：

```bash
cp /root/cf-lottery/configs/cf-lottery-maintenance.{timer,service} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now cf-lottery-maintenance.timer
systemctl start cf-lottery-maintenance.service   # 立即跑一次
```

## 四、建议（待办，非本次改动）

1. **`local-deploy-vps.sh` 增加 timer 幂等安装步骤**：`scp` 两个 unit 文件 +
   `systemctl enable --now`，让默认部署方式自动闭环（当前仅 `deploy-to-vps.sh` 会装）。
2. **可选：`server.ts` 启动时 deferred 补扫**。进程重启后对 `open && drawAt<=now` 的
   scheduled 活动自动 catch-up。`performDraw` 有 CAS 守卫，多实例并发安全，
   但改动涉及生产行为，需单独评审后实施。
3. **文档修正**：`configs/cf-lottery.service` 注释与 README 部署章节需补「手动启用 timer」
   步骤，避免下一位运维踩同一坑。

## 五、结论

- 自动开奖/自动关闭的**代码链路闭环**（docs/206 + afe9823/docs/244），非代码缺陷导致。
- 秒杀「到点不自动关闭」为**运维配置/部署路径问题概率最高**（timer 未装或 `CRON_SECRET`
  缺失），其次为**旧数据属性**（非 lottery / instant / 显式 manual）。
- 按第三节清单在 VPS 执行后即可定位；若第 4 步手动触发成功，则问题在 timer，
  安装后即恢复，无需改代码。
