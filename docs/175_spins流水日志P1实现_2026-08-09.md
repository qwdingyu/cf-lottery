# spins 流水日志 P1 实现（2026-08-09）

## 背景

spins 抽奖次数是 cf-lottery 的核心资产，但现有系统缺乏审计能力：
- 用户「次数从哪来、用到哪去」无法追溯
- 排查财务问题（如签到奖励发放错误、抽奖扣次异常）依赖人工查 entry 表
- 无法统计「今天签到了多少人」「发了多少奖励次数」

docs/172 §5.5 建议新增 `spins_log` 表，记录每次 spins 变动。

## 目标

1. 新增 `spins_log` 表（schema + migration）
2. 在 4 个 spinsLeft 写点记录流水日志
3. 测试覆盖：join/checkin/spin/viral 四种 reason

## 设计

### 表结构

```typescript
export const spinsLog = sqliteTable("spins_log", {
  id: text("id").primaryKey(),
  tenantId: text("tenant_id").notNull(),
  entryId: text("entry_id").notNull(),
  userId: text("user_id").notNull(),            // 面向用户的标识（identityValue）
  delta: integer("delta").notNull(),             // 变动量（正=收入，负=支出）
  balanceAfter: integer("balance_after").notNull(), // 变动后余额快照
  reason: text("reason").notNull(),              // join/checkin/spin/viral/purchase
  refId: text("ref_id"),                         // 关联单据号（spin_id 等）
  createdAt: text("created_at").notNull(),
});
```

索引：
- `idx_spins_log_entry` — 按租户+entry 查流水
- `idx_spins_log_user` — 按租户+用户查流水
- `idx_spins_log_reason` — 按租户+原因+时间查流水（审计）

### 4 个写点

| 写点 | 文件位置 | reason | delta | refId |
|------|----------|--------|-------|-------|
| join 初始发放 | `participation.ts:385` | `join` | spinInit.spinsLeft | 无 |
| 签到奖励 | `commands.ts:552` | `checkin` | reward (>=0) | 无 |
| 抽奖消耗 | `spin-execution.ts:362` | `spin` | -1 | spinId |
| 裂变邀请 | `participation.ts:772` | `viral` | grant.nextLeftDelta | 无 |

### 设计原则

1. **只追加不更新** — 与 lottery_entries 分表解耦，避免热路径读改写
2. **写入失败不抛异常** — 日志是辅助审计，不影响主流程（签到/抽奖已成功）
3. **balanceAfter 是 best-effort 快照** — SQLite 单写者下读改写一致
4. **userId 用 identityValue** — 不 join 直接审计，避免跨表查询
