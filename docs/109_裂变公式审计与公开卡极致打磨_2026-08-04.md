## 一、公式是否正确？

**产品公式正确**（与 041/108 一致）：

| 量 | 定义 |
|----|------|
| `invited` | 有效邀请 = `SUM(shareRecords.joinedCount)`（**不是**点击） |
| `perInvite` | `extraEntriesPerInvite`（默认 1） |
| `maxExtra` | `maxExtraEntries`（默认 10，**不含**基础票） |
| **extra** | `min(invited × perInvite, maxExtra)` |
| **drawWeight** | `1 + extra` |

语义边界（正确、需保持）：

- **不**写入额外 `lottery_entries` → 不占 `maxParticipants`
- 同一人只中一次
- `candidateCount` 仍为真实参与人数

## 二、发现的真实 Bug（非幻觉）

### B1. 加权开奖「扩袋 + 抽 n 去重」可能抽不满名额（P0）

旧实现：把每人复制 `weight` 次进袋，再 `randomSelect(bag, totalWinners)`，落库时 `seenEntryIds` 去重。

反例：2 人、2 个奖，A 权重 10、B 权重 1。袋长 11，只抽 2 个位置，可能抽到 `[A,A]` → 去重后只中 1 人。

**修复**：`weightedSampleUnique` — 按权无放回逐轮抽 1 人，直至满员或池空。

### B2. 排行榜「未进 Top20」名次恒为 21（P1）

旧：`sorted = full.sort().slice(0,20)` 后再 `findIndex`；不在 slice 内则 `rank = 20+1`。

**修复**：`buildViralLeaderboardRanking` 在**全量**排序上算 rank，再 slice Top N。

### B3. 0 邀请不返回 myRank（P1 UX）

旧：`myCount > 0` 才有 myRank → 已参与用户看不到「我」。

**修复**：0 邀请返回 `{ rank: 0, invitedCount: 0 }`，前端展示「尚未上榜」。

### B4. 每次 POST /share 都 insert 新码（P1）

多码导致链接漂移、脏数据。

**修复**：同一 `drawId+sharerEntryId` 已有码则**复用**最新一条。

### B5. my-viral-stats 不校验 entry 归属（P1 安全）

任意 UUID 可窥探统计形态。

**修复**：与 share 相同，entry 必须属于本活动。

### B6. 公开卡 UX 幻觉（P0 产品）

| 幻觉 | 修复 |
|------|------|
| 无 entry 仍暗示能生成链接 | 已参与无 entry → 引导「查结果」；未参与 → 先参与 |
| 加载中整块空白 | 骨架屏 |
| 复制失败仍 toast 成功 | catch 展示 `viralCopyFailed` |
| 「开奖权重」黑话 | `viralWeightExplain` 白话 |
| 终态仍强推邀请 | `inviteOpen` + docs/103 |
| 高亮「是我」仅靠 rank | 行带 `entryId` |
| 无系统分享 | `navigator.share` 次要 CTA |

## 三、公开卡状态机（极致）

```
viral.enabled?
  no  → 不挂载
  yes → ViralLeaderboard
        ├─ 加载 → 骨架
        ├─ 我的邀请（始终有区块，诚实文案）
        │    entryId+stats → 三列统计 + 进度 + 复制/系统分享
        │    isJoined 无 entry → 查结果引导
        │    未参与 → 先参与激励
        │    终态 → 历史数据，弱化 CTA
        └─ leaderboardEnabled?
             yes → Top20 + 真实 myRank / 尚未上榜
             no  → 仅我的邀请
```
