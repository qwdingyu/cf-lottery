# 活动结束时间与支付超时机制闭环设计（2026-08-24）

## 一、背景

直付秒杀场景中，存在两个独立的时间窗口：

| 时间窗口 | 字段 | 含义 | 默认值 |
|---|---|---|---|
| 活动持续时间 | `lotteryDraws.endAt` | 活动可参与的最后时间 | 由管理员配置 |
| 支付超时 | `payment_order_timeout_minutes` | 订单创建后允许付款的最长时间 | 30 分钟 |

**问题**：当 `活动时长 < 支付超时` 时（如 20 分钟活动配 30 分钟超时），活动结束后仍存在 10 分钟的付款窗口期。用户可在这段时间内付款，但活动已结束。

## 二、优化方案

### 2.1 过期条件（docs/271 优化）

`expireOverdueOrders` 的 SQL 查询新增条件：

```
overdue:           (createdAt < cutoff) OR (endAt < now)
staleReservations: (joinedAt < cutoff) OR (endAt < now)
```

即：**订单超时 OR 活动已结束 → 立即过期订单**，取最早者。

### 2.2 时间线闭环

```
T=0      活动开始 (OPEN)
T=5min   用户参与 → joinDraw + createPaymentOrder
T=20min  活动结束 (DRAWN/CLOSED)
          ↓ expireOverdueOrders 被调用 → 过期所有 pending 订单
          ↓ cancelRewardPending → 写 reward_failed
T=20min  之后 → 用户付款 → handlePaymentCallback
          → 订单已 EXPIRED → markAttemptLate → LATE_NEEDS_REFUND
          → settleRewardByPercent 不触发（fulfillmentOk=false）
T=30min  expireOverdueOrders 再次被调用 → 已过期，无操作
```

### 2.3 三路覆盖

| 过期条件 | 触发时机 | 用途 |
|---|---|---|
| `createdAt < cutoff` | 定时/懒清理 | 正常超时释放 |
| `endAt < now` | expireOverdueOrders 被调用时 | 活动结束立即释放 |
| 两者同时满足 | 最早者 | 兜底 |

## 三、代码实现

### 3.1 `expireOverdueOrders` 核心查询

```typescript
// 活动结束子查询
const activityEndedClause = sql`EXISTS (
  SELECT 1 FROM lottery_draws
  WHERE lottery_draws.id = ${paymentOrders.drawId}
    AND lottery_draws.tenant_id = ${tenantId}
    AND datetime(lottery_draws.end_at) < datetime('now')
)`;

// 过期订单查询
const overdue = await tx
  .select({ ... })
  .from(paymentOrders)
  .where(and(
    eq(paymentOrders.tenantId, tenantId),
    eq(paymentOrders.status, PAYMENT_ORDER_STATUS.PENDING),
    sql`(
      datetime(${paymentOrders.createdAt}) < ${cutoff}
      OR ${activityEndedClause}
    )`,
  ));

// 残留预占查询（有 reserved entry 但无订单）
const staleReservations = await tx
  .select({ ... })
  .from(lotteryEntries)
  .where(and(
    eq(lotteryEntries.tenantId, tenantId),
    eq(lotteryEntries.paymentStatus, PAYMENT_ENTRY_STATUS.RESERVED),
    sql`(
      datetime(${lotteryEntries.joinedAt}) < ${cutoff}
      OR EXISTS (
        SELECT 1 FROM lottery_draws
        WHERE lottery_draws.id = ${lotteryEntries.drawId}
          AND lottery_draws.tenant_id = ${tenantId}
          AND datetime(lottery_draws.end_at) < datetime('now')
      )
    )`,
    sql`NOT EXISTS (
      SELECT 1 FROM payment_orders
      WHERE payment_orders.entry_id = ${lotteryEntries.id}
        AND payment_orders.tenant_id = ${tenantId}
    )`,
  ));
```

```

  └── 检查 draw.status

回调层 (payment-service.ts:1344)
  └── handlePaymentCallback(db, ...)

            └── 验证支付
            └── fulfillmentOk → settleRewardByPercent
            └── 更新订单状态
```

## 四、全链路闭环矩阵

| 场景 | 条件 | 结果 |
|---|---|---|
| 活动期内付款 | `T < endAt` AND `T < createdAt + timeout` | 正常付款，发卡，结算奖励 |
| 活动结束后、超时前付款 | `endAt < T < createdAt + timeout` | 订单被 expireOverdueOrders 过期 → 迟到付款 → LATE_NEEDS_REFUND |
| 超时后付款 | `createdAt + timeout < T` | 订单已 EXPIRED → 迟到付款 → LATE_NEEDS_REFUND |
| 超时后未付款 | `createdAt + timeout < T` | expireOverdueOrders 释放 entry + 卡密 + 名额 |
| 活动结束后未付款 | `endAt < T < createdAt + timeout` | expireOverdueOrders 立即释放 entry + 卡密 + 名额 |
| 活动结束后用户重试 | `endAt < T` | 订单已过期 → isRetryingPaymentOrder 返回 false → 无法重试 |

## 五、最佳实践建议

### 5.1 配置建议

```
活动时长 ≤ 支付超时
```

- 20 分钟活动 → `payment_order_timeout_minutes` 设为 15 分钟（≤ 20）
- 1 小时活动 → 设为 30 分钟（≤ 60）
- 24 小时活动 → 设为 60 分钟（用户有充足时间支付）

### 5.2 代码原则

1. **活动结束 ≠ 订单失效**：`handlePaymentCallback` 不检查活动状态，已存在的有效订单应正常履约
2. **但活动结束应触发清理**：`expireOverdueOrders` 通过 `endAt < now` 条件保证活动结束后不再接受新付款
3. **双重保障**：路由层 + `createPaymentOrder` 入口均调用 `expireOverdueOrders`，确保清理及时
4. **幂等性**：`expireOverdueOrders` 多次调用不产生副作用
