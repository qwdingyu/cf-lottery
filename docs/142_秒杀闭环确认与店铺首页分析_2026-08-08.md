## 2. 店铺首页分析

### 业务需求

每个 SaaS 租户需要一个"店铺首页"——展示自己所有公开活动的页面,类似商城首页。

秒杀是活动,促销店铺的销售才是核心。店铺首页让租户的活动可以聚合展示,增强品牌感和转化。

### 现有基础

| 能力 | 状态 |
| --- | --- |
| tenants 表有 `name`、`brandConfig` 字段 | ✅ |
| brandConfig 读写 API(admin-lottery-integrations.ts:276-293) | ✅ |
| home-activities 返回公开活动列表(跨租户) | ✅ |
| landing-activity-feed 组件(活动卡片渲染) | ✅ |
| 前端 LandingView 已集成活动矩阵 | ✅ |

### 实现路径

| 改动 | 规模 |
| --- | --- |
| **后端**:GET /api/public/shops/:tenantName(按租户筛选活动,复用 home-activities 逻辑) | 小(1 个接口) |
| **前端**:ShopView.vue(复用 landing-activity-feed 卡片 + brandConfig 品牌头) | 小(1 页面+1 路由) |
| **URL**:`/shop/:storeSlug`(推荐) | 小 |
| **URL 安全**:用 `store_slug`(UNIQUE),不暴露 tenant_id;与现有 public_slug 模式一致 | 合规 |

### 店铺页面结构

```
店铺头部:brandConfig 品牌名称/logo/描述
活动分类 Tabs:秒杀|免费|抽奖|问卷(复用 landing-activity-feed 筛选)
活动卡片网格(复用已有)
```

### URL 方案(核心)

**否决租户ID(暴露内部ID,违反 AGENTS.md 铁律)**。采用 `store_slug`:

| 维度 | 实现 |
| --- | --- |
| 字段 | `tenants.store_slug TEXT UNIQUE`(迁移) |
| 默认值 | `shop_{tenant_id[0:8]}`(自动生成,可改) |
| L2可配 | 管理端品牌设置页输入 |
| 与现有模式一致 | public_slug(活动)/store_slug(店铺) |

### 建议

**店铺首页是秒杀闭环的自然延伸**——秒杀只是活动,店铺是所有活动的聚合入口,是 SaaS 租户的"门面"。当前品牌配置 API 已就位,活动卡片组件可复用,落地仅需 2 天,是低投入高回报的需求。
