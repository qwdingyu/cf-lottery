# 080 奖品页 i18n 与平台租户详情 UI 整改

> 日期：2026-08-04  
> 原则：有证据、低成本、不臆造 API；对照现有 admin 规范  
> 反馈：`/admin/prizes` 多语言 key 泄漏；`/platform/tenants` 详情弹窗布局灾难

---

## 一、奖品管理多语言

### 证据

- `AdminPrizesView.vue` 全页使用 `$t('adminPrizes.*')` / `t('adminPrizes.*')`
- `frontend/src/i18n/zh-CN.ts` / `en.ts` **此前无 `adminPrizes` 命名空间**
- 切换 EN 时界面显示 `adminPrizes.createPrize` 等 key 原文

### 处置

- 按页面实际 key 全集补齐 **zh-CN + en** 的 `adminPrizes`（约 113 个）
- **未改** Vue 业务逻辑与 API

---

## 二、平台租户详情 UI

### 证据（截图 + 代码）

| 现象 | 原因 |
|------|------|
| 底部控件挤扁、竖排「套餐调整」 | scoped `.adjust-row` 横向 `flex` 把 select/input/按钮挤在一行；标签写在 flex 外且无 `writing-mode` 约束时易错位 |
| 信息区只有左右 label/value 细线 | 自写 `.detail-grid`，未用 `admin.css` 的 `detail-box` / `detail-section` |
| 状态显示 raw `active` | 未 i18n、未 tag 语义 |
| 全文硬编码中文 | 无 `platformTenants` 命名空间 |

### 处置（不改后端契约）

1. **列表**：筛选/表头/操作走 `platformTenants.*`；状态/套餐 tag + 文案  
2. **详情弹窗**：
   - 分区：基本信息 / 用量快照 / 套餐与额度 / 模拟登录  
   - 复用 `detail-box`、`detail-section`、`detail-row`、`modal-form`  
   - 套餐/状态/额度为 **两列表单网格**（窄屏一列），不再横向挤扁  
   - 模拟登录降为 ghost 次操作，与「保存调整」主按钮分离  
   - `hide-actions` + 页脚自管关闭，避免双 footer  
3. **行为保持**：PATCH plan/status/extra*、impersonate 新标签页、列表进后台

### 刻意不做

- 不改平台 tenants API / 分页语义  
- 不引入新 UI 库  
- 不把平台页做成租户运营台副本
