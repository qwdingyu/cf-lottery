# 167 嫁接层顶层设计：平台抽象与 Webhook 统一体系

> 日期：2026-08-09
> 定位：在 cf-lottery 中构建平台无关的嫁接层（Grafting Layer），抽象 QQ/Telegram/其他社交平台，
>       通过 Webhook 形成统一的事件驱动整体
> 方法：基于 cf-lottery 现有 webhook 代码（integration.ts）扩展，
>       吸收 zhenxun_bot 的 AI 层和 qqbot 的意图路由/Agent 模式设计

## 0. 核心结论

**cf-lottery 的 webhook 系统已经完成了 60% 的工作**——事件定义、入队、签名、投递、重试。
剩下的 40% 是构建一个平台抽象层，将 webhook 事件的目标从「一个 URL」抽象为「一个平台目标」。

**不需要推翻 cf-lottery 的 webhook 系统，而是在它之上构建一个「平台适配器层」。**

---

## 1. 现状分析：cf-lottery 的 Webhook 系统已经做了什么

### 1.1 已实现的（代码验证）

| 组件 | 函数/表 | 状态 |
| --- | --- | --- |
| 事件定义 | `WEBHOOK_EVENT_TYPES` | 完整（10+ 事件类型） |
| 事件入队 | `enqueueWebhookEvent()` | 批量入队、去重 |
| 签名 | `signWebhookPayload()` + `createWebhookSigningSecret()` | HMAC-SHA256 |
| 投递 | `dispatchWebhookDelivery()` | HTTP POST + 超时处理 |
| 重试 | `nextWebhookRetryAt()` 指数退避 | 5 次重试 |
| 配置 | `webhookConfigs` 表（URL/事件过滤/签名密钥） | 多租户 |
| 投递记录 | `webhookDeliveries` 表（状态/尝试/响应） | 完整审计 |
| 事件过滤 | `webhookConfigAcceptsEvent()` 按事件类型过滤 | 灵活配置 |

### 1.2 缺失的

| 缺口 | 当前状态 | 需要做什么 |
| --- | --- | --- |
| **平台目标** | Webhook 只能投递到 HTTP URL | 抽象出「平台目标」概念（QQ群/Telegram频道/Slack频道） |
| **消息模板** | 投递的是原始 JSON payload | 每个平台专用的消息模板（文本/卡片/富文本） |
| **入站路由** | 没有入站消息处理 | 接收平台事件并转换为 cf-lottery API 调用 |
| **多平台适配器** | 没有平台抽象 | `PlatformAdapter` 接口 |
| **AI 集成** | 没有 AI 能力 | 可选的 AI 层（自然语言 → 意图 → 工具调用） |

## 3. 核心接口设计

### 3.1 平台抽象接口

```typescript
// ============================================================
// 平台抽象接口（所有平台适配器必须实现）
// ============================================================

/** 平台标识 */
type PlatformType = "qq" | "telegram" | "slack" | "discord" | "custom";

/** 平台目标：一个平台上的具体接收目标 */
interface PlatformTarget {
  platform: PlatformType;
  targetId: string;      // QQ 群号 / Telegram Chat ID / Slack Channel ID
  name: string;
  config?: Record<string, unknown>;
}

/** 平台消息：平台适配器的输出 */
interface PlatformMessage {
  platform: PlatformType;
  targetId: string;
  type: "text" | "image" | "card" | "button" | "template";
  text?: string;
  imageUrl?: string;
  cardData?: Record<string, unknown>;
  buttons?: Array<{ text: string; action: string; url?: string }>;
}

/** 平台适配器接口 */
interface PlatformAdapter {
  readonly platform: PlatformType;
  send(message: PlatformMessage): Promise<{ messageId: string }>;
  sendBatch(messages: PlatformMessage[]): Promise<Array<{ messageId: string }>>;
  listen(handler: InboundHandler): Promise<void>;  // 监听入站事件
}

/** 入站事件：来自平台的用户操作 */
interface InboundEvent {
  platform: PlatformType;
  sourceId: string;         // QQ 群号 / Telegram Chat ID
  userId: string;           // 用户在该平台的 ID
  eventType: "message" | "command" | "callback" | "member_join" | "member_leave";
  text?: string;
  command?: string;         // 命令名（如 /checkin）
  args?: string[];          // 命令参数
  raw?: unknown;            // 原始数据
}

/** 入站事件处理器 */
interface InboundHandler {
  handle(event: InboundEvent): Promise<PlatformMessage | null>;
}

/** 统一事件（从 cf-lottery webhook 接收） */
interface UnifiedEvent {
  id: string;
  type: string;
  createdAt: string;
  tenantId: string;
  data: Record<string, unknown>;
}

/** 事件 → 平台目标映射 */
interface EventRoute {
  eventType: string;           // cf-lottery 事件类型
  targets: PlatformTarget[];
  templateId?: string;
  active: boolean;
}

/** 消息模板 */
interface MessageTemplate {
  id: string;
  platform: PlatformType;
  eventType: string;
  template: string;            // Handlebars 模板
  messageType: "text" | "card" | "template";
  isDefault: boolean;
}

/** AI 意图识别结果 */
interface IntentResult {
  intent: string;
  confidence: number;
  args: Record<string, unknown>;
  fallbackToChat: boolean;     // 是否回退到 AI 对话
}

interface AIEngine {
  recognizeIntent(context: { text: string; userId: string; history: string[] }): Promise<IntentResult>;
  executeTool(toolName: string, args: Record<string, unknown>): Promise<unknown>;
}
```

## 7. 平台适配器实现指南

### 7.1 QQ 适配器（基于 NapCatQQ）

```typescript
class QQAdapter implements PlatformAdapter {
  platform = "qq" as const;

  constructor(private napcat: NapCatClient) {}

  async send(message: PlatformMessage): Promise<{ messageId: string }> {
    switch (message.type) {
      case "text":
        return this.napcat.sendGroupMessage(message.targetId, message.text!);
      case "image":
        return this.napcat.sendGroupImage(message.targetId, message.imageUrl!);
      case "card":
        return this.napcat.sendGroupCard(message.targetId, message.cardData!);
      default:
        return this.napcat.sendGroupMessage(message.targetId, message.text!);
    }
  }

  async listen(handler: InboundHandler): Promise<void> {
    this.napcat.onGroupMessage(async (event) => {
      const inbound: InboundEvent = {
        platform: "qq",
        sourceId: event.groupId,
        userId: event.userId,
        eventType: "message",
        text: event.message,
        raw: event,
      };
      const response = await handler.handle(inbound);
      if (response) await this.send(response);
    });

    this.napcat.onGroupMemberIncrease(async (event) => {
      await handler.handle({
        platform: "qq",
        sourceId: event.groupId,
        userId: event.userId,
        eventType: "member_join",
      });
    });

    this.napcat.onGroupMemberDecrease(async (event) => {
      await handler.handle({
        platform: "qq",
        sourceId: event.groupId,
        userId: event.userId,
        eventType: "member_leave",
      });
    });
  }
}
```

### 7.2 Telegram 适配器

```typescript
class TelegramAdapter implements PlatformAdapter {
  platform = "telegram" as const;

  constructor(private botToken: string) {}

  private api = new TelegramBotAPI(this.botToken);

  async send(message: PlatformMessage): Promise<{ messageId: string }> {
    switch (message.type) {
      case "text":
        return this.api.sendMessage({
          chat_id: message.targetId,
          text: message.text!,
          parse_mode: "HTML",
        });
      case "image":
        return this.api.sendPhoto({
          chat_id: message.targetId,
          photo: message.imageUrl!,
          caption: message.text,
        });
      case "button":
        return this.api.sendMessage({
          chat_id: message.targetId,
          text: message.text!,
          reply_markup: {
            inline_keyboard: message.buttons!.map(b => [{
              text: b.text, callback_data: b.action, url: b.url,
            }]),
          },
        });
      default:
        return this.api.sendMessage({ chat_id: message.targetId, text: message.text! });
    }
  }

  async listen(handler: InboundHandler): Promise<void> {
    // 通过 Webhook 或 Polling 接收 Telegram 更新
    this.api.onWebhookUpdate(async (update) => {
      if (update.message?.text) {
        const inbound: InboundEvent = {
          platform: "telegram",
          sourceId: String(update.message.chat.id),
          userId: String(update.message.from.id),
          eventType: "message",
          text: update.message.text,
          raw: update,
        };
        const response = await handler.handle(inbound);
        if (response) await this.send(response);
      }
    });
  }
}
```

## 10. 关键设计决策

| 决策 | 选项 | 选择 | 理由 |
| --- | --- | --- | --- |
| 嫁接层部署方式 | 独立服务 / 嵌入桥接 | **嵌入桥接** | 减少部署复杂度，同进程通信避免网络延迟 |
| 消息模板引擎 | Handlebars / EJS / 自定义 | **Handlebars** | 无代码执行风险，语法简单，安全 |
| AI 引擎来源 | 自研 / qqbot / zhenxun_bot | **qqbot Agent** | 早期够用，588 行极简，MIT 许可证 |
| 平台适配器注册 | 静态配置 / 动态发现 | **静态配置** | 早期平台数少，简单可靠 |
| 事件路由存储 | 配置文件 / 数据库 | **数据库** | 与 cf-lottery 一致，支持多租户动态配置 |
| 入站处理方式 | 统一处理器 / 按平台独立 | **统一 InboundHandler** | 保持平台无关性，新平台只需实现 Adapter |

## 11. 风险与注意事项

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 平台 API 限频（QQ/Telegram） | 中 | 消息队列 + 限速器，批量发送间隔控制 |
| 消息模板注入攻击 | 低 | Handlebars 无代码执行，渲染时转义 HTML |
| 平台适配器故障 | 中 | 熔断器（Circuit Breaker），降级到文本消息 |
| Webhook 重复投递 | 低 | cf-lottery 已有去重机制（eventId + deliveryId 唯一约束） |
| 多平台消息顺序混乱 | 低 | 每个平台独立队列，不保证跨平台顺序 |
| 许可证污染（AGPL-3.0） | 高 | **只参考设计不复制代码**，zhenxun_bot 的 AI 接口设计可参考，但实现必须自研 |
