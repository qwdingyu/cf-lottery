# 167 嫁接层顶层设计：平台抽象与 Webhook 统一体系

> 日期：2026-08-09（修正版 2026-08-09）
> 定位：在 cf-lottery 中构建平台无关的嫁接层（Grafting Layer），抽象 QQ/Telegram/其他社交平台，
>       通过 Webhook 形成统一的事件驱动整体
> 范围：**仅限 cf-lottery**，不涉及 cf-shop
> 方法：基于 cf-lottery 现有 webhook 代码（integration.ts）扩展，
>       吸收 zhenxun_bot 的渲染库和调度器，参考 qqbot 的意图路由设计
> 修正说明：基于 2026-08-09 对 cf-lottery 全部源码的代码级审查，更正了架构定位、模板引擎选择、平台适配模式

## 0. 核心结论

**cf-lottery 的 webhook 系统已经完成了 60% 以上的工作**——事件定义、入队、签名、投递、重试、审计、入站事件处理全部完整实现。
剩下的 40% 是构建一个「消息模板渲染层」和「平台连接器」，将 webhook 事件的目标从「一个 HTTP URL」扩展为「一个平台目标（QQ群/Telegram频道）」。

**不需要推翻 cf-lottery 的 webhook 系统，也不需要在外部独立部署嫁接服务。嫁接层是 cf-lottery 内部的路由扩展，共用同一个 VPS 进程。**

## 3. 核心接口设计

### 3.1 平台抽象接口

> 修正要点：cf-lottery 全部使用函数式模式（integration.ts 无 class 定义）。平台适配器也用函数式，
> 不引入 class。模板引擎用 cf-lottery 已有的 `interpolate()`（{{variable}} 替换，HTML 安全），不引入 Handlebars。

```typescript
// ============================================================
// 平台抽象接口（函数式，对齐 cf-lottery 现有 integration.ts 风格）
// ============================================================

/** 平台标识（早期只实现 qq，telegram 为扩展目标） */
type PlatformType = "qq" | "telegram";

/** 平台目标：一个平台上的具体接收目标 */
interface PlatformTarget {
  platform: PlatformType;
  targetId: string;      // QQ 群号 / Telegram Chat ID
  name: string;
  config?: Record<string, unknown>;
}

/** 平台消息：平台适配器的输出 */
interface PlatformMessage {
  platform: PlatformType;
  targetId: string;
  type: "text" | "image" | "card";
  text?: string;
  imageUrl?: string;
  cardData?: Record<string, unknown>;
  buttons?: Array<{ text: string; action: string; url?: string }>;
}

/** 平台适配器（函数式，非 class） */
type PlatformAdapter = {
  readonly platform: PlatformType;
  send(message: PlatformMessage): Promise<{ messageId: string }>;
  sendBatch(messages: PlatformMessage[]): Promise<Array<{ messageId: string }>>;
};

/**
 * 平台适配器注册表：platform → adapter
 * 通过此表路由，新增平台只需实现 send/sendBatch 并在注册表登记。
 */
const platformAdapters: Record<PlatformType, PlatformAdapter> = {
  qq: qqAdapter,         // → NapCatQQ HTTP API
  telegram: telegramAdapter, // → Telegram Bot API（P3 扩展）
};

/** 入站事件：来自平台的用户操作（NapCatQQ 消息事件 → 统一结构） */
interface InboundEvent {
  platform: PlatformType;
  sourceId: string;         // QQ 群号 / Telegram Chat ID
  userId: string;           // 用户在该平台的 ID
  eventType: "message" | "command" | "callback" | "member_join" | "member_leave";
  text?: string;
  command?: string;         // 命令名（如 /checkin）
  args?: string[];          // 命令参数
  raw?: unknown;            // 原始数据
}

/** 统一事件（cf-lottery webhook 出站 payload 的结构） */
interface UnifiedEvent {
  id: string;
  type: string;
  createdAt: string;
  tenantId: string;
  data: Record<string, unknown>;
}

/** 事件 → 平台目标映射（扩展自 webhookConfigs，新增 platformType/targetId） */
interface EventRoute {
  eventType: string;           // cf-lottery 事件类型
  targets: PlatformTarget[];
  templateId?: string;
  active: boolean;
}

/** 消息模板（用 interpolate，不用 Handlebars） */
interface MessageTemplate {
  id: string;
  platform: PlatformType;
  eventType: string;
  template: string;            // interpolate 模板（{{var}}）
  messageType: "text" | "card";
  isDefault: boolean;
}
```

## 6. 消息模板系统

> 修正要点：cf-lottery 已使用 `interpolate()`（来自 `@usethink/cf-core/features/email`），
> 轻量 `{{variable}}` 替换，HTML 安全，无代码执行风险。不需要引入 Handlebars。

### 6.1 模板格式

使用 `interpolate(template, data)`，模板语法为 `{{variableName}}`：
- 只支持顶层变量替换，不支持 `{{#each}}` 循环
- 循环逻辑在代码中处理（`data.map().join('\n')` 后传入模板）
- HTML 自动转义（escapeHtml 内置）

### 6.2 模板示例

```typescript
// src/services/templates/draw_published.ts — QQ 群文本模板
export default `🎉 新活动上线！

📌 {{title}}
{{description}}

⏰ {{startAt}} ~ {{endAt}}
🔗 参与链接：{{url}}`;

// src/services/templates/draw_completed.ts — QQ 群文本模板
export default `🎉 开奖啦！

活动：{{title}}
总参与人数：{{participantCount}}
中奖人数：{{winnerCount}}

🥇 中奖名单：
{{winnersList}}

🔗 查看详情：{{resultUrl}}`;

// 使用方式：代码中先构建 winnersList，再传入 interpolate
import { interpolate } from "../../services/email-service";

const winnersList = winners.map(w => `  🏆 ${w.name} - ${w.prize}`).join('\n');
const message = interpolate(template, {
  title: draw.title,
  participantCount: String(count),
  winnerCount: String(winners.length),
  winnersList,
  resultUrl: `https://lottery.example.com/draw/${draw.id}`,
});
```

### 6.3 模板注册模式

沿用 cf-lottery 现有 `email-service.ts` 的模板注册模式：

```typescript
// src/services/templates/index.ts
import drawPublishedQQ from "./draw_published_qq";
import drawCompletedQQ from "./draw_completed_qq";
import checkinSuccessQQ from "./checkin_success_qq";
import spinResultQQ from "./spin_result_qq";

type PlatformTemplateKey = `${WebhookEventType}_${PlatformType}`;

const templates: Record<PlatformTemplateKey, string> = {
  "draw.published_qq": drawPublishedQQ,
  "draw.completed_qq": drawCompletedQQ,
  "entry.created_qq": checkinSuccessQQ,
  "outcome.assigned_qq": spinResultQQ,
  // ... 后续扩展
};

export function renderTemplate(eventType: string, platform: PlatformType, data: Record<string, string>): string {
  const key = `${eventType}_${platform}` as PlatformTemplateKey;
  const tpl = templates[key];
  if (!tpl) return JSON.stringify(data); // 无模板时回退到 JSON
  return interpolate(tpl, data);
}
```

## 7. 平台适配器实现指南

### 7.1 QQ 适配器（基于 NapCatQQ，函数式）

> 修正要点：cf-lottery 是函数式代码库，适配器也用函数创建，不引入 class。
> Telegram 适配器是 P3 扩展，此处仅给出接口占位。

```typescript
// src/services/platform/qq-adapter.ts
import type { PlatformMessage } from "./types";

/** NapCatQQ HTTP API 客户端（轻量封装） */
export function createNapCatClient(env: { napcatUrl: string; napcatToken?: string }) {
  async function request(path: string, body: Record<string, unknown>) {
    const res = await fetch(`${env.napcatUrl}${path}`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        ...(env.napcatToken ? { Authorization: `Bearer ${env.napcatToken}` } : {}),
      },
      body: JSON.stringify(body),
    });
    if (!res.ok) throw new Error(`NapCatQQ ${path} failed: ${res.status}`);
    return res.json();
  }
  return {
    sendGroupMessage(groupId: string, text: string) {
      return request("/send_group_msg", { group_id: groupId, message: text });
    },
    sendGroupImage(groupId: string, url: string) {
      return request("/send_group_msg", { group_id: groupId, message: `[CQ:image,file=${url}]` });
    },
    // 群成员列表（用于 /roster 白名单校验）
    getGroupMemberList(groupId: string) {
      return request("/get_group_member_list", { group_id: groupId });
    },
  };
}

// src/services/platform/adapters.ts
import type { PlatformAdapter } from "./types";
import { createNapCatClient } from "./qq-adapter";

/** 创建 QQ 适配器 */
export function createQQAdapter(env: { napcatUrl: string; napcatToken?: string }): PlatformAdapter {
  const napcat = createNapCatClient(env);
  return {
    platform: "qq",
    async send(message: PlatformMessage) {
      if (message.type === "image" && message.imageUrl) {
        const res = await napcat.sendGroupImage(message.targetId, message.imageUrl);
        return { messageId: String(res.message_id || crypto.randomUUID()) };
      }
      // 默认文本
      const res = await napcat.sendGroupMessage(message.targetId, message.text || "");
      return { messageId: String(res.message_id || crypto.randomUUID()) };
    },
    async sendBatch(messages) {
      const results = [];
      for (const m of messages) results.push(await this.send(m));
      return results;
    },
  };
}
```

### 7.2 入站命令处理（QQ 群 → cf-lottery API）

```typescript
// src/services/platform/inbound.ts
import { createQQAdapter } from "./adapters";
import type { InboundEvent } from "./types";

/** 命令映射表：命令 → { action, drawSlug }（docs/164 §7.2 配置模型） */
const COMMANDS: Record<string, { action: string; drawSlug: string }> = {
  "/签到": { action: "checkin", drawSlug: "group-a-checkin" },
  "/抽奖": { action: "spin", drawSlug: "group-a-lottery" },
  "/排行榜": { action: "leaderboard", drawSlug: "group-a-lottery" },
  "/我的奖品": { action: "my-result", drawSlug: "group-a-lottery" },
  "/分享": { action: "share", drawSlug: "group-a-lottery" },
  "/帮助": { action: "help", drawSlug: "" },
};

/** 处理一条 QQ 群消息事件 → 调用 cf-lottery 公开 API → 返回回复 */
export async function handleInboundEvent(
  event: InboundEvent,
  cfLottery: { baseUrl: string; apiKey: string },
): Promise<{ reply: string } | null> {
  if (event.eventType !== "message" || !event.text) return null;
  const trimmed = event.text.trim();
  const match = COMMANDS[trimmed];
  if (!match) return null;

  // QQ 号 → cf-lottery identityValue（"qq" 身份类型）
  const identityValue = event.userId;

  switch (match.action) {
    case "checkin": {
      const res = await fetch(`${cfLottery.baseUrl}/api/public/draws/${match.drawSlug}/verify-join`, {
        method: "POST",
        headers: { "Content-Type": "application/json", "x-cf-lottery-api-key": cfLottery.apiKey },
        body: JSON.stringify({ identityType: "qq", identityValue }),
      });
      const data = await res.json();
      return { reply: data.ok ? "✅ 签到成功！" : `❌ ${data.message || "签到失败"}` };
    }
    case "spin": {
      const res = await fetch(`${cfLottery.baseUrl}/api/public/draws/${match.drawSlug}/spin`, {
        method: "POST",
        headers: { "Content-Type": "application/json", "x-cf-lottery-api-key": cfLottery.apiKey },
        body: JSON.stringify({ identityType: "qq", identityValue, idempotencyKey: crypto.randomUUID() }),
      });
      const data = await res.json();
      if (!data.ok) return { reply: `❌ ${data.message || "抽奖失败"}` };
      return { reply: data.result?.won ? `🎉 恭喜中奖！${data.result.prizeName}` : `😅 未中奖，再来一次！` };
    }
    case "help":
      return { reply: "可用命令：/签到 /抽奖 /排行榜 /分享 /我的奖品" };
    default:
      return { reply: "暂不支持该命令" };
  }
}
```

## 10. 关键设计决策（修正版）

> 修正要点：Handlebars → interpolate，AI 引擎 → 移除（P2-P3），部署方式 → 内嵌到 cf-lottery。

| 决策 | 选项 | 选择 | 理由 |
| --- | --- | --- | --- |
| 嫁接层部署方式 | 独立服务 / 内嵌到 cf-lottery | **内嵌到 cf-lottery** | 减少部署复杂度，同进程通信避免网络延迟，与现有 webhook 引擎直接集成 |
| 消息模板引擎 | Handlebars / EJS / interpolate | **interpolate**（已有） | cf-lottery 已使用 `interpolate()`，HTML 安全，无代码执行风险，无需引入新依赖 |
| 平台适配器风格 | class / 函数式 | **函数式**（createAdapter） | 对齐 cf-lottery 现有代码风格（integration.ts 全部函数式），无 class 继承复杂性 |
| 平台适配器注册 | 静态配置 / 动态发现 | **静态配置**（Record<PlatformType, PlatformAdapter>） | 早期平台数少（只有 QQ），简单可靠，类型安全 |
| 事件路由存储 | 配置文件 / 数据库 | **数据库**（扩展 webhookConfigs） | 与 cf-lottery 一致，支持多租户动态配置，无需重启 |
| 入站处理方式 | 统一处理器 / 按平台独立 | **统一 InboundHandler** | 保持平台无关性，新平台只需实现适配器 |
| AI 引擎 | 本轮引入 / 后续按需 | **后续按需引入（P2-P3）** | cf-lottery 核心是抽奖活动引擎，AI 对话不是 MVP 必需，不阻塞上线 |

## 11. 风险与注意事项（修正版）

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 平台 API 限频（QQ 消息频率限制） | 中 | 消息队列 + 限速器，批量发送间隔控制（500ms/条） |
| 消息模板注入攻击 | 低 | `interpolate` 自动 HTML 转义，无代码执行风险 |
| NapCatQQ 连接故障 | 中 | 适配器熔断降级（文本消息替代图片），重试连接 |
| Webhook 重复投递 | 低 | cf-lottery 已有去重机制（eventId + deliveryId 唯一约束） |
| QQ 号风控（频繁发消息） | 中 | 控制消息频率，使用合并转发减少单条消息数 |
| 许可证污染（AGPL-3.0） | 高 | **只参考设计不复制代码**，zhenxun_bot 的渲染库/调度器只参考接口设计，实现必须自研 |
| 入站命令绕过身份验证 | 中 | 依赖 NapCatQQ 群成员列表校验，桥接侧不做用户身份信任 |
