# 108 同场额外次数与开奖加权打磨

> 日期：2026-08-04  
> 状态：已实施  
> 前置：docs/041（裂变设计）、docs/107（不接入 shop 会员推广码）

---

## 一、背景与目标

docs/041 落地了裂变配置、分享码、归因、开奖加权与排行榜 API，但审计发现：

1. **开奖加权忽略 `extraEntriesPerInvite`**：袋中票数写成 `1 + min(invited, maxExtra)`，管理端「每邀 N 次」无效。
2. **`my-viral-stats` 同样少算**：`extraEntriesEarned = min(joined, max)`，与管理端文案不一致。
3. **`ViralLeaderboard.vue` 未挂载**：公开页只有参与成功弹窗内的简版裂变卡，排行榜/进度长期不可见。
4. **进度条分子错误**：用「邀请人数 / max」而非「已赚额外 / max」。
5. **分享 URL 不一致**：`my-viral-stats` 返回 `/{slug}?ref=`，`POST /share` 返回 `/lottery/{slug}?ref=`；`GET .../ref/:code` 重定向到 `/{slug}` **丢掉 ref**，好友参与无法归因。

目标：同场「额外次数 / 开奖加权」全链路公式统一、UI 闭环、分享归因不丢，极致打磨后可运营。

---

## 二、统一公式（单一事实源）

新增 `src/services/lottery/viral-weight.ts`：

| 符号 | 含义 |
|------|------|
| `invited` | 有效邀请人数（`shareRecords.joinedCount` 聚合，非点击） |
| `perInvite` | `extraEntriesPerInvite`（默认 1） |
| `maxExtra` | `maxExtraEntries`（默认 10） |
| **extra** | `min(invited × perInvite, maxExtra)` |
| **drawWeight** | `1 + extra`（开奖袋中该 entry 出现次数） |

约束（与 041 一致，不改语义边界）：

- **不**写入额外 `lottery_entries`（不占 `maxParticipants`）
- 同一人仍只中一次（`seenEntryIds`）
- `candidateCount` 仍为真实参与人数
