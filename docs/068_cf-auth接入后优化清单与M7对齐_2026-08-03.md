# 068 cf-auth 接入后优化清单与 M7 对齐

> 日期：2026-08-03  
> 背景：lottery 已完成 cf-auth 生产接入（docs/067）；cf-auth 侧按 docs/013 落地 M7 Admin/限流。

## 一、接入过程复盘：仍可优化

| 优先级 | 项 | 说明 |
|--------|-----|------|
| P0 | 生产 `ADMIN_*` 配齐 | 之后 client 创建/禁用走 auth Admin，少用手写脚本 |
| P0 | 清理 lottery 残留 `LOGTO_*` secrets | 避免运维误用 |
| P1 | `TRUSTED_ORIGINS` 流程 | 每加 RP 改 auth 配置并 redeploy；文档已写入手册 014 |
| P1 | Google OAuth 控制台 URI | 仅绑 `auth.eforge.xyz` callback，勿混 workers.dev |
| P2 | 抽 RP 薄封装 | 多项目复制 `cf-auth-oauth` / provision 会漂移；可后续 monorepo 包 |
| P2 | 浏览器联调 checklist | authorize → callback → session 一页表（065/014 已有） |

## 二、与 cf-auth M7 的关系

- **协议层**：lottery 主路径已可用，不依赖 Admin。  
- **治理层**：第二、第三个项目应优先用 `auth.eforge.xyz/admin` 建 client（见 cf-auth docs/014/015）。  
- **限流**：auth 侧已对 sign-up / authorize / token 做 DB 限流；lottery 自身公开 API 限流仍用本仓 `rate-limit`。

## 三、建议动作（运维）

1. 在 cf-auth 配置 `ADMIN_EMAILS`（你的邮箱）并 redeploy。  
2. 打开 `/admin/clients` 核对 lottery 的 `client_id` 与 redirect。  
3. 新项目严格按 014 手册，**不要**共用 lottery 的 client_id。
