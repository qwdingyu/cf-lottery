# 活动页与模板选择 UX 审查（2026-08-09）

## 背景

用户要求对两条核心链路做 UX 审查：

1. 公众活动页 `https://lucky.eforge.xyz/lottery/af8fec27`（承载秒杀/批发/大转盘/刮刮乐/问卷/签到/预约/接龙等全部玩法）
2. 管理端 `https://lucky.eforge.xyz/admin/draws` 创建活动 → 选择活动模板

方法：**全部结论基于代码逐行核对 + 线上 curl 实测**，未实际渲染的部分标注为推断。审查日期 2026-08-09。

## 总体结论

代码已经过多轮 docs/NNN 驱动的 UX 迭代，成熟度高于一般 MVP：骨架屏、30s 静默轮询、OTP 冷却、iOS 16px 防缩放、safe-area、reduced-motion、诚实语义游戏壳（delayed 仪式短语 / instant 真奖）、支付订单恢复链路均已具备。**剩余问题集中在：部署层性能配置、模板选择弹窗的边界态、模板数据与 i18n/公开文案的串味。**

## 一、公众活动页（/lottery/:slug）

### 已到位（不重复投入）

- 加载：3 卡骨架屏（`LotteryView.vue:26-32`）；30s 静默轮询不闪骨架、失败不擦已有数据（`fetchDraws` :3167；`:3930`）
- 恢复：focus / online / visibilitychange 三通道即时刷新（`:3904-3912`）
- 参与状态刷新恢复：本机 hints + JWT 双轨回填（`hydrateJoinedStateFromSession` :3214）
- 输入：OTP 冷却倒计时、`inputmode="numeric"`、modal 输入 16px 防 iOS 自动缩放（lottery-page.css:588）
- 弹窗：移动端近似 bottom-sheet、safe-area-inset 适配（lottery-page.css:521-545）
- 动画：全部游戏组件覆盖 `prefers-reduced-motion`；转盘提交中 idle 慢转即时反馈（WheelGame.vue）
- 支付：订单快照 sessionStorage 恢复 + pending 轮询 + 履约失败客服 mailto 链路（payment-ux.ts）

### P1-1 静态资源未压缩、无缓存头（实测）

实测证据（2026-08-09 curl）：

```
GET /assets/index-BU6qB-P_.js  → 274,875B，无 Content-Encoding（客户端已声明 gzip, br）
GET /assets/vendor-ByyqpqUP.js → 108,057B，无 Content-Encoding
GET /assets/index-30DFLf7E.css → 61,442B，无 Content-Encoding
HTML /lottery/af8fec27         → 有 Content-Encoding: gzip（仅 HTML 被压缩）
所有 /assets/*                 → 无 Cache-Control 响应头
```

- 首屏传输 ~444KB 未压缩；gzip 后预计 ~130KB，brotli 更低。移动 4G 首屏多耗 1–2s。
- 文件名带内容 hash 却不发 `Cache-Control: immutable`，**每次回访都重新验证/下载**。
- 修复（VPS nginx，不改代码）：
  - `gzip_types` 补 `text/javascript application/javascript text/css`（或直接开 brotli 模块）
  - `location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }`

### P1-2 index.html 空壳白屏

`frontend/index.html:23` 的 `<div id="app"></div>` 完全为空。JS bundle（未压缩 444KB）下载执行期间用户看到纯白屏，骨架屏要等 Vue 挂载后才出现。
修复：在 index.html 内联最小 CSS + 一个品牌色背景/居中转圈，~1KB 成本。

### P1-3 分享卡片无活动信息（OG 为平台级静态文案）

`frontend/index.html:14-21` 的 og:title/description 是固定「抽奖活动平台」。活动链接分享到微信/Telegram/IM 时不显示活动名、奖品图——而分享裂变（viral ?ref=）是这个平台的核心增长动作。
修复选项（按成本）：
- a. VPS 网关对 `/lottery/:slug` 的 HTML 请求做 per-activity meta 注入（查公开 API 拼 og:title/og:image）
- b. 至少加一张品牌 og:image 静态图

注：`document.title` 客户端已更新（fetchDraws :3186），只影响标签页标题，不影响爬虫。

### P2-1 画布游戏未适配 devicePixelRatio（Retina 模糊）

- `WheelGame.vue:35` `canvasSize = 320` 固定 bitmap，CSS 拉到 `min(320px, 82vw)`；dpr=3 手机上等效放大 3 倍，扇面文字发虚
- `ScratchGame.vue` canvas 固定 300×200，CSS 铺满 `min(300px, 92vw)`，涂层文字同样模糊
- 修复：挂载时 `canvas.width = cssSize * dpr; ctx.scale(dpr, dpr)`，指针坐标换算已有 `pointerToCanvas` 比例映射，兼容

### P2-2 禁用双指缩放（无障碍）

`index.html:7` `maximum-scale=1.0, user-scalable=no`。输入框已全部 16px（防聚焦缩放的前提已满足），放开缩放不会引入 iOS 聚焦缩放问题，却能让视障用户放大页面。建议改为 `width=device-width, initial-scale=1.0`。

### P2-3 问卷 radio 字段渲染为 select 下拉

`LotteryView.vue:196`：`field.type === 'select' || field.type === 'radio'` 走同一 `<select>` 分支。管理端配置「单选（radio）」语义，参与者看到的是下拉框。选项 ≤4 时建议渲染为 radio 组（与投票区 vote-option 样式一致），减少一次点按。

### P2-4 弹窗无 body 滚动锁定

全前端无 `document.body.style.overflow` 代码。弹窗（结果/支付/登录）打开时，iOS 边缘橡皮筋滚动会穿透到背景页。修复：弹窗 open/close 时切 `document.body.style.overflow = 'hidden' / ''`（注意多弹窗计数）。

### P3-1 秒杀「未开始」无提醒出口

FlashSaleGame `phase === 'upcoming'` 时按钮禁用显示「未开始」，倒计时到点自动翻可点（本地秒针驱动）。服务端 participation.ts:169 有时间窗硬校验，时钟偏差用户会收到错误 toast，可接受。如需转化可考虑「开抢提醒」订阅，非必须。

## 二、管理端：创建活动 → 选择活动模板

### 现状链路（已核对）

- 模板定义：`src/lib/activity-templates.ts`，共 **10 个模板**：大转盘抽奖（延迟）/刮刮卡抽奖/即时大转盘/报名接龙/资料领取/问卷调研/投票评选/每日签到/审核申请/限时抢购
- 接口：`GET /api/admin/templates`，按系统配置 `enabled_activity_kinds` 服务端过滤（admin-lottery.ts:529-535，实测未授权 401）
- 弹窗：`AdminLotteryView.vue:1242-1258`，icon + name + desc + category 网格卡片
- 应用：`applyTemplate`（:2941）预填名称/描述/时间预设 1d/奖项占位行/秒杀默认值，焦点落到步骤 4
- 字段收口：`template-field-visibility.ts` 对 3 个高频模板隐藏无关区块；编辑已有活动强制全量
- Onboarding 闭环：建租户后 `?new=true` 自动开模板弹窗（:3711）

### P1-A 模板弹窗无加载态、无失败兜底（实测代码确认）

`openTemplatePicker`（:2913）调用 `fetchTemplates()` **不 await**，随后立即打开弹窗：

```ts
function openTemplatePicker() {
  if (templates.value.length === 0) {
    fetchTemplates()   // 未 await
  }
  showTemplateModal.value = true
}
```

- 首次打开：用户看到一个 **720px 宽的空弹窗**，持续整个网络往返
- fetch 失败：`templates.value = []` 且注释写「允许用户直接创建空白活动」，**但弹窗里没有任何空白创建入口**（见 P1-B），用户面对永久空弹窗
- 修复：弹窗内加骨架卡/loading + 失败重试按钮 + 「空白创建」卡

### P1-B 空白创建入口在重构中丢失（git 实证）

- `admin-lottery-page.css:338` 仍有 `.template-card--blank`（虚线卡样式）
- 全 frontend `.vue` 文件 **无任何引用**（git grep 确认）
- git log -S 显示该卡片在 `afbe25c` 引入、`1f8e6a0 refactor: 大文件按模块拆分` 后消失——**重构误删**

影响：想自定义活动的运营者必须任选一个模板再逐字段改。更危险的是误选「限时抢购」会默认带入 `flashSalePaymentRequired: true`（activity-templates.ts flash-sale-rush defaults），虽有发布门禁拦截，但新手会被支付配置要求搞懵。
修复：恢复空白创建卡（applyTemplate 传空 defaults 或直接 `form = emptyForm()` 路径）。

### P1-C 模板 hints 定义了但从不展示

后端每个模板精心编写了 3–4 条 `hints`（如限时抢购的「直付模式必须配置 priceCents、EasyPay/ZPay 支付设置和单一卡密码池」），全前端 grep **无任何渲染**。这些正是新手最需要的关键检查项。
修复：applyTemplate 后在创建表单顶部（adminCreatePathFromTemplate 提示条旁）列出该模板 hints。

### P1-D 模板名称/描述/提示后端硬编码中文（i18n 断裂）

- 管理端 UI 有 zh-CN / en 双语；模板数据是后端中文字符串
- 英文界面下模板卡片全中文；且 `applyTemplate` 把中文 name/description 直接写进 `form.name`/`form.description` → 英文租户创建的活动**公开页标题/描述也是中文**
- 修复：模板返回按 Accept-Language 或前端 locale 二次请求；或模板字段改 i18n key 前端翻译

### P1-E 模板 description 预填为「公开活动描述」（线上实测证实）

模板 description 是**写给运营者看的模板说明文**（「转盘是参与互动壳：用户点击完成登记……适合福利放送、粉丝互动、节日活动。」），却被预填进公开页展示的活动描述。

线上实证（2026-08-09 curl /api/public/draws/af8fec27）：该活动 title=「大转盘抽奖」、description=模板说明原文，运营者一字未改直接发布，**C 端参与者看到的就是这段运营向文档**。

修复（二选一）：
- a. description 不预填，仅在模板卡片展示
- b. 模板结构拆分 `description`（运营向，卡片用）与 `publicDescription`（C 向，预填用）

### P2-A 缺「预约」模板（能力已有，模板缺位）

- 后端已支持 `reservation`：draws.ts:330 映射 calendar 体验、:353 capacity_assignment；enabled_kinds 默认含 reservation（p0-flow.test.ts:54）；GameRegistry 'calendar' 别名 → SubmitGame
- 但 ACTIVITY_TEMPLATES 无预约模板。用户心智中「预约」（课程/门店/号源）是明确场景，与接龙语义不同
- 批发已由 flashSale.pricingTiers 覆盖（flash-sale-rush 模板内），可不单独建模板，但 hints 未展示导致该能力不可见（见 P1-C）

### P2-B 模板卡片无关键参数预览

卡片只有 icon/名称/描述/分类。「大转盘抽奖」vs「即时大转盘」的核心区别（何时出结果、是否需要 weight 配置）要靠读长描述。建议卡片加 2–3 个参数 chips：开奖方式（手动/定时/当场）、是否需奖品、是否涉及付费。

### P2-C 其他改进点

- name 预填=模板名 → 同租户多活动同名（线上实例即如此）；建议留空 + placeholder 显示模板名
- 选错模板无返回：创建弹窗内无「换模板」入口，只能关掉重选（已填内容被覆盖）
- 10 个模板平铺无分类过滤；模板继续增加时需要
