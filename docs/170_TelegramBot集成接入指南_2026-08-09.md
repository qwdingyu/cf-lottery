## 一、概述

本文档描述如何将 **Telegram Bot** 作为新消息平台接入 cf-lottery 平台层。
当前 P0 已支持 QQ (NapCat)，本指南提供 Telegram 的完整接入步骤，确保扩展时无需修改现有共享代码。

### 1.1 架构位置

```
Telegram Bot API        QQ (NapCat) HTTP
     │                      │
     ▼                      ▼
platform-telegram.ts   platform-qq.ts       ← 入站路由（每平台一个文件）
     │                      │
     └──────────┬───────────┘
                ▼
          inbound.ts          ← 入站标准化（平台无关）
                │
                ▼
          commands.ts         ← 命令执行（平台无关）
                │
                ▼
          delivery.ts         ← 出站分发（平台无关）
                │
     ┌──────────┼───────────┐
     ▼          ▼           ▼
telegram-adapter.ts  qq-adapter.ts  ...  ← 适配器（每平台一个文件）
     │          │
     ▼          ▼
Telegram API   NapCat API
```

### 1.2 扩展原则

- **平台名只能出现在**：`types.ts` 联合类型、适配器文件、路由文件、`adapter-factory.ts` 映射表、本指南
- **共享代码不得出现任何平台名**：`commands.ts`、`inbound.ts`、`delivery.ts`、`admin-lottery-platform.ts` 已全部平台无关化
- **新增平台只需**：实现适配器 → 注册一行 → 创建路由 → 编写测试，无需修改共享代码

  botToken: string,
  fetcher: typeof fetch = fetch,

  const apiBase = `https://api.telegram.org/bot${botToken}`;

  return {

      const chatId = message.targetId; // Telegram chat_id（群组 ID 以 -100 开头）
      // 暂不支持 image/card 类型，仅 text

          disable_web_page_preview: true,
        }),

        const errBody = await res.text().catch(() => "");

## 十三、与 QQ 平台的差异对比

| 维度 | QQ (NapCat) | Telegram Bot |
|------|------------|--------------|
| 出站方式 | NapCat HTTP API (`send_group_msg`) | Telegram Bot API (`sendMessage`) |
| 入站方式 | NapCat 反向 WebSocket 或 HTTP 上报 | Telegram Bot API Webhook |
| 出站配置 | `baseUrl`（NapCat 服务器地址） | `botToken`（Bot API 令牌） |
| 入站鉴权 | 共享 token（NapCat 上报头） | URL secret 参数 |
| 适配器提供方 | `napcat` | 无（直接调用 Bot API） |
| 消息格式 | CQ 码 | HTML/Markdown |
| 群组 ID 格式 | 数字字符串（如 `123456`） | 负数字符串（如 `-1001234567890`） |
| 出站速率限制 | 无明确限制 | 约 20 条/分钟/chat |

## 十四、常见问题

### Q: Telegram Bot 收不到消息？

1. 检查 BotFather 中 `/setprivacy` 是否 Disabled
2. 检查 Bot 是否在群中（Bot 需要先被加入群组）
3. 检查 webhook 配置：`getWebhookInfo` 应返回 `ok: true` 和 `pending_update_count: 0`
4. 检查 VPS 防火墙是否开放 443 端口（Telegram 只连接 HTTPS）

### Q: 发送消息失败 400？

1. 检查 botToken 格式是否正确
2. 检查 chat_id 格式（群组 ID 以 `-100` 开头）
3. 检查消息是否超过 4096 字符
4. 检查 HTML 标签是否正确闭合

### Q: 收到 429 Too Many Requests？

1. 适配器需实现指数退避重试
2. 检查是否有多个并发请求发送到同一 chat
3. 降低发送频率
| 数据库泄露 | 攻击者获取数据库可读取所有 botToken | 规划 P1 加密存储闭环 |
| 中间人攻击 | 请求 Telegram API 时 HTTPS 保证传输安全 | 使用 `https://` 确保 TLS |

### 9.2 Webhook 鉴权

| 机制 | 说明 |
|------|------|
| 入站密钥 | 每个平台目标有独立 inboundSecret，URL 中传递 |
| IP 校验 | P1 可增加 Telegram 服务器 IP 范围白名单（`149.154.160.0/20` 等）|
| 请求签名 | Telegram 不支持请求签名，依赖 URL secret 鉴权 |

### 9.3 速率限制

Telegram Bot API 限制：
- 每 chat 约 20 条消息/分钟
- 超出返回 HTTP 429
- 适配器应实现指数退避（至少 3 次重试）

const MAX_TELEGRAM_MSG_LENGTH = 4096;

async function sendLongMessage(
  apiBase: string,
  chatId: string,
  text: string,
  fetcher: typeof fetch,
): Promise<number[]> {
  const messageIds: number[] = [];
  for (let i = 0; i < text.length; i += MAX_TELEGRAM_MSG_LENGTH) {
    const chunk = text.slice(i, i + MAX_TELEGRAM_MSG_LENGTH);
    const res = await fetcher(`${apiBase}/sendMessage`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ chat_id: chatId, text: chunk, parse_mode: "HTML" }),
    });
    const data = (await res.json()) as { ok: boolean; result?: { message_id: number } };
    if (data.result?.message_id) messageIds.push(data.result.message_id);
  }
  return messageIds;
}

### 5.2 添加 Telegram 配置校验

`normalizeAdapterConfig` 已改为平台感知，`validateTelegramAdapterConfig` 函数已实现（见本文档关联的上一轮改造）：

```typescript
function validateTelegramAdapterConfig(
  raw: Record<string, unknown>,
): { ok: true; value: Record<string, string> } | { ok: false; message: string } {
  const botToken = typeof raw.botToken === "string" ? raw.botToken.trim() : "";
  if (!botToken) return { ok: true, value: {} };
  // Telegram Bot API token 格式：<bot_id>:<auth_key>
  if (!/^\d+:[A-Za-z0-9_-]+$/.test(botToken)) {
    return { ok: false, message: "Telegram botToken 格式无效，应为 <bot_id>:<auth_key>" };
  }
  return { ok: true, value: { botToken } };
}
```

2. 发送 `/newbot`，按提示设置 bot 名称和 username
3. BotFather 返回 bot token，格式：`<bot_id>:<auth_key>`，例如 `123456789:ABCdefGHIjklmNOPqrstUVwxyz`
4. 发送 `/setprivacy` 设为 **Disabled**（让 bot 能看到群组中所有消息；否则只能看到以 `/` 开头的命令）
5. 发送 `/setjoingroups` 设为 **Enabled**
6. 记录 bot token，后续配置到平台目标 adapterConfig 中

### 2.2 Webhook 域名

- 需要公网 HTTPS 域名（Telegram 要求 HTTPS，不支持自签名证书）
- 域名指向 cf-lottery 部署的 VPS 或 Cloudflare Worker
- 示例：`https://lottery.example.com/api/platform/telegram`
