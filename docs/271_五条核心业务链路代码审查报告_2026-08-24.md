## 逐链路审查结论

### 1. 排行榜奖励发放（leaderboard-rewards.ts）✅ 通过

| 检查项 | 结果 | 说明 |
|---|---|---|
| 聚合口径 | ✅ | 按 sharerEntryId SUM(joinedCount)，与公开榜 aggregateViralInviteCounts 同口径 |
| 幂等标记 | ✅ | leaderboardRewardedAt CAS + leaderboardRewardedCount 持久化已发张数（docs/270） |
| 码池不足容错 | ✅ | 回滚 leaderboardRewardedAt，下次触发按差额续发（docs/270 修复） |
| maxSpins 裁剪 | ✅ | granted ≤ maxSpinsPerEntry 不变量，超出部分 refId 留 :capped 审计 |
| 并发安全 | ✅ | 先 CAS 标记后发放，rowsAffected 验证完整性 |
| verdict 累加 | ✅ | 事务外累加（R-9 修复），withDbTransaction 重跑不重复计数 |
| tie-break | ✅ | compareViralLeaderboard 与公开榜同一比较函数，先到先得 |

**P4 备注**：bonus_spin 路径直接 SQL 递增 spinsTotalGranted（无显式 CAS），依赖 SQLite 单写事务串行化。当前单实例 VPS 下安全，但若迁移分布式数据库需补充。

### 2. 归因与奖励触发（participation.ts → maybeTriggerReward）✅ 通过

| 检查项 | 结果 | 说明 |
|---|---|---|
| 路径清晰度 | ✅ | 3 条路径 [1][3][4]，路径 [2] 已在 docs/255 P1-2 收敛删除 |
| 事务边界 | ✅ | 所有奖励路径在 joinDraw 同事务内，参与不因奖励失败回滚 |

### 4. 幂等标记机制（referral-rewards-engine.ts）✅ 通过

| 检查项 | 结果 | 说明 |
|---|---|---|
| 三层防护 | ✅ | 幂等层（rewardMilestonesGranted）→ 出口 CAS → 总量约束 |
| 整/部分标记 | ✅ | 整标记=足额发完；部分标记 rewardId:N=已发 N 份，续发差额 |

| 维度 | 行业标准 | cf-lottery 实现 | 对齐度 |
