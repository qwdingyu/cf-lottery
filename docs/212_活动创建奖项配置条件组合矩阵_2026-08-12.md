# 212 活动创建——奖项配置条件组合矩阵

> 日期：2026-08-12
> 背景：活动创建流程中「奖项配置」相关的条件在多个位置（前端奖档区显示、前端 saveDrawTiers 调用、后端 tiers 保存接口、后端发布检查）各有判断，曾因条件不一致导致「限时抢购无法绑定卡密奖品」「资料领取保存奖项失败」等问题。本文固化**完整条件组合矩阵**，确保四层判断永久一致。
> 方法：逐文件代码验证（AdminLotteryView.vue / template-field-visibility.ts / flash-sale-readiness.ts / admin-lottery-draw-ops.ts / publish-check-service.ts / growth-config.ts）。

---

## 0. 结论先行

**「奖项配置」仅两类活动需要**：
1. **lottery（抽奖）**——奖项 = 中奖奖档
2. **claim + flash_sale（直付秒杀/限时抢购）**——奖项 = 绑定唯一卡密奖品（发卡目标）

**其他所有活动（资料领取、问卷、投票、报名、签到、审核、预约等）不需要奖项配置**，前端不显示奖档区、不调用保存接口、后端拒绝保存、发布检查跳过。

**四层判断（奖档区显示 / saveDrawTiers 调用 / 后端保存 / 发布检查）必须永远一致**，任何一层改动需同步其余三层。

## 1. 完整条件组合矩阵

### 1.1 按 activityKind × experienceType 组合

| activityKind | 中文含义 | experienceType | 奖档区显示 | saveDrawTiers 调用 | 后端保存奖项 | 发布检查奖项 | 说明 |
|:---:|:---|:---:|:---:|:---:|:---:|:---:|:---|
| **lottery** | 抽奖 | wheel/slot/scratch/card/grid 等 | ✅ | ✅ | ✅ 允许 | ✅ validateLotteryPrizes | 抽奖奖档（延迟开奖/即时 spin） |
| **claim** | 领取 | **flash_sale** | ✅ | ✅ | ✅ 允许 | ✅ validateFlashSalePayment（仅 paymentRequired） | 直付秒杀/限时抢购，绑定唯一卡密奖品 |
| **claim** | 领取 | reveal | ❌ | ❌ | ❌ 拒绝 | 跳过 | 资料领取/领券，无奖项需求 |
| **claim** | 领取 | 其他（submit 等） | ❌ | ❌ | ❌ 拒绝 | 跳过 | 理论上不出现（claim 仅 flash_sale/reveal） |
| signup_chain | 报名接龙 | list | ❌ | ❌ | ❌ 拒绝 | 跳过 | 报名接龙 |
| survey | 问卷调研 | form | ❌ | ❌ | ❌ 拒绝 | 跳过 | 问卷调研 |
| vote | 投票评选 | ballot | ❌ | ❌ | ❌ 拒绝 | 跳过 | 投票评选 |
| checkin | 每日签到 | submit | ❌ | ❌ | ❌ 拒绝 | 跳过 | 每日签到 |
| approval | 审核申请 | form | ❌ | ❌ | ❌ 拒绝 | 跳过 | 审核申请 |
| reservation | 预约报名 | calendar | ❌ | ❌ | ❌ 拒绝 | 跳过 | 预约报名 |

### 1.2 按「是否需要奖项」分类

```
需要奖项（四层全部放行）：
  lottery（抽奖，任意体验）
  claim（领取）+ flash_sale（直付秒杀/限时抢购）

不需要奖项（四层全部跳过/拒绝）：
  claim（领取）+ reveal（资料领取/领券）
  claim（领取）+ 其他体验
  signup_chain（报名接龙） / survey（问卷调研） / vote（投票评选）
  / checkin（每日签到） / approval（审核申请） / reservation（预约报名）
```

## 2. 四层判断的具体实现

### 2.1 前端：奖档区显示（AdminLotteryView.vue 第 1148 行）

```html
<div v-if="editorVisibility.tiers && (form.activityKind === 'lottery' || (form.activityKind === 'claim' && form.experienceType === 'flash_sale'))" class="field-span-2">
```

- `editorVisibility.tiers`：模板差异可见性（FLASH_SALE_RUSH_VISIBILITY.tiers 必须为 true，docs/204 记录）
- `activityKind === 'lottery'`：抽奖
- `claim && experienceType === 'flash_sale'`：直付秒杀

### 2.2 前端：saveDrawTiers 调用时机（AdminLotteryView.vue 创建/编辑分支）

```typescript
// 创建分支（第 3905 行）与编辑分支（第 3890 行）：
if (form.value.activityKind === 'lottery' || (form.value.activityKind === 'claim' && form.value.experienceType === 'flash_sale')) {
  await saveDrawTiers(drawId)
}
```

- 只在需要奖项的活动调用
- `saveDrawTiers` 内部还有 `validTiers.length === 0 return`（无有效奖档时跳过）

### 2.3 后端：tiers 保存接口（admin-lottery-draw-ops.ts 第 506-515 行）

```typescript
const isFlashSaleDirect = draw.activityKind === "claim" && String(draw.experienceType || "") === "flash_sale";
if (draw.activityKind !== "lottery" && !isFlashSaleDirect) {
  return fail(c, "只有抽奖活动或直付秒杀需要配置奖项", 400);
}
```

- 错误信息明确指向两类活动
- 其余活动 400 拒绝

### 2.4 后端：发布检查（publish-check-service.ts）

| 检查函数 | 条件 | 检查内容 |
|:---|:---|:---|
| `validateLotteryPrizes`（第 469 行） | `activityKind !== "lottery" return` | 抽奖奖项：至少 1 个奖档、奖品有效、中奖名额 > 0、码类库存 |
| `validateFlashSalePayment`（第 111 行） | `!paymentRequired return` | 直付秒杀：priceCents、收款方式、恰好 1 个 active 卡密奖品、独立奖品池 |

### 2.5 前端：发布清单（flash-sale-readiness.ts）

```typescript
const needCodePrize = input.enableFlashSale === true && input.flashSalePaymentRequired === true
// codePrize 检查项：仅直付模式要求恰好 1 个 active 卡密奖品；导流模式视为完成
done: !needCodePrize || selectedCodePrizeCount === 1,
```

- 与后端 `validateFlashSalePayment` 一致（仅 paymentRequired 时检查）

## 3. 边界情况与保护机制

### 3.1 experienceType 下拉框必须含 flash_sale 选项（已修复 66127c6）

- 下拉框选项：wheel/slot/scratch/card/list/queue/form/ballot/calendar/checkin/**flash_sale**/reveal/grid/submit
- 缺少 flash_sale 会导致：直付秒杀活动编辑时下拉框显示空白，切换体验后无法改回
- 直付秒杀体验类型来源：①「限时抢购」模板默认；② 手动选择

### 3.2 handleActivityKindChange 保护直付秒杀（已修复 66127c6）

```typescript
const currentExp = form.value.experienceType
if (!(kind === 'claim' && currentExp === 'flash_sale')) {
  form.value.experienceType = defaultExperienceForActivity(kind, form.value.participationMode || 'open')
}
```

- 切换 activityKind 时，如果目标为 claim 且当前体验是 flash_sale，保留（不重置为 reveal）
- 防止「切一下活动类型就把直付秒杀配置悄悄丢失」

### 3.3 直付秒杀的奖项语义（非抽奖奖档）

| 维度 | lottery 奖档 | claim + flash_sale 奖项 |
|:---|:---|:---|
| 用途 | 中奖档次（多档） | 绑定唯一卡密奖品（发卡目标） |
| 数量 | 1~10 档 | **恰好 1 个**（publish-check 强校验） |
| 中奖份数（winnerCount） | 各档名额 | 卡密库存数量 |
| 权重（weight） | instant 模式使用 | 不适用（claim 非 instant spin） |

### 3.4 编辑回填的完整性

- `handleEdit`：回填 `tiers`（从 `/api/admin/draws/:id` 的 detail.tiers）+ `experienceType`（draw.experienceType）+ flashSale 配置（growthFieldsFromDraw）
- `growthFieldsFromDraw`：完整回填 enableFlashSale/flashSaleStockLimit/flashSalePaymentRequired/flashSalePricingTiers 等
- 二次保存不擦掉配置（`buildPromotionConfigPayload` 编辑态始终带 experience 块）
