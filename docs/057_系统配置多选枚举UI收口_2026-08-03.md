# 057 系统配置多选枚举 UI 收口

> 文档编号：057  
> 创建时间：2026-08-03  
> 状态：已落地  
> 关联：平台运营 `enabled_activity_kinds` / `enabled_participation_modes`；055a 管理端体验增量外的独立收口

---

## 一、背景

L3 平台配置里两项长期以**逗号分隔纯文本**编辑：

- `enabled_activity_kinds` — 可创建的活动类型  
- `enabled_participation_modes` — 可创建时使用的参与模式  

运营易拼错 token、顺序混乱、全清空后创建侧全部被拒，且无中文标签。

早期增量（`9723002` / `0b0b450`）已在定义与 `ConfigField` 上引入复选框，但闭环不完整：

| 缺口 | 风险 |
|------|------|
| `SystemConfigDefinition` 无 `enum` 类型 | 定义与校验脱节 |
| `normalizeSystemConfigValue` 不校验白名单/空选 | API 可写入垃圾或空串 |
| registry 文件尾部残留 `;` | 脏文件 |
| 文案「拒接」笔误 | 信任感 |
| 前端可勾空后点保存 | 无意义失败 |

---

## 二、方案（瑞士军刀：只改编辑层 + 保存规范化）

**存储格式不变**：仍为逗号分隔字符串，创建侧 `split` 逻辑无需改。

1. **定义层**（`system-config-definitions.json`）  
   - `enum` + `enumLabels`  
   - 描述标明「至少一项」；修正拒绝创建文案  

2. **类型层**  
   - 后端 `SystemConfigDefinition`  
   - 前端 `AdminSystemConfigDefinition`（已有）  

3. **规范化**（`normalizeSystemConfigValue`）  
   - 有 `enum`：分割 → 去重 → 拒非法 → **至少一项** → 按 `enum` **定义顺序**输出  

4. **UI**（`ConfigField.vue`）  
   - 有 `enum` 渲染复选框网格  
   - 禁止取消最后一项 + i18n 提示  
   - 勾选顺序与后端一致（按定义序 join）  

5. **测试**（`src/lib/system-config-enum.test.ts`）  
   - 合法子集排序、去重、非法、空选、默认值全量  

**明确不做：** 新配置类型引擎、单选 enum 组件库、改创建校验 SQL。

---

## 四、踩坑与建议

| 项 | 说明 |
|----|------|
| tsconfig exclude registry | 根 `tsc` 可能不编译 registry；以 vitest 导入为准，勿假设 tsc 已覆盖 |
| 顺序 | UI 与 normalize 都按 definition.enum 排序，避免「保存后勾选乱跳」 |
| 扩展新多选 | 仅在 definitions 加 `enum`/`enumLabels` 即可复用 ConfigField + normalize |
